+++ practice | Best run before, best run after
--- task
You timed the same dispersion run five times with the old code and five times with the new code. Write a function `speedup(before, after)` that says how many times faster the new code is.

- `before` and `after` are lists of timings in seconds, one per repeat, in any order.
- Use the fastest run of each list, since noise can only ever add time.
- Return the old best divided by the new best, rounded to 2 decimal places. A number below 1 means the new code is slower.
- If either list is empty, raise `ValueError`.

So `speedup([2.41, 2.30, 2.36], [0.52, 0.49, 0.55])` is `2.30 / 0.49`, which rounds to `4.69`.
--- starter
def speedup(before, after):
    pass
--- solution
def speedup(before, after):
    """Old best time over new best time: how many times faster the new code is."""
    if not before or not after:
        raise ValueError("need at least one timing of each version")
    return round(min(before) / min(after), 2)
--- hint
Which single number from a list of repeats is the fairest estimate of what the code itself costs?
--- hint
Take `min` of each list and divide. Check for an empty list first, before calling `min`.
--- check case | Five repeats of each version

--- check case | The best run, not the average

--- check test | An empty list is an error

+++ practice | Follow the time down the call tree
--- task
A profile of a simulator is given as three dictionaries:

- `cum` maps each function name to its cumtime in seconds (its own time plus everything it calls);
- `own` maps each function name to its tottime in seconds (its own lines only);
- `calls` maps a function name to the list of functions it calls. A function that calls nothing may be missing from `calls`, or map to an empty list.

Write a function `walk_down(cum, own, calls, root)` that starts at `root` and walks down to the hotspot, returning the list of names it visited, `root` first. At each function:

- if it calls nothing, stop there;
- otherwise pick the function it calls with the largest cumtime (the first one in its list on a tie). If the current function's own time is at least that cumtime, stop at the current function: its own lines are where the time goes. Otherwise move down to the picked function and repeat.

So if `main` calls `step`, `step` has own time 5.0 and calls only `log`, whose cumtime is 1.0, the walk from `main` is `["main", "step"]`.
--- starter
def walk_down(cum, own, calls, root):
    pass
--- solution
def walk_down(cum, own, calls, root):
    """Names from root down to the hotspot, following the largest cumtime."""
    path = [root]
    node = root
    while calls.get(node):
        child = max(calls[node], key=lambda name: cum[name])   # first one wins a tie
        if own[node] >= cum[child]:
            break
        path.append(child)
        node = child
    return path
--- hint
Keep a current function and a list of visited names. Loop while the current function calls something.
--- hint
`max(names, key=lambda name: cum[name])` picks the largest cumtime, and on a tie it returns the first one. Compare the current function's own time with that cumtime before moving down.

+++ practice | Own time from total time
--- task
Some tools only report cumtime. If each function is called from one place only, a function's own time is its cumtime minus the cumtimes of the functions it calls.

Write two functions:

- `own_times(cum, calls)` returns a dictionary that maps every name in `cum` to its own time, rounded to 3 decimal places. `cum` maps names to cumtimes in seconds; `calls` maps a name to the list of names it calls, and a function that calls nothing may be missing from it.
- `hotspot(cum, calls)` returns a tuple `(name, own_time)` for the function with the largest own time, taking the one that comes first in `cum` on a tie.

So with `cum = {"drag": 1.25, "table": 0.8, "interp": 0.3}` and `calls = {"drag": ["table", "interp"]}`, the own time of `drag` is `1.25 - 0.8 - 0.3`, which rounds to `0.15`.
--- starter

    pass

    pass
--- solution
def own_times(cum, calls):
    """Each function's own time: its cumtime minus what the functions it calls took."""
    return {name: round(t - sum(cum[c] for c in calls.get(name, [])), 3) for name, t in cum.items()}


def hotspot(cum, calls):
    """The function whose own lines take the most time, and that time."""
    own = own_times(cum, calls)
    name = max(own, key=own.get)
    return name, own[name]
--- hint
`calls.get(name, [])` gives an empty list for a function that calls nothing, so the same formula works for leaves.
--- hint
A dictionary keeps the order its keys were added, and `max` returns the first of several equal values, so `max(own, key=own.get)` settles ties the way the task asks.

+++ practice | The most one fix can buy
--- task
Write a function `amdahl(p, s)` that returns the overall speed-up of a program when a part that takes the fraction `p` of its run time is made `s` times faster, using Amdahl's law: one divided by (1 minus p, plus p divided by s).

- Round the answer to 3 decimal places.
- `s` may be `float("inf")`, a part made infinitely fast.
- If `p` is 1 and `s` is infinite, the whole run takes no time: return `float("inf")`.
- If `p` is below 0 or above 1, or `s` is 0 or less, raise `ValueError`.

So `amdahl(0.4, 5)` is `1 / (0.6 + 0.08)`, which rounds to `1.471`.
--- starter
def amdahl(p, s):
    pass
--- solution
def amdahl(p, s):
    """Overall speed-up when a fraction p of the run is made s times faster."""
    if not 0.0 <= p <= 1.0 or s <= 0:
        raise ValueError("p must be in [0, 1] and s must be positive")
    new_time = (1.0 - p) + p / s          # p / inf is 0.0
    if new_time == 0.0:
        return float("inf")
    return round(1.0 / new_time, 3)
--- hint
Work out the new run time as a fraction of the old one first: the untouched part stays, the sped-up part shrinks.
--- hint
In Python, a number divided by `float("inf")` is `0.0`, so the formula already handles an infinite `s`. The one case it cannot handle is a new run time of exactly zero.
--- check case | A 40 percent part made 5 times faster
amdahl(0.4, 5)
=> 1.471
--- check case | The ceiling for a 30 percent part
amdahl(0.3, float("inf"))
=> 1.429
--- check case | The whole run, and none of it
(amdahl(1.0, float("inf")), amdahl(1.0, 4), amdahl(0.0, 50))
=> (float("inf"), 4.0, 1.0)
--- check test | Impossible inputs are errors
raises(ValueError, lambda: amdahl(1.2, 2)) and raises(ValueError, lambda: amdahl(-0.1, 2)) and raises(ValueError, lambda: amdahl(0.5, 0))

+++ question | What the profiler inflates
--- ask
Under cProfile, `density` (called 29,500 times, a few microseconds each) shows 60 percent of the run, and `solve_orbit` (called 3 times, about a tenth of a second each) shows 30 percent. Without the profiler, how do their real shares most likely compare with these?
--- choice
The shares are exact: cProfile records every call, so its percentages are the real ones.
--- choice correct
The real share of `density` is probably smaller than 60 percent, because the profiler adds a small cost to every call and return, and `density` makes 29,500 calls against 3.
--- choice
The real share of `solve_orbit` is probably smaller, because the profiler slows long functions the most.
--- choice
Both shares shrink by the same factor, so the ratio of 60 to 30 stays the same.
--- why
cProfile is deterministic: its call counts are exact, but it does some bookkeeping on every call and every return. That cost grows with the number of calls, not with how long each call takes, so code made of many small calls looks bigger under the profiler than it really is. Use the profile to find where the time is, then measure the fix without the profiler, with `timeit`, against a baseline taken the same way.

+++ practice | The first packet ID seen twice
--- task
A ground station logs packet IDs in the order they arrive. Write a function `first_repeat(ids)` that returns the first ID to turn up a second time: the one whose second appearance comes earliest in the list. Return `None` if no ID repeats.

- IDs can be numbers or strings.
- It must be linear in the number of IDs: one check runs it on 300,000 packets, which a pair-by-pair comparison cannot finish.

So `first_repeat([7, 3, 9, 3, 7])` is `3`: its second appearance, at position 3, comes before the second 7, at position 4.
--- starter
def first_repeat(ids):
    pass
--- solution
def first_repeat(ids):
    """The first ID whose second appearance comes earliest, or None."""
    seen = set()
    for x in ids:
        if x in seen:
            return x
        seen.add(x)
    return None
--- hint
Walk the list once. What do you need to remember about the IDs you have already passed, and which container answers "have I seen this?" in about the same time however big it gets?
--- hint
A set: check `x in seen` before adding `x`. The first time the check is true, that ID is the answer.
--- check case | The example

=> 3
--- check case | No repeats, and no packets

=> (None, None)
--- check case | Strings, and a repeat right away

+++ practice | The busiest stretch of a flight
--- task
Write a function `busiest_window(x, w)` that finds the stretch of `w` consecutive samples with the largest sum in the load samples `x`, and returns a tuple `(start, mean)`:

- `start` is the index of the first sample of that stretch, as a plain whole number. On a tie, take the earliest stretch.
- `mean` is the average of the `w` samples in it, as a plain float rounded to 6 decimal places.
- `x` is a list or a 1-D NumPy array. If `w` is less than 1 or more than `len(x)`, raise `ValueError`.
- It must be linear in the number of samples, whatever `w` is: one check uses 2,000,000 samples and a window of 100,000.

So `busiest_window([1, 3, 2, 6, 1, 1], 2)` is `(2, 4.0)`: the stretch 2, 6 has the largest sum, 8.
--- starter
import numpy as np


def busiest_window(x, w):
    pass
--- solution
import numpy as np


def busiest_window(x, w):
    """Start and mean of the w-sample stretch with the largest sum."""
    x = np.asarray(x, dtype=np.float64)
    if w < 1 or w > x.size:
        raise ValueError("need 1 <= w <= len(x)")
    totals = np.concatenate(([0.0], np.cumsum(x)))    # totals[k] = sum of the first k samples
    sums = totals[w:] - totals[:-w]                     # one subtraction per stretch
    start = int(np.argmax(sums))                        # argmax returns the first maximum
    return start, round(float(sums[start]) / w, 6)
--- hint
With running totals, the sum of any stretch is one subtraction, however long the stretch is.
--- hint
Put a 0 in front of the cumulative sum, so that the sum of the stretch starting at `i` is `totals[i + w] - totals[i]`. Slicing gives every stretch at once, and `np.argmax` returns the first position of the largest value.
--- check case | The example

=> (2, 4.0)
--- check case | A tie goes to the earliest stretch
busiest_window([5, 0, 5, 0, 5], 2)
=> (0, 2.5)
--- check case | The window is the whole signal
busiest_window([2.0, 4.0], 2)
=> (0, 3.0)
--- check test | A window that does not fit is an error
raises(ValueError, lambda: busiest_window([1.0, 2.0], 0)) and raises(ValueError, lambda: busiest_window([1.0, 2.0], 3))
--- check test | 2,000,000 samples, a window of 100,000

+++ practice | Packets in the last few seconds
--- task
Packets arrive at the times `times`, in seconds, sorted from earliest to latest; several packets may share a time. For each packet, the ground software wants to know how many packets arrived in the `window` seconds up to and including it.

Write a function `recent_counts(times, window)` that returns a list with one whole number per packet: for the packet at position `i`, the count of packets at positions `0` to `i` (itself included) whose time is greater than `times[i] - window`.

- A packet exactly `window` seconds earlier is not counted.
- `window` is greater than 0. An empty `times` gives `[]`.
- It must be linear in the number of packets: one check uses 500,000 packets.

So `recent_counts([0.0, 0.4, 1.0, 1.1, 2.5], 1.0)` is `[1, 2, 2, 3, 1]`.
--- starter
def recent_counts(times, window):
    pass
--- solution
from collections import deque


def recent_counts(times, window):
    """For each packet, how many packets so far arrived in the last `window` seconds."""
    recent = deque()
    counts = []
    for t in times:
        recent.append(t)
        while recent[0] <= t - window:     # too old for this packet, so too old for every later one
            recent.popleft()
        counts.append(len(recent))
    return counts
--- hint
Times only go up. Once a packet is too old for one packet, it is too old for every later packet too, so it can be thrown away for good.
--- hint
Keep the packets still inside the window in a `collections.deque`: append each new time at the back, then pop from the front while the front time is `window` or more seconds older. The answer for each packet is the deque's length.
--- check case | The example
recent_counts([0.0, 0.4, 1.0, 1.1, 2.5], 1.0)
=> [1, 2, 2, 3, 1]
--- check case | Packets that share a time
recent_counts([1.0, 1.0, 1.0, 3.0], 0.5)
=> [1, 2, 3, 1]
--- check case | Exactly one window apart is not counted, and no packets

--- check test | 500,000 packets at 1 kHz

--- task
Before any detailed conjunction check, a screening tool keeps only the pairs of objects whose altitudes are close. Write a function `altitude_pairs(alts, tol)` that returns how many pairs of different objects have altitudes that differ by `tol` or less.

- `alts` is a list or 1-D array of altitudes in kilometers, in no particular order; two objects may share an altitude.

- Return a plain whole number.
- It must take about n log n steps for n objects, not n squared: one check uses 200,000 objects.

So `altitude_pairs([400.0, 402.0, 399.5, 550.0], 2.0)` is `2`: 400 with 402, and 400 with 399.5. (402 and 399.5 differ by 2.5.)
--- starter
def altitude_pairs(alts, tol):
    pass
--- solution
def altitude_pairs(alts, tol):
    """How many pairs of objects have altitudes within tol of each other."""
    a = sorted(alts)
    count = 0
    low = 0
    for high, h in enumerate(a):
        while h - a[low] > tol:     # too far below h, and so too far below every later altitude
            low += 1
        count += high - low          # every altitude from a[low] up to just before h pairs with h
    return count
--- hint
After sorting, the altitudes close to a given one sit right next to it. For each altitude, the ones within `tol` below it form one unbroken run.
--- hint
Sort once. Walk the sorted list with a second index `low` that marks the lowest altitude still within `tol` of the current one; it only ever moves forward. Each altitude pairs with every altitude from `low` up to just before it.

+++ question | Three sizes of the same job
--- ask
A new orbit-matching routine takes 0.30 s on 5,000 objects and 2.40 s on 10,000 objects. If its time grows like n to the power k, what is k?
--- answer
3
3.0
k = 3
k=3
three
--- why
Doubling n multiplied the time by 2.40 / 0.30 = 8. The exponent is k = log(8) / log(2) = 3, so the work grows like n cubed: a loop inside a loop inside a loop over the objects. Going to 20,000 objects would take about 8 times longer again, about 19 seconds. A different algorithm, not a faster version of the same one, is the fix.

def mach(v, T):

import numpy as np


def nearest_station(points, stations, max_bytes):
    """Index of the nearest station for every point, a strip of points at a time."""
    rows = max(1, max_bytes // (len(stations) * 3 * 8))    # rows whose (rows, M, 3) float64 array fits
    nearest = np.empty(len(points), dtype=np.int64)
    for start in range(0, len(points), rows):
        d = points[start:start + rows, None, :] - stations[None, :, :]
        d2 = np.einsum("ijk,ijk->ij", d, d)                   # squared distances, no d**2 array

    return nearest

+++ question | The price of one broadcast
--- ask
`a` holds 2,000 float64 altitudes and `b` holds 50,000. A script runs:

```python
d = a[:, None] - b[None, :]
score = (d * d).sum(axis=1)
```

About how much memory do the arrays need at the peak, ignoring `a`, `b` and the small `score`?
--- choice
About 1.6 MB: 2,000 plus 50,000 numbers, since broadcasting copies nothing.
--- choice
About 800 MB: the one (2000, 50000) array `d`.
--- choice correct
About 1.6 GB: `d` is a (2000, 50000) float64 array of 800 MB, and `d * d` makes a second one of the same size while `d` still exists.
--- choice
About 8 GB: every pair needs a full copy of `b`.
--- why
Broadcasting stretches the inputs without copying them, but the result is a real array with the broadcast shape: 2,000 × 50,000 × 8 bytes = 800 MB. Because `d` has a name, it stays alive while `d * d` builds another 800 MB array, so the peak is about 1.6 GB before the sum shrinks it. Working a strip of rows at a time, or using `np.einsum("ij,ij->i", d, d)` to square and add in one step, keeps the peak far lower.

def thread_ranges(n, threads):
    """Consecutive (start, stop) chunks, as equal as possible, longer ones first."""
    base, extra = divmod(n, threads)
    ranges = []
    start = 0
    for i in range(threads):
        stop = start + base + (1 if i < extra else 0)
        ranges.append((start, stop))
        start = stop
    return ranges


def split_sum(x, threads):
    """Sum each chunk, then sum the chunk totals: the grouping a parallel reduction uses."""
    total = 0.0
    for start, stop in thread_ranges(len(x), threads):
        part = 0.0
        for i in range(start, stop):
            part += x[i]
        total += part
    return total
--- hint

--- hint

import numpy as np


def layout(a):
    """C, F or A: the memory layout Numba compiles for."""
    if a.flags.c_contiguous:
        return "C"
    if a.flags.f_contiguous:
        return "F"
    return "A"


def type_key(value):
    """What Numba's dispatcher looks at for one argument."""
    if isinstance(value, np.ndarray):
        return ("array", value.dtype.name, value.ndim, layout(value))
    if isinstance(value, bool):          # before int: True is also an int

    if isinstance(value, int):

import heapq


def batch_time(waits, threads):
    """Wall time of a batch of waiting requests on a pool of threads."""
    free_at = [0.0] * min(threads, len(waits))    # when each thread is next free
    for w in waits:

--- solution
def run_schedule(schedule, k):
    """Final total after two threads each run total = total + 1, k times, in this interleaving."""
    if len(schedule) != 6 * k:
        raise ValueError("each thread needs exactly 3 * k steps")
    shared = 0
    register = {"A": 0, "B": 0}
    done = {"A": 0, "B": 0}
    for who in schedule:
        if who not in done or done[who] == 3 * k:
            raise ValueError(f"step for {who!r} is not allowed")
        step = done[who] % 3
        if step == 0:
            register[who] = shared        # read
        elif step == 1:
            register[who] += 1            # add
        else:
            shared = register[who]        # write
        done[who] += 1
    return shared

import heapq


def finish_time(jobs, slots):
    """Wall time when jobs, in order, go to whichever of `slots` runners is free first."""
    free_at = [0.0] * min(slots, len(jobs))
    for job in jobs:
        heapq.heappush(free_at, heapq.heappop(free_at) + job)
    return max(free_at, default=0.0)


def wall_time(jobs, workers, cores, kind, pool):
    """Predicted wall time of a batch, from what the jobs do and which pool runs them."""
    if pool not in ("threads", "processes"):
        raise ValueError(f"unknown pool {pool!r}")
    if kind == "io":
        return round(finish_time(jobs, workers), 3)
    if kind == "python":
        if pool == "threads":
            return round(sum(jobs), 3)                  # one GIL: one job at a time
        return round(finish_time(jobs, min(workers, cores)), 3)
    if kind == "numpy":
        return round(finish_time(jobs, min(workers, cores)), 3)
    raise ValueError(f"unknown kind {kind!r}")

    n = 0

        keep = min(w - 1, len(x))                     # the samples the next stretch may still need

        carry = x[len(x) - keep:]
    return None if best_start is None else (best_start, best_sum / w)

import numpy as np


def pages_read(n_rows, n_channels, itemsize, channel, row_start, row_stop, layout, page=4096):
    """Distinct pages holding any byte of one channel over a range of rows."""
    rows = np.arange(row_start, row_stop, dtype=np.int64)
    if layout == "row":
        first = (rows * n_channels + channel) * itemsize
    elif layout == "column":
        first = (channel * n_rows + rows) * itemsize
    else:

    last = first + itemsize - 1                        # a sample may end on the next page
    return int(np.unique(np.concatenate((first // page, last // page))).size)

import numpy as np


def table_lookup(x_tab, y_tab):
    """Build a straight-line table once; the returned lookup refuses to go past its edges."""
    xs = np.array(x_tab, dtype=np.float64)      # own copies: the caller cannot change the table later
    ys = np.array(y_tab, dtype=np.float64)
    low, high = xs[0], xs[-1]

    def lookup(x):
        q = np.asarray(x, dtype=np.float64)
        if np.any(q < low) or np.any(q > high):
            raise ValueError("outside the table")
        out = np.interp(q, xs, ys)
        return float(out) if out.ndim == 0 else out

    return lookup

from collections import OrderedDict


def lru_misses(keys, maxsize):
    """Misses of a least-recently-used cache of the given size over this sequence of calls."""
    cache = OrderedDict()                      # oldest use first, newest last
    misses = 0
    for k in keys:
        if k in cache:
            cache.move_to_end(k)               # a hit makes it the most recently used
            continue
        misses += 1
        if maxsize == 0:
            continue
        cache[k] = True
        if maxsize is not None and len(cache) > maxsize:
            cache.popitem(last=False)          # throw out the least recently used
    return misses
--- hint
Keep the stored keys in order of their last use. A hit moves a key to the newest end; a miss adds it there and, if the cache is now too full, removes the oldest.
--- hint
`collections.OrderedDict` has `move_to_end(key)` and `popitem(last=False)`, which removes the oldest entry.

import numpy as np


def make_impulse(t, F):
    """Precompute running impulse at the samples; return a fast impulse(t0, t1)."""
    t = np.array(t, dtype=np.float64)
    F = np.array(F, dtype=np.float64)
    running = np.concatenate(([0.0], np.cumsum(0.5 * (F[1:] + F[:-1]) * np.diff(t))))

    def since_start(x):
        x = np.asarray(x, dtype=np.float64)
        if np.any(x < t[0]) or np.any(x > t[-1]):
            raise ValueError("time outside the thrust curve")
        k = np.clip(np.searchsorted(t, x, side="right") - 1, 0, len(t) - 2)   # the sample at or before x
        return running[k] + 0.5 * (F[k] + np.interp(x, t, F)) * (x - t[k])

    def impulse(t0, t1):
        out = since_start(t1) - since_start(t0)
        return float(out) if np.ndim(out) == 0 else out

    return impulse
--- hint

import time


def interleaved(fa, fb, warmup, rounds, clock=time.perf_counter):
    """Warm both versions up, then time them in alternating rounds."""
    for _ in range(warmup):              # untimed: compile, load, fill caches, for both
        fa()
        fb()
    times_a, times_b = [], []
    for _ in range(rounds):
        for f, times in ((fa, times_a), (fb, times_b)):
            t0 = clock()
            f()
            times.append(clock() - t0)
    return times_a, times_b

def is_number(field):
    try:
        float(field)
    except ValueError:
        return False
    return True


def top_own(text, k):
    """The k functions with the largest own time, with calls and share of all own time."""
    rows = []
    for line in text.splitlines():
        fields = line.split(None, 5)
        if len(fields) < 6:
            continue
        calls = fields[0].split("/")[0]
        if not all(is_number(f) for f in [calls] + fields[1:5]):
            continue
        location = fields[5].strip()
        if location.endswith(")") and "(" in location:
            name = location[location.rindex("(") + 1:-1]
        else:
            name = location
        rows.append((name, int(calls), float(fields[1])))
    total = sum(own for _, _, own in rows)
    ranked = sorted(rows, key=lambda r: r[2], reverse=True)[:k]     # sorted is stable: ties keep table order
    return [(name, calls, own, round(own / total, 3)) for name, calls, own in ranked]

from collections import Counter


def exact_blocks(sizes, block):
    """How many stretches of consecutive frames add up to exactly `block` bytes."""
    seen = Counter({0: 1})           # how many prefixes had each running total

    count = 0
    for s in sizes:
        total += s
        count += seen[total - block]   # every earlier prefix this far below closes a stretch here
        seen[total] += 1
    return count

from collections import deque

import numpy as np


def max_swing(chunks, w):
    """Start and size of the w-sample stretch whose max minus min is largest, across chunks."""
    high = deque()        # (index, value), values falling front to back: the front is the window's max
    low = deque()         # (index, value), values rising front to back: the front is the window's min
    best = None
    i = -1
    for chunk in chunks:
        for v in np.asarray(chunk, dtype=np.float64).tolist():    # copies the values out of the buffer
            i += 1
            while high and high[-1][1] <= v:
                high.pop()
            high.append((i, v))
            while low and low[-1][1] >= v:
                low.pop()
            low.append((i, v))
            if high[0][0] <= i - w:
                high.popleft()
            if low[0][0] <= i - w:
                low.popleft()
            if i >= w - 1:
                swing = high[0][1] - low[0][1]
                if best is None or swing > best[1]:
                    best = (i - w + 1, swing)
    return best

import numpy as np


def flight_times(v0, m, cda, dt, block):
    """Flight time of every case, vectorized over the cases of each block."""
    v0 = np.asarray(v0, dtype=np.float64)
    out = np.empty(v0.size)
    for s in range(0, v0.size, block):
        v = v0[s:s + block].copy()
        h = np.zeros_like(v)
        t = np.zeros_like(v)
        flying = np.ones(v.shape, dtype=bool)
        while flying.any():
            rho = 1.225 * np.exp(-h / 8500.0)
            v_new = v + (-9.81 - 0.5 * rho * v * np.abs(v) * cda / m) * dt
            h_new = h + v_new * dt
            v = np.where(flying, v_new, v)             # landed cases keep their values
            h = np.where(flying, h_new, h)
            t = np.where(flying, t + dt, t)
            flying = flying & (h >= 0.0)
        out[s:s + block] = t
    return out

+++ problem | Deal the cases out, and time the pool
--- task
Predict what a process pool does with a dispersion. Write a function `pool_run(durations, workers, chunksize, trip_s)` that returns a tuple `(wall, speedup, efficiency)`:

- `durations` lists each case's run time in seconds; there is at least one case.
- The cases are cut, in order, into chunks of `chunksize` consecutive cases (the last chunk may be shorter). Each chunk goes, in order, to whichever of the `workers` workers is free first; at the start every worker is free. A chunk keeps its worker busy for `trip_s` (the fixed cost of one trip through the pipe) plus the sum of its cases' durations.
- `wall` is when the last worker finishes, rounded to 3 decimal places.
- `speedup` is the serial time, the plain sum of the durations with no trips, divided by the unrounded wall time, rounded to 2 decimal places. `efficiency` is the unrounded speed-up divided by `workers`, rounded to 2 decimal places.

--- solution
import heapq


def pool_run(durations, workers, chunksize, trip_s):
    """Wall time, speed-up and efficiency of a pool that deals out chunks of cases."""
    chunks = [trip_s + sum(durations[i:i + chunksize]) for i in range(0, len(durations), chunksize)]
    free_at = [0.0] * min(workers, len(chunks))
    for c in chunks:
        heapq.heappush(free_at, heapq.heappop(free_at) + c)   # to the worker free soonest
    wall = max(free_at)
    s = sum(durations) / wall
    return round(wall, 3), round(s, 2), round(s / workers, 2)

import numpy as np


def block_stats(read_blocks, n_channels):
    """Per-channel mean, standard deviation and peak size from byte blocks that ignore row edges."""
    row_bytes = 8 * n_channels

    def rows():
        leftover = b""
        for block in read_blocks():
            data = leftover + bytes(block)                   # copy out of the reader's buffer
            usable = len(data) - len(data) % row_bytes        # whole rows only
            if usable:
                yield np.frombuffer(data[:usable], dtype=np.float64).reshape(-1, n_channels)
            leftover = data[usable:]                          # the part of a row still to come

    n = 0
    total = np.zeros(n_channels)
    peak = np.zeros(n_channels)
    for r in rows():
        total += r.sum(axis=0)
        peak = np.maximum(peak, np.abs(r).max(axis=0))
        n += len(r)
    mean = total / n
    sq = np.zeros(n_channels)
    for r in rows():
        sq += ((r - mean) ** 2).sum(axis=0)
    return mean, np.sqrt(sq / n), peak

import math

import numpy as np


def kepler_table(e, tol):
    """The fewest-point table of E against M whose straight-line error meets tol."""
    E_grid = np.linspace(0.0, 2 * math.pi, 200_001)
    bend = np.max(e * np.abs(np.sin(E_grid)) / (1 - e * np.cos(E_grid)) ** 3)
    gap = math.sqrt(8 * tol / bend)
    n = math.ceil(2 * math.pi / gap) + 1
    M = np.linspace(0.0, 2 * math.pi, n)
    E = M.copy()
    while True:                                    # Newton's method on every table point at once
        step = (E - e * np.sin(E) - M) / (1 - e * np.cos(E))
        E -= step
        if np.max(np.abs(step)) < 1e-12:
            return M, E


def kepler_E(M, M_tab, E_tab):
    """E for any M: wrap into one orbit, interpolate, unwrap."""
    M = np.asarray(M, dtype=np.float64)
    k = np.floor(M / (2 * math.pi))
    E = np.interp(M - 2 * math.pi * k, M_tab, E_tab) + 2 * math.pi * k
    return float(E) if E.ndim == 0 else E

import heapq


def merge_passes(streams):
    """One time-ordered stream of first arrivals, and how many repeats each station had."""
    tagged = [[(t, k, pid) for t, pid in s] for k, s in enumerate(streams)]

def benchmark(old, new, warmup, rounds, noise_pct, clock):
    """Warm up, time in rounds of alternating order, and give a verdict that respects the noise."""
    for _ in range(warmup):
        old()
        new()

    def timed(f):
        t0 = clock()
        f()
        return clock() - t0

    t_old, t_new = [], []
    for r in range(rounds):
        if r % 2 == 0:
            t_old.append(timed(old))
            t_new.append(timed(new))
        else:
            t_new.append(timed(new))
            t_old.append(timed(old))
    old_min, new_min = min(t_old), min(t_new)

    elif new_min > old_min * margin and 4 * old_wins >= 3 * rounds:
        verdict = "slower"
    else:
        verdict = "no change"
    return {"old_min": round(old_min, 6), "new_min": round(new_min, 6), "speedup": round(old_min / new_min, 2),

Every task pickles its own copy of the argument: 200 × 50 MB = 10,000 MB, which is 10 GB, however little of the array each case reads. Sending it once per worker with an `initializer` (8 workers: 400 MB), memory-mapping a saved `.npy` file, or using shared memory moves a small fraction of that, and often turns a parallel run that is slower than serial into a real speed-up.

+++ question | Row groups that cannot be skipped
--- ask
Two Parquet files hold the same 2,000 s of telemetry in 8 row groups each. In file A the rows are sorted by time; in file B they are shuffled. A read with `filters=[("t", ">=", 600.0), ("t", "<", 1400.0)]` fetches about half of file A's time column but all of file B's. Why?
--- choice
File B was written with a weaker compression method.
--- choice correct
In file B every row group holds times from the whole test, so its minimum and maximum of `t` always overlap the filter and no row group can be skipped.
--- choice
Filters only work on the first column of a file.
--- choice
Shuffled rows make Parquet store each column by row instead of by column.
--- why
A reader skips a row group only when its stored minimum and maximum prove that no row can match. Sorted by time, each row group covers a narrow slice of time, and 4 of the 8 fall entirely outside 600 to 1400 s. Shuffled, every row group spans nearly 0 to 2000 s, so every one must be read and filtered row by row. Writing the file sorted by the column you filter on is what makes the statistics useful.

+++ question | Always second
--- ask
To compare two versions, a script warms up nothing, then times the old version followed by the new one, 20 times in a row, always in that order. The new version wins 14 of the 20 pairs, and its fastest run is 3 percent faster. What is the right conclusion?
--- choice
The new version is 3 percent faster: 14 wins out of 20 settles it.
--- choice
The new version is slower: the old one's slowest run was faster than some new runs.
--- choice correct
Nothing yet: whatever runs second can inherit warm caches and a clock that has sped up, so the order alone could produce this; warm both up and alternate the order.
--- choice
Take the mean of all 40 runs instead of the minimum, and the answer will be reliable.
--- why
Order is a hidden variable. With no warm-up and the new version always second, every advantage the machine gives a second call goes to it, and a 3 percent gap is the size of ordinary noise. Warm up both versions, alternate which runs first, check that the answers match, and compare the minimum, the median and the number of wins before claiming a speed-up.

+++ question | After the cases got fast
--- ask
A dispersion spends 30 s in serial set-up and 2,400 s in its cases, one after another. You compile the case code, which makes every case 10 times faster, and then run the cases on 8 processes with perfect scaling. The set-up is unchanged. How many seconds does the whole run take now?
--- answer
60
60 s
60.0
60 seconds
--- why
Compiling brings the cases to 2,400 / 10 = 240 s, and 8 processes bring that to 30 s. The serial set-up still takes 30 s, so the total is 30 + 30 = 60 s, a 40.5 times speed-up from 2,430 s. Half of what is left is now the serial part: by Amdahl's law, more processes can never take the run below 30 s, so the set-up is the next thing to profile.
