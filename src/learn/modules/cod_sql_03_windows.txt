+++ practice | Each reading beside its satellite's figures
--- task
`batt` (`sat_id`, `ts`, `soc`) holds battery samples. `soc` is the state of charge, a fraction from 0 (empty) to 1 (full).

List every reading together with two numbers worked out from its own satellite's readings:

- `n`: how many readings that satellite has in the table
- `sat_max`: that satellite's highest reading

Keep every row of the table. Return `sat_id`, `ts`, `soc`, `n` and `sat_max`, sorted by `sat_id`, then `ts`.
--- starter
SELECT sat_id, ts, soc, COUNT(*) AS n, MAX(soc) AS sat_max
FROM batt
GROUP BY sat_id
ORDER BY sat_id, ts;
--- solution
SELECT sat_id, ts, soc,
       COUNT(*) OVER (PARTITION BY sat_id) AS n,
       MAX(soc) OVER (PARTITION BY sat_id) AS sat_max
FROM batt
ORDER BY sat_id, ts;
--- hint
Run the starter: GROUP BY squashed each satellite into one row. You want the satellite's figures written onto every row instead.
--- hint
Put `OVER (PARTITION BY sat_id)` after `COUNT(*)` and after `MAX(soc)`, and drop the GROUP BY.
--- check result | All 16 readings, each with its satellite's count and maximum

+++ practice | Readings well below the satellite's best
--- task
Using `batt` (`sat_id`, `ts`, `soc`), list the readings that are more than 0.06 below their own satellite's highest reading.

Return `sat_id`, `ts`, `soc` and `sat_max` (that satellite's highest reading), sorted by `sat_id`, then `ts`.

The starter is the query most people try first. Run it and read the error before you change it.
--- starter
SELECT sat_id, ts, soc, MAX(soc) OVER (PARTITION BY sat_id) AS sat_max
FROM batt
WHERE soc < MAX(soc) OVER (PARTITION BY sat_id) - 0.06
ORDER BY sat_id, ts;
--- solution
WITH w AS (
    SELECT sat_id, ts, soc,
           MAX(soc) OVER (PARTITION BY sat_id) AS sat_max
    FROM batt
)
SELECT sat_id, ts, soc, sat_max
FROM w
WHERE soc < sat_max - 0.06
ORDER BY sat_id, ts;
--- hint
WHERE runs before any window function is worked out, so the maximum does not exist yet when WHERE wants it.
--- hint
Compute `sat_max` in a CTE first. In the outer query it is an ordinary column, and WHERE can test it.

+++ practice | Each satellite's share of the samples
--- task
Return one row per satellite in `batt`:

- `sat_id`
- `samples`: its number of readings
- `pct`: its share of all the readings in the table, as a percentage rounded to 1 decimal

Sort by `sat_id`. Write it as one grouped query, with a window over the grouped rows for the total. The total must come from the data, not be typed in.
--- starter
SELECT sat_id, COUNT(*) AS samples, 0 AS pct
FROM batt
GROUP BY sat_id
ORDER BY sat_id;
--- solution
SELECT sat_id,
       COUNT(*) AS samples,
       ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS pct
FROM batt
GROUP BY sat_id
ORDER BY sat_id;
--- hint
After GROUP BY there are four rows, one per satellite, each with its `COUNT(*)`. A window runs after grouping, so it can add up those four counts.
--- hint
`SUM(COUNT(*)) OVER ()` is the total of the per-satellite counts, on every row. Multiply by `100.0`, not `100`, so the division keeps its decimals.
--- check result | 37.5, 31.3, 25.0 and 6.3 percent
ordered
[["SAT-011", 6, 37.5], ["SAT-012", 5, 31.3], ["SAT-013", 4, 25.0], ["SAT-014", 1, 6.3]]

+++ practice | Latest reading against the fleet
--- task
The power engineer wants one row per satellite: its latest `batt` reading, next to two baselines.

- `sat_id`, `ts` and `soc` of that satellite's latest reading
- `sat_avg`: the satellite's average over all its readings, rounded to 3
- `fleet_avg`: the average of every reading in the table, rounded to 3
- `status`: `'below fleet'` if the latest reading is below the fleet average (unrounded), otherwise `'ok'`

Both averages must use every reading in the table, not only the latest ones. Sort by `sat_id`. Use only what this lesson teaches: aggregates with OVER, a CTE and CASE.
--- starter
SELECT sat_id, MAX(ts) AS ts, 0 AS soc, 0 AS sat_avg, 0 AS fleet_avg, 'ok' AS status
FROM batt
GROUP BY sat_id
ORDER BY sat_id;
--- solution
WITH w AS (
    SELECT sat_id, ts, soc,
           MAX(ts)  OVER (PARTITION BY sat_id) AS latest_ts,
           AVG(soc) OVER (PARTITION BY sat_id) AS sat_avg,
           AVG(soc) OVER ()                    AS fleet_avg
    FROM batt
)
SELECT sat_id, ts, soc,
       ROUND(sat_avg, 3)   AS sat_avg,
       ROUND(fleet_avg, 3) AS fleet_avg,
       CASE WHEN soc < fleet_avg THEN 'below fleet' ELSE 'ok' END AS status
FROM w
WHERE ts = latest_ts
ORDER BY sat_id;
--- hint

--- solution

    SELECT sat_id, soc,
           unixepoch(LEAD(ts) OVER (PARTITION BY sat_id ORDER BY ts)) - unixepoch(ts) AS hold_s

       ROUND(SUM(soc * hold_s) / SUM(hold_s), 3) AS tw_avg

+++ question | Counting with ties
--- ask
A table `k` holds four rows with the values 1, 2, 2 and 3. What four numbers does this print, in order?

```sql
SELECT COUNT(*) OVER (ORDER BY v) AS c
FROM k
ORDER BY v;
```
--- answer
1, 3, 3, 4
1,3,3,4
1 3 3 4
--- why
With an ORDER BY and no frame clause, the frame is `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`. In RANGE mode CURRENT ROW means the current row and all its peers, the rows with the same value. So both 2s see the 1 and both 2s: 3 rows each. With `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` the answer would be 1, 2, 3, 4, with the order of the two 2s left to chance.

+++ question | What the MAX-of-time join returns
--- ask
A teammate finds the latest reading per satellite and channel in `tlm` by joining each row to its key's `MAX(ts)`:

```sql
SELECT t.sat_id, t.channel, t.ts, t.value
FROM tlm AS t
JOIN (SELECT sat_id, channel, MAX(ts) AS max_ts
      FROM tlm GROUP BY sat_id, channel) AS m
  ON m.sat_id = t.sat_id AND m.channel = t.channel AND m.max_ts = t.ts;
```

There are four keys. SAT-021's newest amps sample and its newest volt sample each arrived twice; SAT-022's newest amps and volt samples arrived once each. How many rows does the query return?
--- answer
6
six
--- why
The join keeps every row whose `ts` equals its key's newest time, and duplicates share that time. So SAT-021 gives 2 + 2 rows and SAT-022 gives 1 + 1: six rows for four keys. It is the fan-out from the joins module. `ROW_NUMBER() ... = 1` always returns exactly one row per key, whatever the duplicates.

+++ question | Which label the last island gets
--- ask
A sensor's flags, in time order, are `1 1 0 1 0 0 1 1 1`. With the difference-of-row-numbers trick (row number over all rows minus row number over the rows with the same flag), what label do the three rows of the last island of 1s get?
--- answer
3
three
--- why
Number all nine rows 1 to 9. The 1-rows are rows 1, 2, 4, 7, 8 and 9, and counting only them gives 1 to 6. The last island is rows 7, 8 and 9, counted 4, 5 and 6 among the 1s: 7 − 4 = 8 − 5 = 9 − 6 = 3. The earlier islands get 0 (rows 1 and 2) and 1 (row 4). Each jump equals the number of 0-rows that sat in between.

+++ practice | A station contact report
--- task
Each ground station bills by contact time. Using contacts as in "Contacts per station" (a burst of packets from one satellite at one station; a silence longer than 300 seconds within that satellite and station ends it), return one row per station:

),

+++ question | Which five-minute bin
--- ask
What does this SQLite expression return?

SELECT strftime('%Y-%m-%dT%H:%M:%SZ',

+++ practice | The nearest reading to each anomaly
--- task
`anomaly` (`sat_id`, `ts`, `code`) logs anomalies. For each one, find the same satellite's `batt` reading nearest in time, before or after. If the readings before and after are equally far, take the one before. If there is only one side, take that one.

--- starter

       (SELECT MAX(b.ts) FROM batt AS b WHERE b.sat_id = a.sat_id AND b.ts <= a.ts) AS nearest_ts,
       NULL AS nearest_soc
FROM anomaly AS a
ORDER BY a.sat_id, a.ts;
--- solution
WITH sides AS (
    SELECT a.sat_id, a.ts, a.code,
           (SELECT MAX(b.ts) FROM batt AS b WHERE b.sat_id = a.sat_id AND b.ts <= a.ts) AS before_ts,
           (SELECT MIN(b.ts) FROM batt AS b WHERE b.sat_id = a.sat_id AND b.ts >  a.ts) AS after_ts
    FROM anomaly AS a
),
pick AS (
    SELECT sat_id, ts, code,
           CASE WHEN after_ts IS NULL
                  OR (before_ts IS NOT NULL
                      AND unixepoch(ts) - unixepoch(before_ts) <= unixepoch(after_ts) - unixepoch(ts))
                THEN before_ts ELSE after_ts END AS nearest_ts
    FROM sides
)
SELECT p.sat_id, p.ts, p.code, p.nearest_ts, b.soc AS nearest_soc
FROM pick AS p
JOIN batt AS b ON b.sat_id = p.sat_id AND b.ts = p.nearest_ts
ORDER BY p.sat_id, p.ts;

--- hint

+++ practice | Mode and time in mode, with windows only
--- task
Label every `batt` reading with its satellite's mode at that moment (the latest `mode_log` change at or before it) and with `since_min`: the whole minutes since that mode took effect. Readings with no change at or before them get NULL in both columns.

Do it without any subquery that runs once per reading: stack `mode_log` and `batt` into one stream with UNION ALL, and carry each mode forward with windows. A mode change and a reading at the same moment must count the change as already in force. Return `sat_id`, `ts`, `soc`, `mode` and `since_min`, sorted by `sat_id`, then `ts`.
--- starter
SELECT sat_id, ts, soc, NULL AS mode, NULL AS since_min
FROM batt
ORDER BY sat_id, ts;
--- solution
WITH events AS (
    SELECT sat_id, ts, 0 AS kind, mode, NULL AS soc FROM mode_log
    UNION ALL
    SELECT sat_id, ts, 1 AS kind, NULL, soc FROM batt
),
grouped AS (
    SELECT sat_id, ts, kind, mode, soc,
           COUNT(mode) OVER (PARTITION BY sat_id ORDER BY ts, kind
                             ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS grp
    FROM events
),
filled AS (
    SELECT sat_id, ts, kind, soc,
           MAX(mode) OVER (PARTITION BY sat_id, grp) AS mode,
           MAX(CASE WHEN kind = 0 THEN ts END) OVER (PARTITION BY sat_id, grp) AS mode_from
    FROM grouped
)
SELECT sat_id, ts, soc, mode,
       (unixepoch(ts) - unixepoch(mode_from)) / 60 AS since_min
FROM filled
WHERE kind = 1
ORDER BY sat_id, ts;
--- hint
Give the two kinds of row a `kind` column (0 for a change, 1 for a reading) and order by `ts, kind`, so a change sorts before a reading at the same moment.
--- hint
A running `COUNT(mode)` rises by one at each change and stays flat across the readings after it: that is a group label. Over each group, `MAX(mode)` and the change's `ts` fill every row. Filter to readings only after the windows.

+++ question | How many pairs the all-earlier join builds
--- ask
A table holds 1,000 samples for each of 3 satellites. How many rows does this inner self-join produce?

```sql
SELECT cur.sat_id, cur.ts, prev.ts
FROM samples AS cur
JOIN samples AS prev
  ON prev.sat_id = cur.sat_id
 AND prev.ts < cur.ts;
```
--- answer
1498500
1,498,500
1 498 500
--- why
Within one satellite, the k-th sample pairs with the k − 1 samples before it, so 0 + 1 + … + 999 = 1000 × 999 / 2 = 499,500 pairs. Three satellites give 3 × 499,500 = 1,498,500 rows, to answer a question LAG answers with 3,000 rows in one ordered pass. The pairs grow with the square of the samples per satellite.

+++ problem | A clean status board
--- task
`raw_tm` (`ingest_id`, `sat_id`, `channel`, `ts`, `value`, `station`, `rx_at`, `crc_ok`) holds telemetry as it arrived. One sample is identified by `sat_id`, `channel` and `ts`; some arrived more than once. When copies differ, keep one per sample: a copy that passed its check (`crc_ok` = 1) first, then the one received first (`rx_at`), then the lower `ingest_id`.

After removing the duplicates, return one row per satellite and channel:

- `sat_id`, `channel`, and `ts` and `value` of its newest sample
- `delta`: that value minus the value of the kept sample just before it on the same satellite and channel, rounded to 2; NULL if there is none
- `samples`: how many kept samples the satellite and channel have

Sort by `sat_id`, then `channel`.
--- starter
SELECT sat_id, channel, MAX(ts) AS ts, MAX(value) AS value, NULL AS delta, COUNT(*) AS samples
FROM raw_tm
GROUP BY sat_id, channel
ORDER BY sat_id, channel;
--- solution
WITH kept AS (
    SELECT sat_id, channel, ts, value,
           ROW_NUMBER() OVER (PARTITION BY sat_id, channel, ts
                              ORDER BY crc_ok DESC, rx_at, ingest_id) AS copy_no
    FROM raw_tm
),
clean AS (
    SELECT sat_id, channel, ts, value,
           value - LAG(value) OVER (PARTITION BY sat_id, channel ORDER BY ts) AS delta,
           ROW_NUMBER() OVER (PARTITION BY sat_id, channel ORDER BY ts DESC) AS newest,
           COUNT(*) OVER (PARTITION BY sat_id, channel) AS samples
    FROM kept
    WHERE copy_no = 1
)
SELECT sat_id, channel, ts, value, ROUND(delta, 2) AS delta, samples
FROM clean
WHERE newest = 1
ORDER BY sat_id, channel;

--- task

RANK counts every row before this one and adds 1: six rows come before 12, so its rank is 7. DENSE_RANK counts the distinct values before it: 4, 7 and 9, so 12 is the fourth distinct value. ROW_NUMBER would also give 7 here, but only because 12 has no tie.

+++ question | Ten rows into four buckets
--- ask
`NTILE(4) OVER (ORDER BY v)` runs over a partition of 10 rows. How many rows land in buckets 1, 2, 3 and 4? Give the four sizes in order.
--- answer
3, 3, 2, 2
3,3,2,2
3 3 2 2
--- why
10 = 4 × 2 + 2: every bucket gets 2 rows, and the 2 left over go one each to the first two buckets. Bucket sizes never differ by more than one, and the bigger buckets come first.

+++ question | A running total with a tie
--- ask
A table holds four rows (`t`, `x`): (1, 5), (2, 3), (2, 4) and (3, 1). What is `SUM(x) OVER (ORDER BY t)` on the row (2, 3)?
--- answer
12
twelve
--- why
With an ORDER BY and no frame clause, the frame is `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`, and in RANGE mode the current row brings all its peers. Both rows with `t` = 2 are in the frame, so the sum is 5 + 3 + 4 = 12 on both of them. A ROWS frame would give 8 or 12 depending on which of the tied rows came first.

+++ question | What LAST_VALUE returns
--- ask
What does `LAST_VALUE(soc) OVER (PARTITION BY sat_id ORDER BY ts)` give on each row, when no two readings of a satellite share a `ts`?
--- choice
The satellite's latest reading, on every row.
--- choice correct
The row's own reading, because the default frame ends at the current row.
--- choice
NULL on every row except the satellite's last one.
--- choice
The satellite's latest reading on every row, but only in PostgreSQL; SQLite returns the current row.
--- why
With an ORDER BY inside OVER and no frame, the frame is `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`. LAST_VALUE takes the last row of the frame, and that is the current row (with its peers, which here are none). Both databases behave the same. Write `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`, or use `FIRST_VALUE` with the order reversed, to get the partition's last reading.

+++ question | How many rows a time frame holds
--- ask
One satellite's readings arrive at these seconds: 0, 10, 20, 25, 27, 28 and 60. On the reading at 28 s, how many readings are in the frame `ORDER BY t_s RANGE BETWEEN 10 PRECEDING AND CURRENT ROW`?
--- answer
4
four
--- why
The frame holds every reading with `t_s` from 28 − 10 = 18 up to 28, both ends included: 20, 25, 27 and 28, four readings. A `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW` frame on the same row would hold three readings covering only 3 seconds (25 to 28), and on the reading at 60 it would reach back 35 seconds.

+++ question | The baseline that moved
--- ask
An engineer wants the readings from after 06:30 that sit more than 0.05 below their satellite's average **over the whole day**. She writes:

```sql
WITH w AS (
    SELECT sat_id, ts, soc,
           AVG(soc) OVER (PARTITION BY sat_id) AS day_avg
    FROM soc
    WHERE ts > '2026-06-01T06:30:00Z'
)
SELECT * FROM w WHERE soc < day_avg - 0.05;
```

What is wrong?
--- choice
Nothing: a CTE computes the window before any filtering.
--- choice correct
The WHERE inside the CTE runs before the window, so `day_avg` is the average of the readings after 06:30 only, not of the whole day.
--- choice
A window function cannot be used inside a CTE.
--- choice
`AVG(...) OVER (PARTITION BY sat_id)` needs an ORDER BY to average the whole partition.
--- why
Inside the CTE, WHERE runs first and the window is worked out over the rows that are left, so the baseline moves with the time filter. Move the time filter to the outer query, next to the comparison, and the average is taken over every reading of the day. Without an ORDER BY the frame is already the whole partition; adding one would make it a running average.

+++ question | What the all-earlier self-join costs
--- ask
A report pairs each sample with every earlier sample of the same satellite: `JOIN samples AS prev ON prev.sat_id = cur.sat_id AND prev.ts < cur.ts`. The table grows from 2,000 to 4,000 samples per satellite, with the same number of satellites. About how many times more rows does the join produce?
--- choice
The same number of rows.
--- choice
About 2 times as many.
--- choice correct
About 4 times as many.
--- choice
About 8 times as many.
--- why
Each satellite with n samples gives n(n − 1)/2 pairs, which grows with n²: doubling n multiplies the pairs by about 4 (4000 × 3999 / 2 against 2000 × 1999 / 2 is 4.002). A LAG over the same data handles each row once after one sort, so its work only about doubles.

+++ question | RANK in a dedup
--- ask
A table has 10 rows describing 7 samples. Two samples arrived twice with both copies received in the same second; one sample arrived twice with the copies received a few seconds apart; the other four arrived once. How many rows does this keep?

```sql
WITH n AS (
    SELECT *, RANK() OVER (PARTITION BY sat_id, channel, ts ORDER BY rx_at) AS r
    FROM tlm
)
SELECT * FROM n WHERE r = 1;
```
--- answer
9
nine
--- why
RANK gives rows that tie on the ORDER BY the same number. The two same-second pairs each keep both copies with rank 1; the pair received seconds apart keeps only its earlier copy; the four single samples keep their one row. That is 2 + 2 + 1 + 4 = 9 rows for 7 samples. ROW_NUMBER with a unique tie-breaker such as `rx_at, ingest_id` keeps exactly 7.

+++ question | The first row of the start marks
--- ask
To label runs, a query marks starts with `CASE WHEN flag <> LAG(flag) OVER (PARTITION BY sat_id ORDER BY ts) THEN 1 ELSE 0 END` and labels runs with a running SUM of the marks. What happens on each satellite's first row?
--- choice
The query fails, because LAG has no row to read.
--- choice correct
LAG is NULL, `flag <> NULL` is not true, so the first row gets 0 instead of 1: its first run is labelled 0 and counting the marks misses one run per satellite.
--- choice
The first row gets 1, because a NULL comparison counts as different.
--- choice
LAG reads the last row of the previous satellite, so the mark depends on that satellite.
--- why
Any ordinary comparison with NULL is UNKNOWN, and CASE treats UNKNOWN like false. The runs still come out as separate groups, since label 0 is as good a name tag as any, but a count of starts is one short for every satellite whose first run is the kind you count. `flag IS DISTINCT FROM LAG(flag) ...` (in SQLite also `IS NOT`) treats NULL as a value and marks the first row. The PARTITION BY stops LAG from reaching into another satellite.

+++ question | Choosing a session threshold
--- ask
A year of packet gaps for one satellite shows a big peak at 1 second, dropouts spread from 5 to 40 seconds, nothing at all from 1 minute to 50 minutes, and then passes-apart gaps from 50 minutes to 12 hours. Which inactivity threshold would you choose to cut the packets into passes?
--- choice
30 seconds, just above the packet rate.
--- choice correct
5 minutes, in the empty valley between the longest dropout and the shortest break between passes.
--- choice
2 hours, so that no pass is ever split.
--- choice
50 minutes, the shortest break between passes.
--- why
A threshold shorter than the longest in-pass dropout (40 s) splits passes; one longer than the shortest break between passes (50 minutes) merges them. Anything in the empty valley gives the same passes, so pick a value with room on both sides. 30 seconds would split passes at every longer dropout, 2 hours would merge passes, and 50 minutes sits right on the edge of the next hump.

+++ question | The mean of three buckets
--- ask
One-minute buckets of a channel hold these (count, mean) pairs: (60, 1.0), (60, 2.0) and (30, 4.0). What is the mean of all the samples together?
--- answer
2
2.0
2.00
--- why
Rebuild each bucket's sum: 60 × 1.0 = 60, 60 × 2.0 = 120 and 30 × 4.0 = 120. The total is 300 over 60 + 60 + 30 = 150 samples, so 300 / 150 = 2.0. The plain average of the three means, (1.0 + 2.0 + 4.0) / 3 = 2.33, gives the half-full bucket a full vote. Keep each bucket's sum and count so buckets can be combined later.

+++ question | A handful of lookups in a huge table
--- ask
You need the GPS fix at or before each of 30 anomaly times, from a table of 200 million GPS fixes with an index on `(sat_id, ts)`. Which method fits best?
--- choice
Stack the anomalies and all the GPS fixes with UNION ALL, sort by time, and carry the fix forward with windows.
--- choice correct
For each anomaly, look up the satellite's fixes at or before its time, newest first, with LIMIT 1 (LATERAL in PostgreSQL, a correlated scalar subquery in SQLite).
--- choice
LAG over the GPS table, partitioned by satellite.
--- choice

--- why
With an index, each of the 30 lookups is one hop, so the query touches a few dozen rows.
