+++ question | A script that never sets the stop time
--- ask
This script builds a model and runs it. It never sets the stop time.

```matlab
mdl = 'coolant';
new_system(mdl);
add_block('simulink/Sources/Constant', [mdl '/Heating'], 'Value', '3');
add_block('simulink/Continuous/Integrator', [mdl '/Temp'], ...
          'InitialCondition', '-6');
add_block('simulink/Sinks/To Workspace', [mdl '/Log'], ...
          'VariableName', 'h', 'SaveFormat', 'Timeseries');
add_line(mdl, 'Heating/1', 'Temp/1');
add_line(mdl, 'Temp/1', 'Log/1');
out = sim(mdl);
out.h.Data(end)
```

What value is printed?
--- answer
24
24.0
--- why
A new model's stop time is 10 s, so the run covers 0 to 10 s. The Integrator starts at its Initial condition, $-6$, and adds up a constant 3 every second: $-6 + 3 \times 10 = 24$. It passes through zero at $t = 2$ s on the way. Leaving the stop time at its default is legal, but a script that means a particular run length should set `StopTime` itself.

+++ question | The line that will not draw
--- ask
This script should build a descending probe: a sink rate feeding an altitude Integrator, logged to the workspace. One line stops the script with an error. Which one?

```matlab
mdl = 'probe';                                                   % line 1
new_system(mdl);                                                 % line 2
add_block('simulink/Sources/Constant', [mdl '/Sink rate'], 'Value', '-6');     % line 3
add_block('simulink/Continuous/Integrator', [mdl '/Altitude'], ...
          'InitialCondition', '1500');                           % line 4
add_line(mdl, 'Sink rate/1', 'Altitude/1');                      % line 5
add_block('simulink/Sinks/To Workspace', [mdl '/Log'], 'VariableName', 'h');   % line 6
add_line(mdl, 'Altitude', 'Log/1');                              % line 7
```
--- choice
Line 3, because a block name may not contain a space.
--- choice
Line 5, because `'Sink rate/1'` has a space, so the path cannot be found.
--- choice correct
Line 7, because `'Altitude'` has no port number: `add_line` needs `'Altitude/1'`.
--- choice
Line 4, because an initial condition must be passed as the number `1500`, not as text.
--- why
In `add_line`, each end is a block name followed by `/` and a port number. `'Altitude'` alone names a block, not a port, so the call fails; `'Altitude/1'` is output port 1. Block names may contain spaces, as long as the path matches exactly, so lines 3 and 5 are fine. Parameter values are always passed as text, so `'1500'` in line 4 is correct and a bare `1500` would be the mistake.

+++ question | Why the autopilot gets its own file
--- ask
A vehicle simulation has grown to 4,000 blocks in one flat .slx file. The lead splits the autopilot, the navigation filter and the dynamics into separate .slx files, each included in a thin top model through a Model block. What is the real reason?
--- choice
A referenced model always simulates faster than the same blocks drawn in place, and speed is the whole point.
--- choice correct
Each small file can be reviewed, compared between versions, tested and rebuilt on its own, several engineers can work at once, and the Model block's ports form a checked interface.
--- choice
A single .slx file cannot hold more than a few hundred blocks, so a big model has to be split.
--- choice
Git can show a line-by-line text diff of a small .slx file but not of a large one.
--- why
Model reference is about working on the model, not about a size limit. A flat diagram cannot be reviewed or tested piece by piece, and two people cannot edit it at once. Separate files give separate compilation and checked interfaces, the same argument as splitting a C++ program into translation units. A .slx is a compressed package, so Git sees it as one binary file whatever its size; a small model simply makes the MathWorks comparison tool's picture readable.

+++ question | Two lines into one port
--- ask
An Integrator should add up the sum of two accelerations: one from thrust and one from gravity. You drag the thrust line onto the Integrator's input port, then drag the gravity line onto the same port. What is true?
--- choice
Simulink adds the two lines together automatically where they meet.
--- choice
The second line quietly replaces the first, and the model runs with gravity only.
--- choice correct
An input port accepts only one line. Put a Sum block in front of the Integrator, wire both accelerations into it, and wire the Sum into the Integrator.
--- choice
Simulink stacks the two values into a 2-element vector, and the Integrator integrates each one.
--- why
An output port can feed many inputs, because a branch is a copy of the same value. An input port can take only one line, because a block cannot guess what two values should mean together: added, subtracted, multiplied or bundled. You say which by placing the block that does it. Here that is a Sum with List of signs `++`.

+++ question | A wheel that spins backwards
--- ask
A reaction wheel spins at 300 rad/s when friction starts slowing it at a steady 4 rad/s every second. After 50 s it should spin at $300 - 4 \times 50 = 100$ rad/s. This script prints $-200$ instead. Which line is the bug?

```matlab
mdl = 'wheel';                                                           % line 1
new_system(mdl);                                                         % line 2
add_block('simulink/Sources/Constant', [mdl '/Friction'], 'Value', '-4');   % line 3
add_block('simulink/Continuous/Integrator', [mdl '/Speed']);             % line 4
add_block('simulink/Sinks/To Workspace', [mdl '/Log'], ...
          'VariableName', 'w', 'SaveFormat', 'Timeseries');              % line 5
add_line(mdl, 'Friction/1', 'Speed/1');                                  % line 6
add_line(mdl, 'Speed/1', 'Log/1');                                       % line 7
set_param(mdl, 'StopTime', '50');                                        % line 8
out = sim(mdl);  out.w.Data(end)                                         % line 9
```
--- choice
Line 3: the Value should be `'4'`, because friction is a positive number.
--- choice correct
Line 4: the Integrator keeps its default Initial condition of 0. It needs `'InitialCondition', '300'`.
--- choice
Line 8: the stop time must be passed as the number `50`.
--- choice
Line 9: `Data(end)` is the first logged value, not the last.
--- why
From 0 the Integrator adds up $-4$ for 50 s and reaches $-200$, which is exactly the printed number. The missing piece is the starting value: $300 - 200 = 100$. Changing line 3 to `'4'` would give $+200$, still wrong. A wrong initial condition never raises an error, so the only way to catch it is to know the answer you expect.

+++ question | Two Integrators in a row
--- ask
A model is wired left to right: a Step block with its default settings, a Gain of 4, an Integrator with Initial condition 0, a second Integrator with Initial condition 0, and a To Workspace block. The stop time is 5 s. What is the last logged value?
--- answer
32
32.0
--- why
The default Step is 0 until $t = 1$ s and 1 afterwards, so the first Integrator receives 4 from $t = 1$ s. Its output is $4(t - 1)$, a ramp. The second Integrator adds up that ramp: $\int_1^{t} 4(t' - 1)\,dt' = 2(t - 1)^2$. At $t = 5$ s that is $2 \times 4^2 = 32$. Integrating a constant gives a ramp, and integrating a ramp gives a parabola: that is acceleration, then speed, then distance.

+++ question | A Sum with a spacer
--- ask
A Sum block has List of signs `+|--`. The signals wired to its ports, from the top port down, are 10, 3 and 4. What does it output?
--- answer
3
3.0
--- why
The `|` is a spacer: it takes a place around the circle but makes no port. So the block has three ports, with signs $+$, $-$ and $-$ in port order. The output is $10 - 3 - 4 = 3$. The signs belong to the ports, not to the lines, so the order in which the lines are plugged in decides the answer.

+++ question | A row gain times a column signal
--- ask
A Gain block holds $K = [1\ 2\ 3]$, a 1-by-3 row, and its Multiplication is set to Matrix(K*u). Its input is the 3-element column $u = [4;\ 5;\ 6]$. What comes out?
--- answer
32
32.0
--- why
Matrix(K*u) is MATLAB's `*`. A 1-by-3 row times a 3-by-1 column is a 1-by-1 result: $1 \times 4 + 2 \times 5 + 3 \times 6 = 4 + 10 + 18 = 32$. With the default Element-wise(K.*u), the block would instead multiply partners one by one and output the vector $[4,\ 10,\ 18]$. Same block, same numbers, and a different size of answer: that is why the Multiplication setting deserves a glance.

+++ question | A gain in the feedback path
--- ask
A Step (Step time 0, Final value 1) feeds port 1 of a Sum with List of signs `+-`. The Sum feeds a Gain of 3, the Gain feeds an Integrator with Initial condition 0, and the Integrator's output is $y$. The signal $y$ is also branched through a Gain of 2 into the Sum's port 2. What value does $y$ settle at?
--- answer
0.5
1/2
0.50
.5
--- why
Read the wiring as an equation: $\dot{y} = 3(u - 2y) = 3u - 6y$. It settles when nothing changes, so $\dot{y} = 0$ and $3u = 6y$, giving $y = u/2 = 0.5$. The time constant is $\frac{1}{6}$ s. A gain in the feedback path changes where the loop settles: the loop drives the Sum's output to zero, so it makes $2y$ equal the command, not $y$.

+++ question | A loop with no memory
--- ask
A Step feeds port 1 of a Sum with List of signs `+-`. The Sum feeds a Gain of 4, and the Gain's output is wired straight back into the Sum's port 2. There is no Integrator anywhere. What happens when you run it?
--- choice
The model cannot start, because nobody gave the loop a first value, so Simulink stops with "undefined signal".
--- choice
Simulink uses the Gain's output from the previous time step, so the loop acts as a small delay.
--- choice correct
Simulink reports an algebraic loop: at every time step it must solve $y = 4(u - y)$, which it does by iteration. That works here, giving $y = 0.8u$, but it is slow and fragile.
--- choice
The loop gain is 4, which is more than 1, so the output grows without limit.
--- why
Every block in the loop is memoryless, so each one needs the other's answer before it can produce its own. That is an equation to solve at each step, $y = 4u - 4y$, so $y = 0.8u$, not a formula to evaluate. Simulink detects it and iterates. An Integrator would break the loop, because its output is already known before its input is computed. A real system nearly always has the lag that is missing here.

+++ question | A spring that runs away
--- ask
You build the mass-spring-damper $\ddot{x} = \frac{1}{m}(u - c\dot{x} - kx)$ with $m = 1$, $c = 0.4$ and $k = 4$, from a Sum, three Gains and two Integrators, driven by a unit step. The position does not wiggle at all. It grows faster and faster, without limit. Which mistake explains that?
--- choice correct
The Sum's List of signs is `+-+`, with $c\dot{x}$ on port 2 and $kx$ on port 3, so the spring force is added instead of subtracted.
--- choice
The Sum's List of signs is `++-`, with $c\dot{x}$ on port 2 and $kx$ on port 3, so the damping force is added instead of subtracted.
--- choice
The damping Gain is 4 and the spring Gain is 0.4, swapped.
--- choice
The position Integrator's Initial condition is 1 instead of 0.
--- why
With the spring sign flipped, the model solves $\ddot{x} + 0.4\dot{x} - 4x = u$. Its roots are about $+1.81$ and $-2.21$, and the positive one grows like $e^{1.81t}$ with no wiggle: the "spring" pushes the mass away. A flipped damper gives $\ddot{x} - 0.4\dot{x} + 4x = u$, whose roots are $0.2 \pm 1.99j$: an oscillation that grows. Swapped gains give a heavily damped spring that creeps toward $1/0.4 = 2.5$, and a wrong initial condition gives a ringing that still dies away. The shape of a wrong answer tells you which sign to look at.

+++ question | The first peak of a new equation
--- ask
A sensor mount obeys $0.5\ddot{y} + 3\dot{y} + 18y = 9u$. You build it from blocks, both Integrators start at 0, and $u$ is a unit step at $t = 0$. What is the value of the first peak of $y$? Give three decimal places.
--- answer
0.581
0.58
0.5815
0.582
--- why
Solve for the highest derivative first: $\ddot{y} = 18u - 6\dot{y} - 36y$. That is the wiring, and it also reads as $\ddot{y} + 6\dot{y} + 36y = 18u$. So $\omega_n = \sqrt{36} = 6$ rad/s and $2\zeta\omega_n = 6$, giving $\zeta = 0.5$. It settles where $36y = 18$, at $y = 0.5$. The overshoot is $e^{-\pi \times 0.5/\sqrt{0.75}} = e^{-1.814} = 0.163$, so the peak is $0.5 \times 1.163 = 0.581$, at $t = \pi/(6\sqrt{0.75}) = 0.605$ s.

+++ question | A sine on a Display
--- ask
A Sine Wave block has Amplitude 3, Bias 1, Frequency `pi/4` and Phase 0. It feeds a Display. The stop time is 6 s. What does the Display show at the end of the run?
--- answer
-2
-2.0
--- why
The block computes $y = 3\sin(\frac{\pi}{4}t) + 1$, with the Frequency in rad/s. At $t = 6$ s the angle is $\frac{6\pi}{4} = \frac{3\pi}{2}$, where the sine is $-1$. So $y = 3 \times (-1) + 1 = -2$. The Display holds the last value of the run.

+++ question | A wave three times too slow
--- ask
A test needs a 3 Hz vibration, and an engineer types `3` into a Sine Wave block's Frequency field. How many seconds does one cycle of the wave actually take? Give two decimal places.
--- answer
2.09
2.1
2.094
2.09 s
2*pi/3
2pi/3
--- why
The Frequency field is in radians per second, so `3` means 3 rad/s. One cycle is $2\pi$ radians, so it takes $2\pi/3 = 2.09$ s. A real 3 Hz wave repeats every $1/3 = 0.33$ s, so this one is $2\pi$ times too slow. The right entry is `2*pi*3`, about 18.8 rad/s.

+++ question | A step that goes down
--- ask
A Step block has Step time 3, Initial value 2 and Final value $-1$. It feeds an Integrator with Initial condition 0, which feeds a Display. The stop time is 10 s. What does the Display show?
--- answer
-1
-1.0
--- why
The Integrator adds up the area under the input. For the first 3 s the input is 2, which adds $2 \times 3 = 6$. For the remaining 7 s it is $-1$, which adds $-7$. The total is $6 - 7 = -1$. The Initial value of the Step is not zero here, so the Integrator starts climbing at $t = 0$, not at the step.

+++ question | Proving a change made no difference
--- ask
You changed a filter's gain from 0.50 to 0.52. A reviewer asks you to prove that the altitude response moved by less than 0.01 m everywhere, and to keep the evidence so it can be checked again after the next change. What do you do?
--- choice
Take a screenshot of the Scope before and after the change, and put the two pictures side by side.
--- choice
Add a Display block on the altitude and write down its final value in each run.
--- choice correct
Log the altitude signal, run the model before and after the change, and compare the two runs in the Simulation Data Inspector with the old run as the baseline and an absolute tolerance of 0.01.
--- choice
Wire both runs into one Scope with two inputs, so the curves are drawn on the same axes.
--- why
A Scope shows only the run you just did, and two pictures cannot be subtracted. A Display gives one number, the last value, and says nothing about the rest of the run. The Data Inspector keeps each run, lines up the matching signals, plots their difference and marks the signal as inside or outside the tolerance you set. The saved baseline is also what the next change gets compared against.

+++ question | One number, or a whole row of them
--- ask
This script should print the largest difference between a logged lag response and its exact formula. Instead it prints a long row of numbers.

```matlab
out = sim('lag2');
t = out.y.Time;
y = out.y.Data;
yref = 1 - exp(-t'/2);
err = max(abs(y - yref))
```

What is wrong?
--- choice
`out.y.Data` is a row, so `y - yref` is fine, but `max` works down each column.
--- choice correct
`t'` turns the time column into a row, so `yref` is a row. A column minus a row expands into an N-by-N matrix, and `max` returns the largest value of each column. Drop the transpose so both are columns.
--- choice
Nothing is wrong with the shapes. `max` returns one value per element, so write `max(abs(y - yref), [], 'all')` to get one number.
--- choice
The solver logs unevenly spaced times, so `exp` returns a separate vector for each time step.
--- why
Logged Timeseries data comes in columns, one row per time step. Subtracting a 1-by-N row from an N-by-1 column does not fail in MATLAB: implicit expansion builds every pairing, $y_i - y_{\text{ref}}(t_j)$. Adding `'all'` would print one number, but it would be the largest of those meaningless pairings. The fix is to keep both as columns, for example `yref = 1 - exp(-t/2)`.

+++ question | How big the lag's answer is
--- ask
A Sine Wave with Amplitude 2, Frequency 4 (rad/s) and Bias 0 drives a first-order lag with time constant $\tau = 0.75$ s. Once the start-up part has died away, what is the amplitude of the lag's output? Give three decimal places.
--- answer
0.632
0.63
0.6325
0.633
--- why
A lag answers a steady sine with a sine of the same frequency, scaled by $\frac{1}{\sqrt{1 + (\omega\tau)^2}}$. Here $\omega\tau = 4 \times 0.75 = 3$, so the scale is $\frac{1}{\sqrt{10}} = 0.316$, and the amplitude is $2 \times 0.316 = 0.632$. The phase is $-\arctan(3) = -71.6^\circ$, which is a delay of $1.249/4 = 0.31$ s. Read those two numbers from the logged data, not from a picture.

=== slk01-l04 | Practice: Checking against the analytic answer
--- for

+++ question | Where a lag should be
--- ask
A first-order lag has gain $K = 3$ and time constant $\tau = 0.4$ s, and it is driven by a unit step at $t = 0$ from rest. What should the logged output read at $t = 0.8$ s? Give three decimal places.
--- answer
2.594
2.59
2.5940
2.6
--- why
The exact answer is $y(t) = K(1 - e^{-t/\tau}) = 3(1 - e^{-t/0.4})$. At $t = 0.8$ s that is two time constants: $e^{-2} = 0.1353$, so $y = 3 \times 0.8647 = 2.594$. After two time constants a lag has covered 86.5% of the way to its final value, here 3.

+++ question | Reading the time constant off the data
--- ask
A lag with gain $K = 1$ is driven by a unit step at $t = 0$ from rest. The logged output at $t = 3$ s reads 0.8647. What is the time constant, in seconds?
--- answer
1.5
1.5 s
1.50
--- why
Set $1 - e^{-3/\tau} = 0.8647$. Then $e^{-3/\tau} = 0.1353 = e^{-2}$, so $3/\tau = 2$ and $\tau = 1.5$ s. Recognizing $0.8647$ as "two time constants" and $0.632$ as "one" turns a single logged number into a check on the Gain that sets $\frac{1}{\tau}$.

+++ question | A reference that shares the mistake
--- ask
To check a new mass-spring-damper model, a colleague copies the model's equation into a MATLAB script, solves it with `ode45` at the same tolerance, and compares. The two agree to $10^{-9}$. Why is this a weak check?
--- choice
`ode45` in a script uses a different method from Simulink's `ode45`, so the two can never agree properly.
--- choice correct
The script was written from the same equation, so a wrong sign or a swapped gain in that equation is in both. They agree with each other and are both wrong.
--- choice
$10^{-9}$ is tighter than a double can hold, so the agreement is only rounding error.
--- choice
A check only counts if the reference is computed on a neat grid such as `0:0.01:20`.
--- why
A reference is worth something only if it reaches the answer by a different road. An exact formula derived on paper, `step(tf(1, [m c k]))`, a hand calculation of one point, or a conservation law do not share the model's equation, so they can catch its mistakes. A copy of the model's equations inherits every typo. Test engineers call this independence.

+++ question | Tighter RelTol, same error
--- ask
You verify the lesson's spring ($m = 1$, $c = 0.4$, $k = 4$, unit step) against its exact formula. With RelTol $10^{-10}$ and AbsTol $10^{-6}$ you get $e_{\max} = 2.1 \times 10^{-6}$. With RelTol $10^{-12}$ and the same AbsTol you get $2.1 \times 10^{-6}$ again. What is the best explanation?
--- choice
The error did not shrink when the tolerance got tighter, so the diagram is wrong.
--- choice correct
AbsTol is now the loose setting. The solver accepts an error of about $\text{RelTol} \times |x| + \text{AbsTol}$, and for states smaller than 1 m the $10^{-6}$ floor dominates. Tighten AbsTol too, say to $10^{-12}$, and the error should fall far below $10^{-6}$.
--- choice
RelTol cannot go below $10^{-10}$, so Simulink ignored the $10^{-12}$.
--- choice
The spring is lightly damped, so no tolerance can bring the error below $10^{-6}$.
--- why
The rule "tighten the tolerance and rerun" means both tolerances. Here RelTol times a state of about 0.4 m is around $10^{-11}$, far below AbsTol's $10^{-6}$, so changing RelTol changes nothing. In a Python run of the same solver family, RelTol $10^{-10}$ with AbsTol $10^{-12}$ brings the error to about $3 \times 10^{-11}$. Only when the error stays put after both are tightened should you blame the wiring.

+++ question | A reference with one wrong letter
--- ask
A model of the lesson's spring ($m = 1$, $c = 0.4$, $k = 4$) is checked with this script. The error is $4.6 \times 10^{-3}$ at RelTol $10^{-6}$ and still $4.6 \times 10^{-3}$ at $10^{-10}$ with AbsTol $10^{-12}$. The diagram has been rebuilt twice and looks right. Which line is the bug?

```matlab
t = out.x.Time;  x = out.x.Data;                        % line 1
wn = sqrt(k/m);  zeta = c/(2*sqrt(k*m));                % line 2
wd = wn*sqrt(1 - zeta^2);                               % line 3
x_exact = (1/k)*(1 - exp(-zeta*wn*t).*(cos(wn*t) ...
          + zeta/sqrt(1-zeta^2)*sin(wn*t)));            % line 4
e_max = max(abs(x(:) - x_exact(:)));                    % line 5
```
--- choice
Line 1: the reference must be computed on an even grid, not at the logged times.
--- choice
Line 2: the damping ratio should be $c/(2km)$.
--- choice correct
Line 4: the cosine and sine use `wn`, the undamped frequency, where they need `wd`.
--- choice
Line 5: the `(:)` changes the order of the samples.
--- why
The mass wiggles at $\omega_d = 1.990$ rad/s, not at $\omega_n = 2$ rad/s. The difference is half a percent, invisible on a plot, but over ten swings the two curves drift apart by a few millimeters. An error that does not move with the tolerance points at something fixed: here the reference, not the diagram. Checking the reference against a second one, such as `step(tf(1, [m c k]), t)` on a neat grid, would have caught it at once.

+++ question | When the stiffer spring peaks
--- ask
A mass-spring-damper has $m = 0.5$ kg, $c = 0.6$ N·s/m and $k = 18$ N/m, and starts at rest. A unit step force is applied at $t = 0$. At what time, in seconds, does the first peak of the exact answer come? Give three decimal places.
--- answer
0.526
0.53
0.5262
0.526 s
--- why
$\omega_n = \sqrt{18/0.5} = 6$ rad/s and $\zeta = 0.6/(2\sqrt{18 \times 0.5}) = 0.6/6 = 0.1$. So $\omega_d = 6\sqrt{0.99} = 5.970$ rad/s, and the peak comes half a wiggle in, at $t_p = \pi/\omega_d = 0.526$ s. It settles at $1/k = 0.0556$ m and peaks at $0.0556 \times 1.729 = 0.0961$ m. Knowing both numbers before the run is what makes the logged data a check.

=== slk01-l05 | Practice: Transfer Fcn, State-Space, and the Derivative trap
--- for

+++ question | An integrator hidden in a denominator
--- ask
What do you type into a Transfer Fcn block for $G(s) = \dfrac{4}{s(s + 2)}$?
--- choice
Numerator `[4]`, Denominator `[1 2]`.
--- choice correct
Numerator `[4]`, Denominator `[1 2 0]`.
--- choice
Numerator `[4]`, Denominator `[0 2 1]`.
--- choice
Numerator `[4 0]`, Denominator `[1 2]`.
--- why
Multiply out the bottom: $s(s + 2) = s^2 + 2s + 0$. The coefficients go in descending powers of $s$, including the zero for the missing constant: `[1 2 0]`. Dropping the trailing 0 gives $\frac{4}{s + 2}$, a lag instead of a lag with an integrator. `[0 2 1]` is written in ascending order, and `[4 0]` over `[1 2]` is $\frac{4s}{s+2}$.

+++ question | A State-Space block that outputs velocity
--- ask
A State-Space block holds $0.5\ddot{x} + 2\dot{x} + 8x = F$ with state $[x;\ \dot{x}]$, and its output should be the velocity only. Which set of parameters is right?
--- choice correct
A = `[0 1; -16 -4]`, B = `[0; 2]`, C = `[0 1]`, D = `0`.
--- choice
A = `[0 1; -8 -2]`, B = `[0; 1]`, C = `[0 1]`, D = `0`.
--- choice
A = `[0 1; 16 4]`, B = `[0; 2]`, C = `[0 1]`, D = `0`.
--- choice
A = `[0 1; -16 -4]`, B = `[0; 2]`, C = `[1 0]`, D = `0`.
--- why
Divide by the mass first: $\ddot{x} = -16x - 4\dot{x} + 2F$. The first row of A says "the rate of change of position is the velocity", and the second row is that equation. So A = `[0 1; -16 -4]` and B = `[0; 2]`. Leaving out the division gives the second choice, and dropping the minus signs gives a system that runs away. C picks what comes out: `[0 1]` is the velocity, `[1 0]` the position.

+++ question | How far a filtered derivative jumps
--- ask
A filtered derivative $\dfrac{s}{0.04s + 1}$, built as a Transfer Fcn block, is fed a signal that jumps by 0.5 at $t = 2$ s and is flat before and after. What value does its output jump to right after the jump?
--- answer
12.5
12.50
--- why
For a step of size $\Delta u$, the filter's output jumps to $\Delta u/\tau$ and then decays as $e^{-t/\tau}$. Here $0.5/0.04 = 12.5$. The value is set by $\tau$, not by the solver's step size, so it is the same on every run and at every tolerance. A Derivative block would output 0.5 divided by whatever step the solver took, which could be thousands.

+++ question | The one the block rejects
--- ask
Which of these will a Transfer Fcn block refuse?

+++ question | A lopsided dead zone
--- ask
A Dead Zone block has Start of dead zone $-1$ and End of dead zone 2. What does it output for the inputs 3.5, $-0.4$ and $-2.5$? Write the three numbers in order, separated by spaces.
--- answer
1.5 0 -1.5

[1.5 0 -1.5]

--- why
Inside the band from $-1$ to 2 the output is zero, so $-0.4$ gives 0. Above the band, the output is the input minus the end: $3.5 - 2 = 1.5$. +++ question | Rounding a negative reading
--- ask

--- why
$y = q \cdot \operatorname{round}(u/q)$. Here $-0.63/0.25 = -2.52$, which rounds to the nearest whole number, $-3$. So $y = 0.25 \times (-3) = -0.75$. The output is the nearest multiple of 0.25, and the error, 0.12, is never more than half the interval.

+++ question | A saturated loop, solved by hand
--- ask
A plant is a pure integrator, $\dot{y} = u$. A proportional controller asks for $u = 5(r - y)$, and a Saturation limits $u$ to $\pm 2$. The command is $r = 1$ from $t = 0$, and $y(0) = 0$. What is $y$ at $t = 0.5$ s? Give three decimal places.

The pitch copy clips to $5^\circ$ and arrives at $5/25 = 0.2$ s. Both use the names `lim` and `rate`, yet each finds its own values in its own mask workspace.

+++ question | The rate nobody set
--- ask
A masked actuator has one mask parameter, `lim`. Inside it, the Rate Limiter's slew rates are `rate` and `-rate`, but nobody added `rate` to the mask. Earlier in the session, a script for another model set `rate = 100` in the base workspace. What happens when you run?
--- choice
Simulink stops with "Unrecognized function or variable 'rate'", because a masked subsystem only searches its own mask.
--- choice correct
The search goes past the mask to the model workspace and then the base workspace, finds `rate = 100` and uses it without a word. The actuator slews at $100^\circ/\mathrm{s}$.
--- choice
The Rate Limiter falls back to its default slew rate of 1.
--- choice
The mask copies every base-workspace variable into its own workspace when the model loads, so the block uses a frozen copy.
--- why
A mask does not stop the search. A name it does not define is looked up outward, and whatever the base workspace happens to hold is used. The model looks self-contained and is not. Check that every name used inside a mask is one of its parameters, then run after `clear`: with the base workspace empty, the missing name becomes a loud error instead of a quiet 100.

+++ question | Where each value belongs
--- ask
A vehicle model uses four copies of one gimbal actuator, each with its own position and rate limits. It also uses the gravity constant and the vehicle's dry mass, which three other models of the same vehicle share. The team reviews every parameter change. Where should the values live?
--- choice
All of them in the base workspace, set by one script everyone runs first.

Copying shared constants into four model workspaces makes four places to keep in step, and typed numbers make every change a hunt through the diagram.

+++ question | A step that goes negative, integrated
--- ask
A Step block has Step time 2, Initial value 1 and Final value $-2$. It feeds a Gain of 3, which feeds an Integrator with Initial condition 4. The Integrator's output is logged by a To Workspace block with Variable name `h`, and the stop time is 6 s. What is `out.h.Data(end)`?
--- answer
-14
-14.0
--- why
The Integrator receives $3 \times 1 = 3$ for the first 2 s and $3 \times (-2) = -6$ for the next 4 s. It adds $3 \times 2 + (-6) \times 4 = 6 - 24 = -18$ to its starting value of 4, ending at $-14$. The logged data sits inside the `out` object, and `Data(end)` is its last row.

+++ question | A spring with no damper
--- ask
Two Integrators are chained: the first one's output is the velocity, which feeds the second, whose output is the position $x$. The position goes through a Gain of $-9$ back into the first Integrator's input. There is no other input. The velocity Integrator starts at 0 and the position Integrator at 0.2. What is $x$ at $t = 2$ s? Give three decimal places.
--- answer
0.192
0.19
0.1920
--- why
The wiring says $\ddot{x} = -9x$, a spring with no damping, $\omega_n = 3$ rad/s. Released from 0.2 at rest, the exact answer is $x(t) = 0.2\cos(3t)$. At 2 s the angle is 6 rad, and $0.2\cos 6 = 0.2 \times 0.960 = 0.192$. This is also a free reference with no formula at all: the energy $\frac{1}{2}\dot{x}^2 + \frac{9}{2}x^2$ must stay at $0.18$, and a drift in it measures the solver's error.

+++ question | A difference that peaks at one second
--- ask
A first-order lag model with $K = 1$ and $\tau = 1$ s is compared with the exact step response $1 - e^{-t}$. The largest difference is 0.632, at $t = 1$ s. At RelTol $10^{-10}$ and AbsTol $10^{-12}$ it is still 0.632 at $t = 1$ s. What is the most likely cause?
--- choice
The solver is too loose; 0.632 is the default RelTol error piling up over one time constant.
--- choice correct
The Step block is still at its default Step time of 1 s, so the model's curve is the right curve one second late.
--- choice
The Gain that should be $1/\tau = 1$ was set to $1/2$, so the model's time constant is 2 s.
--- choice
The Integrator's Initial condition is 1 instead of 0.
--- why
An error that ignores the tolerance is a setup or wiring mistake. A one-second delay makes the model read 0 while the formula climbs to $1 - e^{-1} = 0.632$ at $t = 1$ s, and after that the gap shrinks as both head for 1. A time constant of 2 s would give a largest difference of only 0.25, near $t = 1.39$ s. An initial condition of 1 would make the model sit at 1, and the difference would be largest at $t = 0$, where it is 1. The size and the time of the largest difference identify the mistake.

+++ question | Noise through a filtered derivative
--- ask
A pitch angle swings with amplitude 0.05 rad at 0.5 Hz. The attitude sensor adds noise of amplitude 0.0005 rad at 40 Hz. The rate is computed with the filtered derivative $\dfrac{s}{0.01s + 1}$. What is the amplitude of the noise in the computed rate, in rad/s? Give two significant figures.
--- answer
0.046
0.0465
0.0464
0.04646
--- why
In rad/s the noise is at $\omega = 2\pi \times 40 = 251.3$. The filter's gain there is $\frac{\omega}{\sqrt{1 + (\omega\tau)^2}} = \frac{251.3}{\sqrt{1 + 2.513^2}} = \frac{251.3}{2.705} = 92.9$, so the noise's rate is $0.0005 \times 92.9 = 0.046$ rad/s. An ideal derivative would give $0.0005 \times 251.3 = 0.126$. The signal's rate is $0.05 \times 2\pi \times 0.5 = 0.157$ rad/s, almost untouched by the filter. The noise falls from 80% of the signal's rate to about 30%.

+++ question | Velocity out of a State-Space block
--- ask
A State-Space block holds an undamped spring, $\ddot{x} + 16x = F$, with A = `[0 1; -16 0]`, B = `[0; 1]`, C = `eye(2)`, D = `[0; 0]` and Initial conditions `[0.05; 0]`. The force is 0. A Demux with Number of outputs `2` splits the output. What does the Demux's second output read at $t = \pi/8$ s?
--- answer
-0.2
-0.20
-0.200
-.2
-0.2 m/s
--- why
With C = `eye(2)` the output is the whole state, $[x;\ \dot{x}]$, and the Demux's second line is the velocity. Released from 0.05 m at rest, $x = 0.05\cos 4t$ and $\dot{x} = -0.2\sin 4t$. At $t = \pi/8$ s, $4t = \pi/2$, so the velocity is $-0.2$ m/s and the position is 0. A Transfer Fcn block could not run this case, because its states always start at zero.

+++ question | A rotation fed one element too many
--- ask
A 3-element position and a scalar altitude rate are combined by a Mux, and the Mux feeds a Gain holding a 3-by-3 direction cosine matrix with Multiplication Matrix(K*u). Ctrl+D reports a dimension error on the Gain. What is the right fix?
--- choice
Change the Gain's Multiplication to Element-wise(K.*u), so the sizes no longer have to match.
--- choice
Pad the matrix to 4-by-4 with zeros, so it accepts the 4-element vector.
--- choice correct
Rotate only the position: feed the Gain from the position vector itself (or a Selector with Index `[1 2 3]`), and send the altitude rate on its own line or in a bus with the position.
--- choice
Replace the Mux with a Demux, so the Gain receives separate lines.
--- why
The Mux makes a 4-element vector, and a 3-by-3 matrix cannot multiply it. The deeper problem is that a position and a rate are dissimilar, so they should never have shared a vector. Element-wise multiplication would run with the wrong meaning or fail again, and a 4-by-4 matrix hides the mistake. The rotation belongs to the three position components alone, and the other signal travels separately or as its own bus element.

+++ question | Quantize, then clip, or the other way round
--- ask
A sensor path has a Saturation with limits $\pm 1.0$ and a Quantizer with interval 0.3. The input is 1.3. What does the path output with the Quantizer first, and with the Saturation first?
--- choice
1.2 with the Quantizer first, and 0.9 with the Saturation first.
--- choice correct
1.0 with the Quantizer first, and 0.9 with the Saturation first.
--- choice
1.0 either way, because the Saturation always has the last word.
--- choice
0.9 with the Quantizer first, and 1.0 with the Saturation first.
--- why
Quantizer first: $1.3/0.3 = 4.33$ rounds to 4, giving 1.2, and the Saturation then clips it to 1.0. Saturation first: 1.3 becomes 1.0, and $1.0/0.3 = 3.33$ rounds to 3, giving 0.9. So the order changes the largest value the path can ever output. Nonlinear blocks do not commute, which is why the order of blocks in an actuator or sensor model must match the order in the hardware.

+++ question | Three loops, one small command
--- ask
Loop A is a PI loop with a saturating actuator and no anti-windup. Loop B is the same loop with anti-windup. Loop C is the same loop with no saturation at all. All three receive a command so small that the controller's output never reaches the actuator's limit. How do their responses compare?
--- choice
A overshoots most, B less, and C least, because windup builds up whenever an integrator is present.
--- choice correct
All three are identical, because the Saturation passes its input unchanged inside its limits and the anti-windup rule only acts while the actuator is saturated.
--- choice
B is slowest, because anti-windup always stops the integrator from building up the value it needs.
--- choice
C overshoots most, because without a saturation nothing limits the controller's output.
--- why
A nonlinear block behaves linearly when its input stays inside its limits, and anti-windup does nothing unless the actuator is pinned. So for a small command all three are the same linear loop. This is also how you check a nonlinear model: pick a case where the limit is never reached, and it must match the linear result exactly. Windup needs both an integral term and time spent on a limit.

+++ question | A table read past its edge, with Clip
--- ask
A 2-D Lookup Table with linear interpolation and Extrapolation method Clip holds $C_N$ with Mach on Breakpoints 1 and angle of attack on Breakpoints 2:

| $M$ \ $\alpha$ | 0° | 4° | 8° |
|---|---|---|---|
| 0.6 | 0 | 0.20 | 0.44 |

What does it output at Mach 1.2 and $\alpha = 11°$?

0.63
.63
0.630
--- why

+++ question | An actuator written as code
--- ask
A MATLAB Function block models an actuator:

```matlab
function y = act(u)
persistent last
if isempty(last)
    last = 0;
end
dt = 0.1;  R = 20;
c = min(max(u, -6), 6);
d = min(max(c - last, -R*dt), R*dt);
last = last + d;
y = last;
```

It is called once every 0.1 s with the inputs 10, 10, 10, 10, $-10$. What is the fifth output?
--- answer
4
4.0
--- why
`c` clips the command to $\pm 6$, and `d` limits each move to $R \cdot dt = 2$. The outputs are 2, 4, 6, then 6 again, because the clipped command is already reached. On the fifth call `c` is $-6$, the wanted move is $-12$, and it is limited to $-2$, so the output is 4. The code clips first and then limits the rate, the same order as a Saturation followed by a Rate Limiter, so it starts back from $6$ at once instead of from a hidden 10.

+++ question | A value from MATLAB with no type
--- ask
A MATLAB Function block calls an old density routine during simulation:

```matlab
function rho = fcn(h)
coder.extrinsic('legacy_density');
rho = legacy_density(h);
```

The block fails to build, saying it cannot work out the type of `rho`. What is the fix, and what is the catch?
--- choice
Remove `coder.extrinsic`, and the block will compile `legacy_density` into C by itself.
--- choice correct
Assign `rho = 0;` before the call, so the block knows to convert the returned value to a real 1-by-1 double. The catch: the call is left out of generated code, so flight software built from this block cannot compute `rho` this way.
--- choice
Put the call inside an Interpreted MATLAB Function block instead, which can then be code-generated.
--- choice
Declare `rho` as persistent, which gives it a type.
--- why
A value coming back from MATLAB through an extrinsic call has no type the block can know in advance, so you assign the output first to say what to convert it into. Extrinsic calls run only in simulation and never reach the generated code. That is fine for a plot or a log, and wrong for anything the vehicle needs. An Interpreted MATLAB Function block cannot be code-generated at all.

+++ question | A capital letter in a mask
--- ask
A masked actuator's only mask parameter is `lim`, set to 6. The Saturation inside has Upper limit `Lim` and Lower limit `-Lim`. An old script left `Lim = 30` in the base workspace. The actuator receives a command of 12. What does the Saturation output?
--- answer
12
12.0
--- why
MATLAB names are case-sensitive, so `Lim` is not `lim`. The mask does not define `Lim`, so the search continues outward and finds `Lim = 30` in the base workspace. +++ question | A 5 Hz test that is not
--- ask
A test should shake a first-order lag with time constant $\tau = 0.1$ s at 5 Hz. The Sine Wave block has Amplitude 1 and Frequency `5`. What steady output amplitude does the logged data show? Give three decimal places.
--- answer
0.894
0.89
0.8944
--- why
The Frequency field is in rad/s, so the wave runs at 5 rad/s. There $\omega\tau = 0.5$, and the amplitude is $\frac{1}{\sqrt{1 + 0.25}} = 0.894$. At a real 5 Hz, $\omega = 31.4$ rad/s, $\omega\tau = 3.14$, and the amplitude would be $\frac{1}{\sqrt{1 + 9.87}} = 0.303$. Writing the expected number down before the run catches the mistake at once.

+++ question | A filtered PD controller in one block
--- ask
A PD controller with a filtered derivative is $C(s) = K_p + K_d\dfrac{s}{\tau s + 1}$, with $K_p = 4$, $K_d = 2$ and $\tau = 0.02$ s. What goes into a single Transfer Fcn block?
--- choice
Numerator `[2 4]`, Denominator `[0.02 1]`.
--- choice correct
Numerator `[2.08 4]`, Denominator `[0.02 1]`.
--- choice
Numerator `[4 2 0]`, Denominator `[0.02 1]`.
--- choice
Numerator `[2.08 4]`, Denominator `[1 0.02]`.
--- why
Put both terms over the common denominator $\tau s + 1$: $\frac{K_p(\tau s + 1) + K_d s}{\tau s + 1} = \frac{(K_p\tau + K_d)s + K_p}{\tau s + 1} = \frac{2.08s + 4}{0.02s + 1}$. Both are first order, so the block accepts it. Forgetting $K_p\tau$ gives `[2 4]`, and `[1 0.02]` is the denominator $s + 0.02$, a pole at $-0.02$ instead of $-50$. The block holds the same filter the PID Controller block builds, with $N = 1/\tau = 50$.

+++ question | A test bench for three cases
--- ask
A descent model must be run every night on three input cases (nominal, heavy gust, engine-out), and each result compared with a run the team has agreed is correct. What setup does that best?
--- choice
Three copies of the model, one per case, each with its own Scope, checked by eye each morning.
--- choice correct
One model with a Signal Editor block holding the three cases as scenarios; a script sets the Active scenario, runs each case with its signals logged, and compares each run with its baseline in the Simulation Data Inspector, within set tolerances.
--- choice
One model with three Step blocks and a Switch, and a Display on each output to read the final values.
--- choice
One model with an Interpreted MATLAB Function block that loads the case data at every time step.
--- why
Keeping the cases as scenarios means every case runs through exactly the same diagram, and a script can switch between them without anyone touching the mouse. Logged runs compared with a baseline, within tolerances, give a yes-or-no answer to "did anything change?". Copies of a model drift apart, a Scope or a Display is for looking, and an interpreted block is slow and cannot be code-generated.
