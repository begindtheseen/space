+++ practice | Nicknames the compiler can check
--- task
ORBIT's C++ compiler has no Eigen, so this set builds Eigen's ideas by hand, in plain C++.

The starter has a small fixed-size matrix template, `Mat<T, R, C>`: `R` rows and `C` columns of `T`, stored row by row in a `std::array` inside the object. Do not change it. Below it, write:

- four nicknames, the way Eigen names its shapes: `Vector3d` for `Mat<double, 3, 1>`, `Matrix3d` for `Mat<double, 3, 3>`, `Vector4f` for `Mat<float, 4, 1>` and `RowVector3d` for `Mat<double, 1, 3>`;
- a function template `transpose` that takes a `const Mat<T, R, C>&` and returns a `Mat<T, C, R>` whose entry (j, i) is entry (i, j) of the input.

So transposing a `RowVector3d` must give a `Vector3d`, and transposing a 2-by-3 matrix gives a 3-by-2 one. The checks also test that a `Matrix3d` is exactly 72 bytes: nine doubles and nothing else.
--- starter
#include <array>
#include <type_traits>

// A fixed-size matrix: R rows, C columns, stored row by row inside the object.
template <typename T, int R, int C>
struct Mat {
    std::array<T, R * C> v{};
    T& operator()(int i, int j) { return v[i * C + j]; }
    T operator()(int i, int j) const { return v[i * C + j]; }
};

// Write the four nicknames here.
using Vector3d = Mat<double, 1, 1>;
using Matrix3d = Mat<double, 1, 1>;
using Vector4f = Mat<double, 1, 1>;
using RowVector3d = Mat<double, 1, 1>;

template <typename T, int R, int C>
Mat<T, C, R> transpose(const Mat<T, R, C>& a) {
    return {};
}
--- solution
#include <array>
#include <type_traits>

// A fixed-size matrix: R rows, C columns, stored row by row inside the object.
template <typename T, int R, int C>
struct Mat {
    std::array<T, R * C> v{};
    T& operator()(int i, int j) { return v[i * C + j]; }
    T operator()(int i, int j) const { return v[i * C + j]; }
};

// Shape first, then the scalar: d is double, f is float. A vector has one column.
using Vector3d = Mat<double, 3, 1>;
using Matrix3d = Mat<double, 3, 3>;
using Vector4f = Mat<float, 4, 1>;
using RowVector3d = Mat<double, 1, 3>;

// The shape of the answer is worked out by the compiler from the shape of the input.
template <typename T, int R, int C>
Mat<T, C, R> transpose(const Mat<T, R, C>& a) {
    Mat<T, C, R> out;
    for (int i = 0; i < R; ++i)
        for (int j = 0; j < C; ++j) out(j, i) = a(i, j);
    return out;
}
--- hint
A nickname is a `using` line: `using Name = Mat<scalar, rows, cols>;`. A column vector has one column; a row vector has one row.
--- hint

+++ practice | Checked now, or checked later
--- task
In Eigen, each size in a type is either a number fixed when the program is compiled, or `Dynamic`, which equals -1 and means "learned while running". Any size of 0 or more is a real, fixed size.

A matrix product needs the left side's column count to equal the right side's row count. Write three things:

- `constexpr int kDynamic = -1;`
- `constexpr int product_check(int lhs_cols, int rhs_rows)`, which returns `1` when both sizes are fixed and equal (the compiler accepts the product), `-1` when both are fixed and different (the build fails), and `0` when either one is `kDynamic` (only a run-time assertion can check it);
- `constexpr bool allocates(int rows, int cols)`, which returns `true` when a matrix with these sizes keeps its numbers on the heap: that is, when either size is `kDynamic`.

For example, `product_check(4, 3)` is `-1`, `product_check(kDynamic, 3)` is `0`, and `allocates(3, kDynamic)` is `true`. Both functions must be `constexpr`: the checks use them where the compiler needs the answer.
--- starter
constexpr int kDynamic = 0;

int product_check(int lhs_cols, int rhs_rows) {
    return 2;
}

bool allocates(int rows, int cols) {
    return false;
}
--- solution
#include <type_traits>

constexpr int kDynamic = -1;   // never a real size, so it can mean "not known yet"

// 1: the compiler accepts it. -1: the build fails. 0: only a run-time check can tell.
constexpr int product_check(int lhs_cols, int rhs_rows) {
    if (lhs_cols == kDynamic || rhs_rows == kDynamic) return 0;
    return lhs_cols == rhs_rows ? 1 : -1;
}

// A size the compiler does not know cannot be an array member: it needs a heap buffer.
constexpr bool allocates(int rows, int cols) {
    return rows == kDynamic || cols == kDynamic;
}
--- hint
Deal with `kDynamic` first. Only when both sizes are real numbers can you compare them.
--- hint
A fixed-size type stores its numbers in an array member whose length is part of the type, so only a size the compiler does not know forces a heap buffer.
--- check case | 3 columns times 3 rows is accepted
product_check(3, 3)
=> 1
--- check case | 4 columns times 3 rows fails the build
product_check(4, 3)
=> -1
--- check test | One dynamic side, or both, means a run-time check
product_check(kDynamic, 3) == 0 && product_check(3, kDynamic) == 0 && product_check(kDynamic, kDynamic) == 0
--- check test | Zero is a real size
product_check(0, 0) == 1 && product_check(0, 2) == -1 && !allocates(0, 0)
--- check test | Only a dynamic size needs the heap, even when the other size is fixed
!allocates(3, 3) && allocates(3, kDynamic) && allocates(kDynamic, 1) && allocates(kDynamic, kDynamic)
--- check test | Both answers are ready at compile time
std::integral_constant<int, product_check(2, 2)>::value == 1 && std::integral_constant<bool, allocates(6, 6)>::value == false

+++ practice | Velocities that lost their fractions
--- task
This program prints the speed of two velocities, in m/s. It should print:

```
drift speed: 1.00 m/s
gust speed: 2.55 m/s
```

Instead it prints `0.00` and `2.24`. Nothing crashes and there is no error. The fault is one line, and it is the kind of slip the Eigen nicknames invite: remember what the last letter of a nickname means. Fix the program so it prints the two right lines.

#include <array>

template <typename T, int N>

+++ practice | Room for twelve satellites
--- task
A navigation filter gets one range measurement per satellite it can hear, so the count changes from second to second. Flight code must not allocate in its loop, so instead of a dynamic vector it keeps a fixed maximum and a count of the slots in use.

Write a class template `template <int MaxN> struct RangeSet` with:

- `std::array<double, MaxN> r{};` holding the ranges, in metres, and `int n = 0;`, the number in use;
- `static constexpr int capacity = MaxN;`
- `bool push(double range)`: stores `range` in the next free slot and returns `true`. It returns `false` and changes nothing when the set is full, or when `range` is 0 or negative (a range must be positive);
- `double rms() const`: the root mean square of the stored ranges, the square root of the mean of their squares. It returns `0.0` when the set is empty;
- `void clear()`: empties the set.

For example, after pushing 3 and 4, `rms()` is the square root of (9 + 16) / 2, about 3.5355.
--- starter
#include <array>
#include <cmath>

template <int MaxN>
struct RangeSet {
    std::array<double, MaxN> r{};
    int n = 0;
    static constexpr int capacity = 0;

    bool push(double range) { return true; }
    double rms() const { return -1.0; }
    void clear() {}
};
--- solution
#include <array>
#include <cmath>

// A fixed maximum and a count: no heap, and the size of the object is in its type.
template <int MaxN>
struct RangeSet {
    std::array<double, MaxN> r{};
    int n = 0;
    static constexpr int capacity = MaxN;

    bool push(double range) {
        if (n == MaxN || range <= 0.0) return false;
        r[n++] = range;
        return true;
    }

    double rms() const {
        if (n == 0) return 0.0;
        double s = 0.0;
        for (int k = 0; k < n; ++k) s += r[k] * r[k];
        return std::sqrt(s / n);
    }

    void clear() { n = 0; }
};
--- hint
Only the first `n` slots hold real ranges. Loop over those, never over the whole array.
--- hint
Check the two reasons to refuse at the top of `push`: the set is full when `n == MaxN`, and a range must be above zero.
--- check test | Two ranges give the right RMS
[] { RangeSet<4> s; bool ok = s.push(3.0) && s.push(4.0); return ok && s.n == 2 && std::fabs(s.rms() - 3.5355339059) < 1e-9; }()
--- check test | Zero and negative ranges are refused and change nothing
[] { RangeSet<4> s; s.push(5.0); return !s.push(0.0) && !s.push(-2.0) && s.n == 1 && s.rms() == 5.0; }()
--- check test | A full set refuses more, and keeps what it has
[] { RangeSet<3> s; s.push(3.0); s.push(4.0); s.push(12.0); bool refused = !s.push(5.0); return refused && s.n == 3 && std::fabs(s.rms() - std::sqrt(169.0 / 3.0)) < 1e-9; }()
--- check test | An empty set has RMS 0, and clear empties it
[] { RangeSet<2> s; bool empty0 = s.rms() == 0.0; s.push(1.0); s.push(2.0); s.clear(); return empty0 && s.n == 0 && s.rms() == 0.0 && s.push(7.0); }()
--- check test | The capacity is part of the type
RangeSet<12>::capacity == 12 && sizeof(RangeSet<12>) > sizeof(RangeSet<4>)

+++ question | Bytes in a float matrix
--- ask
How many bytes is `sizeof(Eigen::Matrix<float, 4, 4>)`? Type the number.
--- answer
64
64 bytes
--- why
A fixed-size Eigen matrix holds its numbers in an array member and nothing else. Four by four is 16 entries, and a `float` is 4 bytes, so the object is 16 × 4 = 64 bytes. Making one uses no heap at all. A `MatrixXf` of the same size would be a small handle (a pointer and two counts) plus a 64-byte buffer asked for from the heap.

+++ question | One dynamic operand
--- ask
What happens with this code?

```cpp
Eigen::Matrix3d R = Eigen::Matrix3d::Identity();
Eigen::VectorXd v(2);
v << 1.0, 2.0;
Eigen::Vector3d w = R * v;
```
--- choice
The build fails with `INVALID_MATRIX_PRODUCT`, because `R` is a fixed-size 3-by-3 matrix.
--- choice correct
It compiles. A debug build stops with a failed assertion when the product runs, and a release build with `NDEBUG` does no check at all.
--- choice
It compiles, and Eigen pads `v` with a zero, so `w` is (1, 2, 0) in every build.
--- choice
It compiles, and Eigen resizes `v` to three entries before it multiplies.
--- why
The compiler can only refuse a product when both inner sizes are in the types. `R` has 3 columns in its type, but `v` is a `VectorXd`, whose length is a number stored in the object. So the compiler cannot know the sizes clash, and the check is left to a run-time assertion, which `NDEBUG` removes. One dynamic operand is enough to lose the compile-time check. Eigen never pads or resizes an operand to make a product fit.

+++ practice | Lay it down column by column
--- task
A matrix arrives from a C program as a `std::vector<double>` written row by row, and a column-major library wants it column by column. Write two functions:

- `std::vector<double> to_col_major(const std::vector<double>& rm, int rows, int cols)` takes the row-major numbers of a `rows`-by-`cols` matrix and returns the same matrix laid out column-major;
- `std::vector<double> to_row_major(const std::vector<double>& cm, int rows, int cols)` does the reverse.

Every entry keeps its meaning: entry (i, j) moves from offset i × cols + j to offset i + j × rows, or back. If the vector's size is not `rows * cols`, return an empty vector.

For example, the 2-by-3 matrix with rows `1 2 3` and `4 5 6` is `{1, 2, 3, 4, 5, 6}` row-major and `{1, 4, 2, 5, 3, 6}` column-major.
--- starter
#include <vector>

std::vector<double> to_col_major(const std::vector<double>& rm, int rows, int cols) {
    return rm;
}

std::vector<double> to_row_major(const std::vector<double>& cm, int rows, int cols) {
    return cm;
}
--- solution
#include <vector>

// Entry (i, j): row-major offset i * cols + j, column-major offset i + j * rows.
std::vector<double> to_col_major(const std::vector<double>& rm, int rows, int cols) {
    if (rm.size() != static_cast<std::size_t>(rows) * cols) return {};
    std::vector<double> cm(rm.size());
    for (int i = 0; i < rows; ++i)
        for (int j = 0; j < cols; ++j) cm[i + j * rows] = rm[i * cols + j];
    return cm;
}

std::vector<double> to_row_major(const std::vector<double>& cm, int rows, int cols) {
    if (cm.size() != static_cast<std::size_t>(rows) * cols) return {};
    std::vector<double> rm(cm.size());
    for (int i = 0; i < rows; ++i)
        for (int j = 0; j < cols; ++j) rm[i * cols + j] = cm[i + j * rows];
    return rm;
}
--- hint
Loop over every (i, j). Read it from where the input order keeps it, and write it where the output order keeps it.
--- hint
Row-major: skip i whole rows of `cols` entries, then move j along. Column-major: skip j whole columns of `rows` entries, then go down i.
--- check case | A 2-by-3 matrix goes column by column
to_col_major({1, 2, 3, 4, 5, 6}, 2, 3)
=> std::vector<double>{1, 4, 2, 5, 3, 6}
--- check case | And back to row by row
to_row_major({1, 4, 2, 5, 3, 6}, 2, 3)
=> std::vector<double>{1, 2, 3, 4, 5, 6}
--- check case | A single row is laid out the same both ways
to_col_major({7, 8, 9}, 1, 3)
=> std::vector<double>{7, 8, 9}
--- check test | A 3-by-4 matrix survives the round trip, and really moved
[] { std::vector<double> m; for (int k = 0; k < 12; ++k) m.push_back(k * 1.5); auto cm = to_col_major(m, 3, 4); return cm != m && cm[1] == m[4] && to_row_major(cm, 3, 4) == m; }()
--- check test | A size that does not match gives an empty vector
to_col_major({1, 2, 3, 4, 5}, 2, 3).empty() && to_row_major({1, 2}, 2, 2).empty()

+++ practice | A window you can write through
--- task
Eigen's `Map` views memory it does not own, and reads it in the storage order its type names. Build a small version.

The starter has `template <std::size_t R, std::size_t C, bool RowMajor> class MatView`, which holds only a pointer. Write:

- its member `double& operator()(std::size_t i, std::size_t j) const`, which returns a reference to entry (i, j) of the `R`-by-`C` matrix stored at the pointer: row by row when `RowMajor` is `true`, column by column when it is `false`;
- a function template `template <std::size_t N, bool RowMajor> std::array<double, N> mul_vec(const MatView<N, N, RowMajor>& m, const std::array<double, N>& x)` that returns the matrix times the vector.

Nothing is copied: writing `view(i, j) = 5.0` changes the buffer itself. For the nine numbers `{0, -1, 0, 1, 0, 0, 0, 0, 1}`, a row-major view is a quarter turn about z, and it sends (1, 0, 0) to (0, 1, 0).

--- solution
#include <array>
#include <cstddef>

// A view: a pointer and a storage order in the type. It owns nothing and copies nothing.
template <std::size_t R, std::size_t C, bool RowMajor>
class MatView {
public:
    explicit MatView(double* p) : p_(p) {}
    double& operator()(std::size_t i, std::size_t j) const {
        if constexpr (RowMajor) return p_[i * C + j];
        else return p_[i + j * R];
    }
    double* data() const { return p_; }
private:
    double* p_;
};

template <std::size_t N, bool RowMajor>
std::array<double, N> mul_vec(const MatView<N, N, RowMajor>& m, const std::array<double, N>& x) {
    std::array<double, N> y{};
    for (std::size_t i = 0; i < N; ++i)
        for (std::size_t j = 0; j < N; ++j) y[i] += m(i, j) * x[j];
    return y;
}
--- hint
The storage order is a template argument, so the choice can be made at compile time with `if constexpr`, or with an ordinary `if`.
--- hint
Row-major offset: `i * C + j`. Column-major offset: `i + j * R`. `mul_vec` only ever uses `m(i, j)`, so it works for both orders.
--- check test | A row-major view turns x into y

--- check test | The same nine numbers read column by column give the transpose
[] { double b[9] = {0, -1, 0, 1, 0, 0, 0, 0, 1}; MatView<3, 3, false> m(b); auto y = mul_vec(m, std::array<double, 3>{1, 0, 0}); return y[0] == 0 && y[1] == -1 && y[2] == 0; }()
--- check test | Writing through a row-major 2-by-3 view changes the right slot
[] { double b[6] = {}; MatView<2, 3, true> v(b); v(0, 2) = 60.0; v(1, 0) = 7.0; return b[2] == 60.0 && b[3] == 7.0 && v.data() == b; }()
--- check test | Writing through a column-major 2-by-3 view changes a different slot
[] { double b[6] = {}; MatView<2, 3, false> v(b); v(0, 2) = 60.0; v(1, 0) = 7.0; return b[4] == 60.0 && b[1] == 7.0; }()

+++ practice | Every third number
--- task
Three sensors share one buffer, interleaved: a0, b0, c0, a1, b1, c1, and so on. A strided view picks out one sensor without copying, the way a `Map` with an `InnerStride` does.

Write:

- `struct Strided` with members `const double* p;`, `int n;` (how many entries the view has) and `int stride;` (the step, in doubles, from one entry to the next), and a member `double operator[](int k) const` that returns entry `k`, which is `p[k * stride]`;
- `double max_abs(const Strided& s)`, the largest size of any entry, ignoring the sign;
- `double mean(const Strided& s)`, the average of the entries.

Both return `0.0` when `n` is 0. To view sensor b of the buffer above, use `Strided{buf + 1, count, 3}`.
--- starter
struct Strided {
    const double* p;
    int n;
    int stride;
    double operator[](int k) const { return p[k]; }
};

double max_abs(const Strided& s) { return -1.0; }

double mean(const Strided& s) { return -1.0; }
--- solution
#include <cmath>

// A view with gaps: where to start, how many, and how far to step.
struct Strided {
    const double* p;
    int n;
    int stride;
    double operator[](int k) const { return p[k * stride]; }
};

double max_abs(const Strided& s) {
    double best = 0.0;
    for (int k = 0; k < s.n; ++k) best = std::fmax(best, std::fabs(s[k]));
    return best;
}

double mean(const Strided& s) {
    if (s.n == 0) return 0.0;
    double sum = 0.0;
    for (int k = 0; k < s.n; ++k) sum += s[k];
    return sum / s.n;
}
--- hint
Entry k of the view is `stride` doubles further on for each step: `p[k * stride]`.
--- hint
Start the largest size at 0.0, so an empty view returns 0.0 with no special case. The mean does need one: never divide by zero.

+++ question | A Map over a NumPy array
--- ask
Python makes `a = np.arange(6.0).reshape(2, 3)`, so `a` is the 2-by-3 matrix with rows `0 1 2` and `3 4 5`, in NumPy's default layout, and passes its buffer pointer `p` to C++. Which view is the matrix `a` itself, entry for entry?

#include <vector>

// The window m.block(i, j, p, q): start (i, j), size p by q. Column-major in and out.
std::vector<double> block_copy(const std::vector<double>& m, int rows, int cols,
                               int i, int j, int p, int q) {
    if (m.size() != static_cast<std::size_t>(rows) * cols) return {};
    if (i < 0 || j < 0 || p < 0 || q < 0 || i + p > rows || j + q > cols) return {};
    std::vector<double> out;
    out.reserve(static_cast<std::size_t>(p) * q);
    for (int c = 0; c < q; ++c)
        for (int r = 0; r < p; ++r) out.push_back(m[(i + r) + (j + c) * rows]);
    return out;
}

--- solution
// A window onto part of a column-major matrix. Writes go into the matrix itself.
struct BlockRef {
    double* base;
    int ld;          // rows of the whole matrix
    int i, j, p, q;  // start and size of the window

    double& operator()(int r, int c) const { return base[(i + r) + (j + c) * ld]; }

    void set_zero() const {
        for (int c = 0; c < q; ++c)
            for (int r = 0; r < p; ++r) (*this)(r, c) = 0.0;
    }

    void set_identity() const {
        for (int c = 0; c < q; ++c)
            for (int r = 0; r < p; ++r) (*this)(r, c) = (r == c) ? 1.0 : 0.0;
    }
};

// F = [I  dt*I; 0  I], built from blocks.
void make_cv(double* F, double dt) {
    BlockRef{F, 6, 0, 0, 6, 6}.set_identity();
    const BlockRef top_right{F, 6, 0, 3, 3, 3};
    for (int k = 0; k < 3; ++k) top_right(k, k) = dt;
}

--- hint

+++ practice | Predict the covariance one block at a time
--- task
A 6-state tracker keeps position (states 0 to 2) then velocity (states 3 to 5), and a 6-by-6 covariance `P`, stored column-major in a `std::array<double, 36>`. Write

`void predict_cov(std::array<double, 36>& P, double dt)`

which replaces `P` with F P Fᵀ (read "F P F transpose"), where F is the constant-velocity model: the identity with `dt` times the 3-by-3 identity in its top-right block.

You may multiply the full matrices, but thinking in blocks is shorter. Write P as four 3-by-3 blocks, A (top-left), B (top-right), Bᵀ (bottom-left) and D (bottom-right). Then the new blocks are:

- top-left: A + dt (B + Bᵀ) + dt² D
- top-right: B + dt D, and bottom-left: its transpose
- bottom-right: D, unchanged

Be careful about order: every new block is built from the old blocks. `P` is symmetric on the way in and must be symmetric on the way out.
--- starter

}
--- solution
#include <array>

// P <- F P F^T for F = [I dt*I; 0 I], one 3-by-3 block at a time. Column-major 6-by-6.
void predict_cov(std::array<double, 36>& P, double dt) {
    auto at = [&P](int i, int j) -> double& { return P[i + 6 * j]; };
    std::array<double, 36> old = P;   // every new block is built from the old ones
    auto was = [&old](int i, int j) { return old[i + 6 * j]; };
    for (int r = 0; r < 3; ++r) {
        for (int c = 0; c < 3; ++c) {
            const double A = was(r, c), B = was(r, c + 3), Bt = was(r + 3, c), D = was(r + 3, c + 3);
            at(r, c) = A + dt * (B + Bt) + dt * dt * D;   // top-left
            at(r, c + 3) = B + dt * D;                       // top-right
        }
    }
    for (int r = 0; r < 3; ++r)
        for (int c = 0; c < 3; ++c) at(r + 3, c) = at(c, r + 3);   // bottom-left = top-right transposed
}
--- hint
Entry (r, c) of block B is entry (r, c + 3) of P. Block Bᵀ has, at (r, c), entry (r + 3, c) of P, which equals B's (c, r) because P is symmetric.
--- hint
If you overwrite B before you build the new top-left block, the top-left block reads the new B. Keep a copy of the old P, or build every block before you store any.

+++ practice | Two ways to multiply
--- task
Eigen's `*` on two matrices is the matrix product, and `.array()` or `cwiseProduct` gives the entry-by-entry product. Write both by hand, for 3-by-3 matrices stored as `using M3 = std::array<std::array<double, 3>, 3>;` (`m[i][j]` is row i, column j):

- `M3 matmul(const M3& a, const M3& b)`: entry (i, j) is row i of `a` times column j of `b`, multiplied pair by pair and added up;
- `M3 cwise(const M3& a, const M3& b)`: entry (i, j) is `a[i][j] * b[i][j]`;
- `double max_abs_diff(const M3& a, const M3& b)`: the largest size of any entry of `a - b`, the way tests compare two matrices with `(a - b).cwiseAbs().maxCoeff()`.

The checks also show why a test with diagonal matrices cannot tell the two products apart.
--- starter

using M3 = std::array<std::array<double, 3>, 3>;

M3 matmul(const M3& a, const M3& b) { return a; }

M3 cwise(const M3& a, const M3& b) { return a; }

--- solution
#include <array>
#include <cmath>

using M3 = std::array<std::array<double, 3>, 3>;

// The linear-algebra product: row i of a dotted with column j of b.
M3 matmul(const M3& a, const M3& b) {
    M3 out{};
    for (int i = 0; i < 3; ++i)
        for (int j = 0; j < 3; ++j)
            for (int k = 0; k < 3; ++k) out[i][j] += a[i][k] * b[k][j];
    return out;
}

// The coefficient-wise product: same spot times same spot.
M3 cwise(const M3& a, const M3& b) {
    M3 out{};
    for (int i = 0; i < 3; ++i)
        for (int j = 0; j < 3; ++j) out[i][j] = a[i][j] * b[i][j];
    return out;
}

// (a - b).cwiseAbs().maxCoeff()
double max_abs_diff(const M3& a, const M3& b) {
    double worst = 0.0;
    for (int i = 0; i < 3; ++i)
        for (int j = 0; j < 3; ++j) worst = std::fmax(worst, std::fabs(a[i][j] - b[i][j]));
    return worst;
}
--- hint
The matrix product needs three loops: two to pick the entry, one to walk along the row and down the column. The entry-by-entry product needs only two.

--- starter

--- solution
#include <vector>

struct Where { double value; int row; int col; };

// Walk column by column, and only a strictly smaller value moves the answer,
// so the first of several equal values wins.
Where min_coeff(const std::vector<std::vector<double>>& m) {
    if (m.empty() || m[0].empty()) return {0.0, -1, -1};
    const int rows = static_cast<int>(m.size());
    const int cols = static_cast<int>(m[0].size());
    Where best{m[0][0], 0, 0};
    for (int j = 0; j < cols; ++j)
        for (int i = 0; i < rows; ++i)
            if (m[i][j] < best.value) best = {m[i][j], i, j};
    return best;
}

// One answer per column: m.colwise().maxCoeff().
std::vector<double> colwise_max(const std::vector<std::vector<double>>& m) {
    if (m.empty() || m[0].empty()) return {};
    std::vector<double> out = m[0];
    for (const auto& row : m)
        for (std::size_t j = 0; j < out.size(); ++j)
            if (row[j] > out[j]) out[j] = row[j];
    return out;
}
--- hint
Put the column loop outside and the row loop inside. Replace the best answer only on a strictly smaller value, and ties keep the first one.
--- hint

#include <array>
#include <vector>

// rate = scale (per row) times counts, minus bias (per row), clamped to +-limit.
std::array<int, 3> calibrate(const std::vector<std::vector<int>>& counts,
                             const std::array<double, 3>& scale,
                             const std::array<double, 3>& bias,
                             double limit,
                             std::vector<std::vector<double>>& rate) {
    std::array<int, 3> clamped{0, 0, 0};
    rate.assign(3, {});
    for (int i = 0; i < 3; ++i) {

            if (r > limit) { r = limit; ++clamped[i]; }
            else if (r < -limit) { r = -limit; ++clamped[i]; }
            rate[i].push_back(r);
        }
    }
    return clamped;
}

+++ practice | What a = a.transpose() really does
--- task
Eigen evaluates `a = a.transpose()` lazily: it fills the destination column by column, and each entry (i, j) reads the source at (j, i) as it is at that moment, including entries it has already overwritten. Write two functions for a square `n`-by-`n` matrix stored column-major in a `std::vector<double>`:

- `void transpose_in_place(std::vector<double>& m, int n)` really transposes the matrix, in place, the way `transposeInPlace()` does: swap each entry above the diagonal with its mirror below it.

Entry (i, j) is at offset `i + j * n`. The checks compare your naive result with the damage a release build of Eigen really does.
--- starter

--- solution
#include <utility>
#include <vector>

// The lazy loop with no temporary: entry (i, j) reads (j, i) as it is right now.
void naive_transpose(std::vector<double>& m, int n) {
    for (int j = 0; j < n; ++j)
        for (int i = 0; i < n; ++i) m[i + j * n] = m[j + i * n];
}

// The safe way: each pair above and below the diagonal is swapped exactly once.
void transpose_in_place(std::vector<double>& m, int n) {
    for (int j = 0; j < n; ++j)
        for (int i = j + 1; i < n; ++i) std::swap(m[i + j * n], m[j + i * n]);
}
--- hint
The naive version is two loops and one assignment. It needs no care at all: its damage is the point.
--- hint
For the real transpose, visit only the pairs with i greater than j, and swap. Visiting every (i, j) would swap each pair twice and undo the work.

    std::vector<double> a;
    MatX() = default;
    MatX(int r, int c) : rows(r), cols(c), a(static_cast<std::size_t>(r) * c, 0.0) { ++g_allocs; }
    double& operator()(int i, int j) { return a[i + j * rows]; }
    double operator()(int i, int j) const { return a[i + j * rows]; }
};

// out = A * B, written straight into out. out must not be A or B.
static void product_into(MatX& out, const MatX& A, const MatX& B) {
    for (int j = 0; j < out.cols; ++j)
        for (int i = 0; i < out.rows; ++i) {
            double s = 0.0;
            for (int k = 0; k < A.cols; ++k) s += A(i, k) * B(k, j);
            out(i, j) = s;
        }
}

void assign_product(MatX& C, const MatX& A, const MatX& B) {
    if (&C == &A || &C == &B) {            // aliasing: Eigen's default temporary
        MatX tmp(A.rows, B.cols);
        product_into(tmp, A, B);
        C = std::move(tmp);
        return;
    }
    if (C.rows != A.rows || C.cols != B.cols) C = MatX(A.rows, B.cols);
    product_into(C, A, B);                 // no aliasing: what noalias() promises
}
--- hint
Compare addresses: `&C == &A` is true only when they are the same object, not merely equal numbers.
--- hint

--- task
A small flight computer keeps mission time in a `float` and adds the time step every cycle. Write two functions that both start at 0 and add `dt` exactly `ticks` times, both keeping every running value in `float`:

--- starter

    return 0.0f;
}
--- solution
float clock_naive(int ticks, float dt) {
    float t = 0.0f;
    for (int k = 0; k < ticks; ++k) t += dt;
    return t;
}

// Compensated summation in float: lost carries what the last addition rounded away.
float clock_kahan(int ticks, float dt) {
    float t = 0.0f;
    float lost = 0.0f;
    for (int k = 0; k < ticks; ++k) {
        const float y = dt - lost;       // this step, plus what fell off last time
        const float next = t + y;        // big plus small: low bits of y are rounded away
        lost = (next - t) - y;           // exactly what was rounded away, sign flipped
        t = next;
    }
    return t;
}
--- hint
Kahan summation needs four lines in the loop: correct the new term, add it, work out what was lost, and keep the new total.
--- hint
`(next - t)` is the part of `y` that really got in. Subtract `y` from it and you have the loss, with its sign flipped, ready to be taken off the next term.

#include <array>
#include <cmath>

// a*b - c*d with Kahan's method: two fused multiply-adds, one rounding each.
double diff_of_products(double a, double b, double c, double d) {
    const double w = c * d;
    const double err = std::fma(-c, d, w);   // exactly w - c*d
    const double f = std::fma(a, b, -w);     // a*b - w, rounded once
    return f + err;
}

double det2(double m00, double m01, double m10, double m11) {
    return diff_of_products(m00, m11, m01, m10);
}

    return {diff_of_products(u[1], v[2], u[2], v[1]),
            diff_of_products(u[2], v[0], u[0], v[2]),
            diff_of_products(u[0], v[1], u[1], v[0])};
}

--- solution
#include <algorithm>
#include <cmath>
#include <vector>

static double length(const std::vector<double>& v) {
    double s = 0.0;
    for (double x : v) s += x * x;
    return std::sqrt(s);
}

// Eigen's isApprox: |a - b| <= tol * min(|a|, |b|).
bool is_approx(const std::vector<double>& a, const std::vector<double>& b, double tol) {
    if (a.size() != b.size()) return false;
    double d = 0.0;
    for (std::size_t k = 0; k < a.size(); ++k) d += (a[k] - b[k]) * (a[k] - b[k]);
    return std::sqrt(d) <= tol * std::min(length(a), length(b));
}

--- hint

--- solution
#include <cmath>
#include <limits>

// kappa = largest |eigenvalue| / smallest |eigenvalue| for [a b; b c].
double cond_sym2(double a, double b, double c) {
    const double m = 0.5 * (a + c);
    const double r = std::sqrt(0.25 * (a - c) * (a - c) + b * b);
    const double big = std::fmax(std::fabs(m + r), std::fabs(m - r));
    const double small = std::fmin(std::fabs(m + r), std::fabs(m - r));
    if (small == 0.0) return std::numeric_limits<double>::infinity();
    return big / small;
}

// About 16 digits to start with, minus log10(kappa) lost to the problem itself.
int good_digits(double kappa) {
    const double digits = 16.0 - std::log10(kappa);
    if (!(digits > 0.0)) return 0;          // also catches -infinity
    return static_cast<int>(std::floor(digits));
}
--- hint

--- hint

+++ practice | Triangles are easy
--- task
Every decomposition ends in triangular solves. A matrix here is `using Mat = std::vector<std::vector<double>>;`, where `L[i][j]` is row i, column j. `L` is square and lower triangular: only the entries on and below the diagonal matter, and whatever sits above the diagonal must be ignored. Write:

#include <vector>

using Mat = std::vector<std::vector<double>>;

// L y = b, top row first. Only entries on and below the diagonal are read.
std::vector<double> forward_sub(const Mat& L, const std::vector<double>& b) {
    const int n = static_cast<int>(b.size());
    std::vector<double> y(n);
    for (int i = 0; i < n; ++i) {
        double s = b[i];
        for (int j = 0; j < i; ++j) s -= L[i][j] * y[j];
        y[i] = s / L[i][i];
    }
    return y;
}

// L^T x = y, bottom row first. Row i of L^T is column i of L: L^T(i, j) = L[j][i].
std::vector<double> back_sub_t(const Mat& L, const std::vector<double>& y) {
    const int n = static_cast<int>(y.size());
    std::vector<double> x(n);
    for (int i = n - 1; i >= 0; --i) {
        double s = y[i];
        for (int j = i + 1; j < n; ++j) s -= L[j][i] * x[j];
        x[i] = s / L[i][i];
    }
    return x;
}
--- hint
Row i of L y = b reads L[i][0] y₀ + … + L[i][i] yᵢ = bᵢ. Every y before yᵢ is already known, so subtract them and divide by the diagonal.
--- hint
Lᵀ is upper triangular, so start at the last row. Row i of Lᵀ has entries `L[j][i]` for j from i up to the end.

+++ practice | Cholesky that reports failure
--- task
Write `bool cholesky(Mat& A)`, with `using Mat = std::vector<std::vector<double>>;`, which factors a symmetric positive definite matrix as L Lᵀ, in place, the way Eigen's `LLT` does:

- it reads only the lower triangle of `A` (entries on and below the diagonal), so it never checks that the upper triangle matches;
- on success it leaves `L` in the lower triangle, sets every entry above the diagonal to 0, and returns `true`;
- whenever the number under a diagonal square root is 0 or negative, it stops and returns `false`, like `info()` not being `Success`. The contents of `A` do not matter then.

The entries come from A = L Lᵀ one column at a time: the diagonal entry of column j is the square root of A(j, j) minus the squares of the entries to its left in row j, and each entry below it is (A(i, j) minus the sum of L(i, k) L(j, k) for k < j) divided by that diagonal entry.
--- starter

    return true;
}
--- solution
#include <cmath>
#include <vector>

using Mat = std::vector<std::vector<double>>;

// A = L L^T in place. Reads the lower triangle only; fails on a pivot that is not positive.
bool cholesky(Mat& A) {
    const int n = static_cast<int>(A.size());
    for (int j = 0; j < n; ++j) {
        double d = A[j][j];
        for (int k = 0; k < j; ++k) d -= A[j][k] * A[j][k];
        if (d <= 0.0) return false;          // semi-definite or indefinite
        const double ljj = std::sqrt(d);
        A[j][j] = ljj;
        for (int i = j + 1; i < n; ++i) {
            double s = A[i][j];
            for (int k = 0; k < j; ++k) s -= A[i][k] * A[j][k];
            A[i][j] = s / ljj;
        }
        for (int i = 0; i < j; ++i) A[i][j] = 0.0;   // clear the upper triangle
    }
    return true;
}
--- hint
Work column by column. By the time you reach column j, every entry of L to the left of it is finished and stored in `A`.
--- hint
Test the number under the square root before taking it: `d <= 0.0` means the matrix is not positive definite. Only then take `std::sqrt`.

--- task
Factoring costs about n³ operations and each solve only about n², so a filter factors once and reuses the factor for every right-hand side. Write

--- starter

--- solution
#include <cmath>
#include <vector>

using Mat = std::vector<std::vector<double>>;

// Factor A = L L^T once, then two triangular solves per right-hand side.
std::vector<std::vector<double>> chol_solve(const Mat& A, const std::vector<std::vector<double>>& rhs) {
    const int n = static_cast<int>(A.size());
    Mat L(n, std::vector<double>(n, 0.0));
    for (int j = 0; j < n; ++j) {
        double d = A[j][j];
        for (int k = 0; k < j; ++k) d -= L[j][k] * L[j][k];
        if (d <= 0.0) return {};
        L[j][j] = std::sqrt(d);
        for (int i = j + 1; i < n; ++i) {
            double s = A[i][j];
            for (int k = 0; k < j; ++k) s -= L[i][k] * L[j][k];
            L[i][j] = s / L[j][j];
        }
    }

    std::vector<std::vector<double>> out;
    for (const auto& b : rhs) {
        std::vector<double> y(n), x(n);
        for (int i = 0; i < n; ++i) {                 // L y = b
            double s = b[i];
            for (int k = 0; k < i; ++k) s -= L[i][k] * y[k];
            y[i] = s / L[i][i];
        }
        for (int i = n - 1; i >= 0; --i) {            // L^T x = y
            double s = y[i];
            for (int k = i + 1; k < n; ++k) s -= L[k][i] * x[k];
            x[i] = s / L[i][i];
        }
        out.push_back(x);
    }
    return out;
}
--- hint
Keep the factor in its own matrix `L`, filled once, before the loop over the right-hand sides.
--- hint
Inside the loop, solve L y = b from the top down, then Lᵀ x = y from the bottom up, reading `L[k][i]` for the transpose.

#include <array>
#include <cmath>
#include <cstdio>
#include <utility>

// Solve [a00 a01; a10 a11] [x1; x2] = [b0; b1] by elimination with partial pivoting.
std::array<double, 2> solve2(double a00, double a01, double a10, double a11, double b0, double b1) {
    if (std::fabs(a10) > std::fabs(a00)) {   // bring the larger pivot to the top
        std::swap(a00, a10);
        std::swap(a01, a11);
        std::swap(b0, b1);
    }
    const double m = a10 / a00;           // multiplier for row 1, now at most 1 in size
    const double u11 = a11 - m * a01;
    const double c1 = b1 - m * b0;
    const double x2 = c1 / u11;
    const double x1 = (b0 - a01 * x2) / a00;
    return {x1, x2};
}

+++ practice | How many columns really count
--- task
`ColPivHouseholderQR::rank()` tells you how many columns of a least-squares matrix are really independent. Write a simple version with Gram-Schmidt:

`int numeric_rank(std::vector<std::vector<double>> cols, double tol)`

Each inner vector is one column, and all have the same length. Take the columns in the order given. For each column, subtract its projection onto every column you have already kept (after making those unit length), using the column as it stands after each subtraction. Keep the column, as a new unit vector, only if what is left has length greater than `tol` times the column's original length. A column of zeros is never kept. Return how many columns you kept.

For temperatures `T = {10, 15, 20, 25, 30}`, the columns ones, T and 1.8 T + 32 (the same temperatures in Fahrenheit) have rank 2, because the third is a mix of the first two.
--- starter
#include <vector>

int numeric_rank(std::vector<std::vector<double>> cols, double tol) {
    return static_cast<int>(cols.size());
}
--- solution
#include <cmath>
#include <vector>

static double dot(const std::vector<double>& a, const std::vector<double>& b) {
    double s = 0.0;
    for (std::size_t k = 0; k < a.size(); ++k) s += a[k] * b[k];
    return s;
}

// Modified Gram-Schmidt: keep a column only if enough of it is new.
int numeric_rank(std::vector<std::vector<double>> cols, double tol) {
    std::vector<std::vector<double>> kept;   // unit vectors
    for (auto& v : cols) {
        const double original = std::sqrt(dot(v, v));
        if (original == 0.0) continue;
        for (const auto& q : kept) {
            const double c = dot(q, v);
            for (std::size_t k = 0; k < v.size(); ++k) v[k] -= c * q[k];
        }
        const double left = std::sqrt(dot(v, v));
        if (left > tol * original) {
            for (double& x : v) x /= left;
            kept.push_back(v);
        }
    }
    return static_cast<int>(kept.size());
}
--- hint
The projection of v onto a unit vector q is (q · v) q. Subtract it, then move on to the next kept vector using the updated v.
--- hint
Measure the column's length before you subtract anything. After the subtractions, compare what is left with `tol` times that original length.

+++ question | A determinant from the factor
--- ask
Eigen's `LLT` of a 3-by-3 covariance `P` gives a factor `L` whose diagonal is 2, 0.5 and 3. What is the determinant of `P`? Type the number.
--- answer
9
9.0
--- why
The determinant of a triangular matrix is the product of its diagonal, so det L = 2 × 0.5 × 3 = 3. Since P = L Lᵀ and det Lᵀ = det L, det P = (det L)² = 3² = 9. This is also the cheap way to get a determinant from a factorization you already have, and summing the logarithms of the diagonal avoids overflow for big matrices.

#include <array>

// K = P h^T / S with S = h P h^T + r: a 1-by-1 solve is a division.
std::array<double, 2> gain_2x1(const std::array<double, 4>& P, const std::array<double, 2>& h, double r) {
    const double pht0 = P[0] * h[0] + P[1] * h[1];   // (P h^T), row 0
    const double pht1 = P[2] * h[0] + P[3] * h[1];   // (P h^T), row 1
    const double S = h[0] * pht0 + h[1] * pht1 + r;
    return {pht0 / S, pht1 / S};
}

        for (int j = 0; j < 2; ++j)
            for (int k = 0; k < 2; ++k) c[i][j] += a[i][k] * b[k][j];
    return c;
}

M2 solve(const M2& S, const M2& B) {

    const double l11 = std::sqrt(S[1][1] - l10 * l10);

struct Filter2 {
    double x[2];      // position (m), velocity (m/s)
    double P[2][2];   // covariance
};

// x <- F x, P <- F P F^T + diag(0, q), with F = [1 dt; 0 1].
void predict(Filter2& f, double dt, double q) {
    f.x[0] += dt * f.x[1];
    const double p00 = f.P[0][0], p01 = f.P[0][1], p10 = f.P[1][0], p11 = f.P[1][1];
    f.P[0][0] = p00 + dt * (p01 + p10) + dt * dt * p11;
    f.P[0][1] = p01 + dt * p11;
    f.P[1][0] = p10 + dt * p11;
    f.P[1][1] = p11 + q;
}

// Position measurement, H = [1 0]. Gain by division, Joseph-form covariance.
void update_pos(Filter2& f, double z, double r) {
    const double S = f.P[0][0] + r;
    const double k0 = f.P[0][0] / S, k1 = f.P[1][0] / S;
    const double y = z - f.x[0];
    f.x[0] += k0 * y;
    f.x[1] += k1 * y;

    // M = I - K H = [1-k0 0; -k1 1]
    const double m[2][2] = {{1.0 - k0, 0.0}, {-k1, 1.0}};
    double MP[2][2] = {};
    for (int i = 0; i < 2; ++i)
        for (int j = 0; j < 2; ++j)
            for (int k = 0; k < 2; ++k) MP[i][j] += m[i][k] * f.P[k][j];
    const double kk[2] = {k0, k1};
    double out[2][2] = {};
    for (int i = 0; i < 2; ++i)
        for (int j = 0; j < 2; ++j) {
            for (int k = 0; k < 2; ++k) out[i][j] += MP[i][k] * m[j][k];   // (M P) M^T
            out[i][j] += kk[i] * r * kk[j];                                // + K r K^T
        }
    for (int i = 0; i < 2; ++i)
        for (int j = 0; j < 2; ++j) f.P[i][j] = 0.5 * (out[i][j] + out[j][i]);
}
--- hint
Keep copies of the old covariance entries before you overwrite any of them: every new entry is built from the old ones.
--- hint
With H = [1, 0], S = P[0][0] + r and K = (P[0][0], P[1][0]) / S. The matrix I − K H has rows `1 − k0, 0` and `−k1, 1`. Compute (I − K H) P first, then multiply by (I − K H)ᵀ, then add K r Kᵀ.

+++ question | Least squares through the normal equations
--- ask
A teammate fits a model with `x = (A.transpose() * A).inverse() * A.transpose() * b;`, where `A` is a tall 500-by-4 matrix. Apart from the inverse, what is the real numerical problem with this line?
--- choice
`A.transpose() * A` is slow, because it is 500-by-500.
--- choice correct
Forming Aᵀ A squares the condition number, so a fit that should keep 10 good digits keeps about 4. A QR on `A` itself avoids that.
--- choice
It only works when `A` is square, so a 500-by-4 matrix will not compile.
--- choice
`inverse()` on a 4-by-4 matrix allocates on the heap every time.
--- why
The condition number of Aᵀ A is the square of that of A. With κ(A) = 10⁶, a solve on A can keep about 16 − 6 = 10 digits, but Aᵀ A has κ = 10¹² and keeps about 4, before any rounding of the inverse. Aᵀ A is 4-by-4, not 500-by-500, and it compiles fine; a fixed-size 4-by-4 inverse does not allocate at all. The fix is `A.householderQr().solve(b)`, or `colPivHouseholderQr()` if the rank is in doubt.

--- task
Write the three quaternion operations that do nearly all the work, for `struct Quat { double w, x, y, z; };` and `using Vec3 = std::array<double, 3>;`:

  - x = w₁x₂ + x₁w₂ + y₁z₂ − z₁y₂
  - y = w₁y₂ − x₁z₂ + y₁w₂ + z₁x₂
  - z = w₁z₂ + x₁y₂ − y₁x₂ + z₁w₂

#include <array>

struct Quat { double w, x, y, z; };
using Vec3 = std::array<double, 3>;

// Hamilton product: mul(a, b) applies b first, then a.
Quat mul(const Quat& a, const Quat& b) {
    return {a.w * b.w - a.x * b.x - a.y * b.y - a.z * b.z,
            a.w * b.x + a.x * b.w + a.y * b.z - a.z * b.y,
            a.w * b.y - a.x * b.z + a.y * b.w + a.z * b.x,
            a.w * b.z + a.x * b.y - a.y * b.x + a.z * b.w};
}

// For a unit quaternion the conjugate is the inverse: the reverse turn.
Quat conj(const Quat& q) { return {q.w, -q.x, -q.y, -q.z}; }

// v turned by q: the vector part of q (0, v) q*.
Vec3 rotate(const Quat& q, const Vec3& v) {
    const Quat p = mul(mul(q, Quat{0.0, v[0], v[1], v[2]}), conj(q));
    return {p.x, p.y, p.z};
}

--- task
A rigid transform is a rotation and then a move: T p = R p + t. Write a small version of `Isometry3d`:

- `struct Iso { std::array<double, 9> R; Vec3 t; };`, with `R` a rotation matrix stored row by row and `using Vec3 = std::array<double, 3>;`

--- solution
#include <array>

using Vec3 = std::array<double, 3>;

struct Iso {
    std::array<double, 9> R;   // row by row
    Vec3 t;
};

static Vec3 rot(const std::array<double, 9>& R, const Vec3& p) {
    return {R[0] * p[0] + R[1] * p[1] + R[2] * p[2],
            R[3] * p[0] + R[4] * p[1] + R[5] * p[2],
            R[6] * p[0] + R[7] * p[1] + R[8] * p[2]};
}

// T p = R p + t: turn first, then move.
Vec3 transform_point(const Iso& T, const Vec3& p) {
    const Vec3 r = rot(T.R, p);
    return {r[0] + T.t[0], r[1] + T.t[1], r[2] + T.t[2]};
}

// First b, then a: R = Ra Rb, t = Ra tb + ta.
Iso compose(const Iso& a, const Iso& b) {
    Iso out{};
    for (int i = 0; i < 3; ++i)
        for (int j = 0; j < 3; ++j)
            for (int k = 0; k < 3; ++k) out.R[3 * i + j] += a.R[3 * i + k] * b.R[3 * k + j];
    out.t = transform_point(a, b.t);
    return out;
}

// The inverse of a rigid transform: R^T, and -R^T t.
Iso inverse(const Iso& T) {
    Iso out{};
    for (int i = 0; i < 3; ++i)
        for (int j = 0; j < 3; ++j) out.R[3 * i + j] = T.R[3 * j + i];
    const Vec3 r = rot(out.R, T.t);
    out.t = {-r[0], -r[1], -r[2]};
    return out;
}
--- hint
A helper that multiplies a row-major 3-by-3 by a vector serves all three functions.
--- hint
The composed move is where `a` sends b's move: `transform_point(a, b.t)` is exactly Ra tb + ta. For the inverse, transpose R first, then turn t with it and negate.

+++ practice | Slerp that takes the short way
--- task
Write `Quat slerp(const Quat& a, const Quat& b, double t)` for `struct Quat { double w, x, y, z; };`: the unit quaternion a fraction `t` of the way from `a` to `b`, turning at a constant rate, like Eigen's `a.slerp(t, b)`.

- Let d be the dot product of the two quaternions, the sum of the four products. If d is negative, negate every part of `b` (and d): q and −q are the same rotation, and this makes the path the short way round.

--- solution
#include <cmath>

struct Quat { double w, x, y, z; };

// Constant-rate interpolation along the shorter great-circle arc.
Quat slerp(const Quat& a, const Quat& b_in, double t) {
    Quat b = b_in;
    double d = a.w * b.w + a.x * b.x + a.y * b.y + a.z * b.z;
    if (d < 0.0) {                        // -b is the same rotation, the short way round
        b = {-b.w, -b.x, -b.y, -b.z};
        d = -d;
    }
    double wa, wb;
    if (d > 0.9995) {                     // almost equal: blend and normalize
        wa = 1.0 - t;
        wb = t;
        const Quat q{wa * a.w + wb * b.w, wa * a.x + wb * b.x, wa * a.y + wb * b.y, wa * a.z + wb * b.z};
        const double n = std::sqrt(q.w * q.w + q.x * q.x + q.y * q.y + q.z * q.z);
        return {q.w / n, q.x / n, q.y / n, q.z / n};
    }
    const double omega = std::acos(d);
    const double s = std::sin(omega);
    wa = std::sin((1.0 - t) * omega) / s;
    wb = std::sin(t * omega) / s;
    return {wa * a.w + wb * b.w, wa * a.x + wb * b.x, wa * a.y + wb * b.y, wa * a.z + wb * b.z};
}

--- hint

+++ practice | Which types need extra alignment
--- task
Eigen asks for extra alignment only for fixed-size vectorizable types. Write both rules as `constexpr` functions:

- `constexpr int kDynamic = -1;`
- `constexpr bool fixed_vectorizable(int rows, int cols, int scalar_bytes)`: `true` when both sizes are fixed (not `kDynamic`), the matrix has at least one entry, and its total size, rows × cols × scalar_bytes, is a multiple of 16 bytes;
- `constexpr int required_alignment(int rows, int cols, int scalar_bytes, int max_simd_bytes)`: for a type that is not fixed vectorizable, just `scalar_bytes`. Otherwise, the largest of `max_simd_bytes`, `max_simd_bytes / 2`, `max_simd_bytes / 4` and so on, down to 16, that divides the total size. `max_simd_bytes` is 16, 32 or 64 (SSE, AVX or AVX-512).

For example, a `Vector4d` (4 × 1 doubles, 32 bytes) needs 16 on an SSE build and 32 on an AVX build, and a `Vector3d` (24 bytes) needs only 8.
--- starter

bool fixed_vectorizable(int rows, int cols, int scalar_bytes) {
    return false;
}

int required_alignment(int rows, int cols, int scalar_bytes, int max_simd_bytes) {
    return 16;
}
--- solution
#include <type_traits>

constexpr int kDynamic = -1;

// Fixed size, not empty, and an exact number of 16-byte pieces.
constexpr bool fixed_vectorizable(int rows, int cols, int scalar_bytes) {
    if (rows == kDynamic || cols == kDynamic) return false;
    const int bytes = rows * cols * scalar_bytes;
    return bytes > 0 && bytes % 16 == 0;
}

// The widest SIMD load, no wider than the target allows, that tiles the object exactly.
constexpr int required_alignment(int rows, int cols, int scalar_bytes, int max_simd_bytes) {
    if (!fixed_vectorizable(rows, cols, scalar_bytes)) return scalar_bytes;
    const int bytes = rows * cols * scalar_bytes;
    int a = max_simd_bytes;
    while (a > 16 && bytes % a != 0) a /= 2;
    return a;
}
--- hint
Rule out the dynamic and empty cases first. Then it is one remainder: `bytes % 16 == 0`.
--- hint
For the alignment, start at `max_simd_bytes` and halve it while it does not divide the total size, but never go below 16.

+++ practice | Where a member really starts
--- task
The compiler places each member of a struct at the next offset that is a multiple of the member's alignment, and pads the whole struct so its size is a multiple of the largest alignment. That is why a `char` in front of an over-aligned matrix member costs so much. Write:

- `std::size_t align_up(std::size_t n, std::size_t a)`: the smallest multiple of `a` that is at least `n`. `a` is always a power of two;
- `bool is_aligned(std::size_t addr, std::size_t a)`: whether `addr` is a multiple of `a`;
- `std::size_t struct_size(const std::vector<std::array<std::size_t, 2>>& members)`: the `sizeof` of a struct whose members, in order, have the given `{size, alignment}`. `members` is never empty.

For `{{1, 1}, {16, 16}}`, a `char` then a 16-byte, 16-aligned `Vector2d`, the second member starts at offset 16 and the struct is 32 bytes.
--- starter

--- solution
#include <algorithm>
#include <array>
#include <cstddef>
#include <vector>

// Round n up to a multiple of a (a power of two).
std::size_t align_up(std::size_t n, std::size_t a) { return (n + a - 1) / a * a; }

bool is_aligned(std::size_t addr, std::size_t a) { return addr % a == 0; }

// Each member starts at the next multiple of its alignment; the whole struct
// is padded to a multiple of the largest alignment, so arrays of it stay aligned.
std::size_t struct_size(const std::vector<std::array<std::size_t, 2>>& members) {
    std::size_t offset = 0, widest = 1;
    for (const auto& m : members) {
        offset = align_up(offset, m[1]) + m[0];
        widest = std::max(widest, m[1]);
    }
    return align_up(offset, widest);
}
--- hint
Rounding up to a multiple of `a` is `(n + a - 1) / a * a` with whole-number division.
--- hint
Walk the members: move the offset up to the member's alignment, then past its size. At the end, round the total up to the largest alignment you saw.

--- task

--- solution
#include <array>
#include <vector>

// X.mean(axis=0): one mean per column of an n-by-3 row-major buffer.
std::array<double, 3> column_means(const std::vector<double>& X, int n) {
    std::array<double, 3> mu{0.0, 0.0, 0.0};
    if (n == 0) return mu;
    for (int i = 0; i < n; ++i)
        for (int j = 0; j < 3; ++j) mu[j] += X[3 * i + j];
    for (double& m : mu) m /= n;
    return mu;
}

// (X - mu) * w: subtract mu from every row, then scale each column by its weight.
std::vector<double> centered_weighted(const std::vector<double>& X, int n, const std::array<double, 3>& w) {
    const std::array<double, 3> mu = column_means(X, n);
    std::vector<double> S(static_cast<std::size_t>(n) * 3);
    for (int i = 0; i < n; ++i)
        for (int j = 0; j < 3; ++j) S[3 * i + j] = (X[3 * i + j] - mu[j]) * w[j];
    return S;
}
--- hint
Row-major: entry (i, j) of the n-by-3 buffer is `X[3 * i + j]`. `axis=0` adds down each column.
--- hint
Column j uses `mu[j]` and `w[j]` in every row. In Eigen this would be `X.rowwise() - mu` followed by an entry-by-entry product.

--- task
Ceres gets exact Jacobians by running your code on dual numbers: a value that carries its derivatives along. Build a tiny version for three inputs.

--- solution
#include <array>
#include <cmath>

// A value and its derivatives with respect to three inputs.
struct Dual {
    double v;
    std::array<double, 3> d;
};

Dual operator+(const Dual& a, const Dual& b) {
    return {a.v + b.v, {a.d[0] + b.d[0], a.d[1] + b.d[1], a.d[2] + b.d[2]}};
}
Dual operator-(const Dual& a, const Dual& b) {
    return {a.v - b.v, {a.d[0] - b.d[0], a.d[1] - b.d[1], a.d[2] - b.d[2]}};
}
Dual operator*(const Dual& a, const Dual& b) {   // product rule
    Dual out{a.v * b.v, {}};
    for (int k = 0; k < 3; ++k) out.d[k] = a.d[k] * b.v + a.v * b.d[k];
    return out;
}

double root(double x) { return std::sqrt(x); }
Dual root(const Dual& a) {                        // (sqrt a)' = a' / (2 sqrt a)
    const double r = std::sqrt(a.v);
    Dual out{r, {}};
    for (int k = 0; k < 3; ++k) out.d[k] = a.d[k] / (2.0 * r);
    return out;
}

// Written once for any number type T.
template <typename T>
T range(const std::array<T, 3>& p, const std::array<T, 3>& s) {
    const T dx = p[0] - s[0], dy = p[1] - s[1], dz = p[2] - s[2];
    return root(dx * dx + dy * dy + dz * dz);
}

std::array<double, 3> range_gradient(const std::array<double, 3>& p, const std::array<double, 3>& s) {
    std::array<Dual, 3> pd, sd;
    for (int k = 0; k < 3; ++k) {
        pd[k] = Dual{p[k], {0.0, 0.0, 0.0}};
        pd[k].d[k] = 1.0;                         // d p_k / d p_k = 1
        sd[k] = Dual{s[k], {0.0, 0.0, 0.0}};      // the station does not move
    }
    return range(pd, sd).d;
}

--- solution
#include <cmath>
#include <limits>
#include <vector>

// log10 det P = 2 * sum log10 L(j, j), with P = L L^T. Never forms the product.
double log10_det(std::vector<std::vector<double>> P) {
    const int n = static_cast<int>(P.size());
    double sum = 0.0;
    for (int j = 0; j < n; ++j) {
        double d = P[j][j];
        for (int k = 0; k < j; ++k) d -= P[j][k] * P[j][k];
        if (d <= 0.0) return std::numeric_limits<double>::quiet_NaN();
        const double ljj = std::sqrt(d);
        P[j][j] = ljj;
        for (int i = j + 1; i < n; ++i) {
            double s = P[i][j];
            for (int k = 0; k < j; ++k) s -= P[i][k] * P[j][k];
            P[i][j] = s / ljj;
        }
        sum += std::log10(ljj);
    }
    return 2.0 * sum;
}

+++ problem | A measurement update for any state size
--- task
Write a Kalman measurement update for a scalar measurement and any number of states `N`:

```
template <std::size_t N>
void kalman_update(std::array<double, N>& x, std::array<double, N * N>& P,
                   const std::array<double, N>& h, double r, double z);
```

`x` is the state, `P` its N-by-N covariance stored row by row, `h` the measurement row (z is predicted by h x), `r` the measurement variance and `z` the measurement.

- S = h P hᵀ + r, a single number, and the gain is K = P hᵀ / S: a 1-by-1 solve, never an inverse.
- The state becomes x + K (z − h x).
- The covariance becomes the Joseph form (I − K h) P (I − K h)ᵀ + K r Kᵀ, then (P + Pᵀ) / 2, so it is exactly symmetric.

Every new value must be built from the old `x` and `P`. For N = 1 with x = 5, P = 9, h = 1, r = 3 and z = 9, the gain is 0.75, x becomes 8 and P becomes 2.25.
--- starter

#include <cstddef>

template <std::size_t N>
void kalman_update(std::array<double, N>& x, std::array<double, N * N>& P,
                   const std::array<double, N>& h, double r, double z) {
}
--- solution
#include <array>
#include <cstddef>

template <std::size_t N>
void kalman_update(std::array<double, N>& x, std::array<double, N * N>& P,
                   const std::array<double, N>& h, double r, double z) {
    // P h^T and S = h P h^T + r.
    std::array<double, N> Ph{};
    for (std::size_t i = 0; i < N; ++i)
        for (std::size_t j = 0; j < N; ++j) Ph[i] += P[i * N + j] * h[j];
    double S = r, hx = 0.0;
    for (std::size_t i = 0; i < N; ++i) { S += h[i] * Ph[i]; hx += h[i] * x[i]; }

    std::array<double, N> K{};
    for (std::size_t i = 0; i < N; ++i) K[i] = Ph[i] / S;    // a 1-by-1 solve

struct Quat { double w, x, y, z; };

// Pick the largest of the four candidates, so the square root is never of a tiny number.
Quat quat_from_matrix(const std::array<double, 9>& R) {
    auto at = [&R](int i, int j) { return R[3 * i + j]; };
    const double t = at(0, 0) + at(1, 1) + at(2, 2);
    Quat q;
    if (t >= at(0, 0) && t >= at(1, 1) && t >= at(2, 2)) {
        const double s = 2.0 * std::sqrt(1.0 + t);
        q = {s / 4, (at(2, 1) - at(1, 2)) / s, (at(0, 2) - at(2, 0)) / s, (at(1, 0) - at(0, 1)) / s};
    } else if (at(0, 0) >= at(1, 1) && at(0, 0) >= at(2, 2)) {
        const double s = 2.0 * std::sqrt(1.0 + at(0, 0) - at(1, 1) - at(2, 2));
        q = {(at(2, 1) - at(1, 2)) / s, s / 4, (at(0, 1) + at(1, 0)) / s, (at(0, 2) + at(2, 0)) / s};
    } else if (at(1, 1) >= at(2, 2)) {
        const double s = 2.0 * std::sqrt(1.0 + at(1, 1) - at(0, 0) - at(2, 2));
        q = {(at(0, 2) - at(2, 0)) / s, (at(0, 1) + at(1, 0)) / s, s / 4, (at(1, 2) + at(2, 1)) / s};
    } else {
        const double s = 2.0 * std::sqrt(1.0 + at(2, 2) - at(0, 0) - at(1, 1));
        q = {(at(1, 0) - at(0, 1)) / s, (at(0, 2) + at(2, 0)) / s, (at(1, 2) + at(2, 1)) / s, s / 4};
    }
    if (q.w < 0.0) q = {-q.w, -q.x, -q.y, -q.z};   // q and -q: keep w >= 0
    return q;
}

--- solution
#include <array>
#include <cmath>

struct Quat { double w, x, y, z; };

static Quat normalized(Quat q) {
    const double n = std::sqrt(q.w * q.w + q.x * q.x + q.y * q.y + q.z * q.z);
    return {q.w / n, q.x / n, q.y / n, q.z / n};
}

static std::array<double, 3> turn(const Quat& q, const std::array<double, 3>& v) {
    const double w = q.w, x = q.x, y = q.y, z = q.z;
    return {(1 - 2 * (y * y + z * z)) * v[0] + 2 * (x * y - w * z) * v[1] + 2 * (x * z + w * y) * v[2],
            2 * (x * y + w * z) * v[0] + (1 - 2 * (x * x + z * z)) * v[1] + 2 * (y * z - w * x) * v[2],
            2 * (x * z - w * y) * v[0] + 2 * (y * z + w * x) * v[1] + (1 - 2 * (x * x + y * y)) * v[2]};
}

// Convert each message by name at the boundary, then: tracker -> body -> inertial.
std::array<double, 3> boresight_inertial(const std::array<double, 4>& q_ib_wxyz, const std::array<double, 4>& q_bs_xyzw) {
    const Quat q_ib = normalized({q_ib_wxyz[0], q_ib_wxyz[1], q_ib_wxyz[2], q_ib_wxyz[3]});
    const Quat q_bs = normalized({q_bs_xyzw[3], q_bs_xyzw[0], q_bs_xyzw[1], q_bs_xyzw[2]});
    return turn(q_ib, turn(q_bs, {0.0, 0.0, 1.0}));
}

--- solution

#include <cmath>

// atan2(|a x b|, a . b): no arccosine near +-1, so tiny and near-pi angles keep their digits.
double angle_between(const std::array<double, 3>& a, const std::array<double, 3>& b) {
    const double cx = a[1] * b[2] - a[2] * b[1];
    const double cy = a[2] * b[0] - a[0] * b[2];
    const double cz = a[0] * b[1] - a[1] * b[0];
    const double cross = std::sqrt(cx * cx + cy * cy + cz * cz);
    const double dot = a[0] * b[0] + a[1] * b[1] + a[2] * b[2];
    return std::atan2(cross, dot);
}

--- solution
#include <array>
#include <cmath>
#include <vector>

// Per column of a row-major n-by-3 buffer: mean, RMS about the mean, count beyond k * RMS.
std::array<int, 3> outliers(const std::vector<double>& X, int n, double k) {
    std::array<int, 3> count{0, 0, 0};
    if (n == 0) return count;
    for (int j = 0; j < 3; ++j) {
        double mean = 0.0;
        for (int i = 0; i < n; ++i) mean += X[3 * i + j];
        mean /= n;
        double ss = 0.0;
        for (int i = 0; i < n; ++i) ss += (X[3 * i + j] - mean) * (X[3 * i + j] - mean);
        const double limit = k * std::sqrt(ss / n);
        for (int i = 0; i < n; ++i)
            if (std::fabs(X[3 * i + j] - mean) > limit) ++count[j];
    }
    return count;
}

#include <vector>

static int g_allocs = 0;

// A dynamic column-major matrix. Making one, or copying one, is a heap allocation.
struct DynMat {
    int rows, cols;
    std::vector<double> a;
    DynMat(int r, int c) : rows(r), cols(c), a(static_cast<std::size_t>(r) * c, 0.0) { ++g_allocs; }
    DynMat(const DynMat& o) : rows(o.rows), cols(o.cols), a(o.a) { ++g_allocs; }
    DynMat& operator=(const DynMat&) = default;
    double& operator()(int i, int j) { return a[i + j * rows]; }
    double operator()(int i, int j) const { return a[i + j * rows]; }
};

// scratch = F P   (scratch is not an operand: noalias holds)
// P = scratch F^T + Q   (P is no longer read: noalias holds again)
void predict(DynMat& P, const DynMat& F, const DynMat& Q, DynMat& scratch) {
    const int n = P.rows;
    for (int j = 0; j < n; ++j)
        for (int i = 0; i < n; ++i) {
            double s = 0.0;
            for (int k = 0; k < n; ++k) s += F(i, k) * P(k, j);
            scratch(i, j) = s;
        }
    for (int j = 0; j < n; ++j)
        for (int i = 0; i < n; ++i) {
            double s = Q(i, j);
            for (int k = 0; k < n; ++k) s += scratch(i, k) * F(j, k);   // F^T(k, j) = F(j, k)
            P(i, j) = s;
        }
}

+++ problem | A straight-line fit at large temperatures
--- task
Fit y ≈ c₀ + c₁ T by least squares, and return `{c0, c1}`:

`std::array<double, 2> fit_line(const std::vector<double>& T, const std::vector<double>& y)`

The inputs can be awkward: the checks use ten values of T near 10⁷. The textbook normal equations form sums of T² near 10¹⁵, and the cancellation between them loses most of the digits of the slope. Solve it in a way that keeps them, for example the QR idea of making the two columns orthogonal first: work with T minus its mean.

If there are no points, return `{0, 0}`. If every T is the same (including a single point), the slope is not determined: return `{mean of y, 0}`.
--- starter
#include <array>
#include <vector>

std::array<double, 2> fit_line(const std::vector<double>& T, const std::vector<double>& y) {
    const double n = static_cast<double>(T.size());
    double St = 0, Sy = 0, Stt = 0, Sty = 0;
    for (std::size_t k = 0; k < T.size(); ++k) {
        St += T[k]; Sy += y[k]; Stt += T[k] * T[k]; Sty += T[k] * y[k];
    }
    const double c1 = (n * Sty - St * Sy) / (n * Stt - St * St);
    return {(Sy - c1 * St) / n, c1};
}
--- solution
#include <array>
#include <vector>

// Center T first: the columns 1 and (T - mean) are orthogonal, so no digits cancel.
std::array<double, 2> fit_line(const std::vector<double>& T, const std::vector<double>& y) {
    const std::size_t n = T.size();
    if (n == 0) return {0.0, 0.0};
    double mt = 0.0, my = 0.0;
    for (std::size_t k = 0; k < n; ++k) { mt += T[k]; my += y[k]; }
    mt /= n;
    my /= n;
    double num = 0.0, den = 0.0;
    for (std::size_t k = 0; k < n; ++k) {
        const double dt = T[k] - mt;
        num += dt * (y[k] - my);
        den += dt * dt;
    }
    if (den == 0.0) return {my, 0.0};
    const double c1 = num / den;
    return {my - c1 * mt, c1};
}

+++ problem | Move a block that overlaps itself
--- task
A matrix with `rows` rows and `cols` columns is stored column-major in a `std::vector<double> m`. Write

`bool move_block(std::vector<double>& m, int rows, int cols, int si, int sj, int di, int dj, int p, int q)`

which copies the `p`-by-`q` block that starts at row `si`, column `sj` onto the block of the same size that starts at row `di`, column `dj`, like `m.block(di, dj, p, q) = m.block(si, sj, p, q).eval()` in Eigen. The two blocks may overlap, and the result must be as if the whole source block had been read before anything was written. Entries outside the destination block do not change.

If either block does not fit inside the matrix, or `p` or `q` is negative, change nothing and return `false`. Otherwise return `true`.
--- starter
#include <vector>

bool move_block(std::vector<double>& m, int rows, int cols, int si, int sj, int di, int dj, int p, int q) {
    auto fits = [&](int i, int j) { return i >= 0 && j >= 0 && i + p <= rows && j + q <= cols; };
    if (p < 0 || q < 0 || !fits(si, sj) || !fits(di, dj)) return false;
    for (int c = 0; c < q; ++c)
        for (int r = 0; r < p; ++r) m[(di + r) + (dj + c) * rows] = m[(si + r) + (sj + c) * rows];
    return true;
}
--- solution
#include <vector>

// Copy through a buffer, which is what .eval() does, so overlap cannot spoil the source.
bool move_block(std::vector<double>& m, int rows, int cols, int si, int sj, int di, int dj, int p, int q) {
    auto fits = [&](int i, int j) { return i >= 0 && j >= 0 && i + p <= rows && j + q <= cols; };
    if (p < 0 || q < 0 || !fits(si, sj) || !fits(di, dj)) return false;
    std::vector<double> tmp;
    tmp.reserve(static_cast<std::size_t>(p) * q);
    for (int c = 0; c < q; ++c)
        for (int r = 0; r < p; ++r) tmp.push_back(m[(si + r) + (sj + c) * rows]);
    std::size_t k = 0;
    for (int c = 0; c < q; ++c)
        for (int r = 0; r < p; ++r) m[(di + r) + (dj + c) * rows] = tmp[k++];
    return true;
}

+++ question | Factor once, solve many
--- ask
A filter factors an n-by-n covariance with `LDLT` once, then calls `solve()` for k different right-hand sides. Roughly how much work is that, in big-O?
--- choice
O(k n³): each `solve()` repeats the factorization.
--- choice correct
O(n³ + k n²): one factorization, then two triangular substitutions per right-hand side.
--- choice
O(n² + k n): factoring a symmetric matrix is only quadratic.
--- choice
O(k² n³), because the right-hand sides interact.
--- why
The factorization costs about n³ / 3 operations and is done once, when the `LDLT` object is built. Each `solve()` reuses it: a forward and a back substitution, about n² each. That is exactly why flight code keeps the factorization and never forms an inverse, which would cost about n³ on top.

+++ question | A logged step that is always zero
--- ask
This code runs every filter cycle, and the logged step is always 0, although the state clearly moves. Which line is the bug?

```cpp
Eigen::Vector3d x_old = state.head<3>();
propagate(state);
Eigen::Vector3d x_new = state.head<3>();
auto dx = x_new - x_old;                 // (1)
x_old = x_new;                           // (2)

```
--- choice
Line (3): `norm()` on a difference needs `.eval()` first.
--- choice correct
Line (1): `auto` keeps the expression "x_new minus x_old", which is only computed at (3), after line (2) has made the two equal.

The first line: `head<3>()` returns a view, so `x_old` follows the state.

+++ question | Why Vector3d needs no special alignment
--- ask
Why does `Eigen::Vector3d` never need `EIGEN_MAKE_ALIGNED_OPERATOR_NEW`, while `Eigen::Vector4d` can?
--- choice
`Vector3d` is too small to be worth aligning; Eigen aligns only types above 30 bytes.
--- choice correct
Its size, 24 bytes, is not a multiple of 16, so Eigen does not use aligned SIMD loads on it and asks only for a `double`'s alignment. `Vector4d` is 32 bytes, so it is fixed-size vectorizable.
--- choice
`Vector3d` is stored on the heap, and Eigen's allocator aligns heap buffers.
--- choice
`Vector3d` holds floats, which never need alignment.
--- why
Eigen asks for extra alignment only for fixed-size types whose total size is a multiple of 16 bytes, because only those tile exactly into SIMD-sized pieces. 3 × 8 = 24 does not; 4 × 8 = 32 does, and it needs 32-byte alignment on an AVX build. `Vector3d` holds doubles inside the object; nothing about it is on the heap.

+++ question | Shifting a state along by one
--- ask
`x` is an `Eigen::VectorXd` with 5 entries. The line `x.segment(1, 4) = x.segment(0, 4);` should move entries 0 to 3 into slots 1 to 4. What is the right fix?
--- choice
Nothing: Eigen detects the overlap and makes a temporary.
--- choice
`x.segment(1, 4).noalias() = x.segment(0, 4);`
--- choice correct
`x.segment(1, 4) = x.segment(0, 4).eval();`
--- choice
`x.segment(1, 4) = x.segment(0, 4).array();`

+++ question | A gain that is too big
--- ask
A filter's measurement noise `R` was set too small, so its gain is larger than optimal. Which covariance update still reports the true variance of the estimate's error?
--- choice
The short form (I − K H) P, because it is algebraically the same as the Joseph form.
--- choice correct
The Joseph form (I − K H) P (I − K H)ᵀ + K R Kᵀ, computed with the true R, because it is the error covariance for any gain.
--- choice
Neither: no update formula is valid once the gain is not optimal.
--- choice
Whichever one gives the smaller trace, since a smaller covariance is safer.
--- why
The Joseph form is derived without assuming the gain is optimal, so it gives the real error covariance for whatever gain was used, as long as it is given the real noise. The short form equals it only for the optimal gain; with a wrong gain it claims too little uncertainty, or even a negative variance. A smaller covariance is not safer: an overconfident filter ignores the measurements that would correct it.

+++ question | noalias on the wrong line
--- ask
`C` and `B` are `Eigen::Matrix3d`. What does `C.noalias() = C * B;` do?
--- choice
The same as `C = C * B;`, only faster.
--- choice
It fails to compile, because `C` appears on both sides.
--- choice correct
It can silently give a wrong matrix: `noalias()` tells Eigen to write the product straight into `C` while the product is still reading `C`.

+++ question | Which NumPy line is this
