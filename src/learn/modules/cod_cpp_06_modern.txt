+++ practice | Readings outside the band
--- task
A chamber pressure transducer is trusted only between two limits. Write

`int count_outside(const std::vector<double>& kpa, double lo, double hi)`

that returns how many readings are below `lo` or above `hi`. A reading exactly equal to `lo` or `hi` is inside the band.

Use `std::count_if` with a lambda that captures `lo` and `hi`. Write no loop of your own.

For example, with the readings 9650.0, 9702.5, 12500.0, -3.0 and 9710.0 and the band 0 to 10000, the answer is 2.
--- starter
#include <algorithm>
#include <vector>

int count_outside(const std::vector<double>& kpa, double lo, double hi) {
    return -1;
}
--- solution
#include <algorithm>
#include <vector>

// How many readings fall outside the band [lo, hi].
int count_outside(const std::vector<double>& kpa, double lo, double hi) {
    auto outside = [lo, hi](double p) { return p < lo || p > hi; };
    return static_cast<int>(std::count_if(kpa.begin(), kpa.end(), outside));
}
--- hint
`std::count_if(first, last, pred)` counts the elements for which `pred` returns true.
--- hint
The lambda needs `lo` and `hi` from the function, so name them in its capture list: `[lo, hi](double p) { ... }`.
--- check case | The example: one spike and one negative reading

=> 2
--- check case | Readings on the limits are inside

=> 0
--- check case | Every reading outside
count_outside(std::vector<double>{-1.0, 10000.5, 20000.0}, 0.0, 10000.0)
=> 3
--- check case | No readings

=> 0

+++ practice | A power function under the C++11 rules
--- task
Write a `constexpr` function

`constexpr unsigned long long ipow(unsigned long long base, unsigned exp)`

that returns base to the power exp, following the **C++11** rules for `constexpr`: the body is one `return` statement. No loops, no local variables, no `if`. Use recursion, and the conditional operator `?:` for the branches.

Keep the recursion shallow by squaring:

- `ipow(b, 0)` is 1 (so `ipow(0, 0)` is 1 too);
- when exp is even, base to the exp is (base × base) to the exp / 2;
- when exp is odd, it is base × base to the (exp − 1).

The checks use `ipow` at compile time, including for an exponent of 600. Squaring needs about 20 nested calls for that; one call per step down would need 600, more than the compiler allows.
--- starter
constexpr unsigned long long ipow(unsigned long long base, unsigned exp) {
    return 0;
}
--- solution
// C++11 rules: the whole body is one return statement.
// Squaring halves the exponent, so the recursion is only about 2 log2(exp) deep.
constexpr unsigned long long ipow(unsigned long long base, unsigned exp) {
    return exp == 0 ? 1ULL
         : exp % 2 == 0 ? ipow(base * base, exp / 2)
         : base * ipow(base, exp - 1);
}
--- hint
Nest two conditional operators: first test `exp == 0`, then test whether `exp` is even.
--- hint
The even case calls `ipow(base * base, exp / 2)`; the odd case returns `base * ipow(base, exp - 1)`.
--- check test | Works at compile time: 2 to the 10 is 1024
[] { constexpr unsigned long long v = ipow(2, 10); return v == 1024ULL; }()
--- check test | Works at compile time even for an exponent of 600
[] { constexpr unsigned long long v = ipow(1, 600); return v == 1ULL; }()
--- check case | Ten to the twelfth needs 64 bits

=> 1000000000000ULL
--- check case | Three to the fortieth still fits
ipow(3, 40)
=> 12157665459056928801ULL
--- check case | Anything to the zero is 1
ipow(7, 0)
=> 1ULL
--- check case | Zero to the zero is 1 by this definition

+++ practice | Hand the pending log over
--- task
Samples collect in a `pending` vector. Once a second, the logger takes all of them at once. Write

`std::vector<double> drain(std::vector<double>& pending)`

that returns every sample that was in `pending`, in order, and leaves `pending` empty.

It must not copy the samples. The vector you return must use the very same buffer of memory that `pending` was using, so its `data()` pointer equals the one `pending` had before the call.
--- starter
#include <vector>

std::vector<double> drain(std::vector<double>& pending) {
    return {};
}
--- solution
#include <utility>
#include <vector>

// Takes pending's buffer instead of copying it. A moved-from vector is empty.
std::vector<double> drain(std::vector<double>& pending) {
    std::vector<double> out = std::move(pending);
    pending.clear();   // already empty; says so for the reader
    return out;
}
--- hint
`std::move(pending)` lets a new vector take over pending's buffer. Three pointers are copied; no sample is.
--- hint
The standard guarantees a vector left behind by a move construction is empty, so `pending` needs no more work. Calling `clear()` on it anyway is harmless.
--- check test | Returns the samples in order

+++ practice | Time to the next tick
--- task
A control loop runs on ticks at 0, one period, two periods, and so on. Write

`std::chrono::microseconds until_next_tick(std::chrono::microseconds now, std::chrono::milliseconds period)`

that returns the time from `now` until the next tick that comes strictly after `now`.

- If `now` is exactly on a tick, the answer is one whole period.
- If `period` is zero or negative, there are no ticks: return 0 microseconds.
- `now` is never negative.

For example, at 2500 µs with a 1 ms period the answer is 500 µs, and at 3000 µs it is 1000 µs. Do the arithmetic with `std::chrono` durations. A millisecond period turns into microseconds without a cast, because that direction loses nothing.
--- starter
#include <chrono>

std::chrono::microseconds until_next_tick(std::chrono::microseconds now, std::chrono::milliseconds period) {
    return std::chrono::microseconds{-1};
}
--- solution
#include <chrono>

// Time from now to the next tick strictly after it. Ticks are at 0, period, 2 period, ...
std::chrono::microseconds until_next_tick(std::chrono::microseconds now, std::chrono::milliseconds period) {
    if (period <= std::chrono::milliseconds{0}) return std::chrono::microseconds{0};
    const std::chrono::microseconds p = period;   // exact: milliseconds to microseconds loses nothing
    return p - now % p;
}
--- hint
`now % p` is how far `now` is past the last tick, as a duration. The rest of the period is what is left.
--- hint
On a tick, `now % p` is zero, so `p - now % p` is a whole period, which is what the task asks for.
--- check case | Half-way between ticks

--- check case | Exactly on a tick: a whole period

=> std::chrono::microseconds{1000}
--- check case | At time zero
until_next_tick(std::chrono::microseconds{0}, std::chrono::milliseconds{20})
=> std::chrono::microseconds{20000}
--- check case | A 20 ms period, part-way through the third one
until_next_tick(std::chrono::microseconds{45123}, std::chrono::milliseconds{20})
=> std::chrono::microseconds{14877}
--- check case | A zero period has no ticks
until_next_tick(std::chrono::microseconds{500}, std::chrono::milliseconds{0})
=> std::chrono::microseconds{0}
--- check case | A negative period has no ticks
until_next_tick(std::chrono::microseconds{500}, std::chrono::milliseconds{-5})
=> std::chrono::microseconds{0}

+++ practice | A deadband that never filters
--- task
`Deadband` should replace `Filter::step` so that any input within 0.05 of zero becomes 0.0. Code that holds a `const Filter&` calls it through `run`.

`run(Deadband{}, 0.02)` should give 0.0, but it gives 0.02: the base version runs. Find why, and fix `Deadband` so that it really replaces `step`. Mark it so the compiler refuses the mistake if anyone makes it again.
--- starter
#include <cmath>

struct Filter {
    virtual ~Filter() = default;
    virtual double step(double x) const { return x; }
};

// Zeroes small inputs: anything within 0.05 of zero becomes 0.0.
struct Deadband : Filter {
    double step(double x) { return std::fabs(x) < 0.05 ? 0.0 : x; }
};

double run(const Filter& f, double x) { return f.step(x); }
--- solution
#include <cmath>

struct Filter {
    virtual ~Filter() = default;
    virtual double step(double x) const { return x; }
};

// Zeroes small inputs: anything within 0.05 of zero becomes 0.0.
// const makes the signature match the base; override makes the compiler check that it does.
struct Deadband : Filter {
    double step(double x) const override { return std::fabs(x) < 0.05 ? 0.0 : x; }
};

double run(const Filter& f, double x) { return f.step(x); }
--- hint
Compare the two signatures of `step` character by character. A derived function replaces a virtual one only when they match exactly.
--- hint
The base function is `const`; the derived one is not, so it is a new function that hides the base one. Add `const`, and add `override` so a mismatch becomes a compile error.
--- check test | A small positive input is zeroed through the base class

--- check test | A small negative input is zeroed
run(Deadband{}, -0.04) == 0.0
--- check test | A large input passes through

--- check test | The plain Filter still passes everything
run(Filter{}, 0.02) == 0.02
--- check source | Deadband marks its step override

+++ practice | Classify and tally chamber readings
--- task
Write a small health monitor for chamber pressure readings.

- `enum class Health : std::uint8_t { Ok, Low, High, Invalid };` — one byte, because it goes into a telemetry packet.
- `constexpr double kMinKpa = 500.0;` and `constexpr double kMaxKpa = 10000.0;`
- `Health classify(double kpa)`: `Invalid` when the reading is not a number (NaN) or is negative; `Low` below 500; `High` above 10000; `Ok` otherwise. Exactly 500 and exactly 10000 are `Ok`.

Careful with NaN: every comparison with NaN is false, so a NaN slips through `<` and `>` tests unless you test for it first with `std::isnan`.
--- starter
#include <array>
#include <cstdint>
#include <vector>

enum class Health : std::uint8_t { Ok, Low, High, Invalid };

Health classify(double kpa) {
    return Health::Ok;
}

std::array<int, 4> tally(const std::vector<double>& readings) {
    return {};
}
--- solution
#include <array>
#include <cmath>
#include <cstddef>
#include <cstdint>
#include <vector>

enum class Health : std::uint8_t { Ok, Low, High, Invalid };

constexpr double kMinKpa = 500.0;
constexpr double kMaxKpa = 10000.0;

Health classify(double kpa) {
    if (std::isnan(kpa) || kpa < 0.0) return Health::Invalid;   // NaN first: it fails every comparison
    if (kpa < kMinKpa) return Health::Low;
    if (kpa > kMaxKpa) return Health::High;
    return Health::Ok;
}

std::array<int, 4> tally(const std::vector<double>& readings) {
    std::array<int, 4> counts{};
    for (double r : readings) ++counts[static_cast<std::size_t>(classify(r))];
    return counts;
}
--- hint
Test the `Invalid` cases first and return early. `std::isnan` comes from `<cmath>`.
--- hint
An `enum class` does not turn into a number by itself. `static_cast<std::size_t>(classify(r))` gives the index into the counts.
--- check test | Health is one byte
sizeof(Health) == 1
--- check test | NaN is invalid, not Ok
classify(std::nan("")) == Health::Invalid
--- check test | A negative reading is invalid
classify(-1.0) == Health::Invalid
--- check test | The limits themselves are Ok
classify(500.0) == Health::Ok && classify(10000.0) == Health::Ok
--- check test | Just outside the limits
classify(499.9) == Health::Low && classify(10000.5) == Health::High
--- check test | Tally of a mixed list
tally(std::vector<double>{9650.0, 120.0, 12500.0, -3.0, 9700.0, std::nan("")}) == std::array<int, 4>{2, 1, 1, 2}
--- check test | Tally of no readings
tally(std::vector<double>{}) == std::array<int, 4>{0, 0, 0, 0}

+++ question | A thread left behind
--- ask
A logging helper starts a thread and returns:

```cpp
#include <cstdio>
#include <thread>

void log_worker(int id) { std::printf("logger %d running\n", id); }

void start_logger() {
    std::thread t(log_worker, 1);
}   // t is destroyed here
```

What happens when `start_logger` returns?
--- choice
The thread is detached automatically and keeps running on its own.
--- choice
The destructor waits for `log_worker` to finish, then the program carries on.
--- choice correct
`std::terminate` is called and the program ends, even if `log_worker` has already finished.
--- choice
Nothing, as long as `log_worker` finished before the closing brace.
--- why
A `std::thread` stays *joinable* until someone calls `join()` or `detach()` on it, and finishing its work does not change that. Destroying a joinable `std::thread` calls `std::terminate`. So the program ends whether or not the logger printed its line. The fix is to call `t.join()` (wait) or `t.detach()` (let it go) before `t` is destroyed. The concurrency module meets C++20's `std::jthread`, which joins itself in its destructor.

#include <cstddef>
#include <string>
#include <vector>

// Parentheses: the count constructor. Braces here would make a one-element vector.
std::vector<double> history(std::size_t n) {
    return std::vector<double>(n);

// Braces: the initializer_list constructor, so these two values are the elements.

Write a class `TapFilter` that holds the coefficients ("taps") of a small digital filter.

The checks make filters both with braces and with parentheses. Before you run them, work out for yourself what `TapFilter{4, 0.25}` and `TapFilter{}` give.
--- starter
#include <cstddef>

#include <vector>

--- solution
#include <cstddef>
#include <initializer_list>
#include <numeric>
#include <vector>

class TapFilter {
public:
    TapFilter(std::initializer_list<double> taps) : taps_(taps) {}
    TapFilter(std::size_t n, double value) : taps_(n, value) {}   // parentheses: count and value

    std::size_t size() const { return taps_.size(); }
    double sum() const { return std::accumulate(taps_.begin(), taps_.end(), 0.0); }
    double operator[](std::size_t i) const { return taps_[i]; }

    std::vector<double> taps_;
};
--- hint

--- solution
#include <array>
#include <cstddef>
#include <cstdint>

struct AxisCal {
    double bias = 0.0;
    double scale = 1.0;
};

struct ImuCal {
    std::uint32_t serial = 0;
    std::array<AxisCal, 3> axes{};
    bool valid = false;
};

// Members in declaration order. The array gets one AxisCal; the other two
// elements are value-initialized, so they take their default member initializers.
ImuCal bench_cal(std::uint32_t serial, double x_bias) {
    return {serial, {AxisCal{x_bias, 1.0}}, true};
}

std::array<double, 3> apply_cal(const ImuCal& cal, const std::array<double, 3>& raw) {
    if (!cal.valid) return raw;
    std::array<double, 3> out{};
    for (std::size_t i = 0; i < 3; ++i) out[i] = (raw[i] - cal.axes[i].bias) * cal.axes[i].scale;
    return out;
}
--- hint
An aggregate is filled in the order its members are declared: `serial`, then `axes`, then `valid`. Members you leave out keep their defaults.
--- hint
For `axes`, one inner brace list holding a single `AxisCal{x_bias, 1.0}` fills element 0; elements 1 and 2 are value-initialized and so take `bias = 0.0` and `scale = 1.0`.

+++ practice | A byte, checked at run time
--- task
Braces refuse `std::uint8_t id{raw};` when `raw` is an `int` variable, because the compiler cannot prove the value fits. At run time you have to check it yourself. Write:

- `std::optional<std::uint8_t> to_byte(int raw)`: the value as a byte when it is from 0 to 255, and `std::nullopt` otherwise.
- `std::optional<std::uint8_t> checked_sum(std::uint8_t a, std::uint8_t b)`: `a + b` as a byte when the sum fits, and `std::nullopt` when it is above 255.

`to_byte(255)` is 255, `to_byte(256)` and `to_byte(-1)` are empty, and `checked_sum(200, 56)` is empty.
--- starter
#include <cstdint>
#include <optional>

std::optional<std::uint8_t> to_byte(int raw) {
    return static_cast<std::uint8_t>(raw);
}

std::optional<std::uint8_t> checked_sum(std::uint8_t a, std::uint8_t b) {

--- solution
#include <cstdint>
#include <optional>

std::optional<std::uint8_t> to_byte(int raw) {
    if (raw < 0 || raw > 255) return std::nullopt;
    return static_cast<std::uint8_t>(raw);   // proven to fit, so the cast loses nothing
}

std::optional<std::uint8_t> checked_sum(std::uint8_t a, std::uint8_t b) {
    return to_byte(a + b);   // a + b is worked out as an int, so it cannot wrap before the check
}
--- hint
Check the range first, then convert with `static_cast`. The cast is only honest once you know the value fits.
--- hint
Two `std::uint8_t` values are promoted to `int` before they are added, so `a + b` can be 510 without wrapping. Hand that `int` to `to_byte`.
--- check test | 200 fits

+++ question | Three vectors, braces and parentheses
--- ask
What does this print? Type the three numbers separated by spaces.

```cpp
#include <cstdio>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> a{2, "IMU"};
    std::vector<int> b{2, 7};
    std::vector<int> c(2, 7);
    std::printf("%zu %zu %d\n", a.size(), b.size(), b[0] + c[1]);
}
```
--- answer
2 2 9
2, 2, 9
--- why
`b{2, 7}` is a list of two `int`s, so the initializer_list constructor wins: the elements are 2 and 7, and `b[0]` is 2. `c(2, 7)` uses parentheses, which never look at the list constructor: two copies of 7, so `c[1]` is 7, and 2 + 7 is 9. `a{2, "IMU"}` is the interesting one. Braces try the list constructor first, but a `std::string` cannot be made from the number 2, so a list of strings is not viable. Only then does the compiler fall back to the other constructors, and `vector(count, value)` makes two copies of `"IMU"`: size 2. The same braces meant "these elements" for `b` and "count and value" for `a`.

#include <array>
#include <cstddef>
#include <cstdint>

// C++14 constexpr: locals, loops and changing them are all allowed.
constexpr std::array<std::uint8_t, 256> make_parity_table() {
    std::array<std::uint8_t, 256> t{};
    for (std::size_t i = 0; i < t.size(); ++i) {
        unsigned ones = 0;
        for (unsigned v = static_cast<unsigned>(i); v != 0; v >>= 1) ones += v & 1u;
        t[i] = static_cast<std::uint8_t>(ones % 2);

    return t;

#include <cstdint>

// One constant per bit width. The shift happens in 64 bits, where shifting
// by 32 is legal; the result always fits back into 32 bits.
template <int Bits>
constexpr std::uint32_t full_scale_v =

#include <cstdint>
#include <optional>

constexpr std::uint16_t kArmedMask    = 0b1000'0000'0000'0000;
constexpr std::uint16_t kReservedMask = 0b0111'0000'0000'0000;
constexpr std::uint16_t kThrusterMask = 0b0000'1111'0000'0000;
constexpr std::uint16_t kDutyMask     = 0b0000'0000'1111'1111;

constexpr std::optional<std::uint16_t> pack_cmd(bool armed, int thruster, int duty) {
    if (thruster < 0 || thruster > 11 || duty < 0 || duty > 100) return std::nullopt;
    unsigned w = static_cast<unsigned>(thruster) << 8 | static_cast<unsigned>(duty);
    if (armed) w |= kArmedMask;

constexpr int thruster_of(std::uint16_t w) { return (w & kThrusterMask) >> 8; }
constexpr int duty_of(std::uint16_t w) { return w & kDutyMask; }

#include <cstdint>
#include <type_traits>
#include <variant>

struct Heartbeat { std::uint32_t seq; };
struct Pressure  { int channel; double kpa; };
struct Fault     { std::uint16_t code; };

using Message = std::variant<Heartbeat, Pressure, Fault>;

int severity(const Message& m) {
    return std::visit([](const auto& x) {
        using T = std::decay_t<decltype(x)>;          // the alternative's own type
        if constexpr (std::is_same_v<T, Heartbeat>) return 0;
        else if constexpr (std::is_same_v<T, Pressure>) return x.kpa > 9000.0 ? 1 : 0;
        else return (x.code & 0x8000) != 0 ? 3 : 2;   // only Fault is left
    }, m);
}

#include <array>
#include <cstddef>

struct Mat3 {
    static inline int copies = 0;
    static inline int moves = 0;
    std::array<double, 9> a{};   // row-major: element (r, c) is a[3 * r + c]
    Mat3() = default;
    Mat3(const Mat3& o) : a(o.a) { ++copies; }
    Mat3(Mat3&& o) noexcept : a(o.a) { ++moves; }
    Mat3& operator=(const Mat3&) = default;
    double& at(std::size_t r, std::size_t c) { return a[3 * r + c]; }
    double at(std::size_t r, std::size_t c) const { return a[3 * r + c]; }
};

// One named local, returned on every path: NRVO builds it in the caller's storage.
Mat3 multiply(const Mat3& x, const Mat3& y) {
    Mat3 out;
    for (std::size_t r = 0; r < 3; ++r)
        for (std::size_t c = 0; c < 3; ++c)
            for (std::size_t k = 0; k < 3; ++k)
                out.at(r, c) += x.at(r, k) * y.at(k, c);
    return out;
}

Mat3 transpose(const Mat3& m) {
    Mat3 out;
    for (std::size_t r = 0; r < 3; ++r)
        for (std::size_t c = 0; c < 3; ++c)
            out.at(r, c) = m.at(c, r);
    return out;
}

// The inner calls are prvalues bound to const references (materialized, never copied);
// the outer call is a prvalue returned straight into propagate's caller.
Mat3 propagate(const Mat3& P, const Mat3& F) {
    return multiply(multiply(F, P), transpose(F));
}
--- hint
A function that fills one named local and returns it on every path gets NRVO in practice. A prvalue, such as a call returning `Mat3`, is never copied at all.
--- hint
`return multiply(multiply(F, P), transpose(F));` passes two temporaries by `const&`, which copies nothing, and returns a prvalue.

+++ question | Which return does not compile
--- ask
`Port` has both its copy constructor and its move constructor deleted, and a constructor from `int`. Compiled as C++17, which one of these lines does **not** compile?

```cpp
Port make(int n) { return Port{n}; }
```
--- choice
`Port p = Port{3};`
--- choice
`Port p = make(3);`
--- choice correct
`Port p = std::move(make(3));`
--- choice
`Port p = true ? make(1) : make(2);`
--- why
The first, second and fourth initialize `p` from a prvalue of type `Port`: `Port{3}`, the call `make(3)`, and a conditional whose two sides are both prvalues of `Port`, which is itself a prvalue. Since C++17 a prvalue initializes its final object directly, so no copy or move constructor is needed. `std::move(make(3))` is different: `std::move` returns a reference, so the call has to be turned into a real temporary first, and the result is an xvalue that names that temporary. Initializing `p` from an xvalue means moving from it, and the move constructor is deleted. Adding `std::move` never helps a return or an initialization from a prvalue; here it breaks it.

--- task
Write a function template constrained with a concept:

`template <std::floating_point T> T rms_valid(std::span<const T> xs, T limit)`

It returns the root mean square of the samples whose magnitude is at most `limit`: the square root of the mean of their squares. Samples beyond the limit are skipped. If no sample is valid (or there are none at all), return 0.

Pick the valid samples with `std::views::filter`, so nothing is copied. The concept must stop the template from being used with integers: `rms_valid` with a span of `int` should not compile.

For example, for 3.0, -4.0 and 100.0 with a limit of 10.0, the valid samples are 3 and -4, and the answer is the square root of (9 + 16) / 2, about 3.5355.
--- starter
#include <span>

T rms_valid(std::span<const T> xs, T limit) {
    return T{-1};
}
--- solution
#include <cmath>
#include <concepts>
#include <ranges>
#include <span>

template <std::floating_point T>
T rms_valid(std::span<const T> xs, T limit) {
    auto ok = [limit](T x) { return std::abs(x) <= limit; };
    T sum_sq = 0;
    int n = 0;
    for (T x : xs | std::views::filter(ok)) {   // a lazy view: no copy, no allocation
        sum_sq += x * x;
        ++n;
    }
    return n ? std::sqrt(sum_sq / static_cast<T>(n)) : T{0};
}
--- hint
Put the concept where `class` was: `template <std::floating_point T>`. It comes from `<concepts>`.
--- hint
`xs | std::views::filter(ok)` gives only the samples for which `ok` is true. Add up their squares and count them, then take the square root of the mean.

#include <span>

std::size_t status_line(std::span<char> out, int channel, double kpa) {

        char none[1];   // format_to_n with n = 0 writes nothing; it still reports the length
        return static_cast<std::size_t>(std::format_to_n(none, 0, "CH{:02} {:.2f} kPa", channel, kpa).size);

+++ practice | A CRC-8 table the flight binary never computes
--- task
A CRC-8 check byte protects each telemetry packet. Build its lookup table entirely at compile time. Write:

- `consteval std::array<std::uint8_t, 256> make_crc8_table(std::uint8_t poly)`: for each byte value `i`, start with `c = i` and repeat 8 times: if the top bit of `c` is set, `c = (c << 1) ^ poly`, otherwise `c = c << 1`, keeping only the low 8 bits each time. Entry `i` is the final `c`.

- `std::uint8_t crc8(std::span<const std::uint8_t> bytes)`: start with `c = 0`; for each byte `b`, `c = kCrc8[c ^ b]`. Return `c`.

With this polynomial, the CRC of the nine ASCII bytes `"123456789"` is `0xF4`, the standard check value for this CRC.
--- starter

#include <cstdint>
#include <span>

    return 0xFF;
}
--- solution
#include <array>
#include <cstddef>
#include <cstdint>
#include <span>

// consteval: every call must happen while compiling, so this loop never exists in the binary.
consteval std::array<std::uint8_t, 256> make_crc8_table(std::uint8_t poly) {
    std::array<std::uint8_t, 256> t{};
    for (std::size_t i = 0; i < t.size(); ++i) {
        unsigned c = static_cast<unsigned>(i);
        for (int bit = 0; bit < 8; ++bit) {
            c = (c & 0x80u) ? ((c << 1) ^ poly) : (c << 1);
            c &= 0xFFu;
        }
        t[i] = static_cast<std::uint8_t>(c);
    }
    return t;
}

// constinit: initialized during static initialization, or the build fails.
constinit std::array<std::uint8_t, 256> kCrc8 = make_crc8_table(0x07);

std::uint8_t crc8(std::span<const std::uint8_t> bytes) {
    std::uint8_t c = 0;
    for (std::uint8_t b : bytes) c = kCrc8[c ^ b];
    return c;
}
--- hint
Inside the table builder, keep `c` in an `unsigned` so the shift has room, and mask with `0xFF` after each step.
--- hint
`consteval` goes where `constexpr` would on the function; `constinit` goes in front of the variable. The run-time `crc8` is a plain loop over the span.

+++ practice | Engine start with retries
--- task
Write the engine start sequence as a state machine, run once per control cycle:

```cpp
enum class Start { purge, ignite, running, abort };

struct EngineStart {
    Start state = Start::purge;
    int ticks_in_state = 0;
    int attempts = 0;
    void tick(bool flame);   // flame: the flame sensor's reading this cycle
};
```

On each call to `tick(flame)`:

- In `purge`: add 1 to `ticks_in_state`. When it reaches 3, go to `ignite`. The flame sensor is ignored while purging.
- In `ignite`: if `flame` is true, go to `running`. Otherwise add 1 to `ticks_in_state`; when it reaches 4, the attempt has failed: add 1 to `attempts`, then go to `abort` if `attempts` is now 2, or back to `purge` if not.
- `running` and `abort` never change.
- Every change of state sets `ticks_in_state` back to 0.

With no flame at all, the sequence purges on ticks 1 to 3, tries to ignite on ticks 4 to 7, purges again on 8 to 10, tries again on 11 to 14, and aborts at the end of tick 14.
--- starter

--- solution
enum class Start { purge, ignite, running, abort };

struct EngineStart {
    Start state = Start::purge;
    int ticks_in_state = 0;
    int attempts = 0;

    void tick(bool flame) {
        switch (state) {
        case Start::purge:
            if (++ticks_in_state == 3) go(Start::ignite);
            break;
        case Start::ignite:
            if (flame) {
                go(Start::running);
            } else if (++ticks_in_state == 4) {
                ++attempts;
                go(attempts == 2 ? Start::abort : Start::purge);
            }
            break;
        case Start::running:
        case Start::abort:
            break;
        }
    }

private:
    void go(Start next) {   // every change of state restarts the tick count
        state = next;
        ticks_in_state = 0;
    }
};
--- hint
A small private helper that sets the new state and zeroes `ticks_in_state` keeps you from forgetting the reset on one of the paths.
--- hint

+++ question | What an importer can see
--- ask
A module interface unit, `gnc.cppm`, contains:

```cpp
export module gnc;

#define GNC_RATE_HZ 1000

export double limit_rate(double r) { return r > 5.0 ? 5.0 : r; }
double clamp_helper(double x) { return x < 0.0 ? 0.0 : x; }
export constexpr int kAxes = 3;
```

Another file writes `import gnc;`. Which of these can it use?
--- choice
All four: `limit_rate`, `clamp_helper`, `kAxes` and `GNC_RATE_HZ`, as with a header.
--- choice
`limit_rate`, `kAxes` and `GNC_RATE_HZ`, because a macro is always global.
--- choice correct
Only `limit_rate` and `kAxes`.
--- choice
Only `limit_rate`: constants cannot be exported.
--- why
With `#include`, the preprocessor pastes a header's text, so every name and every macro in it reaches the includer. A module is different: importers see only what the interface marks with `export`. `limit_rate` and `kAxes` are exported, so they are visible. `clamp_helper` exists in the module's object file but cannot be named from outside. And macros never cross a module boundary at all: `GNC_RATE_HZ` stays inside `gnc.cppm`. That isolation is one of the benefits modules promise, and one reason a codebase that shares configuration through macros has extra work to do before it can adopt them.

#include <cstddef>

// A pointer plus a shape and a layout rule: like std::mdspan with layout_right.
class MatView {
public:
    MatView(double* data, std::size_t rows, std::size_t cols) : data_(data), rows_(rows), cols_(cols) {}
    double& operator()(std::size_t r, std::size_t c) const { return data_[r * cols_ + c]; }
    std::size_t rows() const { return rows_; }
    std::size_t cols() const { return cols_; }

private:
    double* data_;
    std::size_t rows_;
    std::size_t cols_;
};

// The view is passed by value: copying it copies a pointer and two sizes, never the data.
void set_identity(MatView m) {
    if (m.rows() != m.cols()) return;
    for (std::size_t r = 0; r < m.rows(); ++r)
        for (std::size_t c = 0; c < m.cols(); ++c)
            m(r, c) = (r == c) ? 1.0 : 0.0;
}

enum class SensorError { none, no_reply, out_of_range, over_limit };

// A value of type T, or the reason there is none. Hand-made, like C++23's std::expected.
template <typename T>
class Result {
public:
    static Result ok(T v) { return Result(v, SensorError::none); }
    static Result fail(SensorError e) { return Result(T{}, e); }
    bool has_value() const { return err_ == SensorError::none; }
    explicit operator bool() const { return has_value(); }
    const T& operator*() const { return val_; }
    SensorError error() const { return err_; }
private:
    Result(T v, SensorError e) : val_(v), err_(e) {}
    T val_;
    SensorError err_;
};

// A transducer's raw 12-bit count. A negative raw value means the sensor did not answer.
Result<int> read_counts(int raw) {
    if (raw < 0) return Result<int>::fail(SensorError::no_reply);
    if (raw > 4095) return Result<int>::fail(SensorError::out_of_range);
    return Result<int>::ok(raw);
}

Result<double> pressure_kpa(int raw) {
    const Result<int> counts = read_counts(raw);
    if (!counts) return Result<double>::fail(counts.error());   // pass the reason on
    const double kpa = *counts * (1000.0 / 4095.0);
    if (kpa > 950.0) return Result<double>::fail(SensorError::over_limit);
    return Result<double>::ok(kpa);
}

Result<double> with_backup(int raw, int backup_raw) {
    const Result<double> primary = pressure_kpa(raw);
    const bool sensor_fault = primary.error() == SensorError::no_reply ||
                              primary.error() == SensorError::out_of_range;
    return sensor_fault ? pressure_kpa(backup_raw) : primary;
}
--- hint
A `Result<int>` error cannot be returned as a `Result<double>` directly: make a new one with `Result<double>::fail(counts.error())`.
--- hint

#include <bit>
#include <cstdint>
#include <cstring>

constexpr std::uint16_t swap16(std::uint16_t x) {
    return static_cast<std::uint16_t>((x >> 8) | (x << 8));
}

constexpr std::uint32_t swap32(std::uint32_t x) {
    return (x >> 24)
         | ((x >> 8) & 0x0000'FF00u)
         | ((x << 8) & 0x00FF'0000u)
         | (x << 24);
}

// Chosen while compiling: no run-time test, and no code at all for the branch not taken.
constexpr std::uint32_t to_wire(std::uint32_t x) {
    if constexpr (std::endian::native == std::endian::little) return swap32(x);
    else return x;
}
--- hint
For 32 bits, each of the four bytes moves: the top byte shifts down 24, the bottom byte shifts up 24, and the middle two shift by 8 and must be masked so nothing else comes with them.
--- hint
`if constexpr (std::endian::native == std::endian::little)` is decided by the compiler. Swap in that branch; return `x` unchanged in the other.

+++ practice | and_then and transform, hand-made
--- task
The starter's `Result<T>` holds a value or a `SensorError`, like C++23's `std::expected`, but it has no way to chain steps yet. Add three member functions to it:

- `template <class F> auto and_then(F f) const`: `f` takes a `T` and returns some `Result<U>` (a step that can fail). If this result holds a value, return `f(value)`. If it holds an error, return a `Result<U>` with the same error, **without calling `f`**.
- `template <class F> auto transform(F f) const`: `f` takes a `T` and returns a plain `U` (a step that cannot fail). If this result holds a value, return `Result<U>::ok(f(value))`; otherwise a `Result<U>` with the same error, without calling `f`.

--- solution
#include <utility>

enum class SensorError { none, no_reply, out_of_range, over_limit };

template <typename T>
class Result {
public:
    static Result ok(T v) { return Result(v, SensorError::none); }
    static Result fail(SensorError e) { return Result(T{}, e); }
    bool has_value() const { return err_ == SensorError::none; }
    explicit operator bool() const { return has_value(); }
    const T& operator*() const { return val_; }
    SensorError error() const { return err_; }

    // A next step that can fail: f returns a Result<U>. An error rides past it.
    template <class F>
    auto and_then(F f) const {
        using R = decltype(f(val_));            // some Result<U>
        if (!has_value()) return R::fail(err_);
        return f(val_);
    }

    // A next step that cannot fail: f returns a plain U, wrapped here.
    template <class F>
    auto transform(F f) const {
        using U = decltype(f(val_));
        if (!has_value()) return Result<U>::fail(err_);
        return Result<U>::ok(f(val_));
    }

    T value_or(T fallback) const { return has_value() ? val_ : fallback; }

private:
    Result(T v, SensorError e) : val_(v), err_(e) {}
    T val_;
    SensorError err_;
};

int g_conversions = 0;   // how many times to_kpa has run

Result<int> read_counts(int raw) {
    if (raw < 0) return Result<int>::fail(SensorError::no_reply);
    if (raw > 4095) return Result<int>::fail(SensorError::out_of_range);
    return Result<int>::ok(raw);
}

double to_kpa(int counts) {
    ++g_conversions;
    return counts * (1000.0 / 4095.0);
}

Result<double> check_limit(double kpa) {
    if (kpa > 950.0) return Result<double>::fail(SensorError::over_limit);
    return Result<double>::ok(kpa);
}
--- hint
Inside a member template, `decltype(f(val_))` names the type `f` returns, without calling it. For `and_then` that is the whole result type; for `transform` it is the plain `U` to wrap.
--- hint
Both functions test `has_value()` first. On an error, build the new result type with `fail(err_)` and return it before `f` is ever called.

+++ question | The wrong joint in a chain
--- ask
With the real C++23 `std::expected` on a compiler that has it, a programmer writes this chain. `read_counts` returns `std::expected<std::uint16_t, SensorError>`, and `to_kpa` is `double to_kpa(std::uint16_t counts)`, which cannot fail.

```cpp
auto p = read_counts(raw).and_then(to_kpa);
```

What happens?
--- choice
It works: `and_then` wraps the `double` that `to_kpa` returns in a new `expected`.
--- choice
It compiles, but `to_kpa` is only called when `read_counts` failed.
--- choice correct
It does not compile: the function given to `and_then` must itself return an `expected`. A step that cannot fail joins with `transform`.
--- choice
It compiles, and throws at run time if `read_counts` failed.
--- why
`and_then` is for a next step that can fail, so it expects the function to hand back a whole `expected`, which it returns as it is. g++ stops with a static assertion saying so. `transform` is for a step that cannot fail: it takes the plain value the function returns and wraps it back into an `expected`. So the chain should be `read_counts(raw).transform(to_kpa)`. The same pairing holds on the error side: `or_else` takes a function returning an `expected`, and `transform_error` one returning a plain error.

#include <array>
#include <cstddef>
#include <span>

// Capacity is part of the type, storage is inside the object: no heap, ever.
// When full, push refuses and says so; the caller decides what that means.
template <class T, std::size_t N>
class FixedVec {
public:
    bool push(const T& x) {
        if (full()) return false;
        items_[count_++] = x;
        return true;
    }
    std::size_t size() const { return count_; }
    static constexpr std::size_t capacity() { return N; }
    bool full() const { return count_ == N; }
    const T& operator[](std::size_t i) const { return items_[i]; }
    std::span<const T> view() const { return {items_.data(), count_}; }
    void clear() { count_ = 0; }

private:
    std::array<T, N> items_{};
    std::size_t count_ = 0;
};

// Stores a pointer where the optimizer must assume someone will read it.
volatile std::uintptr_t g_sink = 0;
void keep(const void* p) { g_sink = reinterpret_cast<std::uintptr_t>(p); }

long g_allocs = 0;
bool g_counting = false;

// Replaces the library's operator new for the whole program, containers included.
void* operator new(std::size_t n) {
    if (g_counting) ++g_allocs;
    if (void* p = std::malloc(n)) return p;
    std::abort();   // no exceptions: out of memory is fatal
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t) noexcept { std::free(p); }

template <class F>
long allocations_in(F f) {
    g_allocs = 0;
    g_counting = true;
    f();
    g_counting = false;
    return g_allocs;
}

+++ practice | A static pool of packet slots
--- task
Write a pool that hands out fixed-size slots from storage inside the object, in constant time, and never touches the heap.

```cpp
template <class T, std::size_t N>
class Pool {
public:
    Pool();                    // all N slots free
    T* acquire();              // a free slot, or nullptr when none is left
    void release(T* p);        // gives a slot back
    std::size_t available() const;
};
```

Rules:

- `acquire` and `release` take the same few steps whatever `N` is: no searching through the slots. Keep a stack of free slot indices.
- The most recently released slot is the next one handed out.
- `release` ignores `nullptr`, a pointer that is not one of this pool's slots, and a slot that is already free. None of those may change `available()`.

`T` is a plain struct such as `struct Packet { std::uint16_t id; std::array<std::uint8_t, 30> payload; };`, which can be default-constructed.
--- starter
#include <array>
#include <cstddef>

template <class T, std::size_t N>
class Pool {
public:
    Pool() {}
    T* acquire() { return nullptr; }
    void release(T* p) {}
    std::size_t available() const { return 0; }
};
--- solution
#include <array>
#include <cstddef>
#include <functional>

template <class T, std::size_t N>
class Pool {
public:
    Pool() {
        for (std::size_t i = 0; i < N; ++i) free_[i] = N - 1 - i;   // slot 0 ends up on top
    }

    T* acquire() {
        if (nfree_ == 0) return nullptr;
        const std::size_t i = free_[--nfree_];     // pop the top of the free stack
        in_use_[i] = true;
        return &slots_[i];
    }

    void release(T* p) {
        const std::less<const T*> before;          // safe even for pointers from elsewhere
        if (p == nullptr || before(p, slots_.data()) || !before(p, slots_.data() + N)) return;   // not ours
        const auto i = static_cast<std::size_t>(p - slots_.data());
        if (!in_use_[i]) return;                   // already free
        in_use_[i] = false;
        free_[nfree_++] = i;                       // push: handed out next
    }

    std::size_t available() const { return nfree_; }

private:
    std::array<T, N> slots_{};
    std::array<std::size_t, N> free_{};            // a stack of free slot indices
    std::array<bool, N> in_use_{};
    std::size_t nfree_ = N;
};
--- hint
Keep an array of free slot indices used as a stack, plus a flag per slot saying whether it is handed out. `acquire` pops an index; `release` pushes one.
--- hint
A pointer belongs to the pool when it lies from `slots_.data()` up to, but not including, `slots_.data() + N`; its index is `p - slots_.data()`. `std::less<const T*>` compares pointers safely even when one is not from this array.

+++ question | Virtual calls allowed, dynamic_cast forbidden
--- ask
Many flight subsets permit virtual functions in a control task but forbid `dynamic_cast`. Which is the real reason for treating them differently?
--- choice
Virtual calls are resolved at compile time, while `dynamic_cast` is resolved at run time.
--- choice correct
A virtual call is one indirect call through the vtable, with a fixed cost and every override known at link time. `dynamic_cast` needs RTTI records in the image, and its lookup cost depends on the class hierarchy.
--- choice
`dynamic_cast` allocates memory on the heap to hold its result.
--- choice
Virtual functions cannot fail, but `dynamic_cast` throws an exception when the cast is wrong.
--- why
Both happen at run time, so that is not the difference. A virtual call loads a function address from the object's vtable and calls it: the same small cost every time, and a reviewer can list every function it might reach. `dynamic_cast` has to walk the type information of the hierarchy to decide whether the object really is the requested type, so its time depends on the classes involved, and it needs the type-info records that `-fno-rtti` removes. It does not allocate, and a pointer `dynamic_cast` returns `nullptr` rather than throwing (only the reference form throws). The subset question is always the same: can we bound its time and memory?

+++ practice | Modernize the history buffer
--- task
The starter's `History` class is C++98 style: a buffer from `new[]`, a `#define` capacity, `int` sizes, a raw output pointer with a separate count, and no protection against being copied (a copy would delete the same buffer twice).

Rewrite it as `template <std::size_t N> class History` that keeps the legacy behavior exactly, with modern parts:

- storage in a `std::array<double, N>` inside the object; no `new`, no `delete`, no `#define`;
- `void push(double x)`: stores `x`; once `N` samples are held, each new one overwrites the oldest;
- `std::size_t size() const`: how many samples are held, at most `N`;
- `std::size_t latest(std::span<double> out) const`: writes the newest samples into `out`, newest first, as many as fit and as are held, and returns how many it wrote.

Because the storage is a plain array member, copying a `History` now simply copies the samples, and the copy is independent.
--- starter
#define HIST_CAP 8

// Legacy: keeps the last HIST_CAP samples.
class History {
public:
    History() : data_(new double[HIST_CAP]), head_(0), count_(0) {}
    ~History() { delete[] data_; }
    void push(double x) {
        data_[head_] = x;
        head_ = (head_ + 1) % HIST_CAP;
        if (count_ < HIST_CAP) count_++;
    }
    // Writes up to max of the newest samples into out, newest first. Returns how many.
    int latest(double* out, int max) const {
        int n = max < count_ ? max : count_;
        for (int i = 0; i < n; i++) {
            int idx = (head_ - 1 - i + HIST_CAP) % HIST_CAP;
            out[i] = data_[idx];
        }
        return n;
    }
    int size() const { return count_; }
private:
    double* data_;
    int head_;
    int count_;
};

--- why
A characterization test exists to prove that a refactoring changed nothing. A difference means something in the commit changed behavior, and a function-like macro is the usual suspect: it pastes text, so precedence or double evaluation can make it compute something a function never would. Re-recording the golden file would hide exactly the evidence the test exists to give. The fix is to split the commit: the pure refactorings (which should leave the output identical) in one change, and each behavior change in its own change, with a test that fails before and passes after, and a deliberate update to the golden file. A golden file has no "noise": the same program on the same input prints the same text.

--- task

#include <array>
#include <charconv>
#include <cstddef>
#include <optional>
#include <string_view>

enum class Op { fire, stop, abort };

struct Command {
    Op op;
    int thruster;
    double duty;

// The whole field must be the number: from_chars reports how far it got.
template <class T>
std::optional<T> whole_number(std::string_view s) {
    T value{};
    const char* last = s.data() + s.size();
    if (auto [ptr, ec] = std::from_chars(s.data(), last, value); ec == std::errc{} && ptr == last && !s.empty())
        return value;
    return std::nullopt;
}

std::optional<int> thruster_field(std::string_view s) {
    if (const auto t = whole_number<int>(s); t && *t >= 0 && *t <= 11) return t;
    return std::nullopt;
}

std::optional<Command> parse_command(std::string_view line) {
    // Split on single spaces into at most four fields; an empty field means a doubled or stray space.
    std::array<std::string_view, 4> f{};
    std::size_t n = 0;
    while (true) {
        if (n == f.size()) return std::nullopt;                  // too many fields
        const std::size_t sp = line.find(' ');
        f[n++] = line.substr(0, sp);
        if (f[n - 1].empty()) return std::nullopt;
        if (sp == std::string_view::npos) break;
        line.remove_prefix(sp + 1);
    }

    if (f[0] == "ABORT" && n == 1) return Command{Op::abort, -1, 0.0};
    if (f[0] == "STOP" && n == 2) {
        if (const auto t = thruster_field(f[1])) return Command{Op::stop, *t, 0.0};
    }
    if (f[0] == "FIRE" && n == 3) {
        const auto t = thruster_field(f[1]);
        const auto d = whole_number<double>(f[2]);
        if (t && d && *d >= 0.0 && *d <= 1.0) return Command{Op::fire, *t, *d};
    }
    return std::nullopt;
}

--- solution
#include <array>
#include <concepts>
#include <cstddef>

template <std::floating_point T, std::size_t N>
class Smoother {
    static_assert(N > 0, "a moving average needs a window of at least one sample");

public:
    T push(T x) {
        if (count_ == N) sum_ -= window_[next_];   // the oldest sample leaves the window
        else ++count_;
        window_[next_] = x;
        sum_ += x;
        next_ = (next_ + 1) % N;
        return sum_ / static_cast<T>(count_);
    }

    std::size_t count() const { return count_; }

    void reset() {
        count_ = 0;
        next_ = 0;
        sum_ = T{0};
    }

private:
    std::array<T, N> window_{};
    std::size_t next_ = 0;     // where the next sample goes
    std::size_t count_ = 0;
    T sum_{0};
};

+++ problem | A gain schedule the compiler builds
--- task
A control law's gain depends on dynamic pressure `q`, in kPa: at the table points q = 0, 1, 2, ..., 10 the gain is 2 / (1 + q). Build the table at compile time, in any floating-point precision:

- `template <std::floating_point T> consteval std::array<T, 11> make_gain_table()`: entry `i` is `T(2) / (T(1) + T(i))`, filled by a loop.
- `template <std::floating_point T> constexpr std::array<T, 11> gain_table_v = make_gain_table<T>();` — a variable template, one table per type.
- `template <std::floating_point T> constexpr T gain_at(T q)`: the gain at any `q`, by straight-line interpolation between the two neighbouring table points. For `q` at or below 0, the first entry; at or above 10, the last.

So `gain_at(0.5)` is halfway between 2 and 1, which is 1.5, and `gain_at(25.0)` is 2/11. `gain_at` must be usable at compile time, and must not accept an `int`.

#include <array>
#include <concepts>
#include <cstddef>

// consteval: the loop runs only inside the compiler.
template <std::floating_point T>
consteval std::array<T, 11> make_gain_table() {
    std::array<T, 11> t{};
    for (std::size_t i = 0; i < t.size(); ++i) t[i] = T(2) / (T(1) + static_cast<T>(i));
    return t;
}

// One constant table per floating-point type, each in its own precision.
template <std::floating_point T>
constexpr std::array<T, 11> gain_table_v = make_gain_table<T>();

template <std::floating_point T>
constexpr T gain_at(T q) {
    constexpr const auto& g = gain_table_v<T>;
    if (q <= T(0)) return g.front();
    if (q >= T(10)) return g.back();
    const auto i = static_cast<std::size_t>(q);    // the table point at or below q
    const T frac = q - static_cast<T>(i);
    return g[i] + frac * (g[i + 1] - g[i]);
}

#include <string_view>

// A T, or an error E. Hand-made, with the member functions of C++23's std::expected.
template <class T, class E>
class Expected {
public:
    static Expected ok(T v) { return Expected(v, E{}, true); }
    static Expected fail(E e) { return Expected(T{}, e, false); }
    bool has_value() const { return ok_; }
    explicit operator bool() const { return ok_; }
    const T& operator*() const { return val_; }
    const E& error() const { return err_; }
    T value_or(T fallback) const { return ok_ ? val_ : fallback; }

    // f(T) returns an Expected<U, E>: a step that can fail. Errors pass through.

        using R = decltype(f(val_));
        return ok_ ? f(val_) : R::fail(err_);
    }
    // f(T) returns a plain U: a step that cannot fail. Errors pass through.
    template <class F> auto transform(F f) const {
        using U = decltype(f(val_));
        return ok_ ? Expected<U, E>::ok(f(val_)) : Expected<U, E>::fail(err_);
    }
    // f(E) returns an Expected<T, E>: a recovery. Values pass through.
    template <class F> auto or_else(F f) const {
        return ok_ ? *this : f(err_);
    }
    // f(E) returns a plain error G: converts the error. Values pass through.
    template <class F> auto transform_error(F f) const {
        using G = decltype(f(err_));
        return ok_ ? Expected<T, G>::ok(val_) : Expected<T, G>::fail(f(err_));
    }

private:
    Expected(T v, E e, bool ok) : val_(v), err_(e), ok_(ok) {}

    E err_;
    bool ok_;

Result parse_throttle(std::string_view text) {
    double t = 0.0;
    const char* last = text.data() + text.size();
    auto [ptr, ec] = std::from_chars(text.data(), last, t);
    if (ec != std::errc{} || ptr != last) return Result::fail(Fault::bad_number);

    if (t < 0.40 || t > 1.00) return Result::fail(Fault::out_of_range);
    return Result::ok(t);
}

        .and_then(in_limits)                                  // can fail
        .transform([](double t) { return t * 100.0; })        // cannot fail
        .or_else([](Fault f) {                                 // recovery
            return f == Fault::out_of_range ? Result::ok(40.0) : Result::fail(f);
        });
}

        .and_then(in_limits)
        .transform_error([](Fault f) { return 10 + static_cast<int>(f); });   // Expected<double, int>
    return coded ? 0 : coded.error();
}

#include <cstddef>

enum class Layout { row_major, col_major };

// A pointer, a shape and a layout rule: the parts of a std::mdspan, chosen at run time.
struct MatRef {
    double* data;
    std::size_t rows;
    std::size_t cols;
    Layout layout;
    double& operator()(std::size_t r, std::size_t c) const {
        return layout == Layout::row_major ? data[r * cols + c] : data[r + c * rows];
    }
};

bool multiply_into(MatRef out, MatRef a, MatRef b) {
    if (a.cols != b.rows || out.rows != a.rows || out.cols != b.cols) return false;
    for (std::size_t r = 0; r < out.rows; ++r)
        for (std::size_t c = 0; c < out.cols; ++c) {
            double sum = 0.0;
            for (std::size_t k = 0; k < a.cols; ++k) sum += a(r, k) * b(k, c);
            out(r, c) = sum;
        }
    return true;
}

#include <chrono>

enum class Ign { idle, spark, confirm, lit, fault };

constexpr std::chrono::milliseconds kSparkTimeout{500};
constexpr std::chrono::milliseconds kConfirmTime{200};

class Igniter {
public:
    void start(std::chrono::milliseconds now) {
        if (state_ != Ign::idle) return;
        state_ = Ign::spark;
        since_ = now;
    }

    void tick(std::chrono::milliseconds now, bool flame) {
        switch (state_) {
        case Ign::spark:
            if (flame) {
                state_ = Ign::confirm;
                since_ = now;                        // the flame appeared now
            } else if (now - since_ >= kSparkTimeout) {
                state_ = Ign::fault;
            }
            break;
        case Ign::confirm:
            if (!flame) state_ = Ign::fault;
            else if (now - since_ >= kConfirmTime) state_ = Ign::lit;
            break;
        case Ign::idle:
        case Ign::lit:
        case Ign::fault:
            break;
        }
    }

    Ign state() const { return state_; }

private:
    Ign state_ = Ign::idle;
    std::chrono::milliseconds since_{0};   // when the current timed state began
};

// The span parameter (a pointer and a length) is copied into the frame; the bytes stay the caller's.
Gen<std::span<const std::uint8_t>> chunks(std::span<const std::uint8_t> data, std::size_t max_len) {
    if (max_len == 0) co_return;
    while (!data.empty()) {
        const std::size_t n = std::min(max_len, data.size());
        co_yield data.first(n);        // a view, not a copy
        data = data.subspan(n);
    }
}

std::vector<std::uint8_t> chunk_sums(std::span<const std::uint8_t> data, std::size_t max_len) {
    std::vector<std::uint8_t> sums;
    Gen<std::span<const std::uint8_t>> g = chunks(data, max_len);
    while (g.next()) {
        unsigned s = 0;
        for (std::uint8_t b : g.value()) s += b;
        sums.push_back(static_cast<std::uint8_t>(s & 0xFFu));
    }
    return sums;
}

template <class F>

    g_allocs = 0;
    g_counting = true;
    f();

struct Event {
    std::string_view name;
    std::uint32_t t_ms;
    double value;
};

std::string_view format_event(std::span<char> buf, const Event& e) {
    auto r = std::format_to_n(buf.data(), static_cast<std::ptrdiff_t>(buf.size()),
                              "[t={:>8}] {} = {:.2f}", e.t_ms, e.name, e.value);
    return {buf.data(), static_cast<std::size_t>(r.out - buf.data())};   // exactly what was written
}

std::size_t format_events(std::span<char> buf, std::span<const Event> events) {
    std::size_t used = 0;
    for (const Event& e : events) {
        const std::span<char> rest = buf.subspan(used);
        auto r = std::format_to_n(rest.data(), static_cast<std::ptrdiff_t>(rest.size()),
                                  "[t={:>8}] {} = {:.2f}", e.t_ms, e.name, e.value);
        const auto wanted = static_cast<std::size_t>(r.size);
        if (wanted + 1 > rest.size()) break;   // the line and its newline must both fit
        rest[wanted] = '\n';
        used += wanted + 1;
    }
    return used;
}

```cpp
struct Counted {
    static inline int copies = 0, moves = 0;
    Counted() = default;
    Counted(const Counted&) { ++copies; }
    Counted(Counted&&) noexcept { ++moves; }
};

Counted pick(bool f) { Counted x, y; if (f) return x; return y; }
Counted pass(Counted p) { return p; }
Counted fresh() { return Counted{}; }

int main() {
    Counted a = pick(true);
    Counted b = pass(fresh());
    Counted c = fresh();
    std::printf("%d %d\n", Counted::copies, Counted::moves);
}
```
--- answer
0 2
0, 2
--- why
No line copies, so the first number is 0. `pick` returns one of two locals depending on `f`, so the compiler cannot build both in the one return slot: no NRVO, but the implicit move on return applies to a plain local name, so one move. In `pass(fresh())`, the prvalue `fresh()` initializes the parameter `p` directly, with nothing to elide; returning a by-value parameter can never be elided either, because the caller built `p` in its own place, so it is moved: the second move. `Counted c = fresh();` initializes `c` straight from a prvalue: zero.

+++ question | Two loops over an attitude log
--- ask
What does this print? Type the two numbers separated by a space.

```cpp
#include <array>
#include <cstdio>

struct Att { double roll, pitch, yaw; };

int main() {
    std::array<Att, 2> hist{{{0.1, 0.2, 0.3}, {1.0, 2.0, 3.0}}};
    for (auto [r, p, y] : hist) p = 0.0;
    for (auto& [r, p, y] : hist) y += p;
    std::printf("%.1f %.1f\n", hist[0].yaw, hist[1].yaw);
}
```
--- answer
0.5 5.0
0.5, 5.0
--- why
In the first loop, `auto [r, p, y]` makes each hidden object a copy of the element, so `p = 0.0` changes only the copy and the array keeps its pitches, 0.2 and 2.0. In the second loop, `auto&` binds the hidden object to each element itself, so `y += p` adds the real pitch to the real yaw: 0.3 + 0.2 = 0.5 and 3.0 + 2.0 = 5.0. The names follow the members in declaration order: roll, pitch, yaw.

+++ question | Which accessor is broken
--- ask
Four small accessors, written with C++14 return type deduction. Which one is a real bug?

```cpp
#include <array>
#include <vector>

decltype(auto) newest(const std::vector<double>& v) { return v.back(); }   // A
decltype(auto) doubled(double k) { double s = k * 2.0; return (s); }        // B
auto first(std::vector<double>& v) { return v.front(); }                    // C
decltype(auto) slot(std::array<double, 3>& a, int i) { return a[i]; }       // D
```
--- choice
A: `newest` returns a reference to an element, and the element dies when the function returns.
--- choice correct
B: `(s)` in parentheses makes `decltype(auto)` deduce `double&`, so `doubled` returns a reference to a local that is destroyed at the closing brace.
--- choice
C: `first` returns a reference into `v`, so a caller who changes the result changes the vector by accident.
--- choice
D: `slot` returns a copy, so `slot(a, 1) = 5.0;` silently does nothing.
--- why
For a parenthesized name, `decltype` gives a reference, so B returns `double&` to `s`, which dies as the function returns: using the result is undefined behavior, and g++ warns "reference to local variable returned". A returns `const double&` to an element of the caller's vector, which lives on after the call, so it is fine. C uses plain `auto`, which drops references: it returns a copy of the first element, harmless. D returns `double&`, because `std::array::operator[]` returns a reference and `decltype(auto)` keeps it, so `slot(a, 1) = 5.0;` really writes into the array.

+++ question | Comparing a NaN reading
--- ask
What does this print? Type the four digits exactly as printed.

```cpp
#include <cmath>
#include <compare>
#include <cstdio>

struct Reading {
    double value;
    auto operator<=>(const Reading&) const = default;
};

int main() {
    Reading a{std::nan("")}, b{1.0};
    std::printf("%d%d%d%d\n", a < b, a > b, a == b, a != b);
}
```
--- answer
0001
--- why
Because the member is a `double`, the defaulted `<=>` returns `std::partial_ordering`, and a NaN is *unordered* with every value: neither less, nor greater, nor equivalent. So `a < b` and `a > b`, which are rewritten as `(a <=> b) < 0` and `(a <=> b) > 0`, are both false. `a == b` uses the defaulted `==`, which compares the members with `==`, and NaN equals nothing: false. `a != b` is rewritten as `!(a == b)`: true. So the output is 0, 0, 0, 1.

+++ question | Braces and deduction
--- ask
What does this print? Type the two numbers separated by a space.

```cpp
#include <cstdio>
#include <vector>

int main() {
    std::vector v{1, 2, 3, 4, 5};
    std::vector w{v, v};
    std::vector x{v};
    std::printf("%zu %zu\n", w.size(), x.size());
}
```
--- answer
2 5
2, 5
--- why
Class template argument deduction works out each type from the arguments. `v` is a `std::vector<int>` of five elements. `w{v, v}` is a brace list of two vectors, so it deduces `std::vector<std::vector<int>>` and holds two elements: size 2. `x{v}` looks as if it should do the same with one element, but for a single argument of the vector's own type the rules prefer copying: `x` is a `std::vector<int>`, a copy of `v`, with five elements. Braces plus deduction can surprise you, which is why flight code spells the type out wherever it is not obvious.

+++ question | The one that reaches the heap
--- ask
Inside a 1 kHz control task built with g++ and libstdc++, `buf` is a `std::array<double, 64>` (512 bytes) in static storage. Which of these lines can allocate from the heap?
--- choice
`std::span<const double> s{buf};`
--- choice
`std::optional<std::array<double, 64>> o = buf;`
--- choice correct
`std::function<double()> f = [buf] { return buf[0]; };`
--- choice
`auto g = [&buf] { return buf[0]; };`
--- why
A `std::function` can hold any callable of any size, but its own object has room for only a small one inside it (in libstdc++, about two pointers' worth). This lambda captures the whole 512-byte array by value, so `std::function` stores it on the heap. That is why the flight subset bans `std::function` in a control task: whether it allocates depends on the callable's size and the library. The span is a pointer and a length; the optional stores its array in place, next to a flag; and the plain lambda holding a reference is a small object on the stack.

+++ question | The cycle that allocates
--- ask
A status `std::string` starts empty, and every control cycle appends 4 characters to it with `+=`. On g++ 13 with libstdc++, whose `std::string` keeps up to 15 characters inside the string object itself, on which cycle does the first heap allocation happen? Type the cycle number.
--- answer
4
cycle 4
fourth
the fourth
--- why
After cycles 1, 2 and 3 the string holds 4, 8 and 12 characters, all inside the 16-byte small-string buffer (15 characters plus the terminating zero). Cycle 4 makes it 16 characters, one more than fits, so the string asks the heap for a new buffer. It passed three cycles and failed on the fourth, and the threshold belongs to the library, not to your code: another library could allocate on a different cycle. That is why `std::string` is usually banned in a hard real-time path in favor of a fixed-capacity buffer.

+++ question | A chain of modules
--- ask
A team converts 200 headers into modules, arranged as a chain: each module imports the one before it. Their clean build on a 32-core machine is now slower than it was with headers. What is the most likely reason?
--- choice
The compiler parses a module interface more slowly than the same text in a header.
--- choice correct
A file cannot be compiled until the modules it imports have been compiled into their BMIs, so a chain forces the modules to build one after another, and most cores sit idle.
--- choice
Built module interfaces are larger than headers, so reading them from disk dominates the build time.
--- choice
Modules turn off optimization, so the code generation steps take longer.
--- why
With headers, every `.cpp` file can be compiled on its own, in any order, all at once. With modules, an importer needs the imported module's BMI to exist first. A 200-long chain means 200 compiles in strict order, whatever the number of cores. Each import is still cheaper than re-parsing a header, but the lost parallelism can outweigh it. That is why the lesson warned: "compiled once" does not mean "faster in every build", and a module graph should be kept wide and shallow. Measure before promising a speed-up.

+++ question | Where the coroutine runs
--- ask
What does this print? Type the output exactly, with no spaces.

```cpp
#include <coroutine>
#include <cstdio>
#include <exception>

struct Task {
    struct promise_type {
        Task get_return_object() { return Task{std::coroutine_handle<promise_type>::from_promise(*this)}; }
        std::suspend_never initial_suspend() noexcept { return {}; }
        std::suspend_always final_suspend() noexcept { return {}; }
        void return_void() noexcept {}
        void unhandled_exception() { std::terminate(); }
    };
    std::coroutine_handle<promise_type> h;
    ~Task() { if (h) h.destroy(); }
};

Task steps() {
    std::printf("A");
    co_await std::suspend_always{};
    std::printf("B");
    co_await std::suspend_always{};
    std::printf("C");
}

int main() {
    Task t = steps();
    std::printf("1");
    t.h.resume();
    std::printf("2");
    t.h.resume();
    std::printf("3\n");
}
```
--- answer
A1B2C3
--- why
`initial_suspend` returns `suspend_never`, so calling `steps()` runs its body straight away, up to the first `co_await`: `A` prints before `main` gets control back. Each `co_await std::suspend_always{}` pauses and returns control to whoever resumed it. So `main` prints `1`, resumes (the body prints `B` and pauses again), prints `2`, resumes (the body prints `C`, reaches its end and parks at `final_suspend`), and prints `3`. Had `initial_suspend` returned `suspend_always`, the body would not start until the first `resume()`, and the output would be `1A2B3`.

+++ question | A chain with a recovery
--- ask
On a compiler whose library has C++23's `std::expected`, what does this print? Type the two numbers separated by a space.

```cpp
#include <cstdio>
#include <expected>

enum class Fault { stale, noisy };

int main() {
    std::expected<double, Fault> r1 = 2.0;
    std::expected<double, Fault> r2 = std::unexpected(Fault::stale);
    auto f = [](double x) { return x * 10.0; };
    auto g = [](Fault) { return std::expected<double, Fault>(-1.0); };
    std::printf("%g %g\n", r1.transform(f).or_else(g).value_or(0.0),
                           r2.transform(f).or_else(g).value_or(0.0));
}
```
--- answer
20 -1
20, -1
20.0 -1.0
--- why
`r1` holds a value, so `transform(f)` calls `f` and wraps 20.0; `or_else(g)` sees a value and does nothing; `value_or` returns 20. `r2` holds an error, so `transform` passes it through without calling `f`; `or_else(g)` sees the error and calls `g`, which recovers with the value -1.0; `value_or(0.0)` then has a value to return, so the fallback 0.0 is never used. `%g` prints 20.0 as `20` and -1.0 as `-1`.

+++ question | One element, two layouts
--- ask
A 2 × 3 × 4 block of aerodynamic coefficients is stored in one flat buffer of 24 floats. A `std::mdspan` with extents 2, 3 and 4 is laid over it. At which index of the buffer is the element `[1, 0, 2]` with `std::layout_right` (row-major: the last index moves fastest), and at which with `std::layout_left` (column-major: the first index moves fastest)? Type the two indices, layout_right first, separated by a space.
--- answer
14 13
14, 13
--- why
With `layout_right`, the index is ((i × 3) + j) × 4 + k: skip i whole 3-by-4 slabs, then j rows of 4, then k: (1 × 3 + 0) × 4 + 2 = 14. With `layout_left`, it is i + 2 × (j + 3 × k): the first index moves fastest, so i counts single steps, j steps of 2, and k steps of 2 × 3 = 6: 1 + 2 × 0 + 6 × 2 = 13. The same buffer read with the wrong layout gives a different element, which is why a view has to carry its layout.
