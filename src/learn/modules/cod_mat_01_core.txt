=== mat01-l01 | Practice: The MATLAB desktop

l01-the-matlab-desktop

+++ question | Where ans ends up
--- ask
You type these four lines at the Command Window, one after another:

```matlab
>> a = 4;
>> a^2 + 1
>> b = ans * 2;
>> ans - 7
```

What value does `ans` hold at the end? Type the number.
--- answer
10
--- why
Only results that you do not name go into `ans`. Line 2 has no name, so `ans` becomes $4^2 + 1 = 17$. Line 3 names its result `b`, so `b` is 34 and `ans` is left alone at 17. Line 4 has no name again, so `ans` becomes $17 - 7 = 10$. Reading `ans` inside a line does not change it; only a new unnamed result does.

+++ question | Which lines print
--- ask
A script holds these four lines:

```matlab
x = 3.14159;
y = x * 2
x + y;
disp(y)
```

When you run it, which lines show something in the Command Window?
--- choice
All four, because a script always echoes every line it runs.
--- choice
Lines 2, 3 and 4, because a result with no name is always shown.
--- choice correct
Lines 2 and 4 only. Line 3 ends in a semicolon, so its result goes quietly into `ans`.
--- choice
Line 4 only, because a script needs `disp` to print anything.
--- why
The semicolon is what hides the echo, whether the result has a name or not. Line 1 and line 3 end in semicolons, so they print nothing, although line 3 still stores 9.4248 in `ans`. Line 2 has no semicolon, so MATLAB echoes `y = 6.2832`. `disp(y)` prints the value without its name. A script behaves exactly as if you had typed its lines at the prompt.

+++ question | A loop counter called i
--- ask
While testing a loop, you type `i = 5` at the prompt. Later in the same session you type:

```matlab
>> z = 3 + 2*i
```

What is `z`? Type the value.
--- answer
13
--- why
MATLAB uses `i` for the imaginary unit $\sqrt{-1}$, but a variable beats a built-in name. Your `i = 5` hides the imaginary unit, so `2*i` is 10 and `z` is 13, a real number. `which i` would tell you that `i` is now a variable, and `clear i` brings the imaginary unit back. This is why MATLAB code that means the imaginary unit writes `1i` or `2i` with the number joined to the letter: that form is always imaginary, whatever variables exist.

+++ question | Digits that were only hidden
--- ask
In the default `format short`, you type:

```matlab
>> r = 6778.137
% r = 6.7781e+03
>> d = r - 6778
```

What does MATLAB show for `d`? Type the number as MATLAB shows it, or with fewer trailing zeros.
--- answer
0.1370
0.137
.137
--- why
The echo `6.7781e+03` rounds the number to five significant figures for the screen, but `r` still stores every digit of 6778.137. Subtracting 6778 leaves 0.137, which `format short` shows as `0.1370`. If the display had really thrown the digits away, `d` would be 0.1. The display format changes how numbers look, never what is stored.

+++ question | A script MATLAB cannot find
--- ask
A teammate sends you `load_flight.m`, and you save it in `C:\work\gnc`. Your Current Folder is `C:\Users\you\Documents`. You type `load_flight` and get:

```text
Unrecognized function or variable 'load_flight'.
```

`which load_flight` answers `'load_flight' not found.` What fixes it?
--- choice
Rename the file `load_flight.mlx`, because only live scripts can be run by name.
--- choice correct
Change the Current Folder to `C:\work\gnc`, or add that folder to the search path with `addpath`.
--- choice
Type `import load_flight` first, as you would in Python.
--- choice
Run it as `load_flight.m`, because MATLAB needs the extension.
--- why
MATLAB looks for a name in the workspace, then in the Current Folder, then along the search path. The file sits in neither folder MATLAB searches, so the name means nothing to it. Standing in the right folder, or running `addpath('C:\work\gnc')`, makes the name findable, and `which load_flight` will then print the file's path. MATLAB has no `import` step for scripts, and adding the extension does not help it find a file in a folder it never searches.

+++ question | A script and a variable with one name
--- ask
Your Current Folder holds a script `g.m` whose only line is `disp("hello")`. At the prompt you type:

```matlab
>> g = 9.81;
>> g * 2
>> clear g
>> g
```

What do the second and fourth lines do?
--- choice
The second line runs the script and prints `hello`, because files are checked before variables. The fourth line errors.
--- choice correct
The second line gives `ans = 19.6200`. The fourth line runs the script and prints `hello`.
--- choice
Both lines give 19.62, because `clear g` only clears the screen.
--- choice
The first line errors, because a variable may not share its name with a file.
--- why
When you type a name, MATLAB checks the workspace first, then the Current Folder, then the search path, and the first match wins. While the variable `g` exists, `g` means 9.81, so `g * 2` is 19.62. `clear g` deletes the variable (`clc` is the one that clears the screen), so the next `g` falls through to the file `g.m`, and the script runs. MATLAB allows the clash without complaint, which is exactly why it causes confusing bugs.

=== mat01-l02 | Practice: Everything is a matrix
--- for
l02-everything-is-a-matrix

+++ question | Counting a stepped range
--- ask
How many elements does `3:4:30` have? Type the number.
--- answer
7
--- why
The range starts at 3 and goes up in steps of 4 as far as it can without passing 30: 3, 7, 11, 15, 19, 23, 27. The next would be 31, past the stop. The formula agrees: $\lfloor (30 - 3)/4 \rfloor + 1 = \lfloor 6.75 \rfloor + 1 = 7$. The stop value 30 is not in the range, because it is not a whole number of steps from 3.

+++ question | The count linspace needs
--- ask
You want time samples every $0.02\,\mathrm{s}$ from $t = 1\,\mathrm{s}$ to $t = 3\,\mathrm{s}$, both ends included, built with `linspace(1, 3, n)`. What must `n` be? Type the number.
--- answer
101
--- why
The span is $3 - 1 = 2\,\mathrm{s}$, and $2 / 0.02 = 100$ gaps. With both ends included, 100 gaps need 101 points, the fencepost rule. Check with the spacing formula: $(3 - 1)/(101 - 1) = 0.02$. Writing `n = 100` gives a spacing of $2/99 \approx 0.0202\,\mathrm{s}$, so every sample after the first drifts a little off the intended times.

+++ question | Gluing blocks together
--- ask
What is `size(C)` after these lines? Type the two numbers.

```matlab
A = zeros(2, 3);
B = ones(2, 1);
C = [A B; 5*ones(1, 4)];
```
--- answer
3 4
3x4
3 by 4
3-by-4
[3 4]
3, 4
--- why
Inside the brackets, the space in `A B` joins side by side first: a 2-by-3 and a 2-by-1 have the same number of rows, so they make a 2-by-4. The semicolon then stacks a 1-by-4 row underneath, which fits because both have 4 columns. The result has 3 rows and 4 columns. Had the last piece been `5*ones(1, 3)`, MATLAB would have stopped with a dimensions error.

+++ question | A matrix with no columns
--- ask
`M = zeros(3, 0)` makes a matrix with 3 rows and no columns. What are `size(M)`, `numel(M)` and `length(M)`?
--- choice
`[3 0]`, 0 and 3, because `length` returns the larger dimension.
--- choice correct
`[3 0]`, 0 and 0, because `length` is 0 for any empty matrix.
--- choice
`[3 1]`, 3 and 3, because MATLAB never makes a dimension zero.
--- choice
`[0 0]`, 0 and 0, because every empty matrix is 0-by-0.
--- why
An empty matrix can still have a shape: `zeros(3, 0)` is 3-by-0, so `size` reports `[3 0]`. It holds $3 \times 0 = 0$ numbers, so `numel` is 0. `length` is the largest dimension for a matrix with elements, but it is defined as 0 for any empty one. So a loop `for k = 1:length(M)` safely runs zero times, and `isempty(M)` is true.

+++ question | Three rows that should have been columns
--- ask
A logger hands you the three accelerometer axes as row vectors `ax`, `ay` and `az`, each 1-by-500. A teammate builds the sample matrix with `imu = [ax ay az]` and expects one row per sample and one column per axis. What does the line really make, and what should it be?
--- choice
It makes the intended 500-by-3 matrix, because MATLAB turns rows into columns when it concatenates.
--- choice
It stops with an error, because rows cannot be joined side by side.
--- choice correct
It makes one long 1-by-1500 row. Write `imu = [ax; ay; az]'`, which stacks the rows into a 3-by-500 and then transposes it.
--- choice
It makes a 3-by-500 matrix. Write `imu = reshape([ax ay az], 3, 500)` to get the right shape.
--- why
A space inside brackets joins side by side, and three 1-by-500 rows side by side are one 1-by-1500 row. The data is all there, but in the wrong shape, so `imu(2, :)` would fail. Stacking with semicolons gives a 3-by-500 with one row per axis, and the transpose turns it into 500-by-3. `[ax' ay' az']` works too. The `reshape` choice is wrong because it fills 3 rows down the columns, so the first column would hold `ax(1)`, `ax(2)` and `ax(3)`, three samples of one axis.

+++ question | Axes in rows
--- ask
A ground-test file stores gyro data as `D`, a 3-by-500 matrix: row 1 is the roll rate, row 2 pitch and row 3 yaw, and each column is one sample. Which line gives the mean rate of each axis?
--- choice
`mean(D)`
--- choice correct
`mean(D, 2)`
--- choice
`mean(D(:))`
--- choice
`mean(D, 1)`
--- why
`mean` works down dimension 1, the columns, unless told otherwise. Here each column is one sample, so `mean(D)` and `mean(D, 1)` both give 500 numbers, each mixing the three axes of one sample. `mean(D, 2)` works along each row and gives a 3-by-1 column: one mean per axis. `mean(D(:))` averages all 1500 numbers into one value. Before you pick a dimension, ask which way the samples run.

=== mat01-l03 | Practice: Reaching inside a matrix
--- for
l03-indexing

+++ question | Counting back from end
--- ask
`v = [5 10 15 20 25 30 35]`. What does `v(end-3:end-1)` give? Type the numbers separated by spaces.
--- answer
20 25 30
[20 25 30]
20, 25, 30
--- why
`v` has 7 elements, so `end` is 7 and the range is `4:6`. MATLAB ranges include both ends, so that is positions 4, 5 and 6, holding 20, 25 and 30. The last element, 35, is left out because the range stops at `end-1`.

+++ question | The last three, from Python
--- ask
A Python script takes the last three samples of a list with `x[-3:]`. Which MATLAB expression gives the same three samples in the same order?
--- choice
`x(end-3:end)`
--- choice
`x(-3:end)`
--- choice correct
`x(end-2:end)`
--- choice
`x(end:-1:end-2)`
--- why
The last three positions are `end-2`, `end-1` and `end`, so the range is `end-2:end`, which includes both ends. `end-3:end` has four elements, the classic off-by-one. Negative indices are errors in MATLAB. `end:-1:end-2` picks the right three samples but backwards.

+++ question | A column of a reshaped matrix
--- ask
What is `sum(M(:, 3))` after `M = reshape(1:12, 3, 4)`? Type the number.
--- answer
24
--- why
`reshape` fills down the columns, so `M` has columns `[1; 2; 3]`, `[4; 5; 6]`, `[7; 8; 9]` and `[10; 11; 12]`. Column 3 is 7, 8 and 9, which add to 24. If you pictured `M` filled row by row, as NumPy fills it, the rows would be 1 to 4, 5 to 8 and 9 to 12, column 3 would hold 3, 7 and 11, and you would answer 21. Check one small case by hand whenever you translate a reshape.

+++ question | A missing reading in a mask
--- ask
A sensor log has one reading that was never recorded:

```matlab
v = [3 NaN -2 0 5];
n = nnz(v > 0) + nnz(v <= 0)
```

What is `n`? Type the number.
--- answer
4
--- why
`v > 0` is true for 3 and 5, and `v <= 0` is true for -2 and 0. Every comparison with `NaN` is false, as in Python, so the `NaN` passes neither test and is counted by neither. The two counts add to 4, not 5. A mask like `v(~(v > 0))` would keep the `NaN` along with -2 and 0. When data can hold `NaN`, remove it first with `v(~isnan(v))`, or test for it on its own.

+++ question | A filter that errors
--- ask
To keep readings between 0 and 5, a teammate writes:

```matlab
v = [4 -2 7 0 -5 3];
ok = v(v > 0 && v < 5);
```

The second line stops with an error. Why, and what is the fix?
--- choice
A mask cannot combine two tests. Use `v(v > 0)` and then `ok(ok < 5)`.
--- choice correct
`&&` only works on single true-or-false values, and `v > 0` is a whole array. Use `&`, which works element by element: `v(v > 0 & v < 5)`.
--- choice
The comparisons need brackets around them: `v((v > 0) && (v < 5))`.
--- choice
Logical indexing needs `find`: `v(find(v > 0 && v < 5))`.
--- why
`&&` and `||` short-circuit, so they need a single true-or-false value on each side, and MATLAB refuses an array there. The element-wise `&` compares the two masks position by position and gives `[1 0 0 0 0 1]`, so `ok` is `[4 3]`. Brackets change nothing, and `find` does not help because the error happens before `find` runs. Save `&&` and `||` for `if` and `while` conditions.

+++ question | The first moment any sensor ran hot
--- ask
`T` holds three temperature sensors, one column each, sampled once per second from $t = 0$:

```matlab
T = [70 75 72
     78 82 79
     85 90 81
     88 91 84];
[r, c] = find(T > 80, 1)
```

You want the first sample at which any sensor read above 80. What does this line give, and does it answer the question?
--- choice
`r = 2, c = 2`. Yes: sample 2, at $t = 1\,\mathrm{s}$, sensor 2.
--- choice correct
`r = 3, c = 1`. No: `find` searches down the columns, so it found sensor 1's first hot reading. The first hot sample is sample 2, which `[r, c] = find(T' > 80, 1)` gives as `c = 2`.
--- choice
`r = 3, c = 1`. Yes: `find` searches along the rows, so row 3 is the first hot sample.
--- choice
It returns empty, because `find` with two outputs needs a vector.
--- why
`find` counts in column-major order, down column 1, then down column 2, and so on. Column 1 first passes 80 at row 3 (85), so that is the first match, even though sensor 2 read 82 one sample earlier, in row 2. Transposing makes each column one sample, so the column-order search now walks through time: `find(T' > 80, 1)` stops at sample 2, where sensor 2 reads 82, and returns `r = 2` (the sensor) and `c = 2` (the sample). Sample 2 is at $t = (2 - 1) \times 1 = 1\,\mathrm{s}$.

=== mat01-l04 | Practice: Element-wise versus matrix operations
--- for
l04-element-wise-versus-matrix

+++ question | A row times a column
--- ask
What is `[1 -1 2] * [3; 4; 0.5]`? Type the number.
--- answer
0
--- why
A 1-by-3 row times a 3-by-1 column is a matrix product whose inside sizes match, and its result is 1-by-1: the dot product. $1 \cdot 3 + (-1) \cdot 4 + 2 \cdot 0.5 = 3 - 4 + 1 = 0$. The element-wise `.*` would need both to have the same shape; with this row and column it would stretch them into a 3-by-3 table instead.

+++ question | The same two vectors, both orders
--- ask
`u = [1; 2; 3]` is a column and `w = [4 5]` is a row. What happens with `u * w` and with `w * u`?
--- choice
Both stop with an error, because the vectors have different lengths.
--- choice
Both give a single number, their dot product.
--- choice correct
`u * w` gives a 3-by-2 matrix. `w * u` stops with an error, because the inside sizes are 2 and 3.
--- choice
`u * w` stops with an error, and `w * u` gives a 2-by-3 matrix.
--- why
Write the sizes side by side. `u * w` is $(3 \times 1)(1 \times 2)$: the inside numbers are both 1, so it works, and the outside numbers give a 3-by-2 result, each entry $u_i w_j$. `w * u` is $(1 \times 2)(3 \times 1)$: the inside numbers 2 and 3 differ, so the product is not defined. Matrix products care about order; a dot product needs two vectors of the same length.

+++ question | Squares, then a matrix product
--- ask
What is `y` after these lines? Type the number.

```matlab
x = [1 2 3];
y = x.^2 * x';
```
--- answer
36
--- why
`x.^2` squares each element: `[1 4 9]`, still a 1-by-3 row. `x'` is the column `[1; 2; 3]`. A 1-by-3 row times a 3-by-1 column is their dot product: $1 \cdot 1 + 4 \cdot 2 + 9 \cdot 3 = 1 + 8 + 27 = 36$, which is the sum of the cubes. Powers go before products, so the dot applies to `x` alone.

+++ question | An inverse and a table of reciprocals
--- ask
`D = [2 0; 0 4]`. What is `D.^-1`?
--- choice
`[0.5 0; 0 0.25]`, the same as the inverse `D^-1`.
--- choice correct
`[0.5 Inf; Inf 0.25]`, because each zero becomes 1/0.
--- choice
An error, because a matrix with zeros in it has no inverse.
--- choice
`[-2 0; 0 -4]`, because the power flips each sign.
--- why
The dot makes the power act on each element, so every entry becomes its reciprocal: $1/2$, $1/4$, and $1/0$, which MATLAB gives as `Inf` with no error. The matrix inverse `D^-1` is `[0.5 0; 0 0.25]`: for a matrix with numbers only on the diagonal, the inverse happens to take the reciprocal of those numbers and keep the zeros. That is why the two can look alike on a small test and then differ badly as soon as the matrix has zeros or entries off the diagonal.

+++ question | A rotation that works on three samples only
--- ask
`C` is a 3-by-3 direction cosine matrix and `V` holds velocities, one sample per row, so it is N-by-3. To turn every velocity into the other frame, a teammate writes `W = C * V`. On a three-sample test log it runs and gives wrong numbers. On a real log of 1000 samples it errors. What is the fix?
--- choice
`W = C .* V`, because each sample must be multiplied separately.
--- choice correct
`W = (C * V')'`, or the same thing written `W = V * C'`.
--- choice
`W = C' * V`, because the rotation must be transposed first.
--- choice
`W = V .* C'`, which multiplies matching entries.
--- why
`C * V` needs V to have 3 rows, so it only runs when there happen to be exactly 3 samples, and then it mixes the samples together. Transposing `V` makes each sample a column (3-by-N), `C` turns every column, and the final transpose puts samples back into rows. Since $(\mathbf{C}\mathbf{V}^{\mathsf{T}})^{\mathsf{T}} = \mathbf{V}\mathbf{C}^{\mathsf{T}}$, the shorter form is the same. The element-wise choices multiply entries one by one, which is not a rotation at all; each rotated component is a sum of products.

+++ question | A quarter turn, two ways
--- ask
`R = [0 -1; 1 0]` turns a vector a quarter turn, 90 degrees. Which statement about `R^2` and `R.^2` is right?
--- choice
Both are `[0 1; 1 0]`, because every entry is 0, 1 or -1.
--- choice correct
`R^2` is `[-1 0; 0 -1]`, a half turn. `R.^2` is `[0 1; 1 0]`, which swaps the two components and is not a rotation.
--- choice
`R^2` is `[0 1; 1 0]`, a half turn, and `R.^2` stops with an error.
--- choice
`R^2` is `[1 0; 0 1]`, because a rotation squared is the identity.
--- why
`R^2` is `R*R`: top-left $0 \cdot 0 + (-1) \cdot 1 = -1$, top-right $0 \cdot (-1) + (-1) \cdot 0 = 0$, and so on, giving `[-1 0; 0 -1]`, which points every vector the opposite way: two quarter turns make a half turn. `R.^2` squares each entry, and $(-1)^2 = 1$, so the minus sign vanishes. Its determinant is $0 \cdot 0 - 1 \cdot 1 = -1$, not $+1$, which marks a mirror image rather than a turn. It takes four quarter turns, `R^4`, to get back to the identity.

=== mat01-l05 | Practice: Backslash and linear systems
--- for
l05-backslash-and-linear-systems

+++ question | A two-by-two solve
--- ask
What is `x(1)` after these lines? Type the number.

```matlab
A = [4 -2; 1 1];
b = [2; 5];
x = A \ b;
```
--- answer
2
--- why
`A \ b` solves $4x_1 - 2x_2 = 2$ and $x_1 + x_2 = 5$. From the second, $x_1 = 5 - x_2$. Put that in the first: $20 - 4x_2 - 2x_2 = 2$, so $x_2 = 3$ and $x_1 = 2$. Check with the residual: $4 \cdot 2 - 2 \cdot 3 = 2$ and $2 + 3 = 5$, so `A*x - b` is zero.

+++ question | Dividing from the right
--- ask
What does `x = [7 11] / [1 2; 3 4]` do?
--- choice
It divides element by element and stops with an error, because the sizes differ.
--- choice
It solves $\mathbf{A}\mathbf{x} = \mathbf{b}$ for a column and gives `[-3; 5]`.
--- choice correct
It solves $\mathbf{x}\mathbf{A} = \mathbf{b}$ for a row `x` and gives `[2.5 1.5]`.
--- choice
It computes the least-squares scale factor between the row and the matrix, a single number.
--- why
The slash puts the matrix on the right of the unknown, so `x` is a 1-by-2 row with $x_1 \cdot 1 + x_2 \cdot 3 = 7$ and $x_1 \cdot 2 + x_2 \cdot 4 = 11$. Solving gives $x_2 = 1.5$ and $x_1 = 2.5$; check: $2.5 + 4.5 = 7$ and $5 + 6 = 11$. `[-3; 5]` is what `[1 2; 3 4] \ [7; 11]` gives, the other problem. Order matters because matrix products do not commute.

+++ question | Fitting a parabola
--- ask
`t` and `y` are column vectors of 50 measurements. You want the least-squares fit $y \approx c_1 + c_2 t + c_3 t^2$. Which line builds the matrix `M` for `c = M \ y`?
--- choice
`M = [1 t t^2];`
--- choice correct
`M = [ones(size(t)) t t.^2];`
--- choice
`M = [ones(size(t)) t t*t];`
--- choice
`M = [ones(size(t)); t; t.^2];`
--- why
Each measurement gives one equation, so `M` needs one row per sample and one column per unknown: a column of ones for $c_1$, the times for $c_2$, and the squared times for $c_3$. That makes a 50-by-3 tall matrix, and backslash returns the least-squares fit. `t^2` and `t*t` are matrix products of a 50-by-1 column with itself, which is an error; the square of each time needs `.^`. A lone `1` cannot sit beside a 50-row column. Semicolons stack the pieces into one 150-by-1 column, which is not the system you meant.

+++ question | A right-hand side typed as a row
--- ask
`A` is 2-by-2 and you type `x = A \ [13 14]`. What happens?
--- choice
MATLAB turns the row into a column and solves the system.
--- choice correct
It stops with an error: the right-hand side must have as many rows as `A`, and `[13 14]` has one row.
--- choice
It returns a least-squares answer, because the system is no longer square.
--- choice
It returns the element-wise ratios of the row to the diagonal of `A`.
--- why
`A \ b` solves $\mathbf{A}\mathbf{x} = \mathbf{b}$, so `b` must have one row per equation: 2 here. A 1-by-2 row has only one row, so MATLAB reports that the sizes do not fit. Nothing is turned around for you. Type `[13; 14]`, or write `[13 14]'`. Checking `size` of both sides before a solve catches this at once.

+++ question | Backslash with the pieces swapped
--- ask
To solve $\mathbf{A}\mathbf{x} = \mathbf{b}$ with `A = [2 1; 1 3]` and `b = [13; 14]`, a teammate types `x = b \ A`. What happens?
--- choice
It stops with an error, because `b` is not square.
--- choice
It gives the right answer `[5; 3]`, because backslash does not care about order.
--- choice correct
It runs with no error and returns a 1-by-2 row: the least-squares answer to $\mathbf{b}\mathbf{X} = \mathbf{A}$, a different problem.
--- choice
It gives the inverse of `A` times `b`, the same as `inv(A)*b`.
--- why
Backslash solves for the unknown on the right of whatever is on its left, so `b \ A` treats `b`, a 2-by-1 column, as the coefficient matrix and `A` as the right-hand side. That is a tall system with one unknown per column of `A`, and backslash quietly returns its least-squares fit, about `[0.1096 0.1507]`. No error, and a result of the wrong shape. The fix is `x = A \ b`; reading it as "A under b" matches the equation $\mathbf{A}\mathbf{x} = \mathbf{b}$.

+++ question | Five hundred right-hand sides
--- ask
A calibration must solve $\mathbf{A}\mathbf{x} = \mathbf{b}$ for one 2000-by-2000 matrix `A` and 500 different right-hand sides. Version 1 loops and calls `A \ b` once per right-hand side. Version 2 puts the 500 right-hand sides as the columns of `B` and calls `X = A \ B` once, which factors `A` once and then does two triangle solves per column. Roughly how much less arithmetic does version 2 do?
--- choice
About the same, because each column still needs its own solve.
--- choice
About 3 times less, the same saving as backslash over `inv`.
--- choice correct
About 300 times less.
--- choice
Version 2 does more, because it solves a bigger system.
--- why
Factoring costs about $\tfrac{2}{3}n^3 = \tfrac{2}{3} \cdot 8 \times 10^9 \approx 5.3 \times 10^9$ operations, and each pair of triangle solves about $2n^2 = 8 \times 10^6$. Version 1 factors 500 times: about $500 \times 5.3 \times 10^9 \approx 2.7 \times 10^{12}$. Version 2 factors once and does 500 cheap solves: about $5.3 \times 10^9 + 500 \times 8 \times 10^6 \approx 9.3 \times 10^9$. The ratio is about 290. The factoring is the expensive part, so do it once.

=== mat01-l06 | Practice: Control flow and preallocation
--- for

+++ question | Tripling until it passes 100
--- ask
What is `steps` after this loop? Type the number.

```matlab
n = 1;
steps = 0;
while n < 100
    n = n * 3;
    steps = steps + 1;
end
```
--- answer
5
--- why
Each pass triples `n`: 3, 9, 27, 81, 243. After the fourth pass `n` is 81, still below 100, so the condition is true again and a fifth pass runs, making `n` 243. Now `n < 100` is false and the loop stops with `steps` at 5. A `while` tests its condition before every pass, never in the middle of one.

+++ question | A loop over a matrix
--- ask
What is `total` after this loop? Type the number.

```matlab
total = 0;
for col = [1 2 3; 4 5 6]
    total = total + col(2);
end
```
--- answer
15
--- why
A `for` loop walks through the columns of whatever sits after the `=`. This matrix has three columns, `[1; 4]`, `[2; 5]` and `[3; 6]`, so the loop runs three times, and each time `col(2)` is the bottom number: 4, 5 and 6. They add to 15. With a row vector each column is one number, which is why loops over `1:n` feel like Python; a matrix gives you whole columns.

+++ question | An if on a whole vector
--- ask
What does this print? Type the letter.

```matlab
v = [3 -1 4];
if v
    disp("A")
elseif any(v < 0)
    disp("B")
else
    disp("C")
end
```
--- answer
A
--- why
An `if` on an array is true when every element is nonzero. All three of 3, -1 and 4 are nonzero, so the first branch runs and prints A, even though one element is negative. Many readers expect B. Write `if all(v > 0)` or `if any(v < 0)` to say what you mean; then the test reads the way it behaves.

+++ question | Changing the loop counter
--- ask
What are `count` and `k` after this loop?

```matlab
count = 0;
for k = 1:5
    k = k + 10;
    count = count + 1;
end
```
--- choice
`count` is 1 and `k` is 11, because `k` jumped past the end of the range.
--- choice correct
`count` is 5 and `k` is 15.
--- choice
`count` is 5 and `k` is 5, because the change inside the body is undone.
--- choice
The loop stops with an error, because the loop variable may not be assigned.
--- why
Each pass takes the next value from the range `1:5`, whatever the body did to `k` on the previous pass. So the loop still runs five times and `count` is 5. On the last pass `k` starts as 5 and the body makes it 15, and that is the value left behind after the loop. Changing the loop variable is legal but confusing; use a different name for the changed value.

+++ question | A preallocated history that lies
--- ask
A simulation preallocates and fills a height history, stopping when the vehicle lands:

```matlab
maxSteps = 1000;
h = zeros(1, maxSteps);
h(1) = 100;
for k = 2:maxSteps
    h(k) = h(k-1) - 2.2;
    if h(k) <= 0
        break
    end
end
avgHeight = mean(h);
```

It lands at step 47, yet `avgHeight` comes out near 2.3 m, far too low. What is the bug?
--- choice
The loop should be a `while` loop; `break` does not work inside `for`.
--- choice correct
`h` still holds 953 unused zeros after the landing, and `mean` counts them. Trim with `h = h(1:k)` after the loop.
--- choice
`zeros(1, maxSteps)` should be `zeros(maxSteps)`, so there is room for every step.
--- choice
`h(k-1)` reads past the start of the array on the first pass.
--- why
Preallocating to a safe upper bound is right, but the slots the loop never wrote are still zeros, and they look like real heights. After `break`, `k` holds the last index written, so `h = h(1:k)` keeps only the flight. The true mean over the 47 samples is about 49 m. Filling with `NaN(1, maxSteps)` instead of zeros makes the problem visible, because `mean` then returns `NaN` instead of a wrong but believable number. `zeros(maxSteps)` would make a 1000-by-1000 matrix.

+++ question | Stopping at the right sample
--- ask
`fuel = [12 15 9 20 8]` is the propellant used in each burn, in kg. You want `k` to end as the burn at which the running total first passes 50 kg. Which loop leaves `k` equal to 4? All start with `total = 0;` and, for the `while` loops, `k = 0;`.

Loop A:

```matlab
while total <= 50 && k < numel(fuel)
    k = k + 1;
    total = total + fuel(k);
end
```

Loop B:

```matlab
for k = 1:numel(fuel)
    total = total + fuel(k);
    if total > 50
        continue
    end
end
```

Loop C:

```matlab
while total <= 50 || k < numel(fuel)
    k = k + 1;
    total = total + fuel(k);
end
```

Loop D:

```matlab
for k = 1:numel(fuel)
    if total > 50
        break
    end
    total = total + fuel(k);
end
```
--- choice correct
Loop A
--- choice
Loop B
--- choice
Loop C
--- choice
Loop D
--- why
The running total is 12, 27, 36, 56, so the answer is burn 4. Loop A stops as soon as the total passes 50, with `k` at 4, and its second test stops it at the last burn if the total never gets there. Loop B uses `continue`, which only skips the rest of one pass, so the loop runs to the end and leaves `k` at 5. Loop C joins its tests with or, so it keeps going while either is true and also ends at 5. Loop D checks before adding, so it notices the total one pass late and breaks with `k` at 5: an off-by-one.

+++ question | Rates from a struct array
--- ask
What does the last line give? Type the number.

```matlab
s = struct('name', {'IMU', 'GPS', 'Baro'}, 'rate', {200, 10, 50});
max([s.rate]) - min([s.rate])
```
--- answer
190
--- why
Passing cell arrays to `struct` makes one element per cell, so `s` is a 1-by-3 struct array. `s.rate` produces one value per element, and the square brackets gather them into the numeric row `[200 10 50]`. Its largest value minus its smallest is $200 - 10 = 190$.

+++ question | Braces, then an index
--- ask
What is the value of the last line? Type the number.

```matlab
c = {'LOX', [1 2 3], 9.81};
v = c{2};
v(end) + numel(c)
```
--- answer
6
--- why
Braces take out the contents of a cell, so `v` is the numeric row `[1 2 3]` and `v(end)` is 3. `numel(c)` counts the cells, not what is inside them: there are 3. So the answer is $3 + 3 = 6$. Had the second line been `v = c(2)`, `v` would be a 1-by-1 cell, and `v(end) + 3` would fail, because arithmetic is not defined for cells.

+++ question | High and not boosting
--- ask
A table `T` has seven rows. Its `alt` column is `[2; 8; 15; 24; 31; 29; 22]` (km) and its `phase` column is categorical, holding boost, boost, boost, coast, coast, descent, descent. What does this give? Type the number.

```matlab
nnz(T.alt > 20 & T.phase ~= 'boost')
```
--- answer
4
--- why
`T.alt > 20` is true for rows 4 to 7 (24, 31, 29, 22). `T.phase ~= 'boost'` is also true for rows 4 to 7, because a categorical compares with text by its label. The element-wise `&` keeps rows where both hold: rows 4, 5, 6 and 7, so `nnz` counts 4. This is logical indexing from lesson 3, working on table columns because `T.alt` and `T.phase` are ordinary column arrays.

+++ question | Joining char and joining strings
--- ask
What is `numel(x) + numel(y)`? Type the number.

```matlab
x = ['ab' 'cde'];
y = ["ab" "cde"];
```
--- answer

Square brackets around strings make a string array with one element per piece of text: `["ab" "cde"]` is 1-by-2, so 2. The total is 7. `strlength(y)` would give `[2 3]`, the letters in each string.

+++ question | A comparison that only fails sometimes
--- ask
A logging function holds this test, where `sensor` is a char array such as `'imu'`, `'gps'` or `'baro'`:

```matlab
if sensor == 'gps'
    rate = 10;
end
```

It works for `'imu'` and `'gps'` but stops with an error for `'baro'`. Why, and what is the fix?
--- choice
`'baro'` is not a valid MATLAB name. Rename the sensor.
--- choice correct
`==` on char compares letter by letter, so the two sides must have the same length, and `'baro'` has 4 letters. Use `strcmp(sensor, 'gps')`, or store the names as strings.
--- choice
`if` cannot test text. Convert with `double(sensor)` first.
--- choice
`if` cannot test a whole array. Write `if all(sensor == 'gps')`.
--- why
A char array is an array of letters, so `'imu' == 'gps'` compares three pairs and gives `[0 0 0]`, which `if` reads as false. `'baro' == 'gps'` has four letters against three, and MATLAB stops with a size error. `strcmp` compares two pieces of text of any length and returns one true-or-false value. With strings in double quotes, `==` compares whole pieces of text. Wrapping the test in `all` changes nothing, because the size error happens inside `==` before `all` runs.

+++ question | Scaling every field by name
--- ask
What is `p.cd` after these lines? Type the number.

```matlab
p.mass = 1200;
p.cd = 0.3;
p.area = 1.1;
f = fieldnames(p);
for k = 1:numel(f)
    p.(f{k}) = 2 * p.(f{k});
end
```
--- answer
0.6
0.6000
.6
--- why
`fieldnames(p)` returns a 3-by-1 cell array of the field names as text. `f{k}` takes out the k-th name with braces, and `p.(name)` reaches the field whose name is stored in that text, a dynamic field name. So the loop doubles every field in turn: `mass` becomes 2400, `cd` becomes 0.6 and `area` becomes 2.2. Writing `p.(f(k))` with round brackets would fail, because it passes a cell, not text.

+++ question | Zeros in front
--- ask
What text does `sprintf('%06.2f', 3.14159)` return? Type it without quotes.
--- answer
003.14
--- why
`%06.2f` means a fixed-point number with 2 decimals, at least 6 characters wide, padded with zeros instead of spaces. Rounded to 2 decimals the number is `3.14`, which is 4 characters, counting the decimal point. Two zeros in front make it 6 wide: `003.14`. The width counts every character, not only the digits before the point.

+++ question | One blank, a matrix of values
--- ask
What does this print? Type it exactly, with no spaces.

```matlab
fprintf('%d,', [1 2 3; 4 5 6])
```
--- answer
1,4,2,5,3,6,
--- why
The format spec has one blank, so `fprintf` recycles it once per value, and it reads a matrix in column-major order: down column 1 (1, 4), then column 2 (2, 5), then column 3 (3, 6). Each value is followed by the comma from the template, including the last, and nothing adds a new line. To print the rows in reading order, pass the transpose.

+++ question | Two ways to load
--- ask
What are `a` and `b` after these lines?

```matlab
t = 1:5;
save('run.mat', 't')
t = 0;
S = load('run.mat');
a = numel(t);
load('run.mat')
b = numel(t);
```
--- choice
`a` is 5 and `b` is 5, because both loads bring back the saved `t`.
--- choice correct
`a` is 1 and `b` is 5.
--- choice
`a` is 1 and `b` is 1, because `load` never replaces a variable that already exists.
--- choice
`a` is 5 and `b` is 1.
--- why
`S = load('run.mat')` puts the file's variables into the struct `S`, so the saved row is `S.t` and the workspace `t` is still 0, one element. The bare `load('run.mat')` pours the file's variables straight into the workspace, replacing `t` with the 5-element row without a word. +++ question | More values than a whole pass
--- ask
What does `fprintf('%d %d\n', [1 2 3])` print?
--- choice
`1 2` on one line, then `3 0` on the next, because the missing value is filled with zero.
--- choice correct
`1 2` on one line, then `3` on the next with no new line after it, so the next output continues on that line.
--- choice
Only `1 2`, because the 3 does not fill a whole pass and is dropped.
--- choice
An error, because the number of values is not a multiple of the number of blanks.

`fprintf` recycles the template until the values run out. The first pass uses 1 and 2 and ends with `\n`. +++ question | A number glued into char text
--- ask
A report line is built like this:


`Apogee: 152.43 m`. It works, because square brackets turn numbers into text.

+++ question | A log file with one run in it
--- ask
A script writes three runs to one log file:

```matlab
for run = 1:3
    fid = fopen('campaign_log.txt', 'w');
    fprintf(fid, 'run %d: miss %.1f m\n', run, miss(run));
    fclose(fid);
end
```

Afterwards the file holds only the line for run 3. Why, and what is the fix?
--- choice
`fclose` deletes the file's contents. Leave it out.
--- choice correct
Opening with `'w'` replaces any old file, so each pass throws away the previous line. Open the file once before the loop and close it once after.
--- choice
`fprintf` to a file always overwrites. Use `sprintf` instead.
--- choice
The format spec needs `\t` instead of `\n` so the lines are kept apart.

The `'w'` mode means write, replacing any old file, and it acts every time `fopen` runs. Opening and closing inside the loop therefore empties the file three times, and only the last line survives. === mat01-l09 | Practice: Scripts, functions and workspaces

+++ question | A function that changes its input
--- ask
The file `triple.m` holds:

```matlab
function y = triple(x)
    x = 3 * x;
    y = x + 1;
end
```

At the prompt you type `x = 2; y = triple(x);`. What is `x + y` now? Type the number.
--- answer
9
--- why
The function gets its own workspace with its own `x`, a copy of the value 2. It changes that copy to 6 and returns $6 + 1 = 7$. The caller's `x` is untouched and still 2. So `x + y` is $2 + 7 = 9$. Having the same name inside and outside the function does not link the two variables.

+++ question | Catching one output of two
--- ask
The file `lowHigh.m` holds:

```matlab
function [lo, hi] = lowHigh(v)
    lo = min(v);
    hi = max(v);
end
```

What is `r` after `r = lowHigh([4 9 1])`? Type the number.
--- answer
1
--- why
A function with several outputs hands them back in the order the declaration lists them. When the caller asks for only one, it gets the first, `lo`, the smallest value: 1. To get only the second, write `[~, r] = lowHigh([4 9 1])`, where the tilde skips the first output.

+++ question | A struct passed to a function
--- ask
The file `setMass.m` holds:

```matlab
function p = setMass(p, m)
    p.mass = m;
end
```

A script runs:

```matlab
cfg.mass = 100;
setMass(cfg, 250);
disp(cfg.mass)
```

What does it print? Type the number.
--- answer
100
--- why
A struct is passed by value, like an array. The function changes its own copy and returns it, but the script never assigns the result, so the change is lost. `cfg` still holds 100. The fix is `cfg = setMass(cfg, 250);`. A Python programmer expects the dictionary-like struct to change in place; in MATLAB it does not.

+++ question | Two inputs, one expression
--- ask
What does the last line give? Type the numbers separated by spaces.

```matlab
g = @(x, y) x.^2 - y;
g(3, [1 2])
```
--- answer
8 7
[8 7]
8, 7
--- why
The anonymous function takes two inputs. With `x` equal to 3 and `y` equal to `[1 2]`, it computes $3^2 = 9$ and subtracts each element of `y`: $9 - 1 = 8$ and $9 - 2 = 7$. A scalar minus a row works element by element, so the answer is the row `[8 7]`.

+++ question | A handle that calls a handle
--- ask
What does the last line give? Type the number.

```matlab
f = @(x) x + 1;
g = @(x) f(x) * 2;
f = @(x) x + 100;
g(1)
```
--- answer
4
--- why
When `g` is made, it captures the value of every outside variable it mentions, and `f` is one of them. At that moment `f` is the handle that adds 1. Making a new `f` later changes the workspace variable, not the copy inside `g`. So `g(1)` is $(1 + 1) \times 2 = 4$, not $(1 + 100) \times 2 = 202$. A handle is a value like any other, and it is captured the same way.

+++ question | Why arrayfun forgives a missing dot
--- ask
`arrayfun(@(k) k^2, 1:4)` returns `[1 4 9 16]`, but `integral(@(t) t^2, 0, 1)` stops with an error. Why the difference?
--- choice
`arrayfun` adds the missing dot to the expression for you.
--- choice correct
`arrayfun` calls the handle once per element, so `k` is always one number and `k^2` is fine. `integral` calls it with a whole vector of points at once, and the matrix power of a row is not defined.
--- choice
`integral` only accepts handles to functions stored in files.
--- choice
`k` and `t` are treated differently because `t` is reserved for time.
--- why
The expression `k^2` is a matrix power, which is fine for a single number and an error for a row. `arrayfun` feeds the elements in one at a time and collects the answers, so it never passes a row. `integral` passes many points in one call for speed and expects one answer per point back. Writing `.^` inside anonymous functions makes the same handle work in both places.

+++ question | A handle made too early
--- ask
A script runs these lines in this order:

```matlab
qfun = @(v) 0.5 * rho * v.^2;
rho = 1.225;
qfun(100)
```

What happens on the last line?
--- choice
It returns 6125, because `rho` exists by the time the handle is called.
--- choice correct
It stops with "Unrecognized function or variable 'rho'", because `rho` did not exist when the handle was made.
--- choice
It returns 0, because a missing variable counts as zero.

An anonymous function captures values at the moment it is made. When the first line ran there was no variable `rho`, so MATLAB took `rho` to be the name of a function to look up later. +++ question | A gain sweep that sweeps nothing
--- ask
A script tries three controller gains:

```matlab
Kp = 0.8;
ctrl = @(e) Kp * e;
gains = [0.5 1.0 2.0];
u = zeros(1, 3);
for k = 1:3
    Kp = gains(k);
    u(k) = ctrl(2);
end
```

It prints `u = 1.6 1.6 1.6`. What is wrong, and what is a fix?
--- choice
`u` should be grown with `u(end+1)` instead of preallocated.
--- choice
The loop variable `k` hides the gain. Rename it.
--- choice correct
`ctrl` captured `Kp = 0.8` when it was made, and changing `Kp` later does not reach it. Build `ctrl` inside the loop after setting `Kp`, or make the gain an input: `ctrl = @(e, Kp) Kp * e`.

`Kp * e` needs a dot, `Kp .* e`, to use the new gain.

Every call to `ctrl` uses the captured 0.8, so each result is $0.8 \times 2 = 1.6$. There is no error and no warning, which is what makes this bug dangerous in a trade study. Rebuilding the handle after each change, or passing the gain in explicitly, makes every call say which gain it means. The preallocation and the loop are fine.

+++ question | An accumulator with two handles
--- ask
The file `makeAcc.m` holds:

```matlab
function [inc, get] = makeAcc()
    total = 0;
    inc = @add;
    get = @report;
    function add(x)
        total = total + x;
    end
    function t = report()
        t = total;
    end
end
```

What does the last line give? Type the number.

```matlab
[inc, get] = makeAcc();
inc(5);
inc(2);
[inc2, get2] = makeAcc();
inc2(100);
get()
```
--- answer
7
--- why
`add` and `report` are nested functions, so their handles share the parent's workspace and keep it alive after `makeAcc` returns. The first call to `makeAcc` makes one workspace with its own `total`; `inc` adds 5 and then 2, and `get` reads the same `total`: 7. The second call makes a separate workspace with a separate `total`, so `inc2(100)` does not touch the first one. Nested handles share live variables; anonymous handles copy values.

+++ question | Copying a value object
--- ask

--- why
A value class copies on assignment, like a number. `b = a` makes an independent object, and setting `b.x` changes only that copy. `a.x` stays 1. With a handle class, `b` would be a second name for the same object and `a.x` would be 5.

+++ question | Four workers on a 90 percent loop
--- ask

--- ask
Which of these loops can **not** be written as a `parfor`?

--- why
`applyTo` has its own workspace and cannot see the script's `g0`. It does not need to: when `w` was made, it captured the value 9.81 inside itself. The handle arrives as an ordinary input and carries its captured value with it, so `f(100)` is $100 \times 9.81 = 981$. This is how solvers such as `fzero` and `ode45` get your parameters without you passing them one by one.

+++ question | Handles made in a loop
--- ask
What does the last line give? Type the number.

```matlab
hs = cell(1, 3);
gain = 1;
for k = 1:3
    gain = gain * 2;
    hs{k} = @(x) gain * x + k;
end
gain = 100;
h = hs{2};
h(1)
```
--- answer
6
--- why
Each handle captures the current values of `gain` and `k` when its line runs. On the second pass `gain` has been doubled twice, to 4, and `k` is 2, so `hs{2}` computes $4x + 2$. Setting `gain` to 100 after the loop changes only the workspace. So `h(1)` is $4 + 2 = 6$. In Python, three lambdas made the same way would all see the final values.

+++ question | Defaults and an option
--- ask
The file `pad.m` holds:

```matlab
function out = pad(x, n, opts)
    arguments
        x (1,:) double
        n (1,1) double {mustBeInteger, mustBeNonnegative} = 2
        opts.Value (1,1) double = 0
    end
    out = [x, opts.Value * ones(1, n)];
end
```

What is `sum(pad([1 2 3], Value=7))`? Type the number.
--- answer
20
--- why
The call gives `x` and the option `Value`, but not `n`, so `n` takes its default of 2. `opts.Value * ones(1, 2)` is `[7 7]`, and joining it after `x` makes `[1 2 3 7 7]`. The sum is $6 + 14 = 20$. Name-value options come after the positional inputs, so leaving out `n` does not make MATLAB read `Value` as `n`.

+++ question | Hits counted by value and by handle
--- ask
A class and a function:

```matlab
classdef Tracker
    properties
        Hits = 0
    end
    methods
        function obj = hit(obj)
            obj.Hits = obj.Hits + 1;
        end
    end
end
```

```matlab
function t = processAll(t, n)
    for k = 1:n
        t.hit();
    end
end
```

What is `t.Hits` after `t = processAll(Tracker(), 3);`? And what would it be if the first line were `classdef Tracker < handle`, with nothing else changed?
--- choice
3 and 3.
--- choice correct
0 as written, and 3 as a handle class.
--- choice
3 as written, and 0 as a handle class.
--- choice
0 and 0, because `processAll` returns its input unchanged.
--- why
As a value class, `t.hit()` works on a copy and returns the changed copy, which nobody assigns, so every call is lost and `processAll` returns an object with 0 hits. Inside a function this silent loss is easy to miss. As a handle class, `t` is a reference, so each `t.hit()` changes the one shared object even though its return value is ignored, and the returned `t` reaches that same object with 3 hits. For the value class, the loop body must be `t = t.hit();`.

+++ question | A clamp with no loop
--- ask
This loop clamps a signal `x` to the band from `-L` to `L` and counts how many samples it had to change:

```matlab
y = zeros(size(x));
n = 0;
for k = 1:numel(x)
    if abs(x(k)) > L
        n = n + 1;
    end
    y(k) = min(max(x(k), -L), L);
end
```

Which vectorized pair gives the same `y` and `n`?
--- choice
`y = x; y(abs(x) > L) = L;` and `n = nnz(abs(x) > L);`
--- choice correct
`y = min(max(x, -L), L);` and `n = nnz(abs(x) > L);`
--- choice
`y = min(max(x, -L), L);` and `n = sum(abs(x) >= L);`
--- choice
`y = min(max(x, -L), L);` and `n = numel(find(x > L));`
--- why
`max` and `min` work element by element on a whole array against a scalar, so one line clamps every sample. `abs(x) > L` marks the samples outside the band, and `nnz` counts them. The first choice sets clipped negative samples to `+L`, losing their sign. `>=` also counts samples sitting exactly on the limit, which the loop did not change. `find(x > L)` misses the samples below `-L`.

+++ question | More workers for the same script
--- ask
A campaign script spends 30% of its time reading CSV files, which cannot be split, and 70% in a `parfor` loop. You move from 8 workers to 64. What happens to the speedup?
--- choice
It goes from about 8 to about 64 times.
--- choice
It goes from about 5.6 to about 45 times.
--- choice correct
It goes from about 2.6 to about 3.2 times, and can never pass about 3.3; the CSV reading is the part to attack.
--- choice
It gets worse, because more workers always slow a script down.
--- why
Amdahl's law with $p = 0.7$: for 8 workers $S = 1/(0.3 + 0.7/8) = 1/0.3875 \approx 2.6$, and for 64 workers $S = 1/(0.3 + 0.7/64) \approx 1/0.311 \approx 3.2$. The limit is $1/0.3 \approx 3.3$. Eight times the workers bought about 25% more speed. Profiling the serial 30% and shrinking it, for example by saving the parsed data once in a `.mat` file, is worth far more.

+++ question | Lining up a slow sensor by interpolation
--- ask
Timetable `A` has row times 0, 1, 2 and 3 seconds. Timetable `B` has two rows: 10 at 0.4 seconds and 30 at 1.9 seconds. In `C = synchronize(A, B, 'first', 'linear')`, what is `B`'s value in the row at 1 second? Type the number.
--- answer
18
--- why
`'first'` keeps `A`'s row times, and `'linear'` draws a straight line between `B`'s neighboring samples. From 0.4 s to 1.9 s the value climbs 20 over 1.5 s. At 1 s, 0.6 s have passed, which is $0.6 / 1.5 = 0.4$ of the way, so the value is $10 + 0.4 \times 20 = 18$. With `'previous'` the row would hold 10, the latest sample at or before 1 s, and with `'nearest'` also 10, since 0.4 s is closer than 1.9 s.

+++ question | A band with a gap in it
--- ask
A quick-look figure shades the stretch where dynamic pressure `q` is at or above a limit `L`:

```matlab
tb = [t(find(q >= L, 1)), t(find(q >= L, 1, 'last'))];
xregion(ax(k), tb(1), tb(2));
```

On one flight, `q` is above the limit from 10 s to 20 s, dips below it, and rises above it again from 30 s to 35 s. What does the figure show?
--- choice
Two bands, 10 to 20 s and 30 to 35 s, because `find` returns every stretch.
--- choice correct
One band from 10 s to 35 s, which wrongly shades the dip between 20 s and 30 s.
--- choice
One band from 10 s to 20 s, because `find` stops at the first stretch.

Nothing, because `find` with `'last'` returns an empty result when there are two stretches.

+++ question | A script that works once
--- ask
A driver script, run from the prompt, contains these lines:

```matlab
data = [3 7 5];
max = max(data);
fprintf('peak %d\n', max);
```

The first run prints `peak 7`. Running the script a second time, in the same session, stops with an error on the second line. Why?
--- choice
`fprintf` changed `data` during the first run.
--- choice correct
The first run left a variable called `max` in the base workspace. On the second run `max(data)` means indexing that variable with 3, 7 and 5, and it has only one element.
--- choice
A script can only be run once per session unless it starts with `clear`.
--- choice
`max` is a reserved word, so the line is always illegal; the first run only worked by luck.
--- why
A script runs in the base workspace, so every variable it makes stays there afterwards. On the first run `max` was still the built-in function. The assignment then created a variable `max` holding 7, and variables come before functions when MATLAB looks up a name. On the second run `max(data)` asks for elements 3, 7 and 5 of a 1-by-1 variable, which is an index error. Name the result `peak` instead; running the script after `clear` would also have exposed the problem at once.

+++ question | A transposed table of pairs
--- ask
What is the second line this prints? Type it exactly.

```matlab
fprintf('%d-%d\n', [1 2 3; 4 5 6]')
```
--- answer
3-4
--- why
The transpose makes the 3-by-2 matrix `[1 4; 2 5; 3 6]`. `fprintf` reads it in column-major order: 1, 2, 3, then 4, 5, 6. The template takes two values per pass, so the lines are `1-2`, `3-4` and `5-6`. The transpose trick prints one line per original row only when the template has as many blanks as the matrix has columns. Here the rows have 3 numbers and the template takes 2, so the pairs run across the rows.
