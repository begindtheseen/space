+++ practice | Time to stop
--- task
A lander descends at a speed `v` in m/s and brakes with a steady deceleration of `decel_g` times standard gravity. The time it takes to stop is

t = v / (decel_g × g0), with g0 = 9.80665 m/s².

Write the whole program:

- a `constexpr double kG0 = 9.80665;` at file scope, outside any function;
- a function `double stop_time(double v, double decel_g)` that returns t in seconds;
- a `main` that calls `stop_time` twice and prints exactly these two lines, with `std::printf` and two decimals:

```
200 m/s at 3 g: 6.80 s
90 m/s at 1.5 g: 6.12 s
```

Work both times out with `stop_time`. Do not type 6.80 or 6.12 into the program.
--- starter
#include <cstdio>

// Define kG0 and stop_time here.

int main() {
    return 0;
}
--- solution
#include <cstdio>

constexpr double kG0 = 9.80665;  // standard gravity, m/s^2

// Time to go from speed v to rest at a steady decel_g times g0.
double stop_time(double v, double decel_g) {
    return v / (decel_g * kG0);
}

int main() {
    std::printf("200 m/s at 3 g: %.2f s\n", stop_time(200.0, 3.0));
    std::printf("90 m/s at 1.5 g: %.2f s\n", stop_time(90.0, 1.5));
    return 0;
}
--- hint
A function must be declared before the line that calls it, so write `stop_time` above `main`.
--- hint
`%.2f` in a `printf` format prints a `double` with two decimals. The rest of the line is plain text.
--- check output | Prints both stop times
200 m/s at 3 g: 6.80 s
90 m/s at 1.5 g: 6.12 s
--- check source | Defines stop_time
double\s+stop_time\s*\(
--- check source absent | Works the times out instead of typing them

+++ practice | Inputs that make no sense
--- task
Guidance calls `stop_distance` with values that come from sensors, so it must cope with nonsense instead of returning infinity or a negative distance.

Write `double stop_distance(double v, double decel_g)` returning v² / (2 × decel_g × g0), with g0 = 9.80665, except:

- if `decel_g` is zero or negative, the vehicle cannot stop: return `-1.0`;
- if `v` is negative, the reading is bad: return `-1.0`;
- if `v` is exactly 0 (and `decel_g` is positive), return `0.0`.

For example, `stop_distance(200.0, 3.0)` is about 679.81 and `stop_distance(50.0, 0.0)` is `-1.0`.
--- starter
double stop_distance(double v, double decel_g) {
    return 0.0;
}
--- solution
constexpr double kG0 = 9.80665;  // standard gravity, m/s^2

// Braking distance, or -1.0 when the inputs cannot describe a stop.
double stop_distance(double v, double decel_g) {
    if (decel_g <= 0.0 || v < 0.0) return -1.0;
    return v * v / (2.0 * decel_g * kG0);
}
--- hint
Check the bad cases first and return early. The formula comes last.
--- hint
When `v` is 0 the formula already gives 0.0, so it needs no case of its own once the bad inputs are handled.
--- check test | stop_distance(200.0, 3.0) is about 679.81

=> -1.0
--- check case | A negative speed is a bad reading

+++ practice | A macro that squares the wrong thing
--- task
This program works out the braking distance from the speed over the ground, which is the airspeed minus the wind speed. For 210 m/s into a 10 m/s wind at 3 g, and for 60 m/s with no wind at 1 g, it should print:

```
679.8 m
183.5 m
```

Instead it prints `-32.3 m` and `3.1 m`. The fault is in the one line that begins with `#`. Remember what the preprocessor does with a macro before the compiler sees any of it. Fix the program so it prints the right two lines. You may fix the macro, or replace it with an ordinary function.
--- starter
#include <cstdio>

#define SQ(x) x * x

constexpr double kG0 = 9.80665;  // standard gravity, m/s^2

// Braking distance at decel_g, using the speed over the ground.
double stop_distance_wind(double v_air, double v_wind, double decel_g) {
    return SQ(v_air - v_wind) / (2.0 * decel_g * kG0);
}

int main() {
    std::printf("%.1f m\n", stop_distance_wind(210.0, 10.0, 3.0));
    std::printf("%.1f m\n", stop_distance_wind(60.0, 0.0, 1.0));
    return 0;
}
--- solution
#include <cstdio>

constexpr double kG0 = 9.80665;  // standard gravity, m/s^2

// A function, not a macro: its argument is worked out once, before the multiply.
constexpr double sq(double x) { return x * x; }

// Braking distance at decel_g, using the speed over the ground.
double stop_distance_wind(double v_air, double v_wind, double decel_g) {
    return sq(v_air - v_wind) / (2.0 * decel_g * kG0);
}

int main() {
    std::printf("%.1f m\n", stop_distance_wind(210.0, 10.0, 3.0));
    std::printf("%.1f m\n", stop_distance_wind(60.0, 0.0, 1.0));
    return 0;
}
--- hint
The preprocessor pastes text. Write out by hand what `SQ(v_air - v_wind)` turns into, then apply the usual order of operations.
--- hint
`SQ(v_air - v_wind)` becomes `v_air - v_wind * v_air - v_wind`. Either put brackets around each `x` and around the whole body, `((x) * (x))`, or use a `constexpr` function.
--- check output | Prints both braking distances
679.8 m
183.5 m

+++ practice | The gentlest deceleration that fits
--- task
Braking hardware can be set to 1, 2, 3, 4, 5 or 6 g. Write `int min_whole_g(double v, double alt)` that returns the smallest of those settings whose braking distance from speed `v` fits within `alt` metres, or `0` if even 6 g is not enough.

- The braking distance at `g` is v² / (2 × g × g0), with g0 = 9.80665.
- A distance equal to `alt` fits.
- A lander already at rest (`v` is 0) fits at 1 g, whatever `alt` is, including 0.

For example, from 200 m/s: with 700 m left, 2 g needs 1019.7 m and 3 g needs 679.8 m, so the answer is 3. With 300 m left even 6 g needs 339.9 m, so the answer is 0.
--- starter
int min_whole_g(double v, double alt) {
    return -1;
}
--- solution
constexpr double kG0 = 9.80665;  // standard gravity, m/s^2

double stop_distance(double v, double decel_g) {
    return v * v / (2.0 * decel_g * kG0);
}

// Smallest setting from 1 to 6 g that stops within alt, or 0 if none does.
int min_whole_g(double v, double alt) {
    for (int g = 1; g <= 6; ++g) {
        if (stop_distance(v, g) <= alt) return g;
    }
    return 0;
}
--- hint
Try the settings in order, from 1 up, and return the first one that fits. If the loop ends, none fitted.
--- hint
A helper function for the braking distance keeps the loop short. Compare with `<=`, because a distance equal to `alt` fits.

+++ question | Warnings that stop the build
--- ask
A build of `nav.cpp` ends with this line, and no program is made:

```text
cc1plus: all warnings being treated as errors
```

Which is the right reading of it?
--- choice
The linker found a name defined twice, and `-Werror` made that fatal.
--- choice correct
The compiler found things that are legal C++ but look wrong, reported them as warnings, and `-Werror` turned them into a failed build.
--- choice
The preprocessor could not find a header, so the compiler never started.
--- choice
The source has a syntax error, and `-Werror` is what makes syntax errors stop the build.
--- why
The prefix names the stage: `cc1plus` is the compiler proper, and "warnings being treated as errors" is what `-Werror` prints. The file is legal C++, so without `-Werror` it would have built. A missing header or a syntax error is a plain error that stops the build with or without `-Werror`, and a problem with names defined twice comes from the linker, whose messages start with `/usr/bin/ld`.

+++ question | Which commands link
--- ask
Here are four commands, all run on the same file:

```bash
g++ -std=c++20 -E thrust.cpp -o thrust.ii
g++ -std=c++20 -S thrust.cpp -o thrust.s
g++ -std=c++20 -c thrust.cpp -o thrust.o
g++ -std=c++20 thrust.cpp -o thrust
```

How many of them run the linker? Type the number.
--- answer
1
one
--- why
`-E` stops after the preprocessor, `-S` after the compiler, and `-c` after the assembler. Only the last command, with none of those flags, runs all four stages, so only it runs the linker and makes a program. That is also why a missing definition shows up only in the last one: the first three never try to match names across files.

--- task
Two functions share one packet counter. They are written near the top of the file, but the counter itself must be **defined** further down, below them, the way a variable in another source file would be.

- Near the top, above both functions, write a declaration of an `int` called `g_packet_count` that says "this exists, its memory is elsewhere".
- Write `int send_packet()`, which adds one to `g_packet_count` and returns the new value.
- Write `int packets_sent()`, which returns `g_packet_count` without changing it.
- Below both functions, define `g_packet_count` exactly once, starting at 0.

The checks call `send_packet()` twice, then `packets_sent()`, and expect 1, 2 and 2.
--- starter
// Declare g_packet_count here.

    return 0;
}

    return 0;
}

// Define g_packet_count here.

// A declaration: the variable exists, and its one definition is further down.
extern int g_packet_count;

int send_packet() {
    return ++g_packet_count;

int g_packet_count = 0;

+++ practice | A header's inline helper and a file's private one
--- task
Write the code of one small source file, in the style lesson 02 recommends.

- `inline double clamp_throttle(double cmd)`: returns `cmd` limited to the range 0.0 to 1.0. It is written `inline` because it would live in a header included by many files.
- A helper `bool out_of_range(double cmd)` that is true when `cmd` is below 0.0 or above 1.0. It is private to this file, so put it in an **anonymous namespace**.
- `int count_clamped(double a, double b, double c)`: returns how many of the three commands `clamp_throttle` would change. Use `out_of_range`.

For example, `clamp_throttle(1.4)` is 1.0, `clamp_throttle(-0.2)` is 0.0, and `count_clamped(0.5, 1.2, -0.1)` is 2. The ends of the range are in it: `count_clamped(0.0, 1.0, 0.5)` is 0.
--- starter
inline double clamp_throttle(double cmd) {
    return cmd;
}

int count_clamped(double a, double b, double c) {
    return 0;
}
--- solution
inline double clamp_throttle(double cmd) {
    if (cmd < 0.0) return 0.0;
    if (cmd > 1.0) return 1.0;
    return cmd;
}

namespace {
// Internal linkage: no other file can see this, so no other file can collide with it.
bool out_of_range(double cmd) { return cmd < 0.0 || cmd > 1.0; }
}  // namespace

int count_clamped(double a, double b, double c) {
    int n = 0;
    if (out_of_range(a)) ++n;
    if (out_of_range(b)) ++n;
    if (out_of_range(c)) ++n;
    return n;
}
--- hint
An anonymous namespace is written `namespace { ... }`, with no name. Everything inside it is visible in this file only.
--- hint
`count_clamped` can start a count at 0 and add one for each command that `out_of_range` says is outside the limits.
--- check case | clamp_throttle(1.4)

--- check case | clamp_throttle(-0.2)
clamp_throttle(-0.2)
=> 0.0
--- check case | clamp_throttle(0.35)

+++ question | Which lines break the link
--- ask
This header is included by both `engine.cpp` and `main.cpp`, and the two are linked into one program:

```cpp
// engine.hpp
#pragma once

struct Gains { double kp, ki, kd; };             // line A
inline double clamp_u(double u) {                // line B
    return u > 1.0 ? 1.0 : (u < -1.0 ? -1.0 : u);
}
constexpr double kDt = 0.01;                     // line C
double gain_sum(const Gains& g) {                // line D
    return g.kp + g.ki + g.kd;
}
int g_engine_mode = 0;                           // line E
```

Both files compile. Which lines make the link fail with "multiple definition"?
--- choice
A and D: a struct and a function may only be defined once in the whole program.
--- choice correct
D and E: a function without `inline` and a variable the linker can see, each now defined in two object files.
--- choice
None: `#pragma once` makes sure the header is only compiled once.
--- choice
B, D and E: every function or variable defined in a header breaks the link.
--- why
Each `.cpp` is its own translation unit and gets its own copy of the header's text. `#pragma once` only stops a second copy *inside one* translation unit. A struct is a type, not a symbol, and may be defined in every translation unit that needs it (A). `inline` lets the linker keep one of several identical definitions (B). A `constexpr` variable at file scope has internal linkage, so each file has a private copy (C). That leaves D, an ordinary function, and E, an ordinary variable: two strong definitions each, and the linker refuses.

+++ question | A static counter in a header
--- ask
`seq.hpp` contains exactly one line:

```cpp
static int g_seq = 0;
```

`radio.cpp` includes it and defines `int radio_next() { return ++g_seq; }`. `main.cpp` includes it too, and contains:

```cpp
int radio_next();

int main() {
    radio_next();
    radio_next();
    ++g_seq;
    int last = radio_next();
    std::printf("%d %d\n", last, g_seq);
}
```

The two files are compiled and linked together. What does it print? Type the two numbers with a space between them.
--- answer
3 1
3, 1
--- why
`static` at file scope gives the variable internal linkage: each translation unit that includes the header gets its own private `g_seq`. `radio_next` bumps the one in `radio.cpp` to 1, 2 and then 3. `++g_seq` in `main` bumps a different object, the one in `main.cpp`, from 0 to 1. Nothing collides and nothing warns. To share one counter, the header would declare `extern int g_seq;` and one `.cpp` would define it, or the header would say `inline int g_seq = 0;`.

+++ question | Where the library goes
--- ask
`libnav.a` holds `nav.o`, which defines `predict(State const&, double)`. `main.o` calls `predict`. Which command links?
--- choice
`g++ -L. -lnav main.o -o app`, because libraries must be named before the files that use them.
--- choice correct
`g++ main.o -L. -lnav -o app`, because the linker reads left to right and takes from a library only what is already missing.
--- choice
Both, because the linker reads every file twice.
--- choice
Neither: a static library can only be used with `-c`.
--- why
The linker scans its arguments once, left to right, keeping a list of missing symbols. When it reaches a static library, it takes out only the members that supply something on that list. +++ question | What the standard promises
--- ask

--- choice
`int` is 32 bits.
--- choice

--- why
The standard sets only minimum widths and an order: `int` at least 16 bits, `long` at least 32, and each type at least as wide as the one before. --- ask
What happens with this line?

```cpp

```
--- choice
It compiles, and `x` holds -56, because since C++20 the value wraps modulo 256.
--- choice correct
It does not compile: braces refuse a narrowing conversion of a constant that does not fit.
--- choice
It compiles, and `x` holds 200, because the braces widen the type to fit.
--- choice
It compiles, but reading `x` is undefined behavior.
--- why
With `=`, as in `std::int8_t x = 200;`, the value is converted and `x` holds 200 - 256 = -56, with at most a warning. constexpr unsigned isqrt(unsigned n) {

        if (mid * mid <= n) lo = mid;

}

+++ question | When constexpr is not enough
--- ask
A function validates a telemetry identifier and rejects any value that does not fit in 11 bits. It is written `constexpr`. Why might a reviewer ask for `consteval` instead?
--- choice
`consteval` functions run faster than `constexpr` functions at run time.
--- choice correct
A `constexpr` function quietly runs at run time when its argument is not a constant, so the check could happen in flight. `consteval` makes any such call a compile error.
--- choice
`constexpr` functions cannot contain an `if`, so the range check needs `consteval`.
--- choice
`consteval` makes the result `const`, so nobody can change the identifier afterwards.
--- why
A `constexpr` function is *allowed* to run at compile time, and falls back to an ordinary call when its arguments are only known at run time. For a check whose whole point is to stop the build, that fall-back is a hole: a bad value arriving at run time would be caught, if at all, on the vehicle. A `consteval` function has no run-time form, so every call must be worked out by the compiler. Both kinds may use `if` and loops, and neither says anything about whether the result can be changed later.

+++ practice | A controller step with no kick
--- task
Write one step of a proportional-derivative controller:

`double pd_step(double error, double& prev_error, bool& first, double kp = 2.0, double kd = 0.1, double dt = 0.01)`

It returns `kp * error + kd * derivative`, where the derivative is `(error - prev_error) / dt`. It keeps its memory in the caller's variables, and must handle these cases:

- On the **first** call (`first` is true) there is no previous error, so the derivative is 0. Then set `first` to false.
- If `dt` is zero or negative, the derivative is 0 too, instead of a division by zero.
- Every call ends by storing `error` into `prev_error`.

For example, with the defaults, a first call with error 1.0 returns 2.0. A second call with error 0.8 has a derivative of (0.8 - 1.0) / 0.01 = -20, so it returns 1.6 - 2.0 = -0.4.
--- starter
double pd_step(double error, double& prev_error, bool& first, double kp = 2.0, double kd = 0.1, double dt = 0.01) {

    return kp * error + kd * derivative;
}
--- solution
double pd_step(double error, double& prev_error, bool& first, double kp = 2.0, double kd = 0.1, double dt = 0.01) {
    double derivative = 0.0;
    if (!first && dt > 0.0) derivative = (error - prev_error) / dt;
    first = false;
    prev_error = error;
    return kp * error + kd * derivative;
}
--- hint
Start the derivative at 0.0 and only compute it when this is not the first call and `dt` is positive.
--- hint
`first` and `prev_error` are references, so assigning to them changes the caller's variables: that is how the next call remembers.

#include <cstddef>
#include <vector>

std::vector<double> window_means(const std::vector<double>& v, std::size_t w) {
    std::vector<double> out;
    if (w == 0 || w > v.size()) return out;  // v.size() - w would wrap
    out.reserve(v.size() - w + 1);
    for (std::size_t start = 0; start + w <= v.size(); ++start) {

        out.push_back(sum / static_cast<double>(w));

    return out;

#include <array>
#include <cstddef>

struct SampleBuf {
    std::array<double, 4> data{};
    std::size_t count = 0;
};

bool push(SampleBuf& b, double x) {
    if (b.count == b.data.size()) return false;  // full: the capacity is in the type
    b.data[b.count] = x;
    ++b.count;
    return true;
}

double average(const SampleBuf& b) {
    if (b.count == 0) return 0.0;
    double sum = 0.0;
    for (std::size_t i = 0; i < b.count; ++i) sum += b.data[i];
    return sum / static_cast<double>(b.count);
}

void drop_oldest(SampleBuf& b) {
    if (b.count == 0) return;
    for (std::size_t i = 1; i < b.count; ++i) b.data[i - 1] = b.data[i];
    --b.count;
}
--- hint
`b.data.size()` is the capacity, 4, and it never changes. `b.count` is how many slots are in use; the next free slot is `b.data[b.count]`.
--- hint

+++ question | A reference into a growing vector
--- ask
What is true about this code?

```cpp
std::vector<int> v{1, 2, 3};
int& first = v[0];
v.push_back(4);
first = 10;
```
--- choice
`v[0]` is now 10, because `first` is a reference to it.
--- choice correct
The last line is undefined behavior if `push_back` moved the elements to a bigger block, which it may do, since the vector may be full.
--- choice
It does not compile: a reference to a vector element is not allowed.
--- choice
`push_back` updates every reference into the vector, so the code is safe.
--- why
A `std::vector` keeps its elements in one heap block. When `push_back` needs more room than the capacity, it gets a bigger block, moves the elements, and frees the old one. A vector built from three values often has a capacity of exactly three, so here the move is likely. After it, `first` names freed memory, and writing through it is undefined behavior. Nothing warns; AddressSanitizer reports it as a heap-use-after-free. Take references into a vector only after it has stopped growing, or `reserve` enough first.

Keep the data members private, so no code outside the class can break the invariant. Both reporting functions must work on a `const FuelGauge`.

    double remaining_kg;

--- solution
class FuelGauge {
public:
    explicit FuelGauge(double capacity_kg)
        : capacity_(capacity_kg < 0.0 ? 0.0 : capacity_kg), remaining_(capacity_) {}

    bool burn(double kg) {
        if (kg < 0.0 || kg > remaining_) return false;
        remaining_ -= kg;
        return true;
    }

    bool refill(double kg) {
        if (kg < 0.0 || remaining_ + kg > capacity_) return false;
        remaining_ += kg;
        return true;
    }

    double remaining() const { return remaining_; }
    double capacity() const { return capacity_; }

private:
    double capacity_;   // never changes after construction
    double remaining_;  // invariant: 0 <= remaining_ <= capacity_
};

--- solution
#include <cstdint>

enum class IgniterState : std::uint8_t { Safe, Armed, Firing };

class Igniter {
public:
    explicit Igniter(int max_starts) : starts_(max_starts < 0 ? 0 : max_starts) {}

    bool arm() {
        if (state_ != IgniterState::Safe || starts_ == 0) return false;
        state_ = IgniterState::Armed;
        return true;
    }

    bool fire() {
        if (state_ != IgniterState::Armed) return false;
        state_ = IgniterState::Firing;
        --starts_;
        return true;
    }

    void safe() { state_ = IgniterState::Safe; }

    IgniterState state() const { return state_; }
    int starts_left() const { return starts_; }

private:
    int starts_;
    IgniterState state_{IgniterState::Safe};
};
--- hint
Each order checks the current state first and returns false without changing anything when the order is not allowed from there.

--- ask
After `make_count` returns, which of the objects marked A, B and C still exist?

```cpp
int* make_count() {

    static int b = 2;       // B
    int* c = new int{3};    // C: the int that c points at
```

B and C: B has static storage and lives for the whole program, and C lives on the heap until someone deletes it.

--- solution
#include <cstdint>
#include <string_view>

bool parse_u16(std::string_view s, std::uint16_t& out) {
    if (s.empty()) return false;
    std::uint32_t value = 0;  // wider than the result, so the range check cannot wrap
    for (char c : s) {

    return true;
}

+++ practice | A hex dump with a checksum
--- task
Write `std::string hexdump(const std::vector<std::uint8_t>& bytes)` for a ground tool. It returns every byte as two upper-case hexadecimal digits followed by one space, then `| sum=`, then the checksum as two upper-case hexadecimal digits. The checksum is the sum of all the bytes, modulo 256.

--- starter

#include <string>
#include <vector>

    return out;
}
--- solution
#include <cstdint>
#include <format>
#include <string>
#include <vector>

std::string hexdump(const std::vector<std::uint8_t>& bytes) {
    std::string out;
    std::uint8_t sum = 0;
    for (const auto b : bytes) {
        out += std::format("{:02X} ", b);  // std::format prints a uint8_t as a number

    return out;
}
--- hint

enum class Phase { Coast, Braking, Landed };

constexpr double kG0 = 9.80665;  // standard gravity, m/s^2

constexpr double stop_distance(double v, double decel_g) {
    return v * v / (2.0 * decel_g * kG0);
}

Phase next_phase(Phase p, double alt_m, double v_mps, double decel_g, double margin = 1.2) {
    if (decel_g <= 0.0) return p;  // cannot brake: no stop distance exists
    switch (p) {

        case Phase::Braking:
            return (alt_m <= 0.5 && v_mps <= 1.0) ? Phase::Landed : Phase::Braking;
        case Phase::Landed:
            return Phase::Landed;
    }
    return p;
}

#include <cstddef>
#include <string>
#include <string_view>
#include <vector>

std::vector<std::string> split(std::string_view line, char sep) {
    std::vector<std::string> out;
    std::size_t start = 0;  // where the current field begins
    for (std::size_t i = 0; i < line.size(); ++i) {
        if (line[i] == sep) {
            out.push_back(std::string(line.substr(start, i - start)));
            start = i + 1;
        }
    }
    out.push_back(std::string(line.substr(start)));  // the last field, possibly empty
    return out;
}

#include <array>
#include <cmath>
#include <cstddef>

struct Sensor {
    int id;
    double bias;
    bool healthy;
};

Sensor& worst(std::array<Sensor, 4>& s) {
    std::size_t pick = s.size();  // s.size() means none found yet
    for (std::size_t i = 0; i < s.size(); ++i) {
        if (!s[i].healthy) continue;
        if (pick == s.size() || std::fabs(s[i].bias) > std::fabs(s[pick].bias)) pick = i;
    }
    return pick == s.size() ? s[0] : s[pick];
}

    Sensor& w = worst(s);  // a reference: marking it marks the element in the array
    if (!w.healthy || std::fabs(w.bias) <= max_bias) return -1;
    w.healthy = false;
    return w.id;
}

#include <array>
#include <cstddef>
#include <cstdint>

enum class Fault : std::uint8_t { Overtemp, Undervolt, CommLoss, Count };

class FaultLog {
public:
    void record(Fault f, std::uint32_t t_ms) {
        const auto i = static_cast<std::size_t>(f);
        if (i >= counts_.size()) return;  // not a real fault
        if (counts_[i] == 0) first_[i] = t_ms;
        ++counts_[i];
        ++total_;
    }

    int count(Fault f) const {
        const auto i = static_cast<std::size_t>(f);
        return i < counts_.size() ? counts_[i] : 0;
    }

    std::uint32_t first_time(Fault f) const {
        const auto i = static_cast<std::size_t>(f);
        return i < first_.size() ? first_[i] : 0;
    }

    int total() const { return total_; }

private:
    std::array<int, static_cast<std::size_t>(Fault::Count)> counts_{};
    std::array<std::uint32_t, static_cast<std::size_t>(Fault::Count)> first_{};
    int total_{0};
};

    static FaultLog log;
    return log;
}

--- why
`#include` is handled by the preprocessor, which pastes the named file's text in place of the line. If it cannot find the file, in the current folder or on the `-I` search path, it stops before any C++ is compiled, so this message says nothing about whether the rest of `main.cpp` is correct. The line and column point at the `#include` in `main.cpp`, not into the header. A linker error would begin with `/usr/bin/ld` and talk about undefined references.

+++ question | A copied include guard
--- ask
`valve.hpp` was made by copying `pump.hpp` and editing the contents, but both still start with the same two lines:

```cpp
#ifndef ORBIT_PUMP_HPP
#define ORBIT_PUMP_HPP
```

`main.cpp` includes `pump.hpp`, then `valve.hpp`, and then uses `ValveCmd`, a struct that only `valve.hpp` defines. What happens?
--- choice
The compiler reports "redefinition of 'struct ValveCmd'", because the header was pasted twice.
--- choice correct
The compiler reports that `ValveCmd` was not declared: the guard name is already defined when `valve.hpp` is reached, so the preprocessor drops its whole text.
--- choice
The link fails with "multiple definition", because the two headers define the same guard.
--- choice
It works: include guards belong to the file they are written in, so the two cannot interfere.
--- why
An include guard is only a macro name, and macro names are shared by the whole translation unit. `pump.hpp` defines `ORBIT_PUMP_HPP`. When `valve.hpp` is pasted in, `#ifndef ORBIT_PUMP_HPP` is false, so everything up to its `#endif` vanishes, `ValveCmd` included. The error points at the use in `main.cpp`, far from the real cause. This is the bug `#pragma once` cannot have, and why guard names are built from the project, path and file name.

+++ question | Reading nm to settle a link error
--- ask
Both object files are on the link line, and the link fails with:

```text
undefined reference to `nav::predict(nav::State const&, double)'
```

You ask the object file that should supply it:

```text
$ nm -C --defined-only nav.o
0000000000000000 T nav::predict(nav::State&, double)
0000000000000090 T nav::norm(nav::State const&)
```

What is the fix?
--- choice
Add `nav.o` to the link line.
--- choice correct
In `nav.cpp`, add `const` to `predict`'s first parameter, so the definition matches the declaration the caller was compiled against.
--- choice
Mark `predict` as `inline`, so the linker can keep either version.
--- choice
Move `predict` out of namespace `nav`.
--- why
`nav.o` is in the link and does define a `predict`, but one taking `nav::State&`. The caller needs one taking `nav::State const&`. Those are different overloads with different mangled names, so the `U` in the caller is never matched. `nav.cpp` compiled without complaint because a definition that differs in its parameter types is simply a new overload. `-Wmissing-declarations` would have warned about it. Moving the function out of the namespace would make a third, unrelated symbol.

+++ question | A header edit that make does not see
--- ask
A Makefile builds each `.o` from its `.cpp` with the pattern rule `%.o: %.cpp`, and its flags do **not** include `-MMD -MP`. You add a field to `struct State` in `state.hpp`, which both `nav.cpp` and `main.cpp` include. Then you edit a comment in `nav.cpp` and run `make`. What happens?
--- choice
Both objects are rebuilt, because the compiler tells `make` which headers each file reads.
--- choice correct
Only `nav.o` is rebuilt. `main.o` keeps the old layout of `State`, the link succeeds, and the program can quietly read wrong values.
--- choice
The link fails with "multiple definition of 'State'".
--- choice
`make` refuses to run until `make clean`, because a header changed.
--- why
Without dependency files, `make` knows only that `nav.o` depends on `nav.cpp` and `main.o` on `main.cpp`. You touched `nav.cpp`, so only `nav.o` is rebuilt, with the new `State`. `main.o` was compiled against the old one. A type is not a symbol, so the linker has nothing to compare, and the program breaks the one-definition rule without a single message. `-MMD -MP` makes the compiler write the headers each file read into `.d` files, so editing `state.hpp` rebuilds both.

+++ question | Which line is undefined
--- ask
On a platform where `int` is 32 bits, exactly one of these lines has undefined behavior. Which one?
--- choice
`std::uint32_t a = 4294967295u; a += 1;`
--- choice
`std::int8_t b = static_cast<std::int8_t>(200);`
--- choice correct
`std::uint16_t c = 60000; std::uint32_t d = c * c;`
--- choice
`double e = 3.7; int f = static_cast<int>(e);`
--- why
`c * c` looks unsigned, but both `std::uint16_t` operands are promoted to `int` before the multiply, and 60000 × 60000 = 3,600,000,000 is more than a 32-bit `int` holds (2,147,483,647). That is signed overflow, so the program has no defined meaning, and the wide `std::uint32_t` on the left does not help: the conversion happens only after the overflow. Write `static_cast<std::uint32_t>(c) * c`. The others are all defined: unsigned arithmetic wraps modulo 2^32, so `a` becomes 0; since C++20 a conversion to a signed type that does not fit wraps too, so `b` is -56; and a `double` converted to `int` drops the fraction when the result fits, so `f` is 3.

+++ question | Two narrow operands
--- ask
What does this print?

```cpp
short s = -1;
unsigned short us = 1;
std::printf("%d %d\n", s < us, s < 1u);
```

Type the two numbers with a space between them.
--- answer
1 0
1, 0
--- why
Promotion happens first. In `s < us` both operands are narrower than `int`, and `int` can hold every value of each, so both become `int`: -1 < 1 is true, printed as 1. In `s < 1u`, `s` is promoted to `int`, and then the usual arithmetic conversions meet an `int` and an `unsigned int` of the same rank, so the signed side converts to unsigned: -1 becomes 4294967295, which is not less than 1, printed as 0. The same comparison gives two answers depending on how wide the unsigned operand is.

+++ question | Copies, references and a returned value
--- ask
What does this print?

```cpp
struct P { int n; };

void f(P p)  { p.n += 1; }
void g(P& p) { p.n += 10; }
P h(P p)     { p.n += 100; return p; }

int main() {
    P a{1};
    f(a);
    g(a);
    P b = h(a);
    b.n += 1000;
    std::printf("%d %d\n", a.n, b.n);
}
```

Type the two numbers with a space between them.
--- answer
11 1111
11, 1111
--- why
`f` gets a copy and changes only the copy, so `a.n` stays 1. `g` gets a reference, so `a.n` becomes 11. `h` gets a copy of `a` (11), adds 100 to the copy and returns it, so `b` starts as 111 while `a` stays 11. `b` is its own object, so adding 1000 to it gives 1111 and leaves `a` alone.

+++ question | What auto kept
--- ask
What does this print?

```cpp
std::vector<int> v{1, 2, 3};
auto x = v[0];
auto& y = v[1];
const auto& z = v[2];
x = 10;
y = 20;
v[2] = 30;
std::printf("%d %d %d %d\n", v[0], v[1], z, x);
```

Type the four numbers with one space between each.
--- answer
1 20 30 10
--- why
Plain `auto` drops the reference, so `x` is a copy: setting it to 10 leaves `v[0]` at 1. `auto&` keeps the reference, so `y = 20` changes `v[1]`. `const auto&` is a read-only alias of `v[2]`: it cannot change the element, but it sees the change made through `v[2]`, so it reads 30. `x` itself holds 10.

+++ question | Overloads and a default
--- ask
What does this program print?

```cpp
#include <cstdio>

void put(int)                { std::printf("A"); }
void put(double, int ch = 0) { std::printf("B%d", ch); }

int main() {
    put(1);
    put(1.0);
    put(1, 2);
    put('c');
    std::printf("\n");
}
```

Type the output exactly, with no spaces.
--- answer
AB0B2A
--- why
`put(1)`: an exact match for `put(int)` beats converting `int` to `double`, so A. `put(1.0)`: an exact match for the `double` version, using the default, so B0. `put(1, 2)`: only the second function takes two arguments, so B2, with 1 converted to `double`. `put('c')`: `char` to `int` is a promotion, which beats the standard conversion `char` to `double`, so A.

+++ question | The size of an array parameter
--- ask
On x86-64 Linux, what does `check` print when it is called with an array of 16 `double`s?

```cpp
void check(const double buf[16]) {
    std::printf("%zu\n", sizeof(buf) / sizeof(buf[0]));
}
```

Type the number.
--- answer
1
--- why
An array parameter is not an array. `const double buf[16]` in a parameter list is rewritten as `const double* buf`, and the 16 is ignored. So `sizeof(buf)` is the size of a pointer, 8 bytes on x86-64, and `sizeof(buf[0])` is the size of a `double`, also 8. The division gives 1. g++ warns about it with `-Wsizeof-array-argument`. Passing a `std::array` by reference, or a `std::span`, keeps the length.

+++ question | Birth and death order
--- ask
What does this program print?

```cpp
#include <cstdio>

struct T {
    char c;
    explicit T(char x) : c(x) { std::printf("%c", c); }
    ~T() { std::printf("%c", c - 32); }   // the upper-case letter
};

T g{'g'};

int main() {
    T a{'a'};
    { T b{'b'}; }
    static T s{'s'};
    T c{'c'};
    std::printf("|");
}
```

Type the output exactly, with no spaces.
--- answer
gabBsc|CASG
--- why
`g` has static storage and is constructed before `main` starts: `g`. Then `a`, and `b`, which dies at its own closing brace: `abB`. The static local `s` is constructed when control first reaches it: `s`. Then `c`, and the `|`. When `main` ends, its automatic objects die in reverse order, `c` then `a`: `CA`. After `main` returns, the static objects die in reverse order of construction: `s` was made after `g`, so `S` then `G`.

+++ question | An assert with a call inside
--- ask
This program is built twice: once as a debug build, and once with `-DNDEBUG`.

```cpp
#include <cassert>
#include <cstdio>

int g_tries = 0;

bool try_link() {
    ++g_tries;
    return g_tries >= 2;
}

int main() {
    assert(try_link() || try_link());
    std::printf("%d\n", g_tries);
}
```

What does each build print? Type the debug build's number, then the release build's, with a space between them.
--- answer
2 0
2, 0
--- why
In the debug build the assertion runs. The first `try_link()` makes `g_tries` 1 and returns false, so `||` calls the second, which makes it 2 and returns true. The assertion passes and the program prints 2. With `NDEBUG` defined, `assert(...)` becomes an expression that does nothing, and both calls vanish with it, so the program prints 0. A call with a side effect never belongs inside `assert`: keep the result in a variable first, and assert on the variable.
