+++ practice | Birth and death, in order
--- task
The starter defines a `Stage` that prints a line when it is constructed, copied and destroyed, and a function `make_stage` that returns a new `Stage` by value.

Write the body of `main` so the program prints exactly these eight lines:

```
ctor 1
ctor 2
ctor 3
dtor 3
ctor 4
dtor 4
dtor 2
dtor 1
```

Rules:

- Every line must come from a `Stage` being constructed or destroyed. Do not call `printf` in `main`.
- Stage 4 must be made by calling `make_stage(4)`, and no `copy` line may appear.
- Use only automatic objects and blocks (`{` and `}`). No `new`.
--- starter
#include <cstdio>

struct Stage {
    int id;
    explicit Stage(int i) : id(i) { std::printf("ctor %d\n", id); }
    Stage(const Stage& other) : id(other.id) { std::printf("copy %d\n", id); }
    ~Stage() { std::printf("dtor %d\n", id); }
};

Stage make_stage(int id) { return Stage{id}; }

int main() {
    return 0;
}
--- solution
#include <cstdio>

struct Stage {
    int id;
    explicit Stage(int i) : id(i) { std::printf("ctor %d\n", id); }
    Stage(const Stage& other) : id(other.id) { std::printf("copy %d\n", id); }
    ~Stage() { std::printf("dtor %d\n", id); }
};

Stage make_stage(int id) { return Stage{id}; }

int main() {
    Stage first{1};                          // lives until the end of main
    {
        Stage second{2};                     // lives until this block closes
        {
            Stage third{3};                  // dies at the next brace
        }
        {
            Stage fourth = make_stage(4);    // a prvalue: built straight into fourth, no copy
        }
    }
    return 0;
}
--- hint
An automatic object dies at the closing brace of the block it was declared in, and objects in one block die in the reverse order they were built.
--- hint
Stage 3 and stage 4 must both die while stage 2 is still alive, and stage 3 must die before stage 4 is born. Give each of them its own inner block inside stage 2's block.
--- hint
`Stage s = make_stage(4);` makes no copy: since C++17 a returned prvalue is built directly in the object it initializes.

+++ practice | A result that outlives the call
--- task
Write `const std::array<double, 4>& to_g(const std::array<double, 4>& accel)`.

It converts four accelerations in m/s² into multiples of standard gravity, dividing each by g0 = 9.80665, and returns a **reference** to the converted values. The four results must live in an array with **static storage duration** inside `to_g`, so the reference is still valid after the function returns.

That choice has a cost the checks also test: there is only one result array. A second call overwrites what the first call returned, so a caller who wants to keep a result must copy it into an array of its own.

For example, `to_g({9.80665, 0.0, -19.6133, 4.903325})` gives about 1.0, 0.0, -2.0 and 0.5.
--- starter
#include <array>

const std::array<double, 4>& to_g(const std::array<double, 4>& accel) {
    return accel;   // wrong: hands back the input unchanged
}
--- solution
#include <array>

constexpr double kG0 = 9.80665;   // standard gravity, m/s^2

// The result lives in a static local: it outlives the call, and there is only one of it.
const std::array<double, 4>& to_g(const std::array<double, 4>& accel) {
    static std::array<double, 4> result{};
    for (std::size_t i = 0; i < accel.size(); ++i) result[i] = accel[i] / kG0;
    return result;
}
--- hint
A local array dies when `to_g` returns, so a reference to it would dangle. Declare the result array `static` inside the function.
--- hint
Fill every element on every call. The array is shared by all calls, so whatever the last call wrote is what every reference to it shows.

+++ practice | A mean that remembers too much
--- task
`mean_of` should return the mean of the readings in a vector, or `0.0` for an empty vector. For example, `mean_of({1.0, 2.0, 3.0})` is `2.0` and `mean_of({10.0, 20.0})` is `15.0`.

The first call in a program gives the right answer. Every call after that is wrong: called with `{1.0, 2.0, 3.0}` and then `{10.0, 20.0}`, it returns 2.0 and then 18.0. Find the declaration that causes it, say to yourself which storage duration it has and which one it needs, and fix it.
--- starter
#include <vector>

// Mean of the readings, or 0.0 for an empty vector.
double mean_of(const std::vector<double>& v) {
    static double sum = 0.0;
    if (v.empty()) return 0.0;
    for (double x : v) sum += x;
    return sum / static_cast<double>(v.size());
}
--- solution
#include <vector>

// Mean of the readings, or 0.0 for an empty vector.
double mean_of(const std::vector<double>& v) {
    if (v.empty()) return 0.0;
    double sum = 0.0;   // automatic: a fresh zero on every call
    for (double x : v) sum += x;
    return sum / static_cast<double>(v.size());
}
--- hint
A `static` local is one object for the whole program. Its initializer runs once, the first time, not on every call.
--- hint
The running sum belongs to one call, so it needs automatic storage duration: remove `static`.

+++ question | One counter per thread
--- ask
What does this program print? Type the line exactly.

```cpp
#include <cstdio>
#include <thread>

thread_local int t_frames = 10;
int g_frames = 10;

void tick(int n) {
    for (int i = 0; i < n; ++i) { ++t_frames; ++g_frames; }
}

int main() {
    std::thread a([] { tick(4); });
    a.join();
    tick(1);
    std::thread b([] { tick(2); std::printf("%d %d\n", t_frames, g_frames); });
    b.join();
    return 0;
}
```
--- answer
12 17
--- why
`g_frames` has static storage duration: one object for the whole program, so every tick adds to it, 10 + 4 + 1 + 2 = 17. `t_frames` is `thread_local`: each thread gets its own copy, starting from 10. Thread `b` has only ever added 2 to its own copy, so it prints 12. The 4 added by thread `a` and the 1 added by `main` went into their own copies of `t_frames`. The joins make the order fixed, so there is no data race on `g_frames`.

+++ question | Three counters, one of them unset
--- ask
What does `read_all()` return?

```cpp
int g_count;

int read_all() {
    static int s_count;
    int local_count;
    return g_count + s_count + local_count;
}
```
--- choice
0, because every `int` without an initializer starts at zero.
--- choice correct
Nothing defined: `g_count` and `s_count` are zero, but `local_count` is indeterminate, so reading it is undefined behavior.
--- choice
An unpredictable number, because all three hold whatever was in memory before.
--- choice
It does not compile, because `local_count` is used without an initializer.
--- why
Objects with static storage duration are zeroed before any code runs. That covers the namespace-scope `g_count` and the `static` local `s_count`. An automatic object with no initializer holds an indeterminate value, and reading one is undefined behavior, not merely "some number". It compiles (with `-Wall` g++ warns that it is used uninitialized). The fix is `int local_count{};`, or better, a real starting value.

--- solution
#include <vector>

struct Sensor { int id; int bus; double noise; };

// A pointer into the vector, so the caller can change the sensor; nullptr means "not there".
Sensor* find_sensor(std::vector<Sensor>& sensors, int id) {
    for (Sensor& s : sensors) {
        if (s.id == id) return &s;
    }
    return nullptr;
}

// A pointer parameter says "you may hand me nothing"; check it once, here.
double noise_or(const Sensor* s, double fallback) {
    return s ? s->noise : fallback;
}
--- hint

A pointer tests as `false` when it is null, so `s ? s->noise : fallback` handles both cases.

#include <vector>

struct Reading { int sensor; double value; };

using Visit = void (*)(const Reading& r, void* ctx);

// Calls visit(r, ctx) for every reading, in order. Do not change this function.
void for_each_reading(const std::vector<Reading>& v, Visit visit, void* ctx) {
    for (const Reading& r : v) visit(r, ctx);
}

struct OverLimit { double limit; int count; };

// The one place the context is cast back: it must be the type count_high passed in.
void count_one(const Reading& r, void* ctx) {
    OverLimit* acc = static_cast<OverLimit*>(ctx);
    if (r.value > acc->limit) acc->count += 1;
}

int count_high(const std::vector<Reading>& v, double limit) {
    OverLimit acc{limit, 0};                 // lives until for_each_reading has returned
    for_each_reading(v, &count_one, &acc);
    return acc.count;
}

using Law = double (*)(double);

constexpr int kModeCount = 3;
const Law kLaws[kModeCount] = {&hold, &gentle, &firm};   // read-only: nothing can overwrite an entry

Law law_for(int mode) {
    if (mode < 0 || mode >= kModeCount) return nullptr;   // never index outside the table

struct Frame { int seq; double az; };

// The frame with the largest az, or nullptr when n is 0.
const Frame* peak(const Frame* frames, int n) {

    for (int i = 0; i < n; ++i) {

class EventBus {
public:
    bool subscribe(Handler fn, void* ctx) {
        if (fn == nullptr || count_ == kCapacity) return false;   // refuse, never overrun
        slots_[count_] = Slot{fn, ctx};
        ++count_;
        return true;
    }

    void publish(int value) {
        for (int i = 0; i < count_; ++i) slots_[i].fn(value, slots_[i].ctx);
    }

    int subscribers() const { return count_; }

private:
    struct Slot {
        Handler fn;
        void* ctx;   // handed back untouched; only the handler knows its real type
    };
    static constexpr int kCapacity = 4;
    Slot slots_[kCapacity]{};
    int count_ = 0;
};

+++ question | Which const is which
--- ask
You want a pointer through which you **can** write to the `double` it points at, but which can never be made to point at a different `double`. Which declaration is it?
--- choice
`const double* p = &x;`
--- choice
`double const* p = &x;`
--- choice correct
`double* const p = &x;`
--- choice
`const double* const p = &x;`
--- why
Read right to left from the name: `double* const p` is "p is a const pointer to double". The pointer is frozen, so `p = &y;` fails, but `*p = 1.0;` is fine. `const double*` and `double const*` mean the same thing, a pointer to a `const double`: it can be reseated but not written through. `const double* const` freezes both. A `const` after the star always applies to the pointer; one before the star, on either side of the type name, applies to the pointee.

// Mean of [first, last): first up to but not including last.
double mean_range(const double* first, const double* last) {
    if (first == last) return 0.0;
    double sum = 0.0;

constexpr double kMissing = -999.0;

struct Range { const double* begin; const double* end; };

// Shrinks [first, last) from both ends past the missing samples.
Range trim(const double* first, const double* last) {
    while (first != last && *first == kMissing) ++first;
    // Step last down before reading, so the loop never reads *last or goes below first.
    while (last != first && *(last - 1) == kMissing) --last;
    return Range{first, last};
}

#include <cstddef>
#include <span>

// The newest n samples are the n just before next, wrapping round the end.
double sum_newest(std::span<const double> ring, std::size_t next, std::size_t n) {
    if (n > ring.size()) n = ring.size();
    double sum = 0.0;
    // First the part just below next: up to next samples, newest first.

    return sum;
}

A `Clamp` is often built from a temporary, as in `Clamp c{Limits{-1.0, 1.0}};`, and one `Clamp` must be assignable to another. So the class must **own** its limits. A reference member would dangle as soon as the temporary died, and it would also make the class impossible to assign.
--- starter
struct Limits { double lo; double hi; };

class Clamp {
public:
    explicit Clamp(const Limits& limits) {}
    double apply(double x) const { return x; }
};
--- solution
struct Limits { double lo; double hi; };

class Clamp {
public:
    // Copies the limits in: the Clamp owns them, whatever happens to the argument.
    explicit Clamp(const Limits& limits) : limits_(limits) {
        if (limits_.lo > limits_.hi) {
            double t = limits_.lo;
            limits_.lo = limits_.hi;
            limits_.hi = t;
        }
    }

    double apply(double x) const {
        if (x < limits_.lo) return limits_.lo;
        if (x > limits_.hi) return limits_.hi;
        return x;
    }

private:
    Limits limits_;   // a value, not a reference: nothing to outlive, and assignable
};
--- hint
A reference member initialized from a constructor parameter does not extend a temporary's life. Store a `Limits` by value.
--- hint
A class with a reference member cannot be assigned, because a reference cannot be reseated. A value member copies and assigns without any code from you.

+++ practice | Follow the parent links, with a bound
--- task
A fault tree is stored as a table: `parent[i]` is the index of node `i`'s parent, or `-1` for the root. A review rejected this function, because its stack depth depends on the table, and a corrupt table with a loop in it would recurse until the stack ran out:


Write `int depth_of(const std::vector<int>& parent, int node)` again, with a loop and no recursion. It returns the number of links from `node` up to the root (0 for the root itself), with a defined answer for every bad input:

- it returns `-1` if a parent entry it follows is neither `-1` nor a valid index;
- it follows at most `kMaxLinks` links (32). If it has not reached the root by then, it returns `-1`, which also catches a loop in the table.

A node exactly 32 links below the root is fine and gives 32.
--- starter

    return 0;

--- solution
#include <vector>

constexpr int kMaxLinks = 32;

// Links from node up to the root, or -1 for a bad index, a bad entry, or a table deeper than kMaxLinks.
int depth_of(const std::vector<int>& parent, int node) {
    const int n = static_cast<int>(parent.size());
    if (node < 0 || node >= n) return -1;
    int links = 0;
    while (parent[node] != -1) {
        if (links == kMaxLinks) return -1;        // the bound, enforced: a loop can never run forever
        node = parent[node];
        if (node < 0 || node >= n) return -1;     // a corrupt entry
        ++links;
    }
    return links;
}
--- hint
Keep one variable for the current node and one counter for links followed. Each pass of the loop moves the node to its parent.
--- hint
Check the counter against `kMaxLinks` before following another link, and check every index before you use it to look up the table.

#include <vector>

struct Node { double threshold; int left; int right; };

constexpr int kStackSlots = 8;

// Used by the checks. Keep it.
// A spine of `levels` nodes going left; every spine node also has a leaf on its right.
std::vector<Node> left_comb(int levels) {
    std::vector<Node> t;
    for (int k = 0; k < levels; ++k) {
        int spine = static_cast<int>(t.size());
        t.push_back(Node{1.0, -1, -1});
        t.push_back(Node{2.0, -1, -1});
        t[spine].right = spine + 1;
        if (k + 1 < levels) t[spine].left = spine + 2;
    }
    return t;
}

// Iterative walk with a fixed-size stack: the frame size never depends on the tree.
int count_above(const std::vector<Node>& tree, double limit, int& high_water) {
    int stack[kStackSlots];
    int top = 0;
    high_water = 0;
    if (tree.empty()) return 0;

    stack[top++] = 0;
    high_water = 1;
    int count = 0;
    while (top > 0) {
        const Node& n = tree[static_cast<std::size_t>(stack[--top])];
        if (n.threshold > limit) ++count;
        const int children[2] = {n.right, n.left};   // right first, so left is popped first
        for (int child : children) {
            if (child == -1) continue;
            if (top == kStackSlots) return -1;   // full: refuse instead of writing past the array
            stack[top++] = child;
            if (top > high_water) high_water = top;
        }
    }
    return count;
}
--- hint
`stack[top++] = i` pushes and `stack[--top]` pops. The number of slots in use is always `top`.
--- hint
Test `top == kStackSlots` before each push, and update `high_water` after each push.

+++ practice | Measure a debris cluster
--- task
A radar map is a grid of up to 8 rows of up to 8 characters: `'#'` is a cell with debris, `'.'` is empty. All rows have the same length. A cluster is a set of debris cells joined through their four side neighbours (up, down, left, right, not diagonals).

Write `int cluster_size(const std::vector<std::string>& grid, int row, int col)`, which returns the number of cells in the cluster that contains cell (`row`, `col`). It returns 0 if that cell is empty or outside the grid.

The obvious answer is a recursive flood fill, and flight code does not recurse. Use a loop with an explicit stack in a fixed-size local array. Mark a cell as seen when you **push** it, so no cell is ever pushed twice: then a stack of 64 entries can never overflow, and you can say so in a comment.
--- starter
#include <string>
#include <vector>

int cluster_size(const std::vector<std::string>& grid, int row, int col) {
    return 0;
}
--- solution
#include <string>
#include <vector>

// True when (r, c) is inside the grid and holds debris.
bool is_debris(const std::vector<std::string>& grid, int r, int c) {
    const int rows = static_cast<int>(grid.size());
    if (r < 0 || r >= rows) return false;
    const int cols = static_cast<int>(grid[static_cast<std::size_t>(r)].size());
    return c >= 0 && c < cols && grid[static_cast<std::size_t>(r)][static_cast<std::size_t>(c)] == '#';
}

// Flood fill with an explicit stack. Each cell is pushed at most once (it is marked when
// pushed), and the grid has at most 8 x 8 = 64 cells, so 64 slots can never overflow.
int cluster_size(const std::vector<std::string>& grid, int row, int col) {
    constexpr int kMax = 8;
    if (!is_debris(grid, row, col)) return 0;

    bool seen[kMax][kMax] = {};
    int stack_r[kMax * kMax];
    int stack_c[kMax * kMax];
    int top = 0;
    stack_r[top] = row;
    stack_c[top] = col;
    ++top;
    seen[row][col] = true;

    const int dr[4] = {-1, 1, 0, 0};
    const int dc[4] = {0, 0, -1, 1};
    int size = 0;
    while (top > 0) {
        --top;
        const int r = stack_r[top];
        const int c = stack_c[top];
        ++size;
        for (int k = 0; k < 4; ++k) {
            const int nr = r + dr[k];
            const int nc = c + dc[k];
            if (is_debris(grid, nr, nc) && !seen[nr][nc]) {
                seen[nr][nc] = true;   // marked on push: never pushed twice
                stack_r[top] = nr;
                stack_c[top] = nc;
                ++top;
            }
        }
    }
    return size;
}
--- hint
Keep a `bool seen[8][8]` and two arrays of 64 for the stacked row and column. Push the start cell, then loop while the stack is not empty.
--- hint
When you pop a cell, count it and push each of its four neighbours that is inside the grid, is debris, and has not been seen, marking it seen as you push it.

+++ question | How deep can it go
--- ask
A task on a flight computer has a 16 KiB stack (16,384 bytes). When a recursive search is first called, 400 bytes of the stack are already in use, and `-fstack-usage` reports 176 bytes for each level of the search. At most how many levels can the search go before it overflows? Type a whole number.
--- answer
90
--- why
The space left is 16,384 − 400 = 15,984 bytes, and 15,984 / 176 ≈ 90.8, so 90 whole levels fit and the 91st overflows. Even that number is only as good as the promise that the input never needs more than 90 levels, and a recursive function enforces no such promise. That is why the answer in flight code is a loop with an explicit stack of fixed size, whose worst case is a constant.

+++ question | Why the analysis says unbounded
--- ask
A static stack-analysis tool reports "unbounded" for the worst-case stack use of one task, and the review is blocked. What is the most likely cause?
--- choice
One function in the task has a 20 KB local array.
--- choice correct
Somewhere in the task's call graph a function reaches itself again, directly or through other functions, so the graph has a cycle.
--- choice
A function in the task allocates memory with `new`.
--- choice
One function is called from several different places.
--- why
The tool adds up frame sizes along every path through the call graph. A large local makes the sum large, not unbounded, and `new` uses the heap, not the stack. A function called from many places is still one node with a fixed frame. Only a cycle, meaning recursion, direct or through other functions, has no longest path, because the depth then depends on data the tool cannot see. The fix is to remove the cycle: an explicit stack of fixed capacity.

--- task

#include <new>

template <typename T, std::size_t N>
class FixedQueue {
public:
    FixedQueue() = default;
    FixedQueue(const FixedQueue&) = delete;
    FixedQueue& operator=(const FixedQueue&) = delete;
    ~FixedQueue() {
        while (pop()) {
        }
    }

    bool push(const T& v) {
        if (count_ == N) return false;
        ::new (slot((head_ + count_) % N)) T(v);   // the back is count_ slots after the front
        ++count_;
        return true;
    }

    bool pop() {
        if (count_ == 0) return false;
        slot(head_)->~T();
        head_ = (head_ + 1) % N;                   // wrap round to slot 0
        --count_;
        return true;
    }

    T& front() { return *slot(head_); }
    std::size_t size() const { return count_; }

private:
    T* slot(std::size_t i) { return reinterpret_cast<T*>(storage_) + i; }

    alignas(T) unsigned char storage_[sizeof(T) * N];
    std::size_t head_ = 0;    // index of the oldest item
    std::size_t count_ = 0;   // how many are queued
};

+++ question | A reset that calls delete
--- ask
A colleague writes `ReadingSlot::reset()`, for a slot whose `Reading` was built with placement `new` in the slot's own `storage_` array, like this:

```cpp
void reset() {
    if (!full_) return;
    delete get();
    full_ = false;
}
```

What is wrong with it?
--- choice
Nothing: `delete` runs the destructor, which is what `reset` needs.
--- choice correct
`delete` runs the destructor and then passes the slot's own bytes to `operator delete`, memory that never came from `new`: undefined behavior. `reset` should only call `get()->~Reading()`.
--- choice
It leaks: `delete` does not run the destructor of an object made with placement `new`.
--- choice
It is only wrong when `Reading` has a destructor that does something.
--- why
A `delete` expression is two steps: run the destructor, then call the deallocation function on the address. Placement `new` did only the construction half; the storage belongs to the slot and was never allocated. Handing it to `operator delete` is undefined behavior whatever the type, and in practice corrupts the heap or crashes. The partner of placement `new` is an explicit destructor call, which ends the lifetime and keeps the bytes.

For example, `align_up(21, 8)` is 24, `align_up(24, 8)` is 24, and `align_up(17, 16)` is 32.

--- solution
#include <cstddef>

// A power of two has exactly one bit set, so clearing its lowest set bit leaves zero.
bool is_pow2(std::size_t x) {
    return x != 0 && (x & (x - 1)) == 0;
}

// Adding align - 1 carries any remainder past the next multiple; the mask drops the low bits.
std::size_t align_up(std::size_t offset, std::size_t align) {
    const std::size_t low_bits = align - 1;
    return (offset + low_bits) & ~low_bits;
}
--- hint
For a power of two, `align - 1` is a run of one-bits below its single set bit. Clearing those bits rounds down to a multiple.
--- hint

#include <cstddef>

class Arena {
public:
    Arena(unsigned char* base, std::size_t cap) : base_(base), cap_(cap) {}

    // Same few steps on every call: round up, check, bump. No search, no lock, no system call.
    void* allocate(std::size_t n, std::size_t align) {
        const std::size_t start = (used_ + align - 1) & ~(align - 1);
        if (start > cap_ || n > cap_ - start) return nullptr;   // a defined failure
        used_ = start + n;
        if (used_ > high_) high_ = used_;
        return base_ + start;
    }

    std::size_t mark() const { return used_; }

    // Everything allocated after the mark is given back at once.
    void rewind(std::size_t m) {
        if (m <= used_) used_ = m;
    }

    std::size_t used() const { return used_; }
    std::size_t high_water() const { return high_; }

private:
    unsigned char* base_;
    std::size_t cap_;
    std::size_t used_ = 0;
    std::size_t high_ = 0;
};

- `acquire` returns the index of a free block and marks it in use, or `-1` when all 8 are in use. It hands out the **most recently released** block if there is one; otherwise the lowest block that has never been handed out.
- `release(i)` marks block `i` free and returns `true`. It returns `false`, and changes nothing, if `i` is outside 0 to 7 or block `i` is already free. That second case is a double free, and the pool must survive it.
- `available` is how many blocks are free.
--- starter
class BlockPool {
public:
    int acquire() { return -1; }
    bool release(int i) { return false; }
    int available() const { return 0; }
};
--- solution
class BlockPool {
public:
    int acquire() {
        if (free_top_ > 0) {                      // reuse the most recently released block
            const int i = free_[--free_top_];
            in_use_[i] = true;
            return i;
        }
        if (next_fresh_ < kBlocks) {              // otherwise one never handed out
            in_use_[next_fresh_] = true;
            return next_fresh_++;
        }
        return -1;                                // exhausted: a defined answer, not a crash
    }

    bool release(int i) {
        if (i < 0 || i >= kBlocks || !in_use_[i]) return false;   // out of range, or a double free
        in_use_[i] = false;
        free_[free_top_++] = i;
        return true;
    }

    int available() const { return free_top_ + (kBlocks - next_fresh_); }

private:
    static constexpr int kBlocks = 8;
    bool in_use_[kBlocks] = {};
    int free_[kBlocks] = {};     // released blocks, most recent on top
    int free_top_ = 0;
    int next_fresh_ = 0;         // blocks from here up have never been handed out
};
--- hint
Keep a small stack of released indices (at most 8 of them), a count of blocks never handed out, and a `bool` per block saying whether it is in use.
--- hint
The `bool` per block is what catches a double release: refuse `release(i)` when block `i` is not in use.

+++ practice | A heap that fragments
--- task
Write a tiny first-fit heap over 32 units, to watch fragmentation happen.

```cpp
class TinyHeap {
public:
    int allocate(int units);
    bool release(int start);
    int free_units() const;
    int largest_free() const;
};
```

- `allocate(units)` finds the **lowest** run of at least `units` free units in a row, marks them used as one block, and returns the block's first unit. It returns `-1` if no run is long enough, or if `units` is less than 1.
- `release(start)` frees the whole block that begins at unit `start` and returns `true`. It returns `false` if no block begins there.
- `free_units` is the total number of free units, and `largest_free` the length of the longest run of free units.

Freed neighbours join into one longer run, because the units are simply free again.
--- starter
class TinyHeap {
public:
    int allocate(int units) { return -1; }
    bool release(int start) { return false; }
    int free_units() const { return 0; }
    int largest_free() const { return 0; }
};
--- solution
class TinyHeap {
public:
    // First fit: scan from unit 0 for a long enough run of free units.
    int allocate(int units) {
        if (units < 1) return -1;
        int run = 0;
        for (int i = 0; i < kUnits; ++i) {
            run = used_[i] ? 0 : run + 1;
            if (run == units) {
                const int start = i - units + 1;
                for (int k = start; k <= i; ++k) used_[k] = true;
                length_[start] = units;
                return start;
            }
        }
        return -1;   // may happen with plenty of free units, all in short runs
    }

    bool release(int start) {
        if (start < 0 || start >= kUnits || length_[start] == 0) return false;
        for (int k = start; k < start + length_[start]; ++k) used_[k] = false;
        length_[start] = 0;
        return true;
    }

    int free_units() const {
        int n = 0;
        for (bool u : used_) n += u ? 0 : 1;
        return n;
    }

    int largest_free() const {
        int best = 0;
        int run = 0;
        for (bool u : used_) {
            run = u ? 0 : run + 1;
            if (run > best) best = run;
        }
        return best;
    }

private:
    static constexpr int kUnits = 32;
    bool used_[kUnits] = {};
    int length_[kUnits] = {};   // length of the block starting at each unit, 0 if none starts there
};
--- hint
Keep a `bool` per unit for "in use", and an `int` per unit holding the length of the block that starts there (0 if none does). That second array is how `release` knows how much to free.
--- hint
For first fit, walk the units counting the current run of free ones, resetting to 0 at a used unit. The first time the run reaches `units`, the block starts `units - 1` places back.

--- ask

--- task

- then append `r`, with its `superseded` set to `false` whatever the caller passed.

The checks start from a vector whose capacity is full, so the append must grow the buffer. Any pointer, reference or iterator into the vector taken before `push_back` may point into the old, freed buffer afterwards.
--- starter

struct Reading { int seq; double value; bool superseded; };

}
--- solution
#include <vector>

struct Reading { int seq; double value; bool superseded; };

// Mark first, then grow: no reference into the old buffer is held across push_back.
void append_reading(std::vector<Reading>& log, Reading r) {
    if (!log.empty()) log.back().superseded = true;
    r.superseded = false;
    log.push_back(r);
}

`push_back` can move every element to a new buffer and free the old one, so do the marking **before** the append.
--- hint

+++ practice | A pool slot with no leftovers
--- task
A tracker keeps up to 4 `Track`s in a pool that is part of the object, and reuses slots as targets come and go. A slot handed out a second time still holds whatever the last target left in it, and a caller that reads a field it has not set yet would get the previous target's range or hit count. That is the pool version of an uninitialized read.

Write `class TrackPool` with:

- `Track* acquire(int id)`: finds a free slot, marks it in use, and returns it **fully reset**: `id` set, `range_m` and `rate_mps` 0.0, `hits` 0, `confirmed` false. Returns `nullptr` when all 4 slots are in use.
- `void release(Track* t)`: gives a slot back. It ignores `nullptr` and any pointer that is not one of the pool's own slots.
- `int in_use() const`.
--- starter
struct Track { int id; double range_m; double rate_mps; int hits; bool confirmed; };

class TrackPool {
public:
    Track* acquire(int id) { return nullptr; }
    void release(Track* t) {}
    int in_use() const { return 0; }

private:
    Track slots_[4]{};
    bool used_[4]{};
};
--- solution
struct Track { int id; double range_m; double rate_mps; int hits; bool confirmed; };

class TrackPool {
public:
    Track* acquire(int id) {
        for (int i = 0; i < kSlots; ++i) {
            if (used_[i]) continue;
            used_[i] = true;
            slots_[i] = Track{id, 0.0, 0.0, 0, false};   // every field written: nothing left over
            return &slots_[i];
        }
        return nullptr;
    }

    void release(Track* t) {
        for (int i = 0; i < kSlots; ++i) {
            if (t == &slots_[i]) {                       // only our own slots are accepted
                used_[i] = false;
                return;
            }
        }
    }

    int in_use() const {
        int n = 0;
        for (bool u : used_) n += u ? 1 : 0;
        return n;
    }

private:
    static constexpr int kSlots = 4;
    Track slots_[kSlots]{};
    bool used_[kSlots]{};
};
--- hint
Assigning a whole braced value, `slots_[i] = Track{id, 0.0, 0.0, 0, false};`, sets every field at once, so none can be forgotten.
--- hint
To check that a pointer is one of the pool's slots, compare it with `&slots_[i]` for each `i`.

#include <vector>

struct Sensor { int id; bool failed; };

// erase invalidates the iterator it was given, and hands back a valid one to the next
// element. Advance only when nothing was erased.
void drop_failed(std::vector<Sensor>& sensors) {
    auto it = sensors.begin();
    while (it != sensors.end()) {
        if (it->failed) {
            it = sensors.erase(it);
        } else {
            ++it;
        }
    }

+++ practice | Handles that notice a dead frame
--- task
Raw pointers cannot tell you that their object is gone. A common flight-software answer is a **handle**: a slot index plus a generation number. Every time a slot's object is destroyed, the slot's generation goes up by one, so any handle still carrying the old generation is recognised as stale.

Write `class FrameTable` with 4 slots, each holding one `double` (an `az` value):

- `Handle create(double az)`: stores `az` in the lowest free slot and returns `{index, generation}` for it. Returns `{-1, 0}` when all 4 slots are live.
- `double* get(Handle h)`: a pointer to the slot's value if `h` is live, otherwise `nullptr`.
- `bool destroy(Handle h)`: if `h` is live, frees the slot, raises its generation, and returns `true`. Otherwise returns `false` and changes nothing.
- `int live() const`.

A handle is live only if its index is 0 to 3, that slot is in use, and the generations match. So a use after destroy, a second destroy, and an old handle to a slot that has since been reused are all caught.
--- starter
struct Handle { int index; int generation; };

class FrameTable {
public:
    Handle create(double az) { return Handle{-1, 0}; }
    double* get(Handle h) { return nullptr; }
    bool destroy(Handle h) { return false; }
    int live() const { return 0; }
};
--- solution
struct Handle { int index; int generation; };

class FrameTable {
public:
    Handle create(double az) {
        for (int i = 0; i < kSlots; ++i) {
            if (slots_[i].in_use) continue;
            slots_[i].in_use = true;
            slots_[i].az = az;
            return Handle{i, slots_[i].generation};
        }
        return Handle{-1, 0};
    }

    double* get(Handle h) { return is_live(h) ? &slots_[h.index].az : nullptr; }

    bool destroy(Handle h) {
        if (!is_live(h)) return false;          // stale, destroyed twice, or never valid
        slots_[h.index].in_use = false;
        ++slots_[h.index].generation;           // every old handle to this slot is now stale
        return true;
    }

    int live() const {
        int n = 0;
        for (const Slot& s : slots_) n += s.in_use ? 1 : 0;
        return n;
    }

private:
    struct Slot {
        double az = 0.0;
        int generation = 0;
        bool in_use = false;
    };

    bool is_live(Handle h) const {
        return h.index >= 0 && h.index < kSlots && slots_[h.index].in_use &&
               slots_[h.index].generation == h.generation;
    }

    static constexpr int kSlots = 4;
    Slot slots_[kSlots];
};
--- hint

--- hint
Raise the generation in `destroy`, not in `create`. Then a handle made before the destroy can never match again, even after the slot is reused.

+++ practice | One shadow byte
--- task
AddressSanitizer keeps one shadow byte for every 8 bytes of memory. Group `g` of an allocation covers its bytes `8g` to `8g + 7`. The allocation starts on a multiple of 8.

Write `int shadow_byte(std::size_t size, std::size_t group)`, which returns what the shadow byte of group `group` says for an allocation of `size` bytes:

- `0` when all 8 bytes of the group are inside the allocation;
- `k`, from 1 to 7, when only the first `k` bytes of the group are inside it;
- `-1` when none of them are (the group is redzone, so ASan treats it as poisoned).

For example, a 13-byte allocation has group 0 fully addressable (0), group 1 partly addressable (5), and group 2 poisoned (-1).
--- starter

    return 0;
}
--- solution
#include <cstddef>

// 00 for a full group, 01 to 07 for a partial one, poisoned past the end.
int shadow_byte(std::size_t size, std::size_t group) {
    const std::size_t first = group * 8;         // the group's first byte
    if (first >= size) return -1;                // wholly past the end
    const std::size_t inside = size - first;     // bytes of the allocation from here on
    return inside >= 8 ? 0 : static_cast<int>(inside);
}
--- hint
Work out how many bytes of the allocation lie at or after the group's first byte, `8 × group`.
--- hint

+++ practice | A leak report from an allocation log
--- task
LeakSanitizer's summary is built from what was allocated and never freed. Write a small version of it that works on a log of events.

```cpp

```

An `'a'` event allocates block `id` of `bytes` bytes. An `'f'` event frees block `id` (its `bytes` is ignored). Block ids are never reused. Process the events in order:

- If an `'f'` names a block that has already been freed, stop at once and return `"attempting double-free on block N"`.
- If an `'f'` names a block that was never allocated, stop at once and return `"bad-free on block N"`.
- Otherwise, at the end, if nothing is still allocated, return `"no leaks"`. If something is, return `"Direct leak of B byte(s) in K object(s)"`, where K is how many blocks are still allocated and B their total size.
--- starter

#include <vector>

}
--- solution
#include <string>
#include <vector>

struct Event { char op; int id; int bytes; };

struct Block { int id; int bytes; bool live; };

std::string leak_report(const std::vector<Event>& log) {
    std::vector<Block> blocks;
    for (const Event& e : log) {
        if (e.op == 'a') {
            blocks.push_back(Block{e.id, e.bytes, true});
            continue;
        }
        Block* found = nullptr;
        for (Block& b : blocks) {
            if (b.id == e.id) found = &b;
        }
        if (found == nullptr) return "bad-free on block " + std::to_string(e.id);
        if (!found->live) return "attempting double-free on block " + std::to_string(e.id);
        found->live = false;
    }
    int count = 0;
    int bytes = 0;
    for (const Block& b : blocks) {
        if (b.live) {
            ++count;
            bytes += b.bytes;
        }
    }
    if (count == 0) return "no leaks";
    return "Direct leak of " + std::to_string(bytes) + " byte(s) in " + std::to_string(count) + " object(s)";
}
--- hint
Keep a vector of every block ever allocated, with its size and whether it is still live. A free looks the block up by id.
--- hint
The pointer to the found block is taken only after all the `push_back`s for this event are done, so it cannot dangle. A block found but not live is a double free; a block not found at all is a bad free.

--- check case | Everything freed

=> "no leaks"
--- check case | One of two freed

+++ practice | A quarantine that can be outrun
--- task
ASan catches a use after free because it does not hand a freed block straight back out. It poisons the block and holds it in a **quarantine**, oldest first, and only a block that has left the quarantine can be reused. Write a small model of that, to see both why it works and where it stops working.

```cpp
class ShadowHeap {
public:
    explicit ShadowHeap(int quarantine_size);
    int allocate();
    std::string release(int id);
    std::string access(int id) const;
};
```

- `allocate` reuses the block that left quarantine earliest, if there is one; otherwise it hands out a new id (0, 1, 2, … in order). The block becomes live.
- `release(id)`: if the block is live, it goes to the back of the quarantine and the call returns `"ok"`. If the quarantine now holds more than `quarantine_size` blocks, the oldest one leaves it and becomes reusable. If the block is not live, return `"attempting double-free"` and change nothing.
- `access(id)`: `"ok"` if the block is live; `"heap-use-after-free"` if it is in quarantine; `"unknown"` otherwise.

Notice what the checks show at the end: once a freed block has been reused, a stale access to it reads as `"ok"`. The bug is still there, but it is no longer caught.
--- starter
#include <string>
#include <vector>

class ShadowHeap {
public:
    explicit ShadowHeap(int quarantine_size) {}
    int allocate() { return -1; }
    std::string release(int id) { return ""; }
    std::string access(int id) const { return ""; }
};
--- solution
#include <cstddef>
#include <string>
#include <vector>

class ShadowHeap {
public:
    explicit ShadowHeap(int quarantine_size) : limit_(quarantine_size) {}

    int allocate() {
        int id;
        if (!reusable_.empty()) {
            id = reusable_.front();                       // left quarantine earliest
            reusable_.erase(reusable_.begin());
        } else {
            id = next_id_++;
            state_.push_back(kUnknown);
        }
        state_[static_cast<std::size_t>(id)] = kLive;
        return id;
    }

    std::string release(int id) {
        if (state_of(id) != kLive) return "attempting double-free";
        state_[static_cast<std::size_t>(id)] = kQuarantined;
        quarantine_.push_back(id);
        if (static_cast<int>(quarantine_.size()) > limit_) {
            const int oldest = quarantine_.front();
            quarantine_.erase(quarantine_.begin());
            state_[static_cast<std::size_t>(oldest)] = kReusable;
            reusable_.push_back(oldest);
        }
        return "ok";
    }

    std::string access(int id) const {
        switch (state_of(id)) {
            case kLive: return "ok";
            case kQuarantined: return "heap-use-after-free";   // still poisoned: caught
            default: return "unknown";
        }
    }

private:
    enum State { kUnknown, kLive, kQuarantined, kReusable };

    State state_of(int id) const {
        if (id < 0 || id >= next_id_) return kUnknown;
        return state_[static_cast<std::size_t>(id)];
    }

    int limit_;
    int next_id_ = 0;
    std::vector<State> state_;     // one entry per id handed out so far
    std::vector<int> quarantine_;  // oldest first
    std::vector<int> reusable_;    // in the order they left quarantine
};
--- hint
Give every id a state: live, quarantined, reusable. Keep the quarantine and the reusable blocks as two vectors used first-in, first-out: add at the back, take from the front.
--- hint
`release` first checks that the block is live. After adding it to the quarantine, if the quarantine is over its size, move its front block to the reusable list.

--- check test | Live blocks are fine, and new ids count up

--- check test | A freed block is not reused while it is in quarantine

--- check test | A double free is reported

#include <cstddef>
#include <cstdint>
#include <vector>

struct Field { std::size_t size; std::size_t align; };

// Real structs the checks compare against. Keep them.
struct Beacon { std::uint8_t id; std::uint32_t t_ms; std::uint16_t flags; };
struct Mixed { std::uint16_t a; double b; std::uint8_t c; };
struct Wide { std::uint8_t tag; alignas(16) unsigned char blob[16]; std::uint8_t tail; };

std::size_t round_up(std::size_t n, std::size_t align) {
    return (n + align - 1) / align * align;
}

// Each member goes at the next offset that is a multiple of its own alignment.
std::vector<std::size_t> offsets_of(const std::vector<Field>& fields) {
    std::vector<std::size_t> out;
    std::size_t offset = 0;
    for (const Field& f : fields) {
        offset = round_up(offset, f.align);
        out.push_back(offset);
        offset += f.size;
    }
    return out;
}

// The end is rounded up to the largest alignment, so every element of an array stays aligned.
std::size_t size_of(const std::vector<Field>& fields) {
    std::size_t offset = 0;
    std::size_t biggest = 1;
    for (const Field& f : fields) {
        offset = round_up(offset, f.align) + f.size;
        if (f.align > biggest) biggest = f.align;
    }
    return fields.empty() ? 0 : round_up(offset, biggest);
}
--- hint
Keep a running offset. For each member, round it up to a multiple of the member's alignment, record it, then add the member's size.
--- hint
At the end, round the offset up to the largest alignment of any member. That tail padding is what keeps `arr[1]` aligned in an array.

+++ practice | How many records fit
--- task
A memory budget holds as many records as fit. Using the same `Field` description as the layout recipe, write

```cpp
std::size_t records_that_fit(const std::vector<Field>& fields, std::size_t budget, bool reorder);
```

It returns how many whole records fit in `budget` bytes when the records are laid out as an array. With `reorder` false, the members are in the order given. With `reorder` true, the members are first sorted into decreasing order of alignment (members with equal alignment keep their relative order), which is the order that wastes least.

A record with no fields takes no space; return 0 for it. So does a budget smaller than one record.

For the six housekeeping fields (1, 8, 2, 4, 1 and 2 bytes, each aligned to its size), the record is 32 bytes as given and 24 reordered, so 4096 bytes hold 128 records as given and 170 reordered.
--- starter

#include <vector>

    return 0;
}
--- solution
#include <algorithm>
#include <cstddef>
#include <vector>

struct Field { std::size_t size; std::size_t align; };

std::size_t round_up(std::size_t n, std::size_t align) {
    return (n + align - 1) / align * align;
}

// sizeof a struct with these members, in this order.
std::size_t record_size(const std::vector<Field>& fields) {
    std::size_t offset = 0;
    std::size_t biggest = 1;
    for (const Field& f : fields) {
        offset = round_up(offset, f.align) + f.size;
        if (f.align > biggest) biggest = f.align;
    }
    return fields.empty() ? 0 : round_up(offset, biggest);
}

bool wider(const Field& a, const Field& b) { return a.align > b.align; }

std::size_t records_that_fit(const std::vector<Field>& fields, std::size_t budget, bool reorder) {
    std::vector<Field> order = fields;
    if (reorder) std::stable_sort(order.begin(), order.end(), wider);   // widest first, ties keep their order
    const std::size_t size = record_size(order);
    return size == 0 ? 0 : budget / size;
}
--- hint
First work out the record's size with the layout recipe: round each offset up to the member's alignment, then round the end up to the largest alignment.
--- hint
For the reordered layout, sort a copy of the fields with `std::stable_sort` and a comparison function that puts the larger alignment first. Then divide the budget by the record size.
--- check case | Housekeeping, as given

=> 128
--- check case | Housekeeping, reordered

+++ question | Work out a size
--- ask
On this platform `std::uint16_t` has alignment 2, `std::uint32_t` 4 and `double` 8. What is `sizeof(M)`? Type a whole number.

```cpp
struct M {
    std::uint16_t a;
    double        b;
    std::uint8_t  c;
    std::uint32_t d;
    std::uint8_t  e;
};
```
--- answer
32
--- why
`a` goes at 0 and fills bytes 0 to 1. `b` needs a multiple of 8, so it goes at 8 and fills 8 to 15. `c` goes at 16. `d` needs a multiple of 4, so it goes at 20 and fills 20 to 23. `e` goes at 24, bringing the running offset to 25. +++ practice | Big-endian fields, both ways
--- task
An interface control document says every multi-byte field on the link is big-endian: most significant byte first. Write four functions that work the same on any host, using shifts, never `memcpy`:

- `void put_u16_be(std::uint8_t* p, std::uint16_t v)` writes `v` into `p[0]` and `p[1]`;
- `std::uint16_t get_u16_be(const std::uint8_t* p)` reads it back;
- `void put_u32_be(std::uint8_t* p, std::uint32_t v)` writes `v` into `p[0]` to `p[3]`;
- `std::uint32_t get_u32_be(const std::uint8_t* p)` reads it back.

For example, `put_u32_be(p, 0x0A0B0C0D)` writes the bytes `0A 0B 0C 0D`.
--- starter
#include <cstdint>

void put_u16_be(std::uint8_t* p, std::uint16_t v) {}

--- solution
#include <cstdint>

// Every step works on the value, never on how it sits in memory, so the host's order never leaks in.
void put_u16_be(std::uint8_t* p, std::uint16_t v) {
    p[0] = static_cast<std::uint8_t>(v >> 8);
    p[1] = static_cast<std::uint8_t>(v);
}

std::uint16_t get_u16_be(const std::uint8_t* p) {
    return static_cast<std::uint16_t>((p[0] << 8) | p[1]);
}

void put_u32_be(std::uint8_t* p, std::uint32_t v) {
    for (int i = 0; i < 4; ++i) p[i] = static_cast<std::uint8_t>(v >> (8 * (3 - i)));
}

std::uint32_t get_u32_be(const std::uint8_t* p) {
    std::uint32_t v = 0;
    for (int i = 0; i < 4; ++i) v = (v << 8) | p[i];   // the first byte ends up most significant
    return v;
}
--- hint
For big-endian, the most significant byte goes first: `p[0]` gets `v >> 24` for 32 bits, or `v >> 8` for 16 bits. Casting to `std::uint8_t` keeps the lowest 8 bits.
--- hint
To read back, start from 0 and, for each byte in order, shift what you have left by 8 and or the byte in.

--- starter

--- solution
#include <cstdint>
#include <cstring>
#include <limits>

static_assert(std::numeric_limits<float>::is_iec559, "needs IEEE-754 binary32");
static_assert(sizeof(float) == 4);

// memcpy only turns the float into its bit pattern; the shifts decide the byte order.
void put_f32_be(std::uint8_t* p, float v) {
    std::uint32_t bits;
    std::memcpy(&bits, &v, sizeof bits);
    for (int i = 0; i < 4; ++i) p[i] = static_cast<std::uint8_t>(bits >> (8 * (3 - i)));
}

float get_f32_be(const std::uint8_t* p) {
    std::uint32_t bits = 0;
    for (int i = 0; i < 4; ++i) bits = (bits << 8) | p[i];
    float v;
    std::memcpy(&v, &bits, sizeof v);
    return v;
}
--- hint

--- hint

#include <cstdint>

struct PrimaryHeader {
    std::uint8_t type;        // 0 telemetry, 1 telecommand
    bool sec_hdr;             // a secondary header follows
    std::uint16_t apid;       // 11 bits
    std::uint8_t seq_flags;   // 2 bits
    std::uint16_t seq_count;  // 14 bits
    std::uint16_t data_len;   // 16 bits
};

void put_u16_be(std::uint8_t* p, std::uint16_t v) {
    p[0] = static_cast<std::uint8_t>(v >> 8);
    p[1] = static_cast<std::uint8_t>(v);
}

std::uint16_t get_u16_be(const std::uint8_t* p) {
    return static_cast<std::uint16_t>((p[0] << 8) | p[1]);
}

void encode_header(const PrimaryHeader& h, std::uint8_t* out) {
    // Mask every field to its width first, so a bad value cannot spill into its neighbour.
    const unsigned w0 = ((h.type & 0x1u) << 12) | ((h.sec_hdr ? 1u : 0u) << 11) | (h.apid & 0x7FFu);
    const unsigned w1 = ((h.seq_flags & 0x3u) << 14) | (h.seq_count & 0x3FFFu);
    put_u16_be(out, static_cast<std::uint16_t>(w0));
    put_u16_be(out + 2, static_cast<std::uint16_t>(w1));
    put_u16_be(out + 4, h.data_len);
}

PrimaryHeader decode_header(const std::uint8_t* in) {
    const unsigned w0 = get_u16_be(in);
    const unsigned w1 = get_u16_be(in + 2);
    PrimaryHeader h{};
    h.type = static_cast<std::uint8_t>((w0 >> 12) & 0x1u);
    h.sec_hdr = ((w0 >> 11) & 0x1u) != 0;
    h.apid = static_cast<std::uint16_t>(w0 & 0x7FFu);
    h.seq_flags = static_cast<std::uint8_t>((w1 >> 14) & 0x3u);
    h.seq_count = static_cast<std::uint16_t>(w1 & 0x3FFFu);
    h.data_len = get_u16_be(in + 4);
    return h;
}
--- hint
Build each 16-bit word as a number first: shift each field left to its position and join them with `|`. Then write the three words big-endian.
--- hint
Masks keep a field to its width: `& 0x7FF` for 11 bits, `& 0x3FFF` for 14, `& 0x3` for 2, `& 0x1` for 1. To decode, shift right and mask.

+++ practice | The bits of a double
--- task
Write three small functions on the bit pattern of an IEEE-754 `double`. Use `std::bit_cast` (or `std::memcpy`); never read a `double` through an integer pointer.

- `std::uint64_t double_bits(double x)` returns the 64-bit pattern of `x`.
- `bool sign_bit(double x)` returns whether the top bit (bit 63) is set. That is true for `-0.0`, which compares equal to `0.0`, so a `< 0` test would get it wrong.
- `double flip_sign(double x)` returns `x` with only bit 63 flipped.

For example, `double_bits(1.0)` is `0x3FF0000000000000`.
--- starter
#include <bit>
#include <cstdint>

double flip_sign(double x) { return x; }
--- solution
#include <bit>
#include <cstdint>

constexpr std::uint64_t kSignMask = std::uint64_t{1} << 63;

// bit_cast gives a new value with the same bits: no second pointer, so no aliasing question.
std::uint64_t double_bits(double x) { return std::bit_cast<std::uint64_t>(x); }

bool sign_bit(double x) { return (double_bits(x) & kSignMask) != 0; }

double flip_sign(double x) { return std::bit_cast<double>(double_bits(x) ^ kSignMask); }
--- hint

--- task

--- solution
#include <bit>
#include <cstdint>

struct FloatParts { bool negative; std::uint32_t exponent; std::uint32_t fraction; };

FloatParts parts_of(float f) {
    const std::uint32_t bits = std::bit_cast<std::uint32_t>(f);
    return FloatParts{(bits >> 31) != 0, (bits >> 23) & 0xFFu, bits & 0x7FFFFFu};
}

float from_parts(FloatParts p) {
    const std::uint32_t bits = (p.negative ? 1u << 31 : 0u) | ((p.exponent & 0xFFu) << 23) | (p.fraction & 0x7FFFFFu);
    return std::bit_cast<float>(bits);
}
--- hint

--- hint

// Looking at an object's bytes through unsigned char is always defined.
template <typename T>
std::uint8_t xor_bytes(const T& obj) {

+++ practice | The next float up
--- task
Write `float next_up(float x)`, which returns the smallest `float` greater than `x`, by working on the bit pattern with `std::bit_cast`. Do not call `std::nextafter`.

For positive floats the patterns count upward in the same order as the values, and for negative ones they count the other way. So:

- for a positive finite `x`, add 1 to the pattern;
- for a negative `x`, subtract 1 from the pattern (this moves toward zero), and that includes negative infinity, whose next value up is the most negative finite float;
- both `0.0f` and `-0.0f` give the smallest positive float, whose pattern is 1;
- positive infinity gives positive infinity, and a NaN is returned unchanged.

The checks compare your answers with `std::nextafter`.
--- starter

    return x;

--- solution
#include <bit>
#include <cstdint>

float next_up(float x) {
    if (x != x) return x;                                   // NaN is the only value not equal to itself
    const std::uint32_t bits = std::bit_cast<std::uint32_t>(x);
    if (bits == 0x7F800000u) return x;                      // +infinity has nothing above it
    if (x == 0.0f) return std::bit_cast<float>(std::uint32_t{1});   // +0 and -0: the smallest positive float
    const bool negative = (bits >> 31) != 0;
    return std::bit_cast<float>(negative ? bits - 1 : bits + 1);
}

+++ question | A reset pulse that vanished
--- ask
A driver resets a device by writing 1, then 0, then 1 to its control register, through a pointer declared `std::uint32_t* const kCtrl` that points at the register's fixed address. Built at `-O0` it works. Built at `-O2` the device never resets. What is the most likely cause?
--- choice
At `-O2` the three writes happen too quickly for the device to see them.
--- choice correct
The pointer is not to `volatile`, so the optimizer treats the first two stores as dead (each is overwritten before anything reads it) and emits only the last one.
--- choice
Strict aliasing lets the compiler reorder the writes, so the 0 lands last.
--- choice
`-O2` keeps the register's value in a CPU register, and it is never written to memory at all.
--- why
Without `volatile`, stores to ordinary memory that are overwritten before being read have no observable effect, so the compiler may delete them: only `*kCtrl = 1` survives, and there is no pulse. Declaring the pointee `volatile std::uint32_t` makes every access an observable side effect, so all three stores are emitted, in order. The last choice sounds close, but the final store is still emitted; it is the intermediate ones that go. Aliasing is about pointers of unrelated types, which this code does not have.

#include <cstddef>

class Samples {
public:
    inline static int live_buffers = 0;   // buffers currently allocated

    explicit Samples(int n) : n_(n), data_(n > 0 ? new double[n]() : nullptr) {
        if (data_) ++live_buffers;
    }
    ~Samples() {
        if (data_) --live_buffers;
        delete[] data_;
    }

    // Deep copy: a buffer of our own, holding the same values.
    Samples(const Samples& other) : n_(other.n_), data_(other.n_ > 0 ? new double[other.n_] : nullptr) {
        if (data_) ++live_buffers;
        for (int i = 0; i < n_; ++i) data_[i] = other.data_[i];
    }

    // Copy first, then swap it in, then free the old buffer: safe even when other is *this.
    Samples& operator=(const Samples& other) {
        if (this == &other) return *this;
        double* fresh = other.n_ > 0 ? new double[other.n_] : nullptr;
        for (int i = 0; i < other.n_; ++i) fresh[i] = other.data_[i];
        if (fresh) ++live_buffers;
        if (data_) --live_buffers;
        delete[] data_;
        data_ = fresh;
        n_ = other.n_;
        return *this;
    }

    int size() const { return n_; }
    double& operator[](int i) { return data_[i]; }
    const double* data() const { return data_; }

private:
    int n_;
    double* data_;
};
--- hint

+++ practice | The rule of five, by hand
--- task
`Frames` owns a heap array through a raw pointer. Its destructor, copy constructor and copy assignment are written and correct, and two counters watch it: `allocations` counts every buffer ever allocated, and `live` counts the buffers allocated now.

It has no move operations, so every `std::move` of a `Frames` copies. Add the other two of the five:

- a move constructor that takes over the source's buffer, allocating nothing, and leaves the source empty (size 0, null pointer);
- a move assignment that frees the target's own buffer, takes over the source's, and leaves the source empty. Moving an object into itself must leave it unchanged.

Mark both `noexcept`: they cannot fail, and saying so lets `std::vector` use them when it grows.
--- starter
#include <type_traits>
#include <utility>
#include <vector>

class Frames {
public:
    inline static int allocations = 0;   // buffers ever allocated
    inline static int live = 0;          // buffers allocated now

    explicit Frames(int n) : n_(n), data_(n > 0 ? new double[n]() : nullptr) { counted(); }
    ~Frames() { release(); }

    Frames(const Frames& other) : n_(other.n_), data_(other.n_ > 0 ? new double[other.n_] : nullptr) {
        counted();
        for (int i = 0; i < n_; ++i) data_[i] = other.data_[i];
    }

    Frames& operator=(const Frames& other) {
        if (this == &other) return *this;
        Frames copy(other);
        std::swap(n_, copy.n_);
        std::swap(data_, copy.data_);
        return *this;
    }

    int size() const { return n_; }
    double* data() const { return data_; }

private:
    void counted() { if (data_) { ++allocations; ++live; } }
    void release() { if (data_) --live; delete[] data_; data_ = nullptr; n_ = 0; }

    int n_;
    double* data_;
};
--- solution
#include <type_traits>
#include <utility>
#include <vector>

class Frames {
public:
    inline static int allocations = 0;   // buffers ever allocated
    inline static int live = 0;          // buffers allocated now

    explicit Frames(int n) : n_(n), data_(n > 0 ? new double[n]() : nullptr) { counted(); }
    ~Frames() { release(); }

    Frames(const Frames& other) : n_(other.n_), data_(other.n_ > 0 ? new double[other.n_] : nullptr) {
        counted();
        for (int i = 0; i < n_; ++i) data_[i] = other.data_[i];
    }

    Frames& operator=(const Frames& other) {
        if (this == &other) return *this;
        Frames copy(other);
        std::swap(n_, copy.n_);
        std::swap(data_, copy.data_);
        return *this;
    }

    // Take the pointer, leave the source empty: exactly one owner, nothing copied.
    Frames(Frames&& other) noexcept : n_(other.n_), data_(other.data_) {
        other.n_ = 0;
        other.data_ = nullptr;
    }

    Frames& operator=(Frames&& other) noexcept {
        if (this == &other) return *this;
        release();                 // our old buffer goes back first
        n_ = other.n_;
        data_ = other.data_;
        other.n_ = 0;
        other.data_ = nullptr;
        return *this;
    }

    int size() const { return n_; }
    double* data() const { return data_; }

private:
    void counted() { if (data_) { ++allocations; ++live; } }
    void release() { if (data_) --live; delete[] data_; data_ = nullptr; n_ = 0; }

    int n_;
    double* data_;
};

The move constructor copies the source's pointer and size into the new object, then sets the source's pointer to `nullptr` and its size to 0, so the source's destructor frees nothing.
--- hint

#include <type_traits>
#include <utility>

// The driver's C interface. Keep it.
int g_open = 0;
int g_closes = 0;
int g_next_handle = 100;
int radio_open(int band) {
    if (band < 0 || band > 3) return -1;
    ++g_open;
    return g_next_handle++;
}
void radio_close(int handle) {
    --g_open;
    ++g_closes;
}

// RAII: the constructor acquires, the destructor releases, and ownership moves but never copies.
class Channel {
public:
    explicit Channel(int band) : handle_(radio_open(band)) {}
    ~Channel() { close(); }

    Channel(const Channel&) = delete;
    Channel& operator=(const Channel&) = delete;

    Channel(Channel&& other) noexcept : handle_(other.handle_) { other.handle_ = -1; }

    Channel& operator=(Channel&& other) noexcept {
        if (this != &other) {
            close();                       // the channel we had is ours to close
            handle_ = other.handle_;
            other.handle_ = -1;            // the source no longer owns anything
        }
        return *this;
    }

    bool is_open() const { return handle_ != -1; }
    int handle() const { return handle_; }

    void close() {
        if (handle_ == -1) return;
        radio_close(handle_);
        handle_ = -1;
    }

private:
    int handle_ = -1;
};
--- hint
One member is enough: the handle, with -1 meaning "not open". Every function then tests it: `close` does nothing when it is -1, and a move sets the source's to -1.
--- hint
Declaring the copy pair `= delete` also stops the compiler writing the moves, so write the move constructor and move assignment yourself.

--- solution
#include <memory>
#include <utility>

int g_cards_alive = 0;

struct Card {
    int id;
    explicit Card(int i) : id(i) { ++g_cards_alive; }
    ~Card() { --g_cards_alive; }
};

class Rack {
public:
    std::unique_ptr<Card> install(std::unique_ptr<Card> card) {
        if (!card) return nullptr;
        for (std::unique_ptr<Card>& s : slots_) {
            if (!s) {
                s = std::move(card);   // the rack is now the owner
                return nullptr;
            }
        }
        return card;                   // full: ownership goes back to the caller
    }

    std::unique_ptr<Card> remove(int slot) {
        if (slot < 0 || slot >= kSlots) return nullptr;
        return std::move(slots_[slot]);   // leaves the slot empty
    }

    const Card* at(int slot) const {
        if (slot < 0 || slot >= kSlots) return nullptr;
        return slots_[slot].get();        // a look, not a transfer
    }

    int count() const {
        int n = 0;
        for (const std::unique_ptr<Card>& s : slots_) n += s ? 1 : 0;
        return n;
    }

private:
    static constexpr int kSlots = 4;
    std::unique_ptr<Card> slots_[kSlots];   // destroyed with the rack, cards and all
};
--- hint

#include <memory>
#include <vector>

int g_builds = 0;

struct Table {
    int id;
    std::vector<double> coeffs;
    explicit Table(int i) : id(i), coeffs(64, 0.5 * i) { ++g_builds; }
};

class TableCache {
public:
    std::shared_ptr<const Table> get(int id) {
        for (Entry& e : entries_) {
            if (e.id != id) continue;
            if (auto t = e.table.lock()) return t;   // still in use somewhere: share it
            auto fresh = std::make_shared<Table>(id);
            e.table = fresh;                         // expired: rebuild, remember weakly
            return fresh;
        }
        auto fresh = std::make_shared<Table>(id);
        entries_.push_back(Entry{id, fresh});
        return fresh;
    }

    int cached() const {
        int n = 0;
        for (const Entry& e : entries_) n += e.table.expired() ? 0 : 1;
        return n;
    }

private:
    struct Entry {
        int id;
        std::weak_ptr<const Table> table;   // observes: the users own the table, not the cache
    };
    std::vector<Entry> entries_;
};

Nothing: the compiler removes the copy, because the function never stores it.
--- why
Copying a `shared_ptr` allocates nothing and copies no `State`; it adds one to the strong count in the control block, and destroying the copy takes one away. Both must be atomic, because other threads may copy the same pointer at the same moment. With two threads the counter's cache line bounces between cores, which made each copy about fifty times slower in the lesson's measurement. The compiler cannot remove an atomic update. A function that only reads should take `const State&`.

#include <cstddef>
#include <new>
#include <string>
#include <utility>

int g_live = 0;

struct Part {
    int id;
    std::string name;
    Part(int i, std::string n) : id(i), name(std::move(n)) { ++g_live; }
    Part(const Part& o) : id(o.id), name(o.name) { ++g_live; }
    Part& operator=(const Part& o) = default;

template <typename T, std::size_t N>
class FixedList {
public:
    FixedList() = default;
    FixedList(const FixedList&) = delete;
    FixedList& operator=(const FixedList&) = delete;
    ~FixedList() {
        while (count_ > 0) slot(--count_)->~T();
    }

    bool push_back(const T& v) {
        if (count_ == N) return false;
        ::new (slot(count_)) T(v);
        ++count_;
        return true;
    }

    // Live objects are shifted down by assignment; only the last slot, now a spare copy, is destroyed.
    bool erase(std::size_t i) {
        if (i >= count_) return false;
        for (std::size_t k = i; k + 1 < count_; ++k) *slot(k) = std::move(*slot(k + 1));
        --count_;
        slot(count_)->~T();
        return true;
    }

    T& operator[](std::size_t i) { return *slot(i); }
    std::size_t size() const { return count_; }

private:
    T* slot(std::size_t i) { return reinterpret_cast<T*>(storage_) + i; }

    alignas(T) unsigned char storage_[sizeof(T) * N];
    std::size_t count_ = 0;
};

struct Frame { std::uint8_t id; std::uint16_t seq; float az; double temp_c; };

std::uint16_t get_u16_be(const std::uint8_t* p) {
    return static_cast<std::uint16_t>((p[0] << 8) | p[1]);
}

std::uint32_t get_u32_be(const std::uint8_t* p) {
    std::uint32_t v = 0;
    for (int i = 0; i < 4; ++i) v = (v << 8) | p[i];

    constexpr std::size_t kSize = 12;
    if (in.size() < kSize) return false;          // never read past what we were given
    const std::uint8_t* p = in.data();
    if (p[0] != 0xEB) return false;
    unsigned sum = 0;
    for (std::size_t i = 0; i < 10; ++i) sum += p[i];

    f.seq = get_u16_be(p + 2);

    f.temp_c = static_cast<std::int16_t>(get_u16_be(p + 8)) / 100.0;
    out = f;
    return true;
}

--- solution
#include <cstddef>
#include <span>
#include <vector>

// One pass: track the current run's start and length, remember the best run seen.
std::span<const double> longest_run(std::span<const double> s, double lo, double hi) {
    std::size_t best_start = 0;
    std::size_t best_len = 0;
    std::size_t start = 0;
    std::size_t len = 0;
    for (std::size_t i = 0; i < s.size(); ++i) {
        if (s[i] >= lo && s[i] <= hi) {
            if (len == 0) start = i;
            ++len;
            if (len > best_len) {                 // strictly longer: ties keep the earlier run
                best_len = len;
                best_start = start;
            }
        } else {
            len = 0;
        }
    }
    return s.subspan(best_start, best_len);       // a view into the caller's samples
}

public:

    explicit Trace(int n) : n_(n), data_(new double[n]()) { ++live; }
    ~Trace() {
        if (data_) --live;
        delete[] data_;

        ++live;
        copy_from(o);

    Trace& operator=(const Trace& o) {
        if (this == &o) return *this;
        Trace copy(o);
        std::swap(n_, copy.n_);
        std::swap(data_, copy.data_);
        return *this;

    // One owner at a time: the source gives the array up.
    Trace(Trace&& o) noexcept : n_(o.n_), data_(o.data_) {

        o.data_ = nullptr;
    }

    double& operator[](int i) { return data_[i]; }
    const double* data() const { return data_; }

private:
    void copy_from(const Trace& o) {
        for (int i = 0; i < n_; ++i) data_[i] = o.data_[i];
    }

    int n_;
    double* data_;

--- solution
#include <charconv>
#include <string>
#include <system_error>
#include <vector>

// True, with the value, when the whole token is a whole number.
bool parse_int(const std::string& t, int& value) {
    const char* first = t.data();
    const char* last = t.data() + t.size();
    auto [ptr, ec] = std::from_chars(first, last, value);
    return ec == std::errc() && ptr == last && first != last;
}

bool eval_rpn(const std::vector<std::string>& tokens, double& result) {
    constexpr int kSlots = 6;
    double stack[kSlots];
    int top = 0;
    for (const std::string& t : tokens) {
        int value = 0;
        if (parse_int(t, value)) {
            if (top == kSlots) return false;             // refuse rather than overrun
            stack[top++] = value;
            continue;
        }
        if (t != "+" && t != "-" && t != "*" && t != "/") return false;
        if (top < 2) return false;
        const double b = stack[--top];
        const double a = stack[--top];
        if (t == "/" && b == 0.0) return false;
        double r = 0.0;
        if (t == "+") r = a + b;
        else if (t == "-") r = a - b;
        else if (t == "*") r = a * b;
        else r = a / b;
        stack[top++] = r;
    }
    if (top != 1) return false;
    result = stack[0];
    return true;
}

#include <cstddef>
#include <cstdint>
#include <new>
#include <type_traits>

class Arena {
public:
    Arena(unsigned char* base, std::size_t cap) : base_(base), cap_(cap) {}

    // Align the address itself: the offset alone says nothing when base is misaligned.
    void* allocate(std::size_t n, std::size_t align) {
        const std::uintptr_t start = reinterpret_cast<std::uintptr_t>(base_);
        const std::uintptr_t here = start + used_;
        const std::uintptr_t aligned = (here + align - 1) & ~static_cast<std::uintptr_t>(align - 1);
        const std::size_t offset = static_cast<std::size_t>(aligned - start);
        if (offset > cap_ || n > cap_ - offset) return nullptr;
        used_ = offset + n;
        return base_ + offset;
    }

    void reset() { used_ = 0; }
    std::size_t used() const { return used_; }

private:
    unsigned char* base_;
    std::size_t cap_;
    std::size_t used_ = 0;
};

--- solution
#include <memory>
#include <string>
#include <utility>
#include <vector>

int g_nodes = 0;

struct Node {
    std::string name;
    Node* parent = nullptr;                          // owns nothing
    std::vector<std::unique_ptr<Node>> children;     // owns the children
    explicit Node(std::string n) : name(std::move(n)) { ++g_nodes; }
    ~Node() { --g_nodes; }
};

Node* add_child(Node& parent, const std::string& name) {
    auto child = std::make_unique<Node>(name);
    child->parent = &parent;
    Node* view = child.get();                        // taken before ownership moves
    parent.children.push_back(std::move(child));
    return view;
}

std::unique_ptr<Node> detach(Node& node) {
    Node* p = node.parent;
    if (p == nullptr) return nullptr;
    for (auto it = p->children.begin(); it != p->children.end(); ++it) {
        if (it->get() != &node) continue;
        std::unique_ptr<Node> owned = std::move(*it);   // take ownership out of the slot
        p->children.erase(it);                          // then remove the empty slot
        owned->parent = nullptr;
        return owned;
    }
    return nullptr;
}

std::string path(const Node& n) {
    std::string out = n.name;
    for (const Node* p = n.parent; p != nullptr; p = p->parent) out = p->name + "/" + out;
    return out;
}

+++ problem | Distance in floats
--- task
Two floats are "close" if few representable floats lie between them. Write:

- `std::int64_t ulp_distance(float a, float b)`, the number of steps from one representable `float` to the next that it takes to get from `a` to `b` (0 when they are equal). Positive and negative zero are the same value, so their distance is 0. If either argument is a NaN, return -1.
- `bool nearly_equal(float a, float b, int max_steps)`, which is `true` when the distance is from 0 to `max_steps`, and `false` otherwise, NaN included.

Work on the bit patterns with `std::bit_cast`. Positive floats count upward with their patterns; negative ones count the other way, so map each pattern to a number that increases with the float's value before you subtract.
--- starter
#include <bit>
#include <cstdint>

--- solution
#include <bit>
#include <cstdint>

// A number that increases with the float's value: +0 and -0 both map to 0.
std::int64_t ordered(float x) {
    const std::uint32_t bits = std::bit_cast<std::uint32_t>(x);
    const std::int64_t magnitude = bits & 0x7FFFFFFFu;
    return (bits >> 31) ? -magnitude : magnitude;
}

std::int64_t ulp_distance(float a, float b) {
    if (a != a || b != b) return -1;                 // NaN is not equal to itself
    const std::int64_t d = ordered(a) - ordered(b);
    return d < 0 ? -d : d;
}

bool nearly_equal(float a, float b, int max_steps) {
    const std::int64_t d = ulp_distance(a, b);
    return d >= 0 && d <= max_steps;
}

#include <bit>
#include <cstddef>
#include <cstdint>
#include <cstring>

struct Attitude { std::uint8_t mode; float q[4]; std::uint16_t seq; double t_s; };

// mode at 0, q at 4 to 19, seq at 20 to 21, t_s at 24 to 31: 32 bytes, 5 of them padding.
static_assert(sizeof(Attitude) == 32, "Attitude layout changed");

void put_le(std::uint8_t* p, std::uint64_t v, int bytes) {
    for (int i = 0; i < bytes; ++i) p[i] = static_cast<std::uint8_t>(v >> (8 * i));
}

std::uint64_t get_le(const std::uint8_t* p, int bytes) {
    std::uint64_t v = 0;
    for (int i = 0; i < bytes; ++i) v |= std::uint64_t{p[i]} << (8 * i);
    return v;
}

// Field by field, at offsets the protocol owns: the struct's padding never reaches the wire.
void to_wire(const Attitude& a, std::uint8_t* out) {
    out[0] = a.mode;
    for (int k = 0; k < 4; ++k) put_le(out + 1 + 4 * k, std::bit_cast<std::uint32_t>(a.q[k]), 4);
    put_le(out + 17, a.seq, 2);
    put_le(out + 19, std::bit_cast<std::uint64_t>(a.t_s), 8);
}

Attitude from_wire(const std::uint8_t* in) {
    Attitude a{};
    a.mode = in[0];
    for (int k = 0; k < 4; ++k) a.q[k] = std::bit_cast<float>(static_cast<std::uint32_t>(get_le(in + 1 + 4 * k, 4)));
    a.seq = static_cast<std::uint16_t>(get_le(in + 17, 2));
    a.t_s = std::bit_cast<double>(get_le(in + 19, 8));
    return a;
}

// Padding is not part of the value: compare the members, never the bytes.
bool same(const Attitude& x, const Attitude& y) {
    if (x.mode != y.mode || x.seq != y.seq || x.t_s != y.t_s) return false;
    for (int k = 0; k < 4; ++k) {
        if (x.q[k] != y.q[k]) return false;
    }
    return true;
}

+++ problem | Subscribers that may disappear
--- task
A publisher delivers values to subscribers that other parts of the program own through `shared_ptr`. It must never keep a subscriber alive by itself: when its owner lets go, the subscriber is destroyed, and the publisher forgets it.

```cpp

    void subscribe(const std::shared_ptr<Subscriber>& s);
    int publish(int value);
    int alive() const;

```

- `subscribe` remembers `s` without owning it. Subscribing the same subscriber twice adds it only once.
- `publish(value)` calls `on_value(value)` on every subscriber that still exists, in the order they subscribed, forgets every subscriber that no longer exists, and returns how many received the value.
- `alive` is how many remembered subscribers still exist.

`Subscriber` is in the starter. `g_calls` records the order of delivery: each delivery appends the subscriber's id as a digit.
--- starter

    int id;
    int received = 0;
    int last = 0;
    explicit Subscriber(int i) : id(i) {}
    void on_value(int v) { ++received; last = v; g_calls = g_calls * 10 + id; }
};

class Publisher {
public:
    void subscribe(const std::shared_ptr<Subscriber>& s) {}
    int publish(int value) { return 0; }
    int alive() const { return 0; }
};
--- solution
#include <memory>
#include <vector>

int g_calls = 0;

struct Subscriber {
    int id;
    int received = 0;
    int last = 0;
    explicit Subscriber(int i) : id(i) {}
    void on_value(int v) { ++received; last = v; g_calls = g_calls * 10 + id; }
};

class Publisher {
public:
    void subscribe(const std::shared_ptr<Subscriber>& s) {
        for (const std::weak_ptr<Subscriber>& w : subs_) {
            if (w.lock() == s) return;                 // already subscribed
        }
        subs_.push_back(s);                            // a weak_ptr: observes, never owns
    }

    int publish(int value) {
        int delivered = 0;
        std::vector<std::weak_ptr<Subscriber>> still;
        for (const std::weak_ptr<Subscriber>& w : subs_) {
            if (auto s = w.lock()) {                   // alive for the whole call
                s->on_value(value);
                ++delivered;
                still.push_back(w);
            }
        }
        subs_ = std::move(still);                      // the dead are forgotten
        return delivered;
    }

    int alive() const {
        int n = 0;
        for (const std::weak_ptr<Subscriber>& w : subs_) n += w.expired() ? 0 : 1;
        return n;
    }

private:
    std::vector<std::weak_ptr<Subscriber>> subs_;
};

+++ question | A use after free that goes unreported

ASan only checks accesses in the first few seconds of a run.
--- choice correct
Freed blocks sit poisoned in a quarantine of limited size. Once enough other memory has been freed, the old block leaves quarantine and is reused by a new allocation, so the stale access lands in live memory and looks valid.
--- choice
The optimizer removed the second access, because it was undefined behavior.
--- choice
ASan does not check reads, only writes.
--- why
ASan catches a use after free by keeping the freed block poisoned instead of handing it straight back to the allocator. That quarantine has a fixed budget. After it is exceeded, the oldest blocks are recycled, and a stale pointer into a recycled block points at a valid, addressable allocation, so the shadow check passes. +++ question | A big local on a small stack

`std::array` puts its elements on the heap when they do not fit, so nothing goes wrong.

It is exactly 1000000, because the two threads overwrite each other.
--- choice
It does not compile, because `volatile` variables cannot be shared between threads.
--- why
`volatile` only stops the compiler from removing or reordering accesses to that object relative to other volatile accesses. It gives no atomicity and no ordering between threads. `counter = counter + 1` is a read, an add and a write, and two threads interleave those steps and lose increments. Formally the program has a data race and so no defined meaning at all. The tool for this is `std::atomic<int>` (or a mutex).

+++ question | Why the arena is allowed in the loop
--- ask
Flight rules ban `new` inside the 1 kHz control loop but allow allocating from a bump arena that is reset at the start of each cycle. What is the property that makes the difference?
--- choice
The arena is faster on average.
--- choice correct
Every arena allocation is the same few instructions with no search and no lock, so its worst case equals its best case, and running out is a defined `nullptr` rather than a request that fails with memory still free.
--- choice
The arena can free individual objects, so it never fragments.
--- choice
The arena can never run out of memory.
--- why
The two arguments against the heap in a real-time loop are an unbounded worst-case time (free-list searches, locks, trips to the kernel) and fragmentation (a request that fails although enough memory is free). A bump arena removes both: allocation is round up, check, bump, whose cost does not depend on history, and a reset returns everything at once, so no holes form. It can run out, which is why its failure must be a defined value the caller checks. Average speed was never the argument.

+++ question | new[] released with delete
--- ask
`Sample` has a destructor that does real work. A program runs `Sample* s = new Sample[4];` and later `delete s;`. What is the most accurate description?
--- choice
It is fine: `delete` works out that it is an array.
--- choice
It leaks three of the four objects, but is otherwise harmless.
--- choice correct
It is undefined behavior. With a non-trivial destructor, `new[]` stores the element count just before the first element and returns a pointer past it, so plain `delete` runs one destructor and hands `operator delete` an address that was never the start of an allocation.
--- choice
It does not compile, because the types do not match.
--- why
`new` pairs with `delete` and `new[]` with `delete[]`; any other combination is undefined. The mechanism explains why it really breaks: for a type whose destructor does something, the array form allocates extra bytes for a hidden count (the array cookie), and only `delete[]` knows to step back over it and run every destructor. `-Wall` warns about the mismatch, and AddressSanitizer reports `alloc-dealloc-mismatch`.

+++ question | Counting owners
--- ask
What does this program print? Type the line exactly.

```cpp
#include <cstdio>
#include <memory>

int main() {
    auto a = std::make_shared<int>(5);
    auto b = a;
    std::weak_ptr<int> w = a;
    {
        auto c = w.lock();
        std::printf("%ld ", a.use_count());
    }
    b.reset();
    std::printf("%ld %d ", a.use_count(), w.expired() ? 1 : 0);
    a.reset();
    std::printf("%d\n", w.expired() ? 1 : 0);
}
```
--- answer
3 1 0 1
--- why
`a` and `b` own the int, and `w` only watches it, so the count is 2. Inside the block, `w.lock()` makes a third owner, `c`: 3. When the block ends, `c` goes, and `b.reset()` drops another owner, leaving 1; the int still exists, so `expired()` is false (0). `a.reset()` drops the last owner, the int is destroyed, and `w` now reports expired (1). A `weak_ptr` never changes the count.

+++ question | A global computed from another file's global
--- ask
`a.cpp` defines `double g_scale = compute_scale();`, and `compute_scale()` reads `g_base`, which `b.cpp` defines as `double g_base = read_config();`. With one build command the program works; with the object files linked in the other order, `g_scale` comes out as if `g_base` were 0.0. Which explanation and fix are right?
--- choice
The linker has a bug; pin the link order in the Makefile.
--- choice correct
Dynamic initialization of globals in different source files happens in an unspecified order, and before its turn `g_base` holds only its zero initialization. Make `g_base` a function-local static returned by a function, so it is built on first use, or give it a constant initializer.
--- choice
`g_base` needs to be declared `extern` in `a.cpp`.
--- choice
Globals are initialized in alphabetical order of their names; rename `g_base` so it sorts first.
--- why
Every object with static storage duration is first zeroed, and constant initializers are applied, before any code runs. Initializers that need a function call run afterwards, in order within one file but in an unspecified order across files. So `compute_scale()` may run before `read_config()` has, and read 0.0. A static local inside a function is initialized the first time control reaches it, which removes the ordering question; a `constexpr` or constant initializer removes the dynamic step altogether.
