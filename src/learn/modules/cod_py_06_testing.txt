+++ practice | A test built from facts outside the code
--- task
The function under test, `period(a)`, returns the period in seconds of a circular orbit of radius `a` meters: two pi times the square root of `a` cubed over mu, with mu equal to 3.986004418e14 cubic meters per second squared. It raises `ValueError` when `a` is zero or negative.

Write a test function `test_period(period)`. It takes the function under test as its argument, so the checks can hand it a correct version and several broken ones. Use plain `assert` statements.

- For a correct `period`, it returns quietly.
- For a broken one, it fails with an `AssertionError`.

Check facts you know without running the code:

- A geostationary orbit, radius 42164 km, has a period of one sidereal day, 86164 s. Accept anything within 1 s.
- Four times the radius gives exactly 8 times the period (Kepler's third law). Accept a ratio within 1e-9 of 8.
- `period(0.0)` and `period(-7.0e6)` both raise `ValueError`. If either returns a value instead, the test must fail.

The checks try versions that forget the square root, use `a` squared instead of `a` cubed, forget the two pi, and accept a radius of exactly zero.
--- starter
def test_period(period):
    """Fails with AssertionError when period(a) is not the circular-orbit period."""
    pass
--- solution
def test_period(period):
    """Fails with AssertionError when period(a) is not the circular-orbit period."""
    # A geostationary orbit goes round once per sidereal day.
    assert abs(period(42164.0e3) - 86164.0) < 1.0
    # Kepler's third law: the period grows as a to the power 1.5, and 4 ** 1.5 is 8.
    assert abs(period(4 * 7.0e6) / period(7.0e6) - 8.0) < 1e-9
    # A radius of zero or less is nonsense, and must be refused.
    for bad in (0.0, -7.0e6):
        try:
            period(bad)
        except ValueError:
            pass
        else:
            raise AssertionError(f"period({bad}) returned a value instead of raising ValueError")
--- hint
Each `assert` should use a number you know from outside the code: the length of a sidereal day, or the ratio Kepler's third law predicts. Never copy a number out of the function's own output.
--- hint
Python has no `pytest.raises` here, so build it by hand: call `period(bad)` inside `try`, let `except ValueError` pass, and put `raise AssertionError(...)` in the `else` branch, which runs only when nothing was raised.

+++ practice | Your own pytest.raises
--- task
Write a function `expect_raises(exc_type, fn, match=None)` that does the job of `pytest.raises` for one call.

- Call `fn()` with no arguments.
- If it raises `exc_type`, or any subclass of it, and `match` is `None`, return the exception object.
- If `match` is given, look for it in the exception's message with `re.search(match, str(exc))`, which finds the pattern anywhere in the text. Found: return the exception. Not found: raise `AssertionError` with a message that contains both the pattern and the exception's message.
- If `fn` raises some other kind of exception, do not catch it: let it pass through unchanged.
- If `fn` returns normally, raise `AssertionError("DID NOT RAISE ValueError")`, with the name of `exc_type` in place of `ValueError`.

So `expect_raises(ZeroDivisionError, lambda: 1 / 0)` returns the `ZeroDivisionError`, and `expect_raises(ValueError, lambda: 42)` raises `AssertionError("DID NOT RAISE ValueError")`.

Messages you did not write can change between Python versions. `math.sqrt(-1.0)` says `math domain error` up to Python 3.13, but `expected a nonnegative input, got -1.0` from 3.14, which is what the browser runs. The checks match it with `"domain|nonnegative"`, where `|` means either, so the same test passes on both.
--- starter

--- solution
import re


def expect_raises(exc_type, fn, match=None):
    """Call fn(); return the exc_type it raised, or fail the way pytest.raises does."""
    try:
        fn()
    except exc_type as exc:
        if match is not None and not re.search(match, str(exc)):
            raise AssertionError(f"Regex {match!r} does not match {str(exc)!r}") from None
        return exc
    raise AssertionError(f"DID NOT RAISE {exc_type.__name__}")
--- hint
`except exc_type as exc:` catches that type and all its subclasses, and nothing else. Anything else keeps travelling up, which is exactly what you want.
--- hint
If the `try` block finishes without an exception, the line after the whole `try` statement runs. That is where "DID NOT RAISE" belongs.

+++ practice | A tiny test runner
--- task
Write a function `run_tests(namespace)` that collects and runs tests the way pytest does, from a dictionary of names and objects in definition order, like a module's `globals()`.

Collect, in the dictionary's order:

- every function whose name starts with `test`;
- every class whose name starts with `Test` and that has no `__init__` of its own or inherited (that is, `cls.__init__ is object.__init__`). From such a class, collect each function in its own `__dict__`, in order, whose name starts with `test`. Each of these runs on a fresh instance of the class.

Run each test. It passes if it returns without raising, and fails if it raises any exception. Return a tuple `(progress, failed, code)`:

- `progress`: one character per test, `.` for a pass and `F` for a failure, in run order;
- `failed`: the node ids of the failing tests, in run order: the function's name, or `Class::method` for a method;
- `code`: 0 if every test passed, 1 if any failed, and 5 if nothing was collected.

So a namespace holding a passing `test_a`, a helper `check_b` and a failing `test_c` gives `(".F", ["test_c"], 1)`.
--- starter
def run_tests(namespace):
    pass
--- solution
def run_tests(namespace):
    """Collect and run tests from a namespace; return (progress, failed node ids, exit code)."""
    tests = []
    for name, obj in namespace.items():
        if isinstance(obj, type):
            if name.startswith("Test") and obj.__init__ is object.__init__:
                for meth, fn in vars(obj).items():
                    if meth.startswith("test") and callable(fn):
                        tests.append((f"{name}::{meth}", lambda cls=obj, meth=meth: getattr(cls(), meth)()))
        elif callable(obj) and name.startswith("test"):
            tests.append((name, obj))

    progress = ""
    failed = []
    for node_id, run in tests:
        try:
            run()
            progress += "."
        except Exception:
            progress += "F"
            failed.append(node_id)

    if not tests:
        return "", [], 5
    return progress, failed, 1 if failed else 0
--- hint
Collect first, run second. For a method, store something you can call later that builds a new instance and calls the method on it, so no two tests share an object.
--- hint
`isinstance(obj, type)` tells a class from a function. `vars(cls)` is the class's own dictionary, in the order the methods were written. Watch out for a `lambda` inside a loop: give it default arguments, or every one will see the last class and method.

+++ question | An assert that guards a thruster
--- ask
Flight code checks a quaternion before it commands the thrusters:

```python
assert abs(np.linalg.norm(q) - 1.0) < 1e-9, "quaternion is not unit length"
command_thrusters(q)
```

The program is launched with `python -O`, and a quaternion of length 1.3 arrives. What happens?
--- choice
An `AssertionError` is raised as usual, and the thrusters are not commanded.
--- choice correct
The `assert` line is not in the program at all, so the thrusters are commanded with the bad quaternion.
--- choice
The condition is still checked, but a failure is printed as a warning instead of raised.
--- choice
Python refuses to start, because `-O` cannot be used on a file that contains `assert`.
--- why
`python -O` sets `__debug__` to false, and the compiler then leaves every `assert` statement out of the bytecode: the condition is never even evaluated. A check that someone can switch off from outside cannot keep a vehicle safe. In shipped code, test the condition with `if` and raise a real error such as `ValueError`; keep `assert` for tests.

+++ practice | The window pytest.approx allows
--- task
Write two functions that follow `pytest.approx`'s rules for one number.

`approx_window(expected, rel=None, abs_=None)` returns the allowed gap around `expected`:

- neither given: the larger of `1e-6 * |expected|` and `1e-12`;
- only `abs_` given: exactly `abs_` (the relative part is switched off);
- only `rel` given: the larger of `rel * |expected|` and `1e-12`;
- both given: the larger of `rel * |expected|` and `abs_`.

`approx_eq(actual, expected, rel=None, abs_=None)` returns `True` when `actual` equals `expected` exactly, or when the gap `|actual - expected|` is no bigger than `approx_window(expected, rel, abs_)`. The window is measured from `expected` only, so `approx_eq(1.0, 2.0, rel=0.5)` is `True` while `approx_eq(2.0, 1.0, rel=0.5)` is `False`.
--- starter

    pass


def approx_eq(actual, expected, rel=None, abs_=None):
    pass
--- solution
def approx_window(expected, rel=None, abs_=None):
    """The gap pytest.approx allows around expected, with its rules for rel and abs."""
    if rel is None and abs_ is None:
        return max(1e-6 * abs(expected), 1e-12)
    if rel is None:
        return abs_
    if abs_ is None:
        return max(rel * abs(expected), 1e-12)
    return max(rel * abs(expected), abs_)


def approx_eq(actual, expected, rel=None, abs_=None):
    """True when actual is within the approx window around expected."""
    return actual == expected or abs(actual - expected) <= approx_window(expected, rel, abs_)
--- hint
There are four cases, decided by which of `rel` and `abs_` are `None`. Test `is None`, not truthiness: `abs_=0.0` is given, and means a window of exactly zero.
--- hint
The relative part always uses `abs(expected)`, never `actual`, which is why swapping the two can change the answer.

+++ practice | Many numbers at once, and the strange ones
--- task
`pytest.approx` also compares lists element by element. Write `approx_violations(actual, expected, rel=None, abs_=None)` that returns the list of positions where the two sequences do not match, in order.

- If the lengths differ, raise `ValueError`.
- The window around each expected value follows pytest's rules: neither given, the larger of `1e-6 * |e|` and `1e-12`; only `abs_`, exactly `abs_`; only `rel`, the larger of `rel * |e|` and `1e-12`; both, the larger of `rel * |e|` and `abs_`.
- Two values that are exactly equal always match. That includes two equal infinities.
- An infinite expected value matches only an equal actual value. Its window would be infinite, which would let anything through.
- NaN (not a number) never matches, not even another NaN.
- Otherwise a value matches when `|a - e|` is no bigger than the window.

So `approx_violations([0.1 + 0.2, 5.0], [0.3, 6.0])` is `[1]`.
--- starter

--- solution
import math


def window(e, rel, abs_):
    """pytest.approx's allowed gap around one expected value."""
    if rel is None and abs_ is None:
        return max(1e-6 * abs(e), 1e-12)
    if rel is None:
        return abs_
    if abs_ is None:
        return max(rel * abs(e), 1e-12)
    return max(rel * abs(e), abs_)


def approx_violations(actual, expected, rel=None, abs_=None):
    """Positions where actual and expected differ by more than pytest.approx allows."""
    if len(actual) != len(expected):
        raise ValueError(f"lengths differ: {len(actual)} and {len(expected)}")
    bad = []
    for i, (a, e) in enumerate(zip(actual, expected)):
        if a == e:
            continue
        if math.isnan(a) or math.isnan(e) or math.isinf(e):
            bad.append(i)
        elif abs(a - e) > window(e, rel, abs_):
            bad.append(i)
    return bad
--- hint
Deal with the special values first, in this order: exactly equal, then NaN or an infinite expected value, and only then the window.
--- hint
`nan == nan` is `False`, so an exact-equality test lets no NaN through by itself. `math.isinf(e)` catches an infinite expected value that the actual value did not equal.
--- check case | Rounding noise passes, a real difference does not

=> [1]

def allclose_report(actual, desired, rtol=1e-7, atol=0.0):
    """assert_allclose's findings for two 1-D arrays, or None when they agree."""
    a = np.asarray(actual, dtype=np.float64)
    d = np.asarray(desired, dtype=np.float64)
    if a.shape != d.shape:
        raise ValueError(f"shapes {a.shape} and {d.shape} differ")
    with np.errstate(invalid="ignore"):
        diff = np.abs(a - d)
        ok = (diff <= atol + rtol * np.abs(d)) | (np.isnan(a) & np.isnan(d)) | (a == d)
    if ok.all():
        return None
    bad = np.flatnonzero(~ok)
    worst = int(bad[np.argmax(diff[bad])])
    return {"mismatched": int(bad.size), "total": int(a.size), "worst": worst, "max_abs": float(diff[worst])}
--- hint
Build one boolean array `ok` from three conditions joined with `|`: inside the tolerance, both NaN, or exactly equal. Exactly equal covers two equal infinities, whose difference would be NaN.
--- hint
`np.flatnonzero(~ok)` gives the failing positions in order. `np.argmax` over their differences picks the first of the largest, and indexing back into those positions gives the element's own position.

def case_id(argnames, row, index):
    """The id pytest gives a parametrized case that has no id of its own."""
    names = [n.strip() for n in argnames.split(",")]
    values = [row] if len(names) == 1 else list(row)
    if len(values) != len(names):
        raise ValueError(f"{len(names)} names but {len(values)} values")
    parts = []
    for name, value in zip(names, values):
        if value is None or isinstance(value, (int, float, str, bool)):
            parts.append(str(value))
        else:
            parts.append(f"{name}{index}")
    return "-".join(parts)

def grid_ids(decorators):
    """Case ids of stacked parametrize decorators, listed top to bottom, in run order."""

def run_table(test, cases):
    """Run test over every case; collect passes and failures without stopping."""
    passed, failed = [], []
    for case_id, args in cases:
        try:
            test(*args)
        except Exception as exc:
            reason = type(exc).__name__
            if str(exc):
                reason += f": {exc}"
            failed.append((case_id, reason))
        else:
            passed.append(case_id)
    return {"passed": passed, "failed": failed}

Put the `try` inside the loop, around the single call. Then an exception ends only that case.

--- solution
from contextlib import contextmanager

MISSING = object()


@contextmanager
def patched_attr(obj, name, value):
    """Set obj.name to value inside the block; restore or remove it afterwards."""
    old = getattr(obj, name, MISSING)
    setattr(obj, name, value)
    try:
        yield
    finally:
        if old is MISSING:
            delattr(obj, name)
        else:
            setattr(obj, name, old)


@contextmanager
def patched_item(mapping, key, value):
    """Set mapping[key] (or remove it, for MISSING) inside the block; restore afterwards."""
    old = mapping.get(key, MISSING)
    if value is MISSING:
        mapping.pop(key, None)
    else:
        mapping[key] = value
    try:
        yield
    finally:
        if old is MISSING:
            mapping.pop(key, None)
        else:
            mapping[key] = old
--- hint

--- hint

--- solution
import inspect


def run_with_fixtures(test, fixtures):
    """Build the fixtures test names (and theirs), call test, tear down in reverse."""
    values = {}
    teardowns = []
    building = set()

    def build(name):
        if name in values:
            return values[name]
        if name not in fixtures:
            raise LookupError(f"fixture '{name}' not found")
        if name in building:
            raise RuntimeError(f"fixture '{name}' depends on itself")
        building.add(name)
        fn = fixtures[name]
        args = [build(p) for p in inspect.signature(fn).parameters]
        if inspect.isgeneratorfunction(fn):
            gen = fn(*args)
            values[name] = next(gen)
            teardowns.append(gen)
        else:
            values[name] = fn(*args)
        building.discard(name)
        return values[name]

    def tear_down():
        for gen in reversed(teardowns):
            for _ in gen:              # runs the code after the yield
                pass

    try:
        args = [build(p) for p in inspect.signature(test).parameters]
        return test(*args)
    finally:
        tear_down()

--- ask
This fixture's setup raises before it reaches `yield`:

```python

    handle = start_simulator()        # raises ConnectionError
```

def k_matches(node_id, expr):
    """True when pytest -k expr selects the test with this node id."""
    parts = node_id.split("::")
    names = [parts[0].split("/")[-1].lower()] + [p.lower() for p in parts[1:]]

    def word(w):
        return any(w.lower() in name for name in names)

    def factor(tokens):
        negate = False
        while tokens[0] == "not":
            negate = not negate
            tokens = tokens[1:]
        return word(tokens[0]) != negate

    tokens = expr.split()
    alternatives, current = [], []
    for t in tokens:
        if t == "or":
            alternatives.append(current)
            current = []
        else:
            current.append(t)
    alternatives.append(current)

    def conjunction(tokens):
        terms, term = [], []
        for t in tokens:
            if t == "and":
                terms.append(term)
                term = []
            else:
                term.append(t)
        terms.append(term)
        return all(factor(t) for t in terms)

    return any(conjunction(a) for a in alternatives)

--- solution
def m_select(tests, expr):
    """(selected node ids, number deselected) for pytest -m expr."""
    tokens = expr.replace("(", " ( ").replace(")", " ) ").split()
    if not tokens:
        raise ValueError("empty expression")

    def evaluate(markers):
        pos = 0

        def peek():
            return tokens[pos] if pos < len(tokens) else None

        def take():
            nonlocal pos
            if pos >= len(tokens):
                raise ValueError(f"unexpected end of {expr!r}")
            pos += 1
            return tokens[pos - 1]

        def or_expr():
            value = and_expr()
            while peek() == "or":
                take()
                value = and_expr() or value
            return value

        def and_expr():
            value = not_expr()
            while peek() == "and":
                take()
                value = not_expr() and value
            return value

        def not_expr():
            t = take()
            if t == "not":
                return not not_expr()
            if t == "(":
                value = or_expr()
                if take() != ")":
                    raise ValueError(f"missing ) in {expr!r}")
                return value
            if t in ("and", "or", ")"):
                raise ValueError(f"unexpected {t!r} in {expr!r}")
            return t in markers

        value = or_expr()
        if pos != len(tokens):
            raise ValueError(f"unexpected {tokens[pos]!r} in {expr!r}")
        return value

    evaluate(set())                     # a bad expression fails even with no tests
    selected = [node for node, markers in tests if evaluate(markers)]
    return selected, len(tests) - len(selected)

--- ask
A test is marked `@pytest.mark.xfail(reason="drag above Mach 5 not implemented", strict=True)`. A teammate implements the drag table, and the test now passes. What does the next run report for it, and what is pytest's exit code if every other test passed?

`XPASS`, a quiet note in the summary; the exit code is 0.
--- choice
`PASSED`; the marker is ignored once the test passes, and the exit code is 0.
--- choice correct
A failure, `XPASS(strict)`; the exit code is 1, so the run goes red until someone removes the marker.
--- choice
`SKIPPED`, because an xfail test is not run at all; the exit code is 0.
--- why
An xfail marker is a promise that the test fails today for a known reason. With `strict=True`, breaking that promise, by passing, counts as a failure, and a failure makes the exit code 1. import numpy as np


def for_all(prop, gen, n=100, seed=0):
    """The first generated input for which prop raises, or None if all n pass."""
    rng = np.random.default_rng(seed)
    for _ in range(n):
        x = gen(rng)
        try:
            prop(x)
        except Exception:
            return x
    return None

--- solution
def shrink_int(fails, x):
    """Shrink a failing whole number toward zero until no simpler candidate still fails."""
    while True:
        candidates = [0, int(x / 2)]
        if x > 0:
            candidates.append(x - 1)
        elif x < 0:
            candidates.append(x + 1)
        for c in candidates:
            if c != x and fails(c):
                x = c
                break
        else:
            return x

import math


def unit(v):
    """v scaled to length 1; ValueError for a zero or non-finite vector."""
    if not all(math.isfinite(c) for c in v):
        raise ValueError(f"not a finite vector: {v!r}")
    big = max(abs(c) for c in v)

    scaled = [c / big for c in v]
    n = math.hypot(*scaled)
    return tuple(c / n for c in scaled)

import numpy as np


def quat_violations(qmul, q_to_dcm, n=200, seed=0):
    """Sorted names of the quaternion invariants this library breaks."""
    rng = np.random.default_rng(seed)
    qs = rng.normal(size=(2 * n, 4))
    qs /= np.linalg.norm(qs, axis=1, keepdims=True)
    broken = set()
    for k in range(n):
        p, q = qs[k], qs[n + k]
        if abs(np.linalg.norm(qmul(p, q)) - 1.0) > 1e-12:
            broken.add("unit")
        if np.max(np.abs(q_to_dcm(p) - q_to_dcm(-p))) > 1e-12:
            broken.add("double-cover")
        if np.max(np.abs(q_to_dcm(qmul(p, q)) - q_to_dcm(p) @ q_to_dcm(q))) > 1e-12:
            broken.add("product")
    return sorted(broken)

from pathlib import Path


def save_golden(path, rows, header):
    """Write rows as CSV at full precision, under a '# header' line."""
    lines = [f"# {header}"]
    for row in rows:
        lines.append(",".join("%.17g" % x for x in row))
    Path(path).write_text("\n".join(lines) + "\n")

    """Read a golden file back: a list of rows of floats, skipping # lines and blanks."""
    rows = []
    for line in Path(path).read_text().splitlines():

    return rows

import math


def observed_orders(errors):
    """log2 of each ratio of neighboring errors, one halving of the step apart."""
    if len(errors) < 2:
        raise ValueError("need errors from at least two step sizes")
    if any(e <= 0 for e in errors):

import numpy as np


def verlet(x, v, h, n, accel):
    """n steps of velocity Verlet from (x, v); returns the final (x, v)."""
    x = np.array(x, dtype=float)
    v = np.array(v, dtype=float)
    a = accel(x)
    for _ in range(n):
        v_half = v + 0.5 * h * a
        x = x + h * v_half
        a = accel(x)
        v = v_half + 0.5 * h * a
    return x, v

+++ question | An order of minus a quarter
--- ask
A convergence test runs RK4 on a spring with steps of 1e-3 s and 5e-4 s. The errors at the end time come out as 1.1e-15 and 1.3e-15, so the observed order is about -0.24. What is going on?
--- choice
The RK4 has a bug that makes it diverge as the step shrinks.
--- choice correct
Both errors are at the rounding floor of double precision, so their ratio is noise; the steps are far below the asymptotic range, and the test should use larger steps.
--- choice
RK4's order drops to zero for very small steps, as every method's does, so -0.24 is expected.
--- choice
The exact solution used for comparison must be wrong in its last digits.
--- why
`e(h) = C h^4` only holds while the method's own error dwarfs rounding. At h = 1e-3 the RK4 error on this problem would be around 1e-14 or less, and the answer can never be closer to the truth than a few times machine epsilon, about 1e-15 here. Once both errors sit at that floor, their ratio is a coin toss. Choose steps whose errors land well above rounding, roughly 1e-4 to 1e-11 for RK4, and the observed order comes back to 4.

class ScriptedSensor:
    """A stub sensor: read() hands out a script of readings and exceptions, one per call."""

    def __init__(self, values):
        self.values = list(values)
        self.calls = 0

    def read(self):
        self.calls += 1
        if self.calls > len(self.values):
            raise RuntimeError("script exhausted")
        item = self.values[self.calls - 1]
        if isinstance(item, BaseException) or (isinstance(item, type) and issubclass(item, BaseException)):

        return item

class FakeGyro:

    def __init__(self, rate_hz=100.0, bias=0.002, sigma=0.0005, seed=0, true_rate=None):

--- solution
def line_report(statements, executed):
    """(Stmts, Miss, Cover, Missing) for one file, as coverage.py prints them."""
    missed = [s for s in statements if s not in executed]
    stmts, miss = len(statements), len(missed)
    pc = 100.0 * (stmts - miss) / stmts if stmts else 100.0
    if 0 < pc < 1:
        shown = 1
    elif 99 < pc < 100:
        shown = 99
    else:
        shown = round(pc)
    runs = []
    for s in statements:
        if s in executed:
            if runs and runs[-1]:
                runs.append([])        # a statement that ran ends the current run
        else:
            if not runs:
                runs.append([])
            runs[-1].append(s)
    parts = [str(r[0]) if len(r) == 1 else f"{r[0]}-{r[-1]}" for r in runs if r]
    return stmts, miss, f"{shown}%", ", ".join(parts)

+++ practice | Branches in the report
--- task
Write `branch_report(statements, executed, arcs, taken)` that adds branch coverage to a report row.

- `statements` and `executed` are as in a line report: the statements' line numbers in increasing order, and the set of lines that ran.
- `arcs` is the list of possible branch exits, each a pair `(from_line, to_line)`: an `if` on line 16 whose false side jumps to line 18 gives `(16, 18)`. `taken` is the set of exits that happened.
- Return `(branch, partial, cover, missing)`.
- `branch` is the number of possible exits. `partial` is the number of decision lines that took at least one of their exits and missed at least one.
- `cover` counts statements and exits together: statements that ran plus exits taken, over statements plus exits, as a whole-number percentage with Python's `round` and a `%` sign.
- `missing` lists each missed statement as its number, and each exit not taken as `from->to`, but only when neither of its two lines is itself a missed statement: a missed line already says that the jump to it never happened. Sort everything by its first number, putting a line before an exit that starts at the same number, and join with `", "`.
--- starter

    pass
--- solution
def branch_report(statements, executed, arcs, taken):
    """(Branch, BrPart, Cover, Missing) for one file with branch coverage on."""
    missed = [s for s in statements if s not in executed]
    missed_set = set(missed)
    decisions = {}
    for a, b in arcs:
        decisions.setdefault(a, []).append((a, b))
    partial = sum(1 for exits in decisions.values()
                  if any(e in taken for e in exits) and any(e not in taken for e in exits))
    run = len(statements) - len(missed)
    got = sum(1 for e in arcs if e in taken)
    total = len(statements) + len(arcs)
    cover = f"{round(100.0 * (run + got) / total) if total else 100}%"
    items = [(s, 0, str(s)) for s in missed]
    for a, b in arcs:
        if (a, b) not in taken and a not in missed_set and b not in missed_set:
            items.append((a, 1, f"{a}->{b}"))
    items.sort()
    return len(arcs), partial, cover, ", ".join(text for _, _, text in items)
--- hint
Group the exits by their starting line; each group is one decision. A decision is partial when some of its exits are in `taken` and some are not.
--- hint
For sorting, give each item a key such as `(line, 0)` for a missed statement and `(from_line, 1)` for an exit, so a line comes before an exit that starts at the same number.

--- task
Write `coverage_gate(statements, missed, fail_under, precision=0)` that decides whether a run passes a `fail_under` floor, exactly as coverage.py does.

- The total is `100 * (statements - missed) / statements`, or 100 when there are no statements.
- The run fails when `fail_under` is 100 and the total is anything but exactly 100. Otherwise it fails when `round(total, precision)` is less than `fail_under`.
- Return a tuple: the total as text with `precision` decimals and a `%` sign (with `f"{total:.{precision}f}%"`), and the exit code, 1 for a failed floor and 0 otherwise.

So 444 of 480 statements run against a floor of 90 gives `("92.5%", 0)` with `precision=1`. Notice the rounding: with the default precision of 0, a total of 89.6 rounds to 90 and passes a floor of 90.
--- starter

    pass
--- solution
def coverage_gate(statements, missed, fail_under, precision=0):
    """(total as text, exit code) for a coverage run against a fail_under floor."""
    total = 100.0 * (statements - missed) / statements if statements else 100.0
    if fail_under == 100:
        failed = total != 100.0
    else:
        failed = round(total, precision) < fail_under
    return f"{total:.{precision}f}%", 1 if failed else 0
--- hint
Handle the floor of 100 on its own first: there, only a total of exactly 100 passes, however it would round.
--- hint
`round(total, precision)` rounds to that many decimals. Python rounds a value exactly halfway to the even neighbor, so `round(88.5)` is 88.

def ruff_summary(lines):
    """Totals, safe fixes, files and rule families of a ruff concise run."""
    total, fixable, files, families = 0, 0, set(), {}
    for line in lines:

def lint_docstring(doc, params):
    """numpydoc-style codes for what this docstring is missing, in a fixed order."""
    lines = [l.strip() for l in doc.splitlines()]
    starts = {}
    for i in range(len(lines) - 1):
        t = lines[i]
        if t and lines[i + 1] == "-" * len(t):
            starts[i] = t
    sections = {}
    order = sorted(starts)
    for k, i in enumerate(order):
        end = order[k + 1] if k + 1 < len(order) else len(lines)
        sections[starts[i]] = lines[i + 2:end]

    codes = []
    summary = next((l for l in lines if l), "")
    if not summary[:1].isupper():
        codes.append("SS02")
    if not summary.endswith("."):
        codes.append("SS03")
    entries = sections.get("Parameters", [])
    if any(not any(e.startswith(f"{p} : ") for e in entries) for p in params):
        codes.append("PR01")
    if "Returns" not in sections:
        codes.append("RT01")
    if "Examples" not in sections:
        codes.append("EX01")
    return codes

--- task
Write `parse_examples(doc)` that finds the examples in a docstring the way doctest does, and returns them as a list of `(source, want)` pairs.

--- starter

--- solution
def parse_examples(doc):
    """(source, want) pairs for the >>> examples in a docstring."""
    lines = doc.splitlines()
    examples = []
    i = 0
    while i < len(lines):
        text = lines[i].lstrip()
        if not text.startswith(">>> "):
            i += 1
            continue
        indent = len(lines[i]) - len(text)
        source = [text[4:]]
        i += 1
        while i < len(lines) and lines[i][indent:].startswith("... "):
            source.append(lines[i][indent + 4:])
            i += 1
        want = []
        while i < len(lines) and lines[i].strip() and not lines[i].lstrip().startswith(">>>"):
            want.append(lines[i][indent:])
            i += 1
        examples.append(("\n".join(source), "\n".join(want)))
    return examples

import doctest
import inspect


def doc_report(namespace):
    """Undocumented public functions, and (attempted, failed) doctests for the others."""
    undocumented, results = [], {}
    finder, runner = doctest.DocTestFinder(), doctest.DocTestRunner()
    for name, obj in namespace.items():
        if not inspect.isfunction(obj) or name.startswith("_"):
            continue
        if not (obj.__doc__ or "").strip():
            undocumented.append(name)
            continue
        attempted = failed = 0
        for test in finder.find(obj, globs=dict(namespace)):
            r = runner.run(test, out=lambda s: None)
            attempted += r.attempted
            failed += r.failed
        results[name] = (attempted, failed)
    return {"undocumented": undocumented, "results": results}

import numpy as np
from numpy.testing import assert_allclose


def random_unit_quaternions(n, seed=0):
    q = np.random.default_rng(seed).normal(size=(n, 4))
    return q / np.linalg.norm(q, axis=1, keepdims=True)


def assert_proper_rotation(C):
    assert np.all(np.isfinite(C))
    assert_allclose(C @ C.T, np.eye(3), rtol=0, atol=1e-12)
    assert abs(np.linalg.det(C) - 1.0) < 1e-12

# Tolerance: 1e-9 of each column's largest value, as an absolute tolerance per column.
# Measured noise, simulate() against simulate(grouping="b"): about 1e-16 of scale.
# Smallest physics change to catch, g 9.80665 -> 9.81: about 5e-4 of scale.
REL_TO_SCALE = 1e-9


def check_golden(run, path, update=False):
    """Compare run() with the golden file at path, column by column; rewrite it only on request."""
    got = np.array(run(), dtype=float)
    if update:
        np.savetxt(path, got, fmt="%.17g", delimiter=",")
    elif not os.path.exists(path):
        raise FileNotFoundError(f"no golden file at {path}")
    ref = np.loadtxt(path, delimiter=",", ndmin=2)
    if got.shape != ref.shape:
        raise AssertionError(f"shape {got.shape} differs from the golden {ref.shape}")
    atol = REL_TO_SCALE * np.abs(ref).max(axis=0)
    diff = np.abs(got - ref)
    for c, name in enumerate(["t", "h", "v", "m"][: ref.shape[1]]):
        if np.any(diff[:, c] > atol[c]):
            raise AssertionError(f"column {name}: off by up to {diff[:, c].max()!r}, tolerance {atol[c]!r}")
    return "ok"

def certify(step, accel, energy, x0, v0, h, n):
    """Observed order, time-reversibility and energy growth of an integrator."""
    x0 = np.asarray(x0, dtype=float)
    v0 = np.asarray(v0, dtype=float)

        for _ in range(k):
            x, v = step(x, v, hh, accel)
        return x, v

    order = float(np.log2(np.linalg.norm(finals[0] - finals[1]) / np.linalg.norm(finals[1] - finals[2])))

    reversible = bool(
        np.linalg.norm(xb - x0) <= 1e-9 * max(1.0, np.linalg.norm(x0))
        and np.linalg.norm(-vb - v0) <= 1e-9 * max(1.0, np.linalg.norm(v0))
    )

    errs = []
    x, v = x0, v0
    for _ in range(n):

        errs.append(abs(energy(x, v) / e0 - 1.0))
    q = n // 4
    growth = float(max(errs[-q:]) / max(errs[:q]))
    return {"order": order, "reversible": reversible, "energy_growth": growth}

from itertools import combinations, product


def mcdc_cases(decision, n):
    """A smallest set of inputs in which every condition is shown to change the result alone."""
    inputs = list(product([False, True], repeat=n))
    result = {x: bool(decision(*x)) for x in inputs}

    def shows(i, chosen):
        return any(
            a[i] != b[i] and a[:i] + a[i + 1:] == b[:i] + b[i + 1:] and result[a] != result[b]
            for a in chosen for b in chosen
        )

    for i in range(n):
        if not shows(i, inputs):
            raise ValueError(f"condition {i} never changes the result on its own")
    for size in range(2, len(inputs) + 1):
        for chosen in combinations(inputs, size):
            if all(shows(i, chosen) for i in range(n)):
                return list(chosen)

import inspect


def run_suite(tests, fixtures):
    """Run tests with parametrized cases and yield fixtures; return (progress, failed ids, exit code)."""
    progress, failed = "", []
    for name, fn, cases in tests:
        runs = [(None, {})] if cases is None else cases
        for case_id, args in runs:
            node = name if case_id is None else f"{name}[{case_id}]"
            started, values, outcome = [], {}, "."
            try:
                for p in inspect.signature(fn).parameters:
                    if p in args:
                        values[p] = args[p]
                    elif p in fixtures:
                        gen = fixtures[p]()
                        values[p] = next(gen)
                        started.append(gen)
                    else:
                        raise LookupError(f"fixture '{p}' not found")
            except Exception:
                outcome = "E"
            if outcome == ".":
                try:
                    fn(**values)
                except Exception:
                    outcome = "F"
            for gen in reversed(started):
                for _ in gen:
                    pass
            progress += outcome
            if outcome != ".":
                failed.append(node)
    if not progress:
        return "", [], 5
    return progress, failed, 1 if failed else 0

import numpy as np


def candidates(xs):
    """Simpler lists to try, in order: shorter first, then smaller elements."""
    for i in range(len(xs)):
        yield xs[:i] + xs[i + 1:]
    for i, x in enumerate(xs):
        if x != 0:
            yield xs[:i] + [0] + xs[i + 1:]
    for i, x in enumerate(xs):
        if int(x / 2) != x:
            yield xs[:i] + [int(x / 2)] + xs[i + 1:]
    for i, x in enumerate(xs):
        if x != 0:
            yield xs[:i] + [x - 1 if x > 0 else x + 1] + xs[i + 1:]


def find_minimal(prop, gen, n=200, seed=0):
    """The first failing generated list, shrunk until no simpler candidate fails; or None."""
    def fails(xs):
        try:
            prop(list(xs))
        except Exception:
            return True
        return False

    rng = np.random.default_rng(seed)
    for _ in range(n):
        xs = list(gen(rng))
        if fails(xs):
            while True:
                for c in candidates(xs):
                    if fails(c):
                        xs = c
                        break
                else:
                    return xs

+++ problem | Plan the fast suite from --durations output
--- task
Write `plan_fast_suite(lines, budget, keep=())` that reads the output of `pytest --durations=0` and decides which tests to mark `slow` so the fast suite fits a time budget.

- A duration line has exactly three parts separated by spaces: a time with two decimals and an `s` (`3.00s`), the phase (`setup`, `call` or `teardown`), and a node id. Ignore every other line, such as `9 passed in 5.20s`.
- A test's time is the sum of its phases. Work in whole hundredths of a second, so no rounding error creeps in: `round(seconds * 100)`, and the same for `budget`, which is in seconds.
- Mark tests slow one at a time, the slowest first (ties: the smaller node id first), skipping any in `keep`, which must stay in the fast suite, until the unmarked total is no more than the budget.
- If that is impossible even with every test outside `keep` marked, raise `ValueError`.

Return a tuple: the sorted list of node ids to mark, and the fast suite's total in seconds, a float with two decimals at most.
--- starter
def plan_fast_suite(lines, budget, keep=()):
    pass
--- solution
def plan_fast_suite(lines, budget, keep=()):
    """(tests to mark slow, fast-suite seconds) so the unmarked tests fit the budget."""
    totals = {}
    for line in lines:
        parts = line.split()
        if len(parts) != 3 or not parts[0].endswith("s") or parts[1] not in ("setup", "call", "teardown"):
            continue
        try:
            hundredths = round(float(parts[0][:-1]) * 100)
        except ValueError:
            continue
        totals[parts[2]] = totals.get(parts[2], 0) + hundredths
    limit = round(budget * 100)
    fast = sum(totals.values())
    marked = []
    for node in sorted(totals, key=lambda n: (-totals[n], n)):
        if fast <= limit:
            break
        if node in keep:
            continue
        marked.append(node)
        fast -= totals[node]
    if fast > limit:
        raise ValueError(f"the tests in keep alone take {fast / 100:.2f} s, over the budget")
    return sorted(marked), fast / 100

--- ask
Which of these assertions passes?

--- choice

+++ question | Order from three step sizes
--- ask
An integrator with no known exact answer is run to the same end time with steps `h`, `h/2` and `h/4`. The final states differ by `|y_h - y_h2| = 6.4e-5` and `|y_h2 - y_h4| = 1.6e-5`. What is the observed order?
--- answer
2
2.0

--- why
Both differences shrink like `h^p`, one halving apart, so their ratio is `2^p`. Here the ratio is 6.4e-5 / 1.6e-5 = 4, and log2 of 4 is 2. The unknown true answer cancels out, which is why three runs are enough when there is no exact solution to compare with.
