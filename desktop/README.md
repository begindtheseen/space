# ORBIT desktop shell

The Mac app is a thin Electron shell around the web build. It has no npm runtime
dependencies — Node and Electron built-ins only — and it never bundles the web app
into itself: `dist/` travels beside the shell as a *bundle*, and the updater can
replace that bundle without a new app. This file is the condensed architecture; the
user-facing story is in the root README ("Install on a Mac", "Updates", "Publishing an
update").

## Files

| File | Role |
| --- | --- |
| `main.js` | Entry point. Boot sequence, environment overrides, fatal-error handling |
| `paths.js` | Every filesystem location, derived from this directory or `userData` |
| `protocol.js` | Serves the active bundle at `app://orbit/` |
| `window.js` | Main window, bounds persistence, navigation and permission guards |
| `splash.js`, `splash.html`, `splash/` | Splash window (photo, font, credit in `SOURCE.json`) |
| `menu.js` | macOS menu: About, Check for Updates…, Edit, View, Window, Help |
| `preload.cjs` | The `window.orbit` bridge (CommonJS: preloads must be) |
| `ipc.js` | Main-side IPC handlers; validates every argument |
| `config.js` | `config.json`: the GitHub token, encrypted with `safeStorage` |
| `updater.js` | Pure-Node updater: resolve, check, download, apply, rollback, quarantine |
| `zip.js`, `crc32.js` | Dependency-free zip extraction (store + deflate, CRC-checked) |
| `semver.js` | `parse`, `compare`, `gt`, `gte`, `valid`; prerelease < release |
| `test/*.test.ts` | Vitest unit tests for the updater, zip reader, semver, crc32 |
| `test/e2e.mjs` | Playwright end-to-end run against a fake GitHub API |
| `icon/icon.png` | 1024² app icon, generated by `scripts/make-icon.mjs` |

## Versions

`package.json` is the single source of truth:

```jsonc
{
  "version": "1.0.0",                                  // shell version and bundle version
  "orbit": {
    "updates": { "repo": "begindtheseen/space" },      // GitHub owner/repo hosting Releases
    "minShell": "1.0.0"                                // oldest shell that may run this bundle
  }
}
```

- Shell version: `app.getVersion()`.
- Bundle version: `dist/orbit-bundle.json` → `{ version, minShell, builtAt, commit }`,
  stamped by `scripts/stamp-bundle.mjs` after `vite build`.
- Release tag `vX.Y.Z` must equal `package.json.version`; CI refuses otherwise.
- Bump `orbit.minShell` whenever `desktop/` changes in a way old shells cannot run.

## Where things are at runtime

Packaged (`ORBIT.app/Contents/Resources/`):

```
app.asar        desktop/** + package.json
dist/           the built-in bundle (extraResources, outside the asar)
```

In development (`electron .` from the repo) the built-in bundle is `<repo>/dist`.

`userData` (`~/Library/Application Support/ORBIT/`):

```
bundles/
  current.json   { "version": "1.0.1" | null, "previous": "1.0.0" | null }
  bad.json       { "versions": ["1.0.1"] }   quarantined by the boot watchdog
  1.0.1/         an extracted bundle: index.html, assets/, orbit-bundle.json …
  tmp/           in-flight downloads, wiped at boot
config.json      { "tokenEnc": "<base64 safeStorage>" }  (plaintext "token" only if safeStorage is unavailable)
window.json      { x, y, width, height }
```

IndexedDB lives under the `app://orbit` origin, which never changes, so learner data
survives every bundle update.

## Boot

1. Register the `app` scheme as privileged; `app.enableSandbox()` unless `--no-sandbox`
   was passed (root in CI); apply `ORBIT_USER_DATA`; take the single-instance lock.
2. On ready: `updater.resolveActive()` picks the bundle to serve (below), and
   `protocol.handle('app', …)` serves it. Only host `orbit`; paths are decoded and
   rejected if they contain `..`, NUL or a backslash or resolve outside the bundle
   directory; MIME from a fixed map; `Cache-Control: no-cache`; no CSP header (the
   playground loads Pyodide and sql.js from cdn.jsdelivr.net).
3. Splash window (760×460, frameless, no preload) and the main window (1280×820,
   hidden) are created; the main window loads `app://orbit/` (or `ORBIT_DEV_URL`).
4. The window is shown when the renderer sends `orbit:ready` (or, for the trusted
   built-in bundle, 300 ms after `did-finish-load`) *and* the splash has been up for the
   minimum time. Then the splash fades and closes.
5. Failure during boot (`did-fail-load`, `render-process-gone`, or no `orbit:ready`
   within 15 s on a downloaded bundle): a downloaded bundle is quarantined and the app
   relaunches; the built-in bundle shows an error and quits. If quarantining itself
   fails (nothing could be written under `bundles/`), the app shows an error naming
   that folder and quits rather than relaunching into the same bundle again. The
   renderer sends `orbit:ready` only after React's first commit, and never once its
   error boundary has taken over, so a bundle that crashes in its first render is
   caught by the watchdog too.
6. A few seconds after boot the updater checks quietly (not in E2E mode).

Active bundle resolution, synchronous at startup:

1. `builtIn = { dir, version: dist/orbit-bundle.json.version ?? app.getVersion() }`.
2. Read `current.json`. `bundles/<version>` is valid iff `index.html` and
   `orbit-bundle.json` exist, its `version` matches, it is newer than the built-in one,
   `shell >= minShell`, and it is not in `bad.json`.
3. Valid → use it; otherwise use the built-in bundle and reset `current.json`.
4. Garbage-collect bundle directories that are neither current nor previous; wipe `tmp/`.

## Updater

`Updater` is a plain `EventEmitter` with injectable `fetchImpl`, `getToken` and `log`,
which is what makes it unit-testable without Electron. It emits `'state'` on every
transition, `'relaunch'` when the shell should restart, and `'quit'` when it should
exit so a downloaded app can be swapped in.

```
idle → checking → up-to-date | available | shell-required | error
       available → downloading → ready → (apply) relaunch
       shell-required: shellUpdate downloading → ready → (installShell) quit, swap, open
                                   └→ manual | error (with the reason; the card links the DMG)
```

- **check**: `GET {apiBase}/repos/{repo}/releases/latest` with
  `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`,
  `User-Agent: ORBIT-desktop/<shell>` and `Authorization: Bearer <token>` when one is
  stored. 401 → "GitHub rejected the access token." 404 without a token → asks for one.
  Then it fetches the `orbit-manifest.json` asset (`Accept: application/octet-stream`),
  following redirects by hand and **dropping the Authorization header** on the hop — the
  signed storage URL GitHub redirects to rejects it. `manifest.version <= active` →
  up-to-date; `manifest.bundle.minShell > shell` → shell-required (with the DMG link);
  otherwise available.
- **download**: streams `orbit-bundle-<version>.zip` to `bundles/tmp/`, hashing as it
  goes; aborts past the promised size; verifies size and SHA-256; extracts with
  `zip.js`; checks `index.html` and `orbit-bundle.json.version`; renames into place;
  removes the version from `bad.json`. Any failure → `error` with a plain message and
  the temp files removed.
- **apply**: `current.json = { version: latest, previous: active }` → relaunch.
- **rollback**: `current.json = { version: null }` → relaunch (the built-in bundle).
- **quarantine(v)**: adds `v` to `bad.json` and points `current.json` at `previous`.
  The two writes are independent (either alone keeps the next boot off `v`); it throws
  only when neither could be written.
- A failed **check** after a download keeps `ready` (with `error` set) as long as the
  extracted bundle still validates, so an offline laptop can still restart into it.
- **downloadShell** (only in `shell-required`): asks the injected `shellInstaller`
  (`shellInstall.js`) whether this copy can replace itself — macOS, packaged, not
  running from App Translocation, parent folder writable — and reports
  `shellUpdate.status = 'manual'` with the reason when not. Otherwise streams
  `ORBIT-<v>-universal-mac.zip` (same auth and redirect handling as the bundle) to
  `userData/shell-update/`, verifies its size and SHA-256 against `shell.zipSize` /
  `shell.zipSha256` (or the size GitHub reports, for releases without them), unpacks
  it with `ditto`, and checks the app's `CFBundleShortVersionString` and
  `codesign --verify --deep --strict`. Then `shellUpdate.status = 'ready'`.
- **installShell**: writes and starts, detached, a bash script that waits for this
  process to exit, moves the app aside, moves the new one into its place (a rename on
  the same volume, else `ditto`), clears quarantine, deletes the download and opens the
  new app — and puts the old app back and opens it if the move fails. Its log is
  `userData/shell-update.log`. Then emits `'quit'`. The next boot deletes any
  `shell-update/` left behind.
- The app therefore jumps straight to the latest release whatever version it is on;
  only shells from before 1.1.1, which have no `downloadApp`, fall back to the DMG link.

### Automatic updates (1.1.3+)

With `autoUpdate` (on unless `ORBIT_AUTO_UPDATE=0`), updates arrive the way they do
in any other app, with nothing to press:

- Whatever **check** finds is fetched in the background: `download()` for a bundle,
  `downloadShell()` for an app when the release needs one and this copy can replace
  itself. Checks run 4 s after launch, every hour from the main process (so ORBIT
  sitting in the dock with no window still keeps up), and every 30 minutes or on focus
  from the renderer.
- A verified bundle is **staged**: `current.json = { version: new, previous: active }`
  is written at once, so the next launch opens it whether or not anyone presses
  Restart now (which still works, and simply relaunches into it). The running session
  is untouched. State carries `staged: true`. If the staged bundle never boots, the
  watchdog's `quarantine()` sends the launch after back to `previous`.
- A verified app is swapped in **on quit**: `will-quit` calls `installOnExit()`, which
  starts the same swap script with `reopen = 0`, so the new app is simply there next
  time. Install and reopen still installs it straight away.
- State carries `autoUpdate: true`. On older shells, which lack all of this, the
  renderer starts the downloads itself (`src/lib/updateWatch.ts`), and a restart
  finishes the update.

`orbit.minShell` only moves when a bundle genuinely cannot run on older shells — every
bump sends everyone a whole app instead of a small bundle, so keep it where it is
unless the bridge the bundle needs has changed.

Release manifest (`orbit-manifest.json`, written by `scripts/make-bundle.mjs`):

```json
{
  "schema": 1,
  "version": "1.0.1",
  "publishedAt": "2026-09-22T00:00:00Z",
  "notes": "markdown release notes",
  "bundle": {
    "name": "orbit-bundle-1.0.1.zip",
    "url": "https://github.com/begindtheseen/space/releases/download/v1.0.1/orbit-bundle-1.0.1.zip",
    "sha256": "…64 hex…",
    "size": 6123456,
    "minShell": "1.0.0"
  },
  "shell": {
    "version": "1.0.1",
    "dmgUrl": "https://github.com/begindtheseen/space/releases/download/v1.0.1/ORBIT-1.0.1-universal.dmg",
    "zipUrl": "https://github.com/begindtheseen/space/releases/download/v1.0.1/ORBIT-1.0.1-universal-mac.zip",
    "zipSha256": "…64 hex…",
    "zipSize": 212345678
  }
}
```

`shell.zipSha256` and `shell.zipSize` are added by the release job once the Mac app
is built (the manifest itself is written on Linux, before it exists).

Release asset names: `orbit-manifest.json`, `orbit-bundle-<v>.zip`,
`ORBIT-<v>-universal.dmg`, `ORBIT-<v>-universal-mac.zip` (CI), and
`ORBIT-<v>-arm64-mac.zip` / `ORBIT-<v>-x64-mac.zip` from local Linux builds.

## The bridge

`preload.cjs` exposes `window.orbit` with `contextIsolation` and the sandbox on. The
web app treats it as optional — in a browser it is simply absent.

```ts
interface OrbitBridge {
  platform: 'darwin' | 'win32' | 'linux'
  versions: { shell: string; bundle: string; builtIn: string; electron: string }
  ready(): void
  updates: {
    getState(): Promise<UpdateState>
    check(): Promise<UpdateState>
    download(): Promise<UpdateState>
    apply(): Promise<void>
    rollback(): Promise<void>
    downloadApp(): Promise<UpdateState>   // shell-required: fetch + verify the latest app (1.1.1+)
    installApp(): Promise<void>           // quit, swap it in, open it (1.1.1+)
    setToken(token: string | null): Promise<UpdateState>
    onState(cb: (s: UpdateState) => void): () => void
  }
  openExternal(url: string): Promise<void>            // https: and mailto: only
  onNavigate(cb: (path: string) => void): () => void  // menu → '/settings'
}
```

Every main-side handler validates its arguments and returns
`{ ...state, status: 'error', error }` rather than throwing across IPC. Tokens must match
`/^[A-Za-z0-9_]{20,255}$/`. Window guards: `setWindowOpenHandler` opens `https:` links
externally and denies everything else; `will-navigate` allows only `app://orbit/*` (and
the dev URL's origin); permission requests are denied; webviews cannot attach.

## Environment overrides

| Variable | Effect |
| --- | --- |
| `ORBIT_UPDATE_API_BASE` | GitHub API base (default `https://api.github.com`); the e2e run points it at a local fake |
| `ORBIT_USER_DATA` | `userData` directory, set before ready |
| `ORBIT_E2E=1` | Splash minimum 300 ms, boot watchdog 3 s, no auto-check, no automatic downloads (unless `ORBIT_AUTO_UPDATE=1`), and apply/rollback quit instead of relaunching so a harness can relaunch itself |
| `ORBIT_AUTO_UPDATE=0` | Turn off automatic downloads, staging and install-on-quit; the Settings buttons do it all by hand |
| `ORBIT_DEV_URL` | Load a Vite dev server instead of `app://orbit/` |

## Packaging

`electron-builder.yml`: `desktop/**` and `package.json` go into `app.asar`; `dist/`
goes beside it as an extra resource; universal DMG + zip; ad-hoc signing by
`scripts/after-pack.cjs` (`codesign` on macOS, `rcodesign` on Linux when present), no
notarisation. Scripts:

```
npm run build:bundle   vite build with a relative base, then stamp dist/orbit-bundle.json
npm run bundle         + release/orbit-bundle-<v>.zip and release/orbit-manifest.json
npm run desktop        build:bundle, then run the shell from the repo
npm run desktop:pack   build:bundle, then electron-builder --mac (DMG needs macOS)
npm run desktop:zip    release/ORBIT-<v>-<arch>-mac.zip drag-install zips from release/mac*/
npm run desktop:icon   regenerate desktop/icon/icon.png from public/icon.svg
npm run desktop:e2e    the end-to-end run (needs a built bundle; use xvfb-run -a on Linux)
```

On Linux the mac zips can be built per architecture (universal and DMG need macOS):

```bash
npx electron-builder --mac zip --arm64 --x64 -c.mac.target=zip --publish never
```

## Testing

- `npx vitest run desktop/test` — updater state machine against a fake fetch, zip
  fixtures (deflate, stored, path traversal must throw), semver, crc32.
- `xvfb-run -a npm run desktop:e2e` — launches the real app with `ORBIT_E2E=1` against a
  fake GitHub API on localhost, walks check → download → restart → rollback →
  quarantine → token, screenshots into `release/e2e/`, exits non-zero on any failure.
- Running as root here needs `--no-sandbox` on the Electron binary
  (`npx electron --no-sandbox .`); the e2e run passes it itself.
