## Problems in the module definitions (src/curriculum/coding.ts, not edited)

### Wrong: fix these

1. **cod_lnx_02_scripting · lnx02_c1** (`set -euo pipefail` card)
   - **Problem:** it says pipefail makes a pipeline "return the first non-zero status". Bash returns the rightmost non-zero status: `(exit 3)|(exit 5)|true` gives 5. Quiz q1's explanation already says this correctly.
   - **Fix:** replace "return the first non-zero status" with "return the status of the rightmost command that failed".

2. **cod_py_02_idiomatic · py02_q2** (decorator and pytest quiz)
   - **Problem:** it says pytest "no longer collects" the wrapped tests, and the explanation says collection relies on `__name__`. That is false. pytest collects by the name bound in the module, so the tests are still collected. Without `wraps`, pytest sees the signature `(*args, **kwargs)`, so fixtures are not injected, and marks set on the original function are lost.
   - **Fix, question:** "A decorator is applied to test functions, and now their fixtures are not injected and their marks are lost. Likely cause?"
   - **Fix, explanation:** "pytest reads the test's signature to inject fixtures and reads its `__dict__` for marks. `functools.wraps` copies `__wrapped__` (so the real signature is visible), `__name__`, `__doc__` and `__dict__` onto the wrapper."

3. **cod_py_02_idiomatic · py02_c6** (why `functools.wraps`)
   - **Problem:** it says the wrapper "replaces the original `__name__`, `__doc__`, `__module__` and `__wrapped__`" and "breaks pytest test collection". Without `wraps` there is no `__wrapped__` at all, and the pytest damage is to fixtures and marks, not collection.
   - **Fix:** "Without it the wrapper's own `__name__`, `__doc__` and `__module__` hide the original's, and there is no `__wrapped__` pointing back to it. That breaks help(), tracebacks, pytest fixture injection and marks, and any tool that inspects signatures."

4. **cod_cpp_02_memory · cpp02_ex2** (struct layout and wire format)
   - **Problem:** the solution names the reordered struct `PacketPacked`, but it is not packed; it is only reordered, 16 bytes with 1 byte of padding. Lesson 10 uses `PacketPacked` for the real `__attribute__((packed))` 15-byte struct, so the names clash.
   - **Fix:** rename `PacketPacked` to `PacketOrdered` everywhere in the solution.

5. **cod_cpp_02_memory · cpp02_c7** (padding and wire formats)
   - **Problem:** "Serialise field by field with memcpy in a defined order and endianness" reads as if a per-field `memcpy` sets the endianness. It does not: `memcpy` copies the host byte order. The exercise solution itself warns about this.
   - **Fix:** "…Serialise field by field in a defined order, placing each byte with shifts so the endianness is fixed (use memcpy only to get a float's bit pattern into an integer), instead of memcpy-ing the whole struct."

6. **cod_lnx_01_shell · lnx01_ex1** (worst-case miss distance)
   - **Problem:** the solution `awk -F'[: ]+' '{print $1 ":" $3}'` is correct only if the line starts with `MISS_DISTANCE_M`. If a timestamp comes first, as in the lessons' own logs, `$3` picks up part of the time.
   - **Fix:** use `$NF`, the last field, which works for both shapes: `awk -F'[: ]+' '{print $1 ":" $NF}'`.

### Unclear or incomplete: recommended

7. **cod_py_01_basics · py01_c12** (mutability)
   - **Problem:** the back ends "mutable ones cannot and cannot.", which reads as garbled.
   - **Fix:** "…Immutable objects can be dict keys and can be safely shared; mutable ones cannot be dict keys, and sharing them lets one change show up everywhere."

8. **cod_py_02_idiomatic · py02_c8** (dataclass vs plain class)
   - **Problem:** it says a dataclass generates "optionally `__eq__`". `__eq__` is generated by default and is only turned off with `eq=False`. Ordering is the optional part (`order=True`).
   - **Fix:** "A dataclass generates `__init__`, `__repr__` and `__eq__` (and ordering with `order=True`) from annotated fields…"

9. **cod_lnx_01_shell · lnx01_c8** (why `&` jobs die)
   - **Problem:** true but incomplete. The kernel sends SIGHUP to the shell and the foreground process group. A background job has its own process group and dies because bash passes the SIGHUP on to its jobs.
   - **Fix:** "Closing the terminal sends SIGHUP to the shell (and the foreground group), and bash passes it on to every job it owns…"

10. **cod_py_01_basics · py01_c13** (`is` vs `==`)
    - **Problem:** "small-int and string interning": small ints are cached, strictly, not interned.
    - **Fix:** "small-integer caching and string interning make `is` appear to work…"

11. **cod_cpp_01_basics · cpp01_c5** (`int8_t x = 200`)
    - **Problem:** "with -Wconversion the compiler warns" is true for g++. clang++ warns even without the flag (`-Wconstant-conversion` is on by default).
    - **Fix:** "…and compilers warn (g++ with -Wconversion; clang++ by default)."

12. **cod_cpp_01_basics · cpp01_q4** (-O2 vs -O0)
    - **Problem:** the correct answer mentions "floating-point contraction", which the module teaches in only one added sentence, in lesson 05. The question is still answerable from undefined behaviour alone.
    - **Fix (either):** leave it as is, or change the choice to "-O2 can expose latent undefined behaviour and change floating-point results, so both configurations must be tested".

13. **cod_cpp_01_basics · cpp01_c13** (`std::array`)
    - **Problem:** it uses "aggregate" without a definition. Lesson 09 now defines it after the key block, so no change is needed.

14. **Spelling**

    - **Fix:** change them to American spelling to match the course voice.

15. **cod_lnx_02_scripting · lnx02_ex2**
    - **Problem:** it splits on `-F'[= ]'` (one character), while the lessons teach `-F'[= ]+'`. Both work on the prompt's single-spaced lines.
    - **Fix:** optional; `-F'[= ]+'` is more robust.
